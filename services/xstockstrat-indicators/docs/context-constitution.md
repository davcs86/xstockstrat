## Rules (`INDICATORS-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **INDICATORS-1** | **Pin BLAS/OMP/MKL/NUMEXPR/VECLIB thread counts to 1 in the child subprocess env, *before* numpy is imported** (passed via the `_sandbox_env()` dict, not set inside the formula). | Numeric libs spawn one worker thread per core on import, each reserving a large buffer that overflows the sandbox rlimit → `OpenBLAS error: Memory allocation still failed after 10 retries`. Days lost to a "flaky sandbox." The same abort also occurs with pinned threads when the memory headroom is too tight; it is classified `memory_exceeded` (feature 228). | `app/services/sandbox.py#_THREAD_LIMIT_ENV` (~L52), applied in `#_sandbox_env` (~L161); PR #663 | `app/services/sandbox.py#_THREAD_LIMIT_ENV` (~L52) |
| **INDICATORS-2** | **The sandbox memory cap uses `RLIMIT_DATA`, never `RLIMIT_AS`.** | `RLIMIT_AS` counts virtual address space, which numpy/pandas over-reserve on import (hundreds of MiB never resident) → the 128 MiB cap rejects pandas with `MemoryError` before any real allocation. `RLIMIT_DATA` tracks actual allocation, keeping the budget enforceable. The limit is the runtime-measured pre-lockdown `VmData` baseline plus `indicators.sandbox.memory_bytes` headroom (feature 228); the baseline is neither a tunable nor a constant (`@AC-6 @feature-209`), so a larger `allowed_imports` costs container memory, not formula budget. `RLIMIT_DATA` is the first line, not the only one (feature 300): a parent-side watchdog samples the process group every `_TICK_S` and kills on `VmData` growth or resident memory beyond the same headroom, because DigitalOcean was observed not to enforce the rlimit and shared mappings never count against it. Residuals: a one-tick burst goes unreported, and per-run fail-open when the parent cannot observe the child. | `_VMDATA_PROBE` `app/services/sandbox.py:66` (fail-closed); `setrlimit(resource.RLIMIT_DATA, (_cap, _cap))` `:623` (cap `:622`, "not RLIMIT_AS" note `:618`); `_HANDOFF` `:85`, `_sample_group` `:367`, `_over_budget` `:428`, `_watch` `:434`; PR #663 | `app/services/sandbox.py:623` |
| **INDICATORS-3** | **Deserialize a protobuf `Struct` with `MessageToDict()`, never `dict()`.** | `dict()` unwraps only the top level; nested `ListValue`/`Struct` fields stay as protobuf objects and crash the sandbox at `json.dumps(input_data)` with "Object of type ListValue is not JSON serializable". | `app/handlers/servicer.py#ExecuteFormula` (`MessageToDict(request.input_data)` ~L300); `app/services/parameters.py:50,153`; PR #650 | `app/handlers/servicer.py#ExecuteFormula` (`MessageToDict(request.input_data)` ~L300) |
| **INDICATORS-4** | **Restricted builtins are built by copying a safe subset into a fresh `__builtins__`, never by deleting names off the shared `builtins` module.** | Mutating/`del`-ing names off `builtins` breaks the interpreter (import machinery, `delattr`) so even `result = 1` fails with `NameError`. | `app/services/sandbox.py#"_restricted_builtins = {{}}"` (~L588; safe-subset copy ~L588-597) | `app/services/sandbox.py#"_restricted_builtins = {{}}"` (~L588) |
| **INDICATORS-5** | **Header authz is read per-method off `context.invocation_metadata()` (admin = `x-access-scope & 0x04`; author = `x-user-id`) — there is no interceptor; owner-scoped RPCs go through the `@owner_scoped` decorator → `_reader` (empty `x-user-id` → UNAUTHENTICATED; `system` without a SAN-bound grant → PERMISSION_DENIED), and admin scope grants an audited READ only — `ExecuteFormula`/update/delete are never admin-grantable.** | Python services thread propagation per method (not via a Go-style interceptor); its only outbound per-request call is the feature-224 ledger `audit.admin_read` append (`app/admin_audit.py`), and `x-internal-caller` grants additionally require the mTLS peer SAN `xstockstrat-analysis` (`_internal_grant`, `app/peer_identity.py`). | `app/handlers/servicer.py#_has_admin_scope` (~L120), `x-user-id` read in `#_reader` (~L130; read ~L133) | `app/handlers/servicer.py#_has_admin_scope` |
| **INDICATORS-6** | **The sandbox child must run as a DISTINCT UID (nobody 65534) — the container therefore runs as root (no `USER` in the Dockerfile) so the child can `setuid` down.** | A same-UID seccomp filter cannot block `process_vm_readv` / `/proc/<parent>/environ` reads of the parent's in-memory secrets; cross-UID is what closes that. Adding a `USER` line removes the root parent and silently breaks the drop (feature 209). | `app/services/sandbox.py#_SANDBOX_UID` (~L62) + `#"os.setuid({_SANDBOX_UID})"` (~L77); Dockerfile has no `USER`; feature 209 design §1 | `app/services/sandbox.py#"os.setuid({_SANDBOX_UID})"` (~L77) |
| **INDICATORS-7** | **The seccomp filter is an ALLOWLIST (`defaction=ERRNO(EPERM)`, native arch only) loaded AFTER the numeric-lib import and immediately BEFORE `exec(source)` — never before `execve`, never a denylist.** | Post-import shrinks the surface to compute-only, and **no file-open syscall (`openat` etc.) is allowed**, because module-attribute traversal reaches the real `os` past the import guard. Allowed modules' lazy attributes must therefore be resolved before the load. An allowlist fails **closed** (compat x86/x32 arches + io_uring + unknown syscalls → EPERM), where a denylist fails open on a forgotten bypass. `_SECCOMP_ALLOW` is the audited set (feature 209). | `app/services/sandbox.py#_SECCOMP_ALLOW` (~L107); build `#"_flt = _seccomp.SyscallFilter"` (~L636) + load `#"_flt.load()"` (~L642); feature 209 design §3 | `app/services/sandbox.py#_SECCOMP_ALLOW` (~L107) |
| **INDICATORS-8** | **`PR_SET_NO_NEW_PRIVS` must stay set before the seccomp load — never disable it.** | An unprivileged `seccomp()` filter load requires `no_new_privs` (else EACCES); `pyseccomp` sets it by default on `.load()` and the wrapper also sets it explicitly. Disabling it breaks the nobody-child load. | `app/services/sandbox.py#"prctl(38, 1, 0, 0, 0)"` (~L613) | `app/services/sandbox.py#"prctl(38, 1, 0, 0, 0)"` (~L613) |
| **INDICATORS-9** | **`Popen(start_new_session=True)` + `killpg(SIGKILL)` before the leader is reaped (timeout, watchdog breach) is load-bearing for the NPROC bound. The `finally: _killpg(proc)` is NOT a safety net on the success / non-zero-exit paths:** `_killpg` kills `proc.pid` only while `proc.returncode is None`, so once `communicate()` has reaped the child the call is a no-op and a `fork()+sleep(∞)` grandchild that outlives a normally-exiting child is never killed (findings; a real post-reap sweep is a separate design decision). `communicate()` is the only reaper, so a sample or a kill never races a recycled pid.** | A `fork()+sleep(∞)` grandchild survives the direct-child kill and `RLIMIT_CPU` (burns no CPU) and would hold a uid-65534 `RLIMIT_NPROC` slot forever → permanent DoS. The process-group kill is what makes the NPROC bound hold (feature 209). | `app/services/sandbox.py#_killpg` `:656` (`os.killpg(proc.pid, …)` `:665`); `start_new_session` `:729`; timeout-path kill `:761`; `finally: _killpg(proc)` `:856` | `app/services/sandbox.py#_killpg` |
| **INDICATORS-10** | **`import pyseccomp` in the child wrapper BEFORE `RLIMIT_NPROC` is set (and before the seccomp load).** | `pyseccomp`'s `find_library` forks `ldconfig`, which fails under the NPROC cap (commit `fafa11f`) — never make the import lazy. | `app/services/sandbox.py#"Import before RLIMIT_NPROC"` (one authoritative site) | `app/services/sandbox.py#"Import before RLIMIT_NPROC"` |
| **INDICATORS-11** | **`tempfile.gettempdir()` is resolved (pre-cached) in the child BEFORE `RLIMIT_FSIZE=0` is applied.** | numpy/pandas probe temp dirs by writing a byte; with `FSIZE=0` that yields "No usable temporary directory". The `import tempfile` looks unused — don't drop or reorder it. | `app/services/sandbox.py#"import tempfile as _tempfile"` (one authoritative site) | `app/services/sandbox.py#"import tempfile as _tempfile"` |
| **INDICATORS-12** | **`indicators.formulas.author` is a user id (UUID) or `SYSTEM_AUTHOR`; a non-UUID author is a legacy row that the owner cannot read (`app/handlers/servicer.py#_can_read_formula`, ~L151). Repair only through `app.maintenance.legacy_authors`, whose rewrite UPDATE carries the system/UUID guard in the SQL.** | The read guard allows only the owner or the system author, so a formula whose author is a username is invisible to its owner (staging, 2026-10-22, feature 276). | `app/maintenance/legacy_authors.py` `REWRITE_SQL` (`:32-36`); runbook `docs/runbooks/legacy-formula-authors.md` | `app/maintenance/legacy_authors.py:32-36` |
| **INDICATORS-13** | **Soft-deleted formulas stay readable and executable by id; pending saga copies are hidden in four places.** `FormulasRepository.get_by_id` has no `deleted_at` filter and `_load_formula` filters only `pending_intent_id`; `repo.delete` soft-deletes on purpose ("strategies referencing it keep evaluating"), `_list` excludes deleted rows, `UpdateFormula` returns `FAILED_PRECONDITION`, and `_row_to_formula` reports `deleted=True`. A pending template copy (`pending_intent_id` set) is invisible only in `_load_formula`, `UpdateFormula`, `DeleteFormula` and `_list`, so a new read path built on bare `get_by_id` leaks uncommitted copies. | Adding `deleted_at IS NULL` to `get_by_id`/`_load_formula` makes saved strategies that reference a deleted formula fail at execution; answering Get/Execute of a deleted id with NOT_FOUND is equally wrong. The intent is stated only in repo comments. | `app/services/formulas_repository.py#delete` (comment), `#get_by_id`; `app/handlers/servicer.py#_load_formula`; `app/maintenance/legacy_authors.py` ("get_by_id serves soft-deleted rows too") | `app/services/formulas_repository.py#delete` |

## Gotchas & scars

- **The seed formula id is a deterministic UUIDv5 that xstockstrat-analysis consumes as config.** `FORMULA_ID = d1ff5e6b-6d9c-589d-b95e-defd862c702b` (`app/formulas/fundamentals_value_quality.py`, seeded `app/services/seed_formulas.py:35`) is read by analysis as `analysis.fundsignal.scoring_formula_id` **when an operator sets it** (the seeded value is empty — "empty = built-in default", config migration 008) (feature 062). Changing the UUID or the `SYSTEM_AUTHOR` breaks the cross-service link. Evidence: the `SYSTEM_AUTHOR` guards in `app/handlers/servicer.py#UpdateFormula` / `#DeleteFormula` (~L561, ~L664). The UUID is also hardcoded in applied analysis seed data — `services/xstockstrat-analysis/migrations/029_seed_fundamentals_blend_strategy.up.sql#d1ff5e6b-6d9c-589d-b95e-defd862c702b` and `services/xstockstrat-analysis/tests/test_seed_strategy_templates.py#_SYSTEM_FORMULA_ID` (~L37) — so changing it now breaks seeded rows, not just an operator-set key.
