## Gotchas & scars

- **Webhook and commsgun workers differ on purpose — don't copy one onto the other.** Commsgun escalation is at-least-once (`escalated_at` stamped after the alert, re-raised every tick: `src/fanout/commsgunWorker.ts#sweep`, `#stampEscalated`) while `src/fanout/webhookWorker.ts#markDead` has no persisted marker; commsgun logs only a SQLSTATE/fixed word (`commsgunWorker.ts#errorCode`, "a pg error message can quote row values") while the webhook worker logs `err?.message`; commsgun honours `Retry-After` and its `stop()` is async (awaits terminal steps before `pool.end()` in `src/index.ts#main`). Copying the webhook catch blocks into commsgun code would leak recipient/subject text into logs.

- **The Web Push channel gates on severity ONLY; unlike the sibling `FanoutDispatcher` it deliberately does NOT gate on `context.conviction`** ("Never gate on a context key — no producer reliably writes one"). An agent copying fanout's conviction gate into `webPush.dispatch` silently drops pushes for conviction-less alerts. Evidence: `src/fanout/webPush.ts#dispatch` severity gate (~L98-105) vs `fanout.ts#dispatch` conviction gate (~L68-79).
- **VAPID misconfig fails loud ONCE and disables the channel (`vapidConfigured=false`), never throwing per-send.** If all three VAPID vars are present but `VAPID_SUBJECT` isn't `mailto:`/`https:`, the constructor logs ERROR once and disables push — because a malformed subject would otherwise throw on every `sendNotification` and be swallowed to WARN by the per-dispatch catch (a channel that looks enabled but black-holes every push). "Simplifying" the subject regex to a non-empty check re-introduces the silent black-hole. Evidence: `src/fanout/webPush.ts#subjectValid`/`vapidConfigured` (~L67-78).
- **Web Push message TTL and the outbound send timeout are two deliberately-separate constants — never re-conflate them.** `WEBPUSH_TTL_SECONDS = 3600` and `WEBPUSH_SEND_TIMEOUT_MS = 10000` (`src/fanout/webPush.ts#WEBPUSH_TTL_SECONDS` ~L18-19) are passed distinctly to `webpush.sendNotification({ TTL, timeout })` (`#deliver` ~L179-183), pinned by a regression test asserting `opts.TTL === 3600` and a separate real `opts.timeout` (`src/__tests__/webPush.test.ts` "sends a deliberate 1h message TTL" ~L486). The shipped 2026-09-03 defect reused one value for both, passing the 10s HTTP timeout as the TTL — so every push got a 10-second message TTL and any device offline > ~10s silently never received the OS alert. Reusing one constant for both re-opens a whole class of dropped trading alerts with no error.
