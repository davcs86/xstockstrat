## Gotchas & scars

- **`@bufbuild/protobuf/wkt` `timestampFromDate(date)` is the canonical Date→Timestamp *constructor*** (`protoTime.ts` has no construct helper, only decode). Request-building code uses it: `useSignalAttribution.ts:2`, `ConfirmFillDialog.tsx:5`, `OrderFilters.tsx:8`, `insights/backfills/page.tsx:4`, `trader/api/ledger/export/route.ts:3` (N=5). Hand-rolling `{ seconds: BigInt(Math.floor(d.getTime()/1000)), nanos: … }` in a request body is verbose, BigInt-mix-prone, and diverges from this convention.
- **Exhaustive `Record<ProtoEnum, …>` render maps are keyed so `tsc` fails on a new enum value** — `roleLabels.ts:5-10` (`ROLE_LABELS: Record<Role,string>`) generalizes the `opportunityShared.tsx` convention ("adding a proto Role value without a label here fails `tsc`"). At least five files now carry them: `src/lib/sectors.ts#SECTOR_LABEL` (feature 217), `src/lib/roleLabels.ts#ROLE_LABELS`, `src/lib/opportunityShared.tsx` (6 maps, incl. `FUNDAMENTALS_GAP`), `src/lib/readinessCue.ts#READINESS_CUE`, `src/components/trader/orderShared.tsx` (`TIF_LABEL`, `INTENT_STATE_RENDER`) — plus `BacktestDiagnostics.tsx` (`NO_TRADE_MESSAGE`, now incl. `FUNDAMENTALS_UNAVAILABLE`) and `hooks/useTemplates.ts`. Building a role/enum→label with a `switch`+`default` or a partial object renders a new proto enum value as a bare number/blank at runtime instead of failing the build. Evidence: `src/lib/roleLabels.ts:5-10`, `src/lib/opportunityShared.tsx`.
- **PWA support state must resolve SYNCHRONOUSLY; never gate loading on `navigator.serviceWorker.ready`.** `PushToggle` decides support synchronously from feature-detection + `Notification.permission`; reading the existing subscription via `.ready` is fired as best-effort background work, because `.ready` "can hang indefinitely in some headless environments (CI), leaving the control stuck on the spinner." `await`-ing `.ready` before rendering makes the toggle stick on the spinner in CI/headless and flakes the e2e. Evidence: `src/app/accounts/notifications/PushToggle.tsx:31-62`.

- **On any `status >= 400` the BFF dispatch strips `content-encoding`/`grpc-encoding`/`content-length` and forces `content-type: application/json`** — a forwarded downstream `ConnectError` otherwise carries the gRPC response's content-type/encoding and the browser Connect client surfaces a generic "HTTP <status>" instead of the real validation message. Load-bearing for error-message fidelity; don't "simplify" it away. Evidence: `src/lib/bffShared.ts#createDispatch` (`uRes.status >= 400` ~L140-145, comment ~L138-139).
- **`#901`/`#884` — config-value staleness after save (see `xstockstrat-config`'s CONFIG-6/7/PROTO-5).** `NamespaceEditor`'s Value column and edit-prefill originally read `ConfigKeyMeta.defaultValue` (never updated by `SetConfig`), so every successful save *looked* like a silent no-op until `currentValue` was added (display at `src/app/config-ui/[namespace]/NamespaceEditor.tsx:135`, edit-prefill at `:308`); separately, Save on a `trading_mode='all'` row failed until the page started echoing the row's own registered scope instead of its viewed filter. A future config-metadata read must use `currentValue`, and a future Save must echo the row's own scope, not the page's filter state.
- **`63a3655` — strategy pickers must filter on `live_enabled`, not just `active`.** The Decide "why this fired" picker and the Watchlists per-symbol strategy binding both listed every `active` strategy regardless of `live_enabled`. The real trading loop was independently verified already-correct — this was a read-surface-only gap.
- **`d92960b` — `symbolLocked` is the canonical convention for a page keyed to one fixed symbol.** Signal-detail's `OrderForm` symbol field was fully editable despite the whole page (chart/conviction/edge) being keyed to one symbol; the fix introduced `symbolLocked` (`OrderForm.tsx#symbolLocked`, ~L97, `const symbolLocked = Boolean(initialSymbol)`) as the pattern any future single-symbol-context order ticket should reuse rather than reinventing.
- **BFF deadlines are opt-in and per-handler.** `forward(call, {timeoutMs})` is the only way to bound a BFF unary call; without it a stalled upstream leaves the browser query pending forever and a fundamentals/snapshot card never reaches its error state (feature 220). Fundamentals reads use `FUNDAMENTALS_TIMEOUT_MS` (15 s); `forwardAdmin` takes no options, so an admin handler that needs a deadline must use `forward(call, {admin:true, timeoutMs})`. Evidence (N=4): `src/lib/bffShared.ts#FUNDAMENTALS_TIMEOUT_MS` (authoritative), `src/lib/traderBff.ts#getFundamentals`, `src/lib/insightsBff.ts#getFundamentals`, `src/lib/insightsBff.ts#getFundamentalsMulti`; `listOpportunities` hardcodes its own `30_000`.
- **Feature-215 fundamentals-skip rows take badge precedence and bypass the conviction floor.** `fundamentalsUnavailable` is checked BEFORE `muted` in every badge slot (desktop `OpportunityRow`, mobile `SignalRow`) and before the action badge on the detail `OpportunitySection`; the e2e mock exempts these rows from the conviction floor alongside muted/data-unavailable rows, mirroring the backend. Reordering the branches renders a skip row as a muted/action badge. Evidence: `src/app/insights/opportunities/page.tsx#fundUnavailable` (~L489), `src/components/mobile/SectionRenderer.tsx#fundamentalsUnavailable` (~L170), `src/app/trader/positions/[symbol]/page.tsx#OpportunitySection` (~L979), `e2e/mock-backend.ts#"fundamentals-skip rows are exempt"` (~L873).
