# xstockstrat-ui — Constitution

Derived by `/context-constitution` 2026-07-24; last refreshed 2026-11-13 (`main-dev` @ `52f6d5a`).
Captures the **non-obvious** local invariants of the consolidated Next.js UI + gRPC BFF (`/trader`,
`/insights`, `/config-ui`, `/accounts`; HTTP 3000). The service CLAUDE.md is thorough, so this file
holds the asymmetries and scars the docs *don't* state. Does not restate documented/CI-enforced rules
(see `## Pointers`).

> Inherits all rules of the root constitution (`../../../docs/context-constitution.md`). This file lists only
> what is specific to **xstockstrat-ui**.

## Rules (`UI-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **UI-1** | **Timestamp→millis/Date conversion has THREE sanctioned forms — `src/lib/protoTime.ts` (`timestampToMillis`/`timestampToDate`, feature 068) OR the official `@bufbuild/protobuf/wkt` `timestampDate()` helper — never a hand-rolled `ts.seconds * 1000` / `new Date(ts)`.** protobuf-es `Timestamp` is `{seconds: bigint, nanos: number}`: `ts.seconds * 1000` throws `Cannot mix BigInt`, and `new Date(ts)` isn't a Date. | Several call sites still hand-roll the conversion (the exact set drifts with every feature — don't maintain a count; grep `\.seconds \* 1000`/`Number(.*\.seconds` before copying a neighbor). The `@bufbuild/protobuf/wkt` `timestampDate()` is now used at `config-ui/users/page.tsx` (~L168) and `trader/api/ledger/export/route.ts` (~L38) and is a sanctioned alternative, not a violation. Copying a *hand-rolled* site perpetuates the drift. | canonical `src/lib/protoTime.ts` (+ `protoTime.test.ts`); official helper `@bufbuild/protobuf/wkt` `timestampDate`; a hand-rolled site to *not* copy: `src/lib/chart.ts#Number(b.time.seconds)` (~L41) | `src/lib/protoTime.ts` |
| **UI-2** | **Browser typed clients are named per (service × segment) and hard-bound to that segment's BFF `baseUrl`** — import the client whose baseUrl matches the segment the component renders under. | `analysisClient` (`/insights/api`) vs `traderAnalysisClient` (`/trader/api`): importing the wrong one marshals to a BFF handler map with no matching entry → **404**. Since feature 153 both build on `makeBrowserTransport(baseUrl)` rather than a bare `createConnectTransport`. | `src/lib/browserClients/analysisClient.ts#makeBrowserTransport('/insights/api')` (~L5) vs `traderAnalysisClient.ts#makeBrowserTransport('/trader/api')` (~L6) (20 files in `src/lib/browserClients/`, growing) | `src/lib/browserClients/traderAnalysisClient.ts#makeBrowserTransport('/trader/api')` (~L6) |

> **UI-2 exception (sanctioned) — the unified `/trader/positions/[symbol]` page reuses `/insights`-segment browser clients.** `analysisClient`, `insightsIngestClient`, and `insightsPortfolioClient` (all `baseUrl: '/insights/api'`) are called directly from this `/trader`-segment page rather than re-registered in `traderBff.ts` (feature 125 design decision, 2026-08-10): the base URLs are root-relative so the browser `fetch()` stays same-origin regardless of which segment rendered the page; no segment-specific ingress routing exists — `.do/app.yaml`'s single `/` catch-all routes both `/trader/api` and `/insights/api` to the same DO component; the session cookie is `path: '/'`, not segment-scoped; and `bffShared.ts`'s `requireSession` re-checks the session on every dispatch independent of which BFF router handled it. This trades `/trader`'s BFF self-containment for avoiding duplicate one-line `forward()` registrations — do not treat it as precedent for arbitrary cross-segment reuse without re-verifying these four facts still hold.

| **UI-3** | **BFF handlers use the `forward`/`forwardAdmin` combinators and NEVER trust a body-supplied user — identity is resolved backend-side from the propagated `x-user-id` header** (`backendHeaders`). Since the platform-wide header-identity move, most handlers are plain `forward()`; an explicit `{ ...req, userId }` body survives ONLY where the value is a **cross-user filter** (`listOrders`, `streamOrderUpdates`, `streamAlerts` — empty = all users), the insights per-user secret write's **target row** (`insightsBff.ts` `userId: claims.user_id`), or a **server-forced ledger stream key** (`traderBff.ts#queryEvents` forces `copilotStreamKey(claims.user_id)` + `ownerOnly` and checks `account:` keys against `listBrokerAccounts`; `traderBff.ts#appendEvent` forces the stream key, event type and `sourceService`; `insightsBff.ts#queryEvents` forces `portfolio:${claims.user_id}`; `insightsBff.ts#setConfig` forces `userId`/`environment`/`createKey`); the config-ui `{ ...req, environment }` fill is the other explicit body. No BFF injects an `author` (feature 241 — config attributes from `x-user-id`). | The pre-DRY inline `requireSession`+`backendHeaders` shape trips the DRY guard rail; trusting a body `user_id` for identity is an IDOR (security invariant, root PLAT-11). | defs `src/lib/bffShared.ts#forward` (~L77), `#forwardAdmin` (~L93); header identity `src/lib/traderBff.ts#"Ownership comes from the x-user-id header"` (~L35); surviving filters `traderBff.ts#listOrders` (~L40-46), `#streamOrderUpdates` (~L58-64), `#streamAlerts` (~L97-103); insights target row `insightsBff.ts#userId: claims.user_id` (~L190; `#setConfig` ~L178-197); config-ui environment fill `configUiBff.ts#{ ...req, environment }` (~L54) | `src/lib/traderBff.ts#"Ownership comes from the x-user-id header"` (~L35) |
| **UI-4** | **The `x-access-scope` bitmap is computed here and consumed by backends** — `rolesToAccessScope` (READ 0x01/WRITE 0x02/ADMIN 0x04/TRADING 0x08); the bit meanings must stay in parity with every backend's `scope & 0x04` check. | UI is the producer of the header value backends gate on (root PLAT-5). | `src/lib/auth.ts#rolesToAccessScope` (~L86-97), `#ADMIN_SCOPE` (`0x04`, ~L84), `#hasAdminScope` (~L100-102); forwarded `bffShared.ts#backendHeaders` (scope header ~L53) | `src/lib/auth.ts#rolesToAccessScope` (~L86-97) |
| **UI-5** | **The `/accounts` segment deliberately uses plain Next REST route handlers, NOT the Connect `[...connect]` BFF** (a `NextRequest` isn't a Connect `HandlerContext`). Follow the local REST pattern there, not the BFF pattern. | The three other segments proxy via `createDispatch`; `/accounts` has no `[...connect]` route and no `accountsBff.ts`. The backend-header builder was DRY-extracted to `src/lib/restBackendHeaders.ts` (feature-127/finding-driven) and is **imported**, not re-implemented locally — reuse it. Consumers: `accounts/api/authorized-apps/route.ts` and `accounts/api/profile/route.ts`. | route handler `src/app/accounts/api/authorized-apps/route.ts#import { restBackendHeaders }` (~L6); shared builder `src/lib/restBackendHeaders.ts#restBackendHeaders` (~L9) | `src/lib/restBackendHeaders.ts#restBackendHeaders` (~L9) |
| **UI-6** | **`SCREEN_RESULT_STATUS_INSUFFICIENT_DATA` is retry-eligible signal, not an error.** The insights screener gates its background re-scan poll on rows carrying it (`pendingRows.length > 0`) and renders warning/pending badges; `ScreenResult.score_unavailable` (feature 144) is the *distinct* permanent "no usable criteria" case (since feature 245 also a status-OK evaluation-fault row). The analysis producer side of this contract is recorded in the analysis constitution (feature-144 scar). | `src/app/insights/screener/page.tsx#pendingRows` (~L125), poll gate (~L131), INSUFFICIENT_DATA render (~L257), `scoreUnavailable` (~L200,274); shared poll predicate `src/hooks/useScreenSymbols.ts#hasPendingRows` (~L16-18; the polling is bounded — `POLL_INTERVAL_MS` 60 s, `MAX_POLL_ATTEMPTS` 5 (~L22-23), then a "Gave up checking" notice, `insights/screener/page.tsx` ~L567-602 — and INSUFFICIENT_DATA has two causes, a bars gap and a fundamentals source unavailable (`pendingFundamentals` ~L123-126, `!r.gap`), both feeding the auto-recheck); trader consumer `src/components/trader/SymbolScreening.tsx#insufficient` (~L65; "Not evaluated" ~L254) | `src/app/insights/screener/page.tsx#pendingRows` (~L125) |
| **UI-7** | **Config-UI writes are guarded to THIS deployment's native environment: `configUiBff` fills an `UNSPECIFIED` env with `nativeConfigEnvironment()` and rejects any `SetConfig` not matching the native scope (`FailedPrecondition`); the compare normalizes `UNSPECIFIED` AND deprecated `DEV` → `STAGING` before matching (mirrors backend `resolveEnv`/`ENV_MAP`).** `APPLICATION_ENV` is server-only (never in the client bundle). ## Gotchas & scars

- **`@bufbuild/protobuf/wkt` `timestampFromDate(date)` is the canonical Date→Timestamp *constructor*** (`protoTime.ts` has no construct helper, only decode). Request-building code uses it (import sites): `useSignalAttribution.ts` (~L2), `ConfirmFillDialog.tsx` (~L5), `OrderFilters.tsx` (~L8), `insights/backfills/page.tsx` (~L4), `trader/api/ledger/export/route.ts` (~L3) (N=5). Hand-rolling `{ seconds: BigInt(Math.floor(d.getTime()/1000)), nanos: … }` in a request body is verbose, BigInt-mix-prone, and diverges from this convention. Hand-rolled deviants today (do not copy, N=4): `src/app/insights/strategies/[id]/page.tsx` (~L97), `src/app/trader/positions/[symbol]/page.tsx` (~L1182), `src/hooks/useDataExplorer.ts` (~L54), `src/hooks/useOhlcBars.ts` (~L26-27, both window bounds); the two `/accounts` REST routes also each carry an identical local Timestamp→Date decode helper (`#tsToISO`, ~L8-11) instead of `protoTime`.
- **mTLS server-name pin parity with the e2e mock.** `src/lib/connectClients.ts#makeTransport` (takes `endpoint` and `targetService`) pins `checkServerIdentity` to the target service NAME, not the dialed host. The e2e mock backend serves one multi-SAN leaf built from `e2e/helpers/devCerts.ts#BACKEND_SERVICES`, so adding a backend client in `connectClients.ts` without adding its name there fails the e2e handshake (`e2e/mtls-transport.spec.ts` covers the mechanism). The UI loads `MTLS_*` lazily on the first RPC, so a missing cert fails at first dial, not at boot.
- **Every proto-enum→label/render map is a `Record<Enum, …>`** (see `opportunityShared.tsx`, `roleLabels.ts`) so `tsc` fails on a new value; never `switch`+`default` or a partial object.
- **PWA support state must resolve SYNCHRONOUSLY; never gate loading on `navigator.serviceWorker.ready`.** `PushToggle` decides support synchronously from feature-detection + `Notification.permission`; reading the existing subscription via `.ready` is fired as best-effort background work, because `.ready` "can hang indefinitely in some headless environments (CI), leaving the control stuck on the spinner." `await`-ing `.ready` before rendering makes the toggle stick on the spinner in CI/headless and flakes the e2e. Evidence: `src/app/accounts/notifications/PushToggle.tsx#Resolve support SYNCHRONOUSLY` (~L31-62).

- **On any `status >= 400` the BFF dispatch strips `content-encoding`/`grpc-encoding`/`content-length` and forces `content-type: application/json`** — a forwarded downstream `ConnectError` otherwise carries the gRPC response's content-type/encoding and the browser Connect client surfaces a generic "HTTP <status>" instead of the real validation message. Load-bearing for error-message fidelity; don't "simplify" it away. Evidence: `src/lib/bffShared.ts#createDispatch` (`uRes.status >= 400` ~L199-204, comment ~L197-198).
- **`#901`/`#884` — config-value staleness after save (see `xstockstrat-config`'s CONFIG-6/7/PROTO-5).** `NamespaceEditor`'s Value column and edit-prefill originally read `ConfigKeyMeta.defaultValue` (never updated by `SetConfig`), so every successful save *looked* like a silent no-op until `currentValue` was added (display at `src/app/config-ui/[namespace]/NamespaceEditor.tsx` (~L134), edit-prefill (~L308)). A future config-metadata read must use `currentValue`.
- Strategy pickers that bind live behaviour filter on `live_enabled`, not just `active`.
- **`d92960b` — `symbolLocked` is the canonical convention for a page keyed to one fixed symbol.** Signal-detail's `OrderForm` symbol field was fully editable despite the whole page (chart/conviction/edge) being keyed to one symbol; the fix introduced `symbolLocked` (`OrderForm.tsx#symbolLocked`, ~L98, `const symbolLocked = Boolean(initialSymbol)`) as the pattern any future single-symbol-context order ticket should reuse rather than reinventing.
- **Unary BFF calls default to 30 s (`DEFAULT_UNARY_TIMEOUT_MS`), streams are unbounded;** register a long RPC with a per-call `{ timeoutMs }` from `src/lib/deadlines.ts` or it fails at 30 s with `DeadlineExceeded` (→504).
- **Feature-215 fundamentals-skip rows take badge precedence and bypass the conviction floor.** `fundamentalsUnavailable` is checked BEFORE `muted` in every badge slot (desktop `OpportunityRow`, mobile `SignalRow`) and before the action badge on the detail `OpportunitySection`; the e2e mock exempts these rows from the conviction floor alongside muted/data-unavailable/formula-unreadable rows, mirroring the backend. Precedence (feature 289): fundamentals-skip → non-held `formulaUnreadable` (the `READINESS_CUE.unreadable` cue replaces the action badge) → `muted` → action; a held unreadable row keeps its action badge and adds the cue. Reordering the branches renders a skip row as a muted/action badge. Evidence: `src/app/insights/opportunities/page.tsx#fundUnavailable` (~L505; precedence chain ~L513-527), `src/components/mobile/SectionRenderer.tsx#fundamentalsUnavailable` (~L172; `formulaUnreadable` ~L248), `src/app/trader/positions/[symbol]/page.tsx#OpportunitySection` (~L980; branches ~L1009-1021), `e2e/mock-backend.ts#"unreadable rows are exempt from the CONVICTION floor"` (~L968).
- **The order-side colours `--color-buy`/`--color-sell`/`--color-paper`/`--color-warning` are a three-site parity contract outside the theme files.** They are literals in the *unlayered* `:root` of `src/app/globals.css`, and the `@theme inline` self-references (`--color-buy: var(--color-buy)`) are deliberate — `@theme inline` alone prunes variables nothing names. Values are pinned in `globals.css`, `src/styles/themes/checkThemeBundle.cjs#SHARED_ROLES` (~L17; the `pnpm build` gate) and `e2e/theme/theme-bundle.spec.ts#SHARED` (~L19); change all three, never move them into `src/styles/themes/*.css` or delete the self-reference (scar: feature 307 `implementation-spec.md`).
- **Tailwind scans all non-test text under `src/`, comments and strings included** (`globals.css` `@import 'tailwindcss' source('..')` with only the `*.test.ts` and `styles/themes` exclusions). A palette utility *name* in a comment emits palette CSS and `checkThemeBundle` fails the build on the colour collision; `noColorLiterals.test.ts` does not catch utility names.
