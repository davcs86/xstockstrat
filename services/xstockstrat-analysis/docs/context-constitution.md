## Rules (`ANALYSIS-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **ANALYSIS-1** | **Tail-align (right-align) `ComputeIndicator` results to the input bars** — result point `i` goes at bar `i + (n − len(points))`, leading bars stay `None`. Never head-align (`result[0]→bar[0]`). | `ComputeIndicator` drops a contiguous warm-up head; head-aligning time-shifts every warm-up indicator series across rules/backtests/live/diagnostics — the PR #769 bug. | `align_indicator_points()` `app/services/evaluator.py:437`, used `:288`; also used in `app/handlers/servicer.py:1209,1214` (imported `:55`); PR #769 | `app/services/evaluator.py:437` |
| **ANALYSIS-2** | **The headline grade is evidence-weighted empirical-Bayes, not outcome-weighted**: `overall = (Σ wᵢ·sᵢ + 0.5·k)/(Σ wᵢ + k)` with `wᵢ = trading_days`, `k = analysis.scoring.shrinkage_days`; `Σw==0 → None` (never an equal-weighted fallback); `provisional` below `min_evidence_symbols`/`min_evidence_days`. | A last-run-wins or equal-weighted headline lets a throwaway single-symbol run overwrite a well-evidenced grade. | `_aggregate_cells` `servicer.py:4022` (called `:2055`); provisional `:2061` | `app/handlers/servicer.py:4022` |
| **ANALYSIS-3** | **Evidence eligibility is keyed on a fingerprint of the DB-returned `definition_json`, excluding `display_name`/`active`/`live_enabled`** — hash the row, never the request proto dict; stamp only when `strategy_id == strategy_id_ref`. | Column-authoritative fields are overlaid at read time, so hashing the request won't canonicalize identically; including `display_name` would reset all evidence on a rename. `NULL` fingerprint cells never contribute (SQL `NULL = x` is never true). | `_definition_fingerprint` `servicer.py:4223`, stamped `:628-632`; filter `app/repositories/backtest_run_symbols.py:75` | `app/handlers/servicer.py:4223` |
| **ANALYSIS-4** | **The custom-formula evaluation path requires `len(raw) == n` and raises `FormulaExecutionError` on mismatch — it does NOT tail-align (unlike builtins, ANALYSIS-1).** | An arbitrary user formula has no contiguous-warm-up-head invariant, so tail-aligning a short list would silently misalign bars. | `app/services/evaluator.py:331-334` (`len(raw) != n → FormulaExecutionError`) | `app/services/evaluator.py:331-334` |
| **ANALYSIS-5** | **`_INDICATOR_SERIES` must stay in parity with the indicators engine's extra output keys** (`bb.upper`/`macd.signal`/`stoch.d`); dotted-ref strategy rules break otherwise. | The two are hand-maintained mirrors across service boundaries. | `app/services/evaluator.py:78-87`; owner xstockstrat-indicators | `app/services/evaluator.py:78-87` |
| **ANALYSIS-6** | **A strategy cannot be bound to a soft-deleted formula: write-time `_refuse_deleted_bindings` rejects the bind; read/run-time `_deleted_formula_warnings` surfaces `formula.deleted` as a warning** (feature 086 — cross-service mirror of indicators' soft-delete = filter-on-read). | Binding to a retired formula would run source the author soft-deleted; the guard depends on the `deleted` flag indicators sets, hand-mirrored across the service boundary (like ANALYSIS-5). | `_refuse_deleted_bindings` `app/handlers/servicer.py:502`, `_deleted_formula_warnings:476` (`_deleted_formula_warning:211`, `formula.deleted:498-499`); owner xstockstrat-indicators | `app/handlers/servicer.py:502` |
| **ANALYSIS-7** | **`_load_strategy_definition`'s live/watchlist read paths must gate on `active AND live_enabled`, mirroring `live_loop.py`'s own gate** — the two must never diverge. | `ListOpportunities`/watchlist-binding pickers had no such gate at all until `63a3655` — a binding to a disabled/deactivated strategy produced real-looking Decide-queue rows even though the live trading loop correctly excluded it. A future edit to either gate independently reintroduces the bug class. | `_load_strategy_definition` def `servicer.py:3418`, gate (`active AND live_enabled`) `:3433`; sibling gate `app/engine/live_loop.py`; `docs/reports/2026-08-07-disabled-strategies-usable.md` | `app/handlers/servicer.py:3418` |
| **ANALYSIS-8** | **`_compute_opportunities` bounds concurrent bars fetches with the process-singleton `_bars_fetch_sem`** (default 2, matching marketdata `DB_POOL_MAX`) and dedups **per compute pass** via `bars_by_symbol`/`benchmark_bars_cache`, caching `[]` on a failed fetch — so a symbol is fetched at most once *per pass* and a failure degrades that candidate to empty-readiness/hold, never retried within the pass and never raised. | A per-candidate refetch of a shared symbol would multiply load and can starve the marketdata pool; caching `[]` on failure is a deliberate degrade-not-retry trade-off (feature 141). ## Gotchas & scars

- **DB/ledger/notify writes are best-effort (`try/except → log.warning`), with ONE deliberate exception: `ScoreStrategy`'s stale-grade DB `delete` is *not* best-effort** (per CLAUDE.md). Evidence: `servicer.py` `ScoreStrategy:1918`, the non-best-effort stale-grade delete `:1961-1969` (`log.warning` then `context.abort(UNAVAILABLE)`); the *other* trigger-path delete `:2115` **is** ordinary best-effort (log-only). (Instance of root PLAT-N1 + its documented exception.)
- **`analysis.strategy.scored` ledger event scoping** — see `CLAUDE.md` § Ledger Events Emitted (the RunBacktest/UPDATE recompute paths intentionally do not emit it).
- **Python config zero-trap applies to *every* int/float/str key here except the two opt-outs documented per-key in `CLAUDE.md`'s Config Keys table** (`get_int_present`, mirroring `get_bool`'s `HasField`) — every other int/float/str key here is still trapped (root gotcha; also a defect in findings). Evidence: `app/config/watcher.py:95,101,130` (trap) vs `:103-114` (`get_int_present`).
- **`resolve_environment`/`resolve_trading_mode` are hand-mirrored, byte-for-byte, across three Python services** (analysis, indicators, ingest) with no shared library. Extending or changing the env/mode resolution semantics in one and forgetting the other two silently reintroduces a scoping mismatch (see the SEV-1 scar below). **Post-147 residual:** `resolve_trading_mode` (`:28-32`) still reads the `TRADING_MODE` env var (`:48`) and sends it as the `WatchConfig` **subscription scope**, even though feature 147 removed the `trading_mode` *config axis* — worth a look on the next scoping change. Evidence: `app/config/watcher.py:17-32`; identical diff shape in `services/xstockstrat-{indicators,ingest}/app/config/watcher.py` (commit `d7d185f`).
- **SEV-1 scar (root PLAT-8): `WatchConfig` silently subscribed at dev/unspecified scope for this service's entire lifetime until 2026-08-07.** Fixed by `d7d185f` (mirrors the earlier Go-side fix in trading/portfolio/marketdata).
- **`63a3655` — disabled strategies usable in the opportunities queue (see ANALYSIS-7).** `ListOpportunities`' `_load_strategy_definition` had no `active`/`live_enabled` gate at all — a watchlist bound to a disabled strategy still produced real-looking Decide-queue rows, even though `live_loop.py` correctly excluded it from actual order/alert execution. Full writeup: `docs/reports/2026-08-07-disabled-strategies-usable.md`.
- **`bef4258` — screener silently passed criteria it couldn't evaluate.** When FMP fundamentals were unavailable, fundamental criteria were dropped from `criterion_scores` but the result still defaulted to `status=OK, passed=true` — indistinguishable from a genuine pass. Fixed in `app/services/screener.py` to fail closed to `SCREEN_RESULT_STATUS_INSUFFICIENT_DATA`. Full writeup: `docs/reports/2026-08-08-screener-fundamental-criteria-silently-inert.md`.
- **Feature 144 — screener soft-criterion neutral-fallback scored like real data.** `_build_result`'s `technical_score = weighted_sum / weight_total if weight_total > 0 else 0.5` fallback fired whenever every criterion configured for a scan had no usable data for one specific candidate (e.g. an ETF with no P/E ratio) — the resulting `0.5` was indistinguishable from a genuinely-computed mid-range score and could outrank real, worse-looking data. Fixed via an additive `ScreenResult.score_unavailable` bool (proto field 14) set when `weight_total <= 0 and len(criteria) > 0`, plus a server-side `results.sort(key=lambda r: (r.score_unavailable, -r.score))` so a flagged candidate can never outrank a real one. Deliberately **not** folded into `SCREEN_RESULT_STATUS_INSUFFICIENT_DATA` (which drives the UI's active re-check polling loop, correct only for genuinely-transient causes). A near-identical neutral-fallback shape also exists in `app/engine/fundsignal_loop.py`'s `_builtin_score` (the file grew past its original `:294` anchor; scoring now spans the loop + `app/services/fundamentals_scoring.py`), feeding the fundamentals signal producer's cross-sectional buy/sell/hold quantile — **left unfixed**, different subsystem/blast radius, flagged as a candidate follow-up. Full writeup: `docs/roadmap/features/144-fix-screener-soft-criterion/context.md`.
