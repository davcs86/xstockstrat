## Gotchas & scars

- **DB/ledger/notify writes are best-effort (`try/except → log.warning`), with ONE deliberate exception: `ScoreStrategy`'s stale-grade DB `delete` is *not* best-effort** (per CLAUDE.md). Evidence: `servicer.py#ScoreStrategy` (~L2519), the non-best-effort stale-grade delete (~L2577; `log.warning` then `context.abort(UNAVAILABLE)`); the *other* trigger-path delete **is** ordinary best-effort (log-only). (Instance of root PLAT-N1 + its documented exception.)
- **`analysis.strategy.scored` ledger event scoping** — see `CLAUDE.md` § Ledger Events Emitted (the RunBacktest/UPDATE recompute paths intentionally do not emit it).
- **Cross-module contract (`consumer-observed`): `fees_total` is sourced from the `portfolio.position.closed` ledger payload key `fees_total`; an absent key ⇒ `0.0` ⇒ net == gross with no error.** Producer is xstockstrat-portfolio's `position.closed` emitter (not read here). If portfolio renames/drops the key or emits cents-vs-dollars, attribution silently under-counts fees. Evidence: `app/engine/pnl_pattern_consumer.py#_num(payload.get("fees_total"))` (~L264).
- **Python config zero-trap applies to *every* int/float/str key here except the two opt-outs documented per-key in `CLAUDE.md`'s Config Keys table** (`get_int_present`, mirroring `get_bool`'s `HasField`) — every other int/float/str key here is still trapped (root gotcha; also a defect in findings). Evidence: `app/config/watcher.py#get_str`/`#get_int`/`#get_float` (trap `or default` ~L96,104,133) vs `#get_int_present` (~L107-118).
- **`resolve_environment`/`resolve_trading_mode` are hand-mirrored, byte-for-byte, across three Python services** (analysis, indicators, ingest) with no shared library. Extending or changing the env/mode resolution semantics in one and forgetting the other two silently reintroduces a scoping mismatch (see the SEV-1 scar below). **Post-147 residual:** `resolve_trading_mode` (~L30-34) still reads the `TRADING_MODE` env var (~L49) and sends it as the `WatchConfig` **subscription scope**, even though feature 147 removed the `trading_mode` *config axis* — worth a look on the next scoping change. Evidence: `app/config/watcher.py#resolve_environment` (~L19-34); identical diff shape in `services/xstockstrat-{indicators,ingest}/app/config/watcher.py` (commit `d7d185f`).
- **SEV-1 scar (root PLAT-8): `WatchConfig` silently subscribed at dev/unspecified scope for this service's entire lifetime until 2026-08-07.** Fixed by `d7d185f` (mirrors the earlier Go-side fix in trading/portfolio/marketdata).
- **`63a3655` — disabled strategies usable in the opportunities queue (see ANALYSIS-7).** `ListOpportunities`' `_load_strategy_definition` had no `active`/`live_enabled` gate at all — a watchlist bound to a disabled strategy still produced real-looking Decide-queue rows, even though `live_loop.py` correctly excluded it from actual order/alert execution. Full writeup: `docs/reports/2026-08-07-disabled-strategies-usable.md`.
- **`bef4258` — screener silently passed criteria it couldn't evaluate.** When FMP fundamentals were unavailable, fundamental criteria were dropped from `criterion_scores` but the result still defaulted to `status=OK, passed=true` — indistinguishable from a genuine pass. Fixed in `app/services/screener.py` to fail closed to `SCREEN_RESULT_STATUS_INSUFFICIENT_DATA`. Full writeup: `docs/reports/2026-08-08-screener-fundamental-criteria-silently-inert.md`.
- **Feature 144 — screener soft-criterion neutral-fallback scored like real data.** `_build_result`'s `technical_score = weighted_sum / weight_total if weight_total > 0 else 0.5` fallback fired whenever every criterion configured for a scan had no usable data for one specific candidate (e.g. an ETF with no P/E ratio) — the resulting `0.5` was indistinguishable from a genuinely-computed mid-range score and could outrank real, worse-looking data. Fixed via an additive `ScreenResult.score_unavailable` bool (proto field 14) set when `weight_total <= 0 and len(criteria) > 0`, plus a server-side `results.sort(key=lambda r: (r.score_unavailable, -r.score))` so a flagged candidate can never outrank a real one. Deliberately **not** folded into `SCREEN_RESULT_STATUS_INSUFFICIENT_DATA` (which drives the UI's active re-check polling loop, correct only for genuinely-transient causes). A near-identical neutral-fallback shape also exists in `app/engine/fundsignal_loop.py`'s `_builtin_score` (the file grew past its original `:294` anchor; scoring now spans the loop + `app/services/fundamentals_scoring.py`), feeding the fundamentals signal producer's cross-sectional buy/sell/hold quantile — fixed by feature 246: skip by omission (an all-missing row is never scored or ranked, unlike 144's rank-last `score_unavailable`), with absence read from `missing_metrics`. Full writeup: `docs/roadmap/features/144-fix-screener-soft-criterion/context.md`.
