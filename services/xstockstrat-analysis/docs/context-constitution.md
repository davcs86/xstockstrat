## Gotchas & scars

- **DB/ledger/notify writes are best-effort (`try/except → log.warning`), with ONE deliberate exception: `ScoreStrategy`'s stale-grade DB `delete` is *not* best-effort** (per CLAUDE.md). Evidence: `servicer.py#ScoreStrategy` (~L2616), the non-best-effort stale-grade delete (~L2671; `log.warning` then `context.abort(UNAVAILABLE)`); the *other* trigger-path delete **is** ordinary best-effort (log-only). (Instance of root PLAT-N1 + its documented exception.)
- **`live_loop.py` imports six private `_` helpers (plus two public ones) from `servicer.py`** (`app/engine/live_loop.py` ~L41-50) while `servicer.py` imports `live_loop` only lazily inside a function (~L5389, "avoids import cycle"). Renaming or moving a servicer helper breaks the live loop and `entry_backfill`, and nothing flags it at the servicer.
- **Cross-module contract (`consumer-observed`): `fees_total` is sourced from the `portfolio.position.closed` ledger payload key `fees_total`; an absent key ⇒ `0.0` ⇒ net == gross with no error.** Producer is xstockstrat-portfolio's `position.closed` emitter (not read here). If portfolio renames/drops the key or emits cents-vs-dollars, attribution silently under-counts fees. Evidence: `app/engine/pnl_pattern_consumer.py#_num(payload.get("fees_total"))` (~L428).
- **A stored `0`/`""` is honoured by every getter here; the 34 keys where it is unsafe read through `int_positive`/`float_positive`/`str_nonempty` (feature 244, root gotcha).** A new config read must join `FR3_KEYS` (clamped) or `HONOUR_KEYS` in the AST guard, or the guard fails; `default_fill_model` stays an unclamped `get_int` because `0` = legacy, stored or absent. Evidence: `app/config/watch_core.py#_typed` (`HasField` ~L206) / `#get_int` (~L217); `get_int_present`/`get_float_present` aliases `app/config/watcher.py` (~L66-67) and `#int_positive` (~L72); `tests/test_config_read_classification.py#FR3_KEYS`.
- **`resolve_environment`/`resolve_trading_mode` are hand-mirrored across three Python services** (analysis, indicators, ingest) with no shared library — the shared `app/config/watch_core.py` copies are now CI-enforced byte-identical (group `py`, agent included, `scripts/check-watcher-copies.sh`), but these two `watcher.py` functions sit outside it and their docstrings already differ. Extending or changing the env/mode resolution semantics in one and forgetting the other two silently reintroduces a scoping mismatch (see the SEV-1 scar below). **Post-147 residual:** `resolve_trading_mode` (~L28-32) still reads the `TRADING_MODE` env var (~L47) and sends it as the `WatchConfig` **subscription scope**, even though feature 147 removed the `trading_mode` *config axis* — worth a look on the next scoping change. Evidence: `app/config/watcher.py#resolve_environment` (~L17-32); identical diff shape in `services/xstockstrat-{indicators,ingest}/app/config/watcher.py` (commit `d7d185f`).
- **`bef4258` — screener silently passed criteria it couldn't evaluate.** When FMP fundamentals were unavailable, fundamental criteria were dropped from `criterion_scores` but the result still defaulted to `status=OK, passed=true` — indistinguishable from a genuine pass. Fixed in `app/services/screener.py` to fail closed to `SCREEN_RESULT_STATUS_INSUFFICIENT_DATA`. Full writeup: `docs/reports/2026-08-08-screener-fundamental-criteria-silently-inert.md`.
- **Feature 144 — screener soft-criterion neutral-fallback scored like real data.** `_build_result`'s `technical_score = weighted_sum / weight_total if weight_total > 0 else 0.5` fallback fired whenever every criterion configured for a scan had no usable data for one specific candidate (e.g. an ETF with no P/E ratio) — the resulting `0.5` was indistinguishable from a genuinely-computed mid-range score and could outrank real, worse-looking data. Fixed via an additive `ScreenResult.score_unavailable` bool (proto field 14) set when `weight_total <= 0 and len(criteria) > 0`, plus a server-side sort on `(score_unavailable, eval_failed, -score)` so a flagged candidate can never outrank a real one; an evaluation-fault row sorts after a feature-144 row (feature 245). Deliberately **not** folded into `SCREEN_RESULT_STATUS_INSUFFICIENT_DATA` (which drives the UI's active re-check polling loop, correct only for genuinely-transient causes). A near-identical neutral-fallback shape also exists in `app/engine/fundsignal_loop.py`'s `_builtin_score` (the file grew past its original `:294` anchor; scoring now spans the loop + `app/services/fundamentals_scoring.py`), feeding the fundamentals signal producer's cross-sectional buy/sell/hold quantile — fixed by feature 246: skip by omission (an all-missing row is never scored or ranked, unlike 144's rank-last `score_unavailable`), with absence read from `missing_metrics`. Full writeup: `docs/roadmap/features/144-fix-screener-soft-criterion/context.md`.
