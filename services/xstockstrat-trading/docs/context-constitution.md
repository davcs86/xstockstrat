## Rules (`TRADING-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **TRADING-1** | **Every RPC is implemented twice** — a Connect method *and* a `grpcTradingAdapter` twin — and only the adapter is registered (`grpcHdl.GRPCHandler()`). A new RPC must add both, or it is unreachable over the wire. | The served surface is the gRPC adapter; a Connect-only method compiles but is never registered. | Connect order RPCs `internal/handler/trading.go#TradingHandler.PlaceOrder`…`StreamOrderUpdates` (~L30-135), adapter twin `#GRPCHandler`/`grpcTradingAdapter` (~L137-221), broker-account Connect (~L270-337)/adapter (~L339-385); registration `cmd/server/main.go#grpcHdl.GRPCHandler() (~L143)` | `internal/handler/trading.go#GRPCHandler (~L137-221)` |
| **TRADING-2** | **Proto enums persist as hand-mapped lowercase strings; `0` floats persist as SQL NULL** (`sideStr`/`typeStr`/`statusStr`/`modeStr` on write, `parse*` on read; `nullableFloat` maps 0→NULL for price columns). | The `CHECK (side IN ('buy','sell'))` constraint and every read path assume the string/NULL contract; storing the enum int or a literal 0.0 diverges. (Root PLAT-F1 is the platform statement of this.) | write uses helpers at `internal/repository/trading_repo.go#UpsertOrder` (~L88-91); helper defs `#sideStr` (~L428), `#typeStr` (~L435), `#statusStr` (~L450), `#modeStr` (~L469), `#nullableFloat` (~L476); `parse*` (~L492-538); time-in-force follows the same contract via `tifStr` / `parseTif` (`internal/repository/tif.go`) — lowercase `day|gtc|ioc|fok|opg|cls` in a TEXT column with **no DB CHECK**, unknown/empty reads back as UNSPECIFIED, Go owns validation (migration `010_normalize_tif`) | `internal/repository/trading_repo.go#sideStr…parseMode (~L428-538)` |
| **TRADING-3** | **Broker adapters return the sentinel `broker.ErrInvalidCredentials` only for HTTP 401/403; every other failure is a wrapped transient error.** Credential-health classification branches on `errors.Is(err, ErrInvalidCredentials)`. | A new adapter returning a plain error on 401 makes credential-health classify auth failure as UNKNOWN, so `syncPositions` never skips a dead account and hammers the broker every cycle. | authoritative `internal/broker/broker.go#ErrInvalidCredentials (~L10)`; honored `internal/broker/alpaca.go` (~L509), `ibkr.go` (~L572); consumed `internal/service/trading.go#credentialStatusFromError (~L2873)` | `internal/broker/broker.go#ErrInvalidCredentials (~L10)` |

(Instance of root PLAT-N1.) | `s.orders` writes `internal/service/trading.go` (~L642,830,934,1172,1345); best-effort persist warns `"db upsert order failed"` (~L646), `"db upsert after broker submit failed"` (~L745) | `internal/service/trading.go#submitOrder` `s.orders[orderID] = order` (~L642) |
| **TRADING-5** | **The `credStatus` cache gates DB writes and rolls back on persist failure** — `validateAndRecordCredential` skips the write when status is unchanged and restores the prior cached value if the write fails, so the next cycle retries. | Prevents redundant writes and a lost-update on a transient DB error. | `internal/service/trading.go#validateAndRecordCredential (~L2520)` | `internal/service/trading.go#validateAndRecordCredential (~L2520)` |
| **TRADING-6** | **Order-intent dedup IDs are content hashes with the client nonce EXCLUDED** — `placeOrderRequestHash` clones the request and clears `ClientOrderId` before sha256; Replace/Cancel derive a UUIDv5 content hash with no nonce at all. | Hashing the whole message (nonce included) makes two *distinct* logical orders that reuse a stale nonce collide, so the second silently returns the first's stored result. Both are authoritative single-site definitions of the intent-ID contract, so a new mutating RPC wired into `order_intents` must follow it. | `internal/service/order_intent.go#placeOrderRequestHash (~L33-40)`; `#deriveReplaceCancelIntentID (~L44-52)` | `internal/service/order_intent.go#placeOrderRequestHash (~L33-40)` |
| **TRADING-7** | **Time-in-force is validated per broker BEFORE any broker call, via `validateTIF(tif, brokerType)` against the `allowedTIFs` matrix (IBKR has no OPG/CLS); wire strings come from `tifToWireString`.** `PlaceOrder` always validates; `ReplaceOrder` only when a TIF is supplied; the internal bracket and flatten paths hard-code DAY and bypass validation. A new broker needs an `allowedTIFs` entry — a missing entry is nil, so every TIF is rejected. | A new submit path that forwards TIF without `validateTIF` sends an unsupported value to the broker; adding a broker without a matrix entry makes every order fail `InvalidArgument`. | `internal/service/tif_validation.go#allowedTIFs`, `#validateTIF`; call sites `trading.go#PlaceOrder`, `#ReplaceOrder`; bypass sites in the bracket/flatten builders | `internal/service/tif_validation.go#validateTIF` |

| **TRADING-N2** | **Halt is memory-first, resume is DB-first — a deliberate crash-safety inversion.** `ResumeAccountSvc` clears the persisted halt (`accountRepo.UpdateHaltStatus(...false...)`) *before* deleting the in-memory `s.halted`/`haltReasons`/`haltedLastPolled` entries (the reverse of `haltAccount`'s memory-first order), so a crash between the two leaves the account **still halted** (safe). | Clearing the in-memory halt map first (or in one lock block) lets a crash leave a previously-halted account trading with no persisted halt on the next boot-hydrate. Don't reorder. | `internal/service/trading.go#ResumeAccountSvc (~L2942-2970)` (DB clear ~L2961, map deletes ~L2967-2969) | `internal/service/trading.go#ResumeAccountSvc (~L2942-2970)` |

## Gotchas & scars

- **Async emits are detached (`context.Background()`), never the request ctx** — passing the request ctx (canceled on return) silently drops the ledger/alert event. This is not "one exception" anymore (`syncAccountPositions`) — any **poller-owned long-lived context** may emit synchronously on purpose, since it isn't a per-request ctx: feature 102's reconciliation poller (`emitReconciliationFinding`, `resolveUnknownIntents`) also does. The rule is per-request-ctx-never, poller-ctx-may. Evidence: detached call sites `internal/service/trading.go#submitOrder` `go s.emitLedgerEvent(context.Background(), …)` (~L649,665,755) (`#emitLedgerEvent` def ~L3571); synchronous-on-poller-ctx `#emitReconciliationFinding` (~L1844), `#resolveUnknownIntents` (~L2117). (Root PLAT-N1.)
- **`broker_type` SMALLINT must stay in lockstep with `common.v1.BrokerType`** (1=ALPACA, 2=IBKR; OFFLINE is now a third value) — cast without validation; documented only in migration comments. Renumbering the enum silently mis-maps brokers. Evidence: casts `internal/service/trading.go` `commonv1.BrokerType(…brokerType)` / `int32(…BrokerType)` (~L472,630,677,1436,2136,2427,2442,2849,3295,3319); migrations 002/003.
- **Cross-module contract: `AdminScope = 0x04` must stay bit-for-bit in parity across Go/Python/Node.** Producer/peers: Go `middleware.AdminScope` (`internal/middleware/authz.go#AdminScope` ~L13, self-documents the parity), Python `_ADMIN = 0x04` (`services/xstockstrat-agent/app/scopes.py` ~L35), Node `ADMIN_SCOPE` (`xstockstrat-config/src/grpc/authz.ts#ADMIN_SCOPE` ~L8). The agent tool pre-checks the same bit (`services/xstockstrat-agent/app/tools.py` `manage_account` resume branch `scope & 0x04`, ~L2201) before calling trading's `ResumeAccount`, which re-checks it at `internal/service/trading.go#ResumeAccountSvc` (~L2943). Renumbering the admin bit in any one service silently makes an operator RPC callable by traders, or desyncs the agent pre-check from the server. (Validate against xstockstrat-identity's scope assignment as the owning producer.)
- **SEV-1 scar (root PLAT-8): `WatchConfig` silently subscribed at dev/all scope for the service's entire lifetime until 2026-08-07.** `config.Watcher` declared `environment`/`tradingMode` fields and sent them on every request, but `NewWatcher` never populated them — so every environment-tagged config row (e.g. `trading.risk.bracket_orders_enabled=false` seeded for production by `config` migration 013) was silently unreachable. Fixed by commit `1413399`'s `resolveEnvironment`/`resolveTradingMode` helpers (`internal/config/config.go#NewWatcher` ~L80, `#resolveEnvironment` ~L110, `#resolveTradingMode` ~L119). Any new per-env config key is at risk of the same silent no-op unless the service's `NewWatcher` call site is checked. (Feature 147 later dropped the `trading_mode` request half entirely — `resolveTradingMode` lingers but is no longer sent.)
