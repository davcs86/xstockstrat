## Rules (`TRADING-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **TRADING-1** | **Every RPC is implemented twice** — a Connect method *and* a `grpcTradingAdapter` twin — and only the adapter is registered (`grpcHdl.GRPCHandler()`). A new RPC must add both, or it is unreachable over the wire. | The served surface is the gRPC adapter; a Connect-only method compiles but is never registered. | Connect order RPCs `internal/handler/trading.go#TradingHandler.PlaceOrder`…`StreamOrderUpdates` (~L30-135), adapter twin `#GRPCHandler`/`grpcTradingAdapter` (~L137-221), broker-account Connect (~L270-337)/adapter (~L339-385); registration `cmd/server/main.go#grpcHdl.GRPCHandler() (~L163)` | `internal/handler/trading.go#GRPCHandler (~L137-221)` |
| **TRADING-2** | **Proto enums persist as hand-mapped lowercase strings; `0` floats persist as SQL NULL** (`sideStr`/`typeStr`/`statusStr`/`modeStr` on write, `parse*` on read; `nullableFloat` maps 0→NULL for price columns). **`UpsertOrder`'s `ON CONFLICT … DO UPDATE` rewrites only `broker_order_id`/`status`/`filled_qty`/`filled_avg_price`/`updated_at`/`account_id`/`broker_type`/`filled_at`/`fees` — never `qty`, `limit_price`, `stop_price` or `time_in_force`** (see the findings log: `ReplaceOrder`). | The `CHECK (side IN ('buy','sell'))` constraint and every read path assume the string/NULL contract; storing the enum int or a literal 0.0 diverges. (Root PLAT-F1 is the platform statement of this.) | write uses helpers at `internal/repository/trading_repo.go#UpsertOrder` (~L89-93); helper defs `#sideStr` (~L436), `#typeStr` (~L443), `#statusStr` (~L458), `#modeStr` (~L477), `#nullableFloat` (~L484); `parse*` (~L500-546); time-in-force follows the same contract via `tifStr` / `parseTif` (`internal/repository/tif.go`) — lowercase `day|gtc|ioc|fok|opg|cls` in a TEXT column with **no DB CHECK**, unknown/empty reads back as UNSPECIFIED, Go owns validation (migration `010_normalize_tif`) | `internal/repository/trading_repo.go#sideStr…parseMode (~L436-546)` |
| **TRADING-3** | **Broker adapters return the sentinel `broker.ErrInvalidCredentials` only for HTTP 401/403, or for deterministically unusable credentials (missing/unparseable key material, decrypt failure, LST-signature mismatch, `ssodh/init` not authenticated). It may come from any IBKR call, not just `ValidateCredentials`. Every other failure is a wrapped transient error.** Credential-health classification branches on `errors.Is(err, ErrInvalidCredentials)`. | A new adapter returning a plain error on 401 makes credential-health classify auth failure as UNKNOWN, so `syncPositions` never skips a dead account and hammers the broker every cycle. Wrapping a transient handshake failure (503, timeout) in the sentinel would instead mark a healthy account INVALID. | authoritative `internal/broker/broker.go#ErrInvalidCredentials (~L10)`; honored `internal/broker/alpaca.go` (~L534), IBKR `internal/broker/ibkr_session.go#loadKeyMaterial (~L79)`, `#ibkrAuthStatusErr (~L128)`, `#mintLST (~L214-263)`, `#initBrokerage (~L277)`, `#ibkrFinalAuthErr (~L441)`; consumed `internal/service/trading.go#credentialStatusFromError (~L3107)` and the `reconcileTick` skip (~L2084, ~L2173) | `internal/broker/broker.go#ErrInvalidCredentials (~L10)` |
| **TRADING-4** | **DB persistence is best-effort; the in-memory `s.orders` map — not the DB — is the source of truth the fill poller iterates.** For **broker-routed** orders write errors are logged (`persistOrderBestEffort`), never returned. **Offline accounts invert this**: `recordOfflineOrder` and `ConfirmOrder` persist to the DB *before* the cache write and return `Internal` on failure, because there is no broker to reconcile against — the DB is authoritative there. | Treating a DB write failure as fatal, or relying on the DB alone for fill polling, breaks cross-restart reconciliation (`LoadInflightOrders`, ~L337). (Instance of root PLAT-N1.) | `s.orders` writes `internal/service/trading.go#submitOrder` (~L691); best-effort persist `#persistOrderBestEffort` (~L3868; callers `submitOrder` ~L736/751, `CancelOrder` ~L1428, `ReplaceOrder` ~L1609; the fill poller's log-only `UpsertOrder` now sits in `#applyBrokerOrderStatus` ~L1877); offline fail-hard `#recordOfflineOrder` (`"persist offline order"` ~L883), `#ConfirmOrder` (`"persist confirmed order"` ~L998, DB before `s.orders` ~L1001) | `internal/service/trading.go#submitOrder` `s.orders[orderID] = order` (~L691) |
| **TRADING-5** | **The `credStatus` cache gates DB writes and rolls back on persist failure** — `validateAndRecordCredential` skips the write when status is unchanged and restores the prior cached value if the write fails, so the next cycle retries. | Prevents redundant writes and a lost-update on a transient DB error. | `internal/service/trading.go#validateAndRecordCredential (~L2735)` | `internal/service/trading.go#validateAndRecordCredential (~L2735)` |
| **TRADING-6** | **Order-intent dedup IDs are content hashes with the client nonce EXCLUDED** — `placeOrderRequestHash` clones the request and clears `ClientOrderId` before sha256; Replace/Cancel derive a UUIDv5 content hash with no nonce at all. | Hashing the whole message (nonce included) makes two *distinct* logical orders that reuse a stale nonce collide, so the second silently returns the first's stored result. Both are authoritative single-site definitions of the intent-ID contract, so a new mutating RPC wired into `order_intents` must follow it. | `internal/service/order_intent.go#placeOrderRequestHash (~L33-40)`; `#deriveReplaceCancelIntentID (~L44-52)` | `internal/service/order_intent.go#placeOrderRequestHash (~L33-40)` |
| **TRADING-7** | **Time-in-force is validated per broker BEFORE any broker call, via `validateTIF(tif, brokerType)` against the `allowedTIFs` matrix (IBKR has no OPG/CLS); wire strings come from `tifToWireString`.** `PlaceOrder` always validates; `ReplaceOrder` only when a TIF is supplied; the internal bracket and flatten paths hard-code DAY and bypass validation. A new broker needs an `allowedTIFs` entry — a missing entry is nil, so every TIF is rejected. | A new submit path that forwards TIF without `validateTIF` sends an unsupported value to the broker; adding a broker without a matrix entry makes every order fail `InvalidArgument`. | `internal/service/tif_validation.go#allowedTIFs`, `#validateTIF`; call sites `trading.go#PlaceOrder`, `#ReplaceOrder`; bypass sites in the bracket/flatten builders | `internal/service/tif_validation.go#validateTIF` |

## Gotchas & scars

- **`broker_type` SMALLINT must stay in lockstep with `common.v1.BrokerType`** (1=ALPACA, 2=IBKR; OFFLINE is now a third value) — cast without validation; documented only in migration comments. Renumbering the enum silently mis-maps brokers. Evidence: casts `internal/service/trading.go` `commonv1.BrokerType(…brokerType)` / `int32(…BrokerType)` (~L521,679,726,1575,2318,2637,2652,3087,3540,3555,3567,3938); migrations 002/003.
- **`AdminScope = 0x04` parity (root PLAT-5)** — the agent pre-checks the same bit (`services/xstockstrat-agent/app/tools.py` `manage_account` resume branch `scope & 0x04`) before calling `ResumeAccount`, which re-checks it at `internal/service/trading.go#ResumeAccountSvc`; renumbering the bit in one service desyncs the agent pre-check from the server.
- **SEV-1 scar → root PLAT-8**; fixed in `1413399` (`internal/config/config.go#resolveEnvironment`). Any new per-env config key needs the `NewWatcher` call site checked.
