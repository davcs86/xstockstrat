## Rules (`MARKETDATA-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **MARKETDATA-1** | **`Bar.Timeframe` is stored/queried as the canonical DB string (`15m`/`1h`/`1d`), never the Alpaca spelling.** The Alpaca wire spelling (`15Min`/`1Hour`/`1Day`) is used only on the outbound request, then the canonical string is written back onto the source Bar, because `InsertBars` persists that field. Since feature 196 the deprecated string is **never returned to a caller**: `scanBars` and the stream leave it unset and `omitDeprecatedTimeframe` clears it on source bars after persistence; `Bar.TimeframeEnum` (feature 080, via `internal/timeframe.FromString`) is the response contract. | Reads filter `WHERE timeframe=$2` on the canonical string; a writer that stores the Alpaca spelling makes bars invisible to reads — the "1Day vs 1d" bug `internal/timeframe` was created to fix. | canonical `internal/timeframe/timeframe.go#FromString (~L47)` (`#ToCanonical ~L15`); wire map `internal/alpaca/client.go#alpacaTimeframe (~L104)`; shared builder `internal/alpaca/client.go#barFromAlpaca (~L136-145)` (write-back `TimeframeEnum` ~L143); read `WHERE timeframe=$2` `internal/repository/marketdata_repo.go#QueryBars (~L102)`, scan `#scanBars (~L129)`; response-edge clear `internal/service/marketdata_service.go` `omitDeprecatedTimeframe` | `internal/timeframe/timeframe.go#FromString (~L47)` |
| **MARKETDATA-2** | **Streamed bars carry `1m` and must NOT be persisted** — the stream path deliberately does not `InsertBars`; storage of the continuously-ingested timeframe (`marketdata.stream.bar_ingest_timeframe`, default `1d` since feature 143 narrowed it from `15m,1d`) is owned by `StartBarIngestPoller`/`ingestRecentBars`. Since feature 143, `15m`/`1h` are neither ingested nor fetchable — `GetBars`/`BackfillBars` reject any non-`1d` request; historical `15m`/`1h` rows stay stored and remain inspectable via `GetDataCoverage`/deletable via `DeleteBackfilledData` (both deliberately permissive), just never refreshed. Since feature 080, streamed bars also carry the explicit `TimeframeEnum: TIMEFRAME_1MIN` label — this is a label only, not a storability signal. | "Fixing" the stream path to persist pollutes the ohlcv table with 1m bars. Assuming `1h` is continuously fresh will silently feed a stale bar to any `1h` consumer — same failure mode the bug fix closed for `1d`. | producer `internal/alpaca/stream.go` (streamed bars are labelled only via `TimeframeEnum: commonv1.Timeframe_TIMEFRAME_1MIN` (~L252), comment above it; the former `streamBarTimeframe="1m"` const no longer exists and feature 196 leaves the deprecated string `Timeframe` unset); consumer `internal/service/marketdata_service.go#StartBarStream (~L1384)`; ingest `#resolveIngestTimeframes (~L1113)`, `#StartBarIngestPoller (~L1081)`, `#ingestRecentBars (~L1155)` | `internal/service/marketdata_service.go#StartBarStream (~L1384)` |

| **MARKETDATA-5** | **Pollers re-read their interval from config every tick and treat `<=0` as "pause, keep last".** | Reading the interval once at startup means config changes never take effect live; `<=0` is the documented pause sentinel. | warm poller `marketdata_service.go#StartWarmQuotePoller` `<=0` (~L1008,1019); bar-ingest `#StartBarIngestPoller` `<=0` (~L1084,1095) | `internal/service/marketdata_service.go#StartWarmQuotePoller (~L1005)` |
| **MARKETDATA-6** | **`DeleteBars` always constrains on the symbol predicate (`$1`) — never an unbounded delete — and is gated on `scope & 0x04`.** `buildDeleteBarsQuery` is extracted as a pure function precisely to unit-test this. | An empty symbol or a changed bitmask turns a targeted delete into a table wipe (DBA gate, FR-5). | `internal/repository/marketdata_repo.go#buildDeleteBarsQuery (~L234)` (`#DeleteBars ~L254`, symbol-`$1` predicate ~L235); gate `scope&0x04==0` `marketdata_service.go` (~L467) | `internal/repository/marketdata_repo.go#buildDeleteBarsQuery (~L234)` |
| **MARKETDATA-7** | **`resolveEnvironment` fails *open* to `ENVIRONMENT_STAGING` on any non-`"production"` value** — only the literal `"production"` matches; everything else (including `"development"` and typos) silently resolves to STAGING. | A misconfigured `APPLICATION_ENV` doesn't error — it silently subscribes this service to staging-scoped config (root PLAT-8). | **MARKETDATA-8** | **`GetBars` is dual-mode by range presence.** No `Range.Start` = an implicit-window "latest bars" read: it sizes a default lookback, serves the *newest* page via `QueryRecentBars` (not oldest-forward `QueryBars`), and is the **only** path that arms the feature-140 staleness self-refresh (newest stored bar older than one interval → live refetch, rate-limited by `staleCheckDue`) and warms the symbol for the daily ingester. ## Gotchas & scars

- **Belt-and-suspenders param defaulting**: Alpaca params (`Adjustment="all"`, `feed="iex"`) are re-defaulted in `adjustmentParam()`/`feedParam()`/`connectAndRead` in addition to `NewClient`, so a Client built without `NewClient` still behaves. Adding a new configured param only in `NewClient` leaves a path that 403s on the free plan. Evidence: `internal/alpaca/client.go#do (~L83)`, `#feedParam (~L95)`, `#adjustmentParam (~L148)`, `stream.go#connectAndRead (~L179-181)`.
- **Pollers/stream run on the long-lived `main` ctx, so their ledger/notify emits carry no propagation headers** (intentional — background work has no inbound request). An agent copying `emitEvent` from a poller into a request-path method drops the headers. Evidence: `cmd/server/main.go` (`go svc.StartWarmQuotePoller(ctx)` ~L156, `go svc.StartBarIngestPoller(ctx)` ~L158).
- **SEV-1 scar (root PLAT-8): `WatchConfig` silently subscribed at zero-value scope until 2026-08-07.** `Watcher.environment`/`.tradingMode` fields existed and were sent on every `WatchConfigRequest`, but `NewWatcher` never populated them — so this service (and portfolio) had been silently requesting `UNSPECIFIED` scope since those fields were introduced. Fixed by commit `1413399`'s `resolveEnvironment`/`resolveTradingMode` (MARKETDATA-7). (Feature 147 later dropped the `trading_mode` request half.)
- **`4c91465` — int32-truncation fix in the pool-size env parser.** `strconv.Atoi(v)` + `int32(n)` silently wraps an out-of-range `DB_POOL_MAX` into an arbitrary (possibly negative) `MaxConns` instead of erroring — a CodeQL-caught bug in a connection-pool-budget-sensitive path (root's ~22-connection cluster budget). Fixed via `strconv.ParseInt(v, 10, 32)`. Worth checking any other service that parses an env var straight into an `int32` field the same way. Evidence: `internal/repository/pool.go#ParseInt (~L25)`.

- **Never set `Accept-Encoding` on SEC EDGAR requests.** The EDGAR client once set `Accept-Encoding: gzip, deflate` by hand, which disables `net/http`'s transparent gzip decompression (the Transport only auto-decompresses when it added the header itself); SEC's CDN serves gzip, so every fetch failed JSON decode with `invalid character '\x1f'`, CIK resolution failed for every symbol, and the feature-198 historical fundamentals backfill produced zero rows (commit `f7d2916`, #1164). Evidence: `internal/edgar/edgar_client.go` (the "Never set Accept-Encoding here" comment above `c.hc.Do(req)`).
