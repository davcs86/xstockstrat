## Rules (`INGEST-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **INGEST-1** | **The BACKFILL repositories are proto-free** — `backfill_jobs.py` / `backfill_chunks.py` must not `import ingest_pb2`; the servicer owns all proto↔row conversion. **Known exception:** `signal_sources.py` imports `ingest_pb2` for `SIGNAL_SCOPE_OWN` / `SIGNAL_SCOPE_SYSTEM` in `owner_scope_predicate` (feature 224) — do not read it as precedent for the backfill repos. | The deliberate proto isolation is what makes repos unit-testable without gen stubs. | `app/repositories/backfill_jobs.py#module docstring (~L1-7)`; exception `app/repositories/signal_sources.py#owner_scope_predicate (~L39)` | `app/repositories/backfill_chunks.py#module docstring (~L1-7)` |
| **INGEST-2** | **Dynamic SQL column names are allow-listed (`_UPDATABLE_COLUMNS`), never interpolated from input** — see `backfill_jobs.py#update_job` (~L59-76) for the placeholder-numbering mechanism. | f-stringing a user value is injection. | `app/repositories/backfill_jobs.py#update_job` (~L59-76; `_UPDATABLE_COLUMNS` ~L13-26) | `app/repositories/backfill_jobs.py#update_job (~L59)` |
| **INGEST-3** | **`page_token` is a raw integer offset, not an opaque cursor.** | Treating it as a base64/opaque token breaks pagination continuity. | `servicer.py#ListBackfillJobs` (`offset = int(request.page.page_token)` ~L894), `#QuerySignals` (`offset_val = request.page.page_token` ~L1265); `list_jobs(offset=)` | `app/handlers/servicer.py#ListBackfillJobs (~L883)` |
| **INGEST-4** | **`0.0`/`0` mean "unset" for `conviction` on both write and read** — write stores `None` when `conviction <= 0`; read returns `0.0` when NULL. Consumers must read `0.0` as *unknown confidence*, not zero. (Feature 092 F-9 additionally rejects `conviction` outside `[0.0, 1.0]` up front, `servicer.py#_ingest_external_signal` ~L1035.) | The proto documents the sentinel; treating 0.0 as a real confidence misweights signals. | write `servicer.py#_ingest_external_signal` (`… else None` ~L1055), read `#QuerySignals` (`… else 0.0` ~L1302); proto `ingest.proto#ExternalSignal` (`conviction` ~L127) | `app/handlers/servicer.py#_ingest_external_signal (~L1055)` |
| **INGEST-5** | **`QuerySignals` producer semantics** (consumed by analysis; since feature 224 a headered read is owner-scoped by `SignalScope`, default own + `system`): results are `ORDER BY ingested_at DESC` (arrival order; feature 022 **now DOES return `sig.ingested_at`**, `servicer.py#QuerySignals` ~L1316); the active/expiry filter is **opt-in** (no `active_window` → all signals returned regardless of `valid_until`); `symbol` is upper-cased on write (`symbol_upper`, one call reused across insert/dedup-claim/response) and query. | Consumers that assume expiry is always applied, or that sort by validity, get wrong results. | `servicer.py#QuerySignals` (~L1203), `ORDER BY ingested_at DESC` (~L1279), `ingested_at` returned (~L1316), write `#_ingest_external_signal` `symbol_upper` (~L1057), query-side `.upper()` (~L1234); proto `ingest.proto#QuerySignalsRequest` (~L146, `active_window` ~L150) | `app/handlers/servicer.py#QuerySignals (~L1203)` |
| **INGEST-6** | **Extractors are pure JSON parsers — `BaseExtractor.extract(RawInput) -> list[dict]` takes already-fetched data; all network I/O and secret resolution live in the poll loop, never in `extract()`** (feature 166). | Implementing a new source extractor that resolves secrets or does httpx I/O inside `extract()` breaks its no-network unit-testability — the whole reason the abstraction exists. | contract `app/extractors/base.py#McpClientInput` (~L43-48), `#BaseExtractor` (~L61-65); `McpClientExtractor` imports no network/secret code `app/extractors/mcp_client.py` (docstring ~L1-7, class ~L23); the credential-bearing fetch is in `app/engine/mcp_client_loop.py#poll_one_source` (`mcp_client.fetch` ~L150) | `app/extractors/base.py#McpClientInput (~L43)` |
| **INGEST-7** | **`credentials_ref` splits on the FIRST dot → `(namespace, dotted-key)`; the key legitimately contains dots and is passed verbatim to `GetSecret`** (e.g. `"ingest.mcp_credential.<uuid>"` → `("ingest", "mcp_credential.<uuid>")`; since feature 224 the key is an opaque per-user UUID resolved with `user_id` = the source owner). | A naive `ref.split(".")` unpack (or splitting on the last dot) mangles the secret key → `PERMISSION_DENIED`/not-found from the config `keyPrefixes` grant. | `app/config/watcher.py#split_credentials_ref` (~L21-26), used `app/engine/mcp_client_loop.py#poll_one_source` (~L140) | `app/config/watcher.py#split_credentials_ref (~L21)` |
| **INGEST-8** | **The `mcp_client` poll loop sleeps BEFORE its first cycle** (`while True: interval = …; sleep(interval); run_one_cycle()` — interval recomputed each tick), so no poll fires at boot — the first fetch is one `poll_interval_seconds` (default 300s) after startup. | An integration test (or an operator) expecting sources to be polled immediately at service start is wrong — they are not. | `app/engine/mcp_client_loop.py#run_mcp_client_loop` (~L226-236: `while True` ~L230, `asyncio.sleep` ~L234 before `run_one_cycle` ~L236) | `app/engine/mcp_client_loop.py#run_mcp_client_loop (~L226)` |
| **INGEST-10** | **Backfill cancel guards rely on the in-memory `_canceled_jobs` set alone, which is correct only with single-instance ingest and with `CancelBackfill` as the sole `CANCELED` writer, adding the job to the set BEFORE its `CANCELED` write.** The queued-start guard in `_run_backfill`, its `except` guard, the fundamentals pre-finalize guard, `_finalize_backfill` and the per-chunk `run_one` check read only the set (no DB re-read). `_resume_job` additionally skips a persisted `CANCELED` row after a restart (feature 261). | A second ingest instance has its own empty set, so a cancel received by instance A cannot stop a job queued on instance B, which then overwrites `CANCELED` with `RUNNING`/`COMPLETED` (debt-radar D-34 re-opened). Reordering the add after the write, or adding another `CANCELED` writer, opens the same window in-process. Ingest runs `instance_count: 1` (`.do/app.yaml`, `.do/app.dev.yaml` ~L240); scaling it requires a persisted-status check first. | `servicer.py#CancelBackfill` (~L911; set-add ~L938 before the `CANCELED` `update_job` ~L939, the only `CANCELED` write in `app/`); set guards `#_run_backfill` (~L513, ~L534), `#_execute_fundamentals_backfill` (~L568), `#_finalize_backfill` (~L688), `#run_one` (~L801); persisted-status skip `#_resume_job` (~L759); guard test `tests/test_ingest_servicer.py#test_o3_cancel_registers_set_before_canceled_write` (~L842) | `app/handlers/servicer.py#CancelBackfill (~L938)` |
| **INGEST-11** | **Owner-scoped RPCs get their owner through the `@owner_scoped` decorator, which stores the RPC name in the `_CURRENT_RPC` contextvar that `self._owner(context)` reads.** Decorated RPCs (N=7): `IngestSignal`, `QuerySignals`, `ListSignalSources`, `ManageSignalSource`, `ListTemplates`, `ManageTemplate`, `InstantiateTemplate`. The backfill RPCs and `NormalizeRawData` are undecorated: `GetBackfillStatus` / `ListBackfillJobs` return every job to any caller (platform-wide, undocumented; findings). | A new RPC that calls `self._owner(context)` without the decorator raises `LookupError` on `_CURRENT_RPC.get()`; calling `_resolve_owner` directly with a made-up rpc name bypasses the `_SYSTEM_GRANTS` key. `CLAUDE.md` states the identity gate (feature 225) but not this mechanism. | `app/handlers/servicer.py#owner_scoped` (decorators ~L981/1202/1327/1404/1553/1561/1618), `#_owner` (~L386), `#_SYSTEM_GRANTS` (~L108), `#_SYSTEM_GRANT_SAN` (~L112) | `app/handlers/servicer.py#owner_scoped` |
| **INGEST-12** | **A finished backfill job reaches notify through ONE path — the `webhook_handoff` loop — and at most once per job.** The loop is started after `resume_incomplete_jobs()` and waits before its first cycle; the markers `webhook_enqueued_at` / `webhook_rejected_at` close the job for good, whatever status it shows later. The request is built from the row's columns only and never carries `error`. A terminal status write only sets `_webhook_wake`. The background call carries a freshly minted `x-trace-id` and no `x-user-id` / `x-access-scope` (no inbound request to propagate from; a recorded C-03 exception). | Calling `FanoutWebhook` inline at one of the terminal-write sites sends a second event for a job the restart reconcile flips `FAILED` and resume then completes, and skips the retry a notify outage needs. A cycle that runs before resume would hand off `FAILED` for a job about to be re-driven. `error` can hold internal addresses and the receiver is external. Keying the hand-off per status instead of per job re-sends on a late status change. | `app/engine/webhook_handoff_loop.py#run_one_cycle`, `#_fanout_request`, `#run_webhook_handoff_loop`; start order `app/main.py#run_webhook_handoff_loop` (after `resume_incomplete_jobs`); candidates and markers `app/repositories/backfill_jobs.py#list_webhook_handoff_candidates`, `#mark_webhook_enqueued`, `#mark_webhook_rejected`; wake `app/handlers/servicer.py#_webhook_wake`; `tests/test_webhook_handoff_loop.py` | `app/engine/webhook_handoff_loop.py#run_one_cycle` |

## Gotchas & scars

- **The `validate_config_json` allow-list is a deliberate superset of the DB CHECK constraint** (signal `source_type`) — tightening it to match a single migration wrongly rejects valid mediated types. Migration `011` widened the CHECK to include `mcp_client`/`derived`, both mirrored in the validator. Evidence: `app/repositories/signal_sources.py#validate_config_json` (~L235; `derived` ~L268, `mcp_client` ~L272).
- **`_STR_TO_ENUM` must keep resolving stored `15m`/`1h`** (feature 143): it derives `timeframe_enum` for historical/resumed rows on the read path, even though `_BARS_PER_DAY`/`_TF_ALIASES` are now `1d`-only. Evidence: `servicer.py#_STR_TO_ENUM`, `backfill_chunks.py#_BARS_PER_DAY`.
