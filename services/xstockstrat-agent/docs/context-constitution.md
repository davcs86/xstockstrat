## Rules (`AGENT-*`) — binding, easy-to-miss conventions

|---|---|---|---|---|
| **AGENT-1** | **Every backend RPC opens its own ephemeral `async with mtls.secure_channel(EP, "xstockstrat-<target>") as channel:` and discards it — no pooled/module-level channel or stub.** (Feature 210 swept the former `grpc.aio.insecure_channel(EP)` dials to the mutual-TLS factory `app/mtls.py` `secure_channel`; the connect-per-call shape is unchanged.) **Scoped exception (feature 295):** the two lifespan `WatchConfig` channels (`agent`, `indicators`; `app/config/watcher.py`) are the only long-lived ones — every unary RPC stays ephemeral. | Caching a persistent channel at import diverges from every call site and breaks the connect-per-call assumption the whole client layer follows. | `app/client.py` (72 `mtls.secure_channel` opens: 70 in `app/client.py`, 2 in `app/auth.py` — the exact line list drifts on every added tool, don't enumerate it); factory `app/mtls.py` | `app/mtls.py` |
| **AGENT-2** | **Import `gen.*` stubs *inside* each function body (`# noqa: PLC0415`), never at module top.** | The whole `client.py` follows the lazy-import contract (also keeps import-time light); a top-level `from gen.foo.v1 import …` breaks the convention. It is a convention, not a lint gate: ruff selects only `E,F,I,UP` (`pyproject.toml#[tool.ruff.lint]`), so PLC0415 is not enforced and the `# noqa: PLC0415` directives are inert. | first lazy `from gen.*` at `app/client.py#from gen.indicators.v1 import indicators_pb2 (~L153)`; the one top-level exception is `app/auth.py#from gen.identity.v1 (~L13)` (HTTP-transport path only) | `app/client.py#from gen.indicators.v1 import indicators_pb2 (~L153)` |
| **AGENT-3** | **The *real caller's* derived `x-access-scope`** — computed from the caller's roles by `app/scopes.py` `roles_to_access_scope` — is forwarded so the backend role check *verifies* admin rather than trusting an asserted constant. Since PR #994 it rides on EVERY outbound call via `CallerPropagationMiddleware` (AGENT-4), not just the management write tools; forwarding scope on an open read path is harmless (reads don't gate on it). The management write tools still *derive* the scope through `app/tools.py` `_caller_access_scope` for their own raise-if-missing-claims guard, and the client wrappers still pass an explicit `("x-access-scope", …)` that `_metadata()` de-duplicates against the middleware-bound context. *(Feature 092 removed the old hardcoded `("x-access-scope","7")` `_admin_metadata()` tuple.)* `manage_formula` relies on the indicators backend's author-ownership check, not an admin bit (see AGENT-3b). | Omitting the scope on a write path silently fails the backend role check. | `app/tools.py#_caller_access_scope (~L137)`; `app/scopes.py#roles_to_access_scope (~L39)`; `CallerPropagationMiddleware` | `app/tools.py#_caller_access_scope (~L137)` |
| **AGENT-3b** | **A sibling choke point, `_caller_user_id`, sits alongside `_caller_access_scope` — both route through the shared `_require_claims`** — and it must be used (never a plain claims dict-get) anywhere a tool needs the caller's *own* identity rather than their role. It raises rather than falling back to `""` on a missing `user_id`. | Notify's `EmitAlertRequest.target_user_id == ""` is the BROADCAST sentinel (`packages/proto/notify/v1/notify.proto#EmitAlertRequest.target_user_id (~L71)`; `#target_user_id = 7;    // empty = broadcast (~L45)`) — a silent empty-string fallback on identity lookup would silently broadcast an alert a caller meant to keep private. Introduced by feature 111 to close a real caller-identity-spoofing gap (see Gotchas & scars). | `app/tools.py#_require_claims (~L119)`, `#_caller_user_id (~L158)` | `app/tools.py#_caller_user_id (~L158)` |
| **AGENT-4** | **The agent is a platform EDGE and forwards the full propagation trio — `x-user-id` + `x-access-scope` + `x-trace-id` — on EVERY outbound backend gRPC (PR #994, reversing the old "originates, forwards nothing" stance).** A single `CallerPropagationMiddleware` (a `ServerMiddleware` registered in `register_tools`) binds the caller's identity onto `client`'s per-request contextvar (`client.set_caller`/`reset_caller`) for the duration of each `tools/call`, and `client._metadata()` reads that context — so every `client.*` helper forwards the trio with **no per-tool plumbing** (reads included, not just writes). Every header is sourced from the OAuth-verified claims `app/main.py` `_authorized` stamped on the request scope — **never** a caller-supplied parameter, so the feature-111 anti-spoofing guarantees still hold — and a fresh `x-trace-id` is **minted at the edge** when the claims carry none (on the HTTP path `_authorized` mints it before `ValidateToken` and stamps it on the claims, so the auth call and the tool calls share one trace). `_metadata(*extra)` de-duplicates a legacy per-call header against the context, and returns only `extra` when no context is bound (stdio, the pre-token OAuth handshake, direct unit-test calls). PLAT-4 now applies to the agent like any other edge. | Downstream services resolve ownership/audit/trace from these headers; an edge that dropped them (the old stance) left reads unattributable and traces broken at the agent boundary. Sourcing from verified claims — not request params — keeps the forwarding safe. | `app/tools.py#CallerPropagationMiddleware (~L193)` + `#_claims_from_scope_state (~L181)`; `app/client.py#_metadata (~L80)`/`#set_caller (~L62)`/`#reset_caller (~L70)` | `app/tools.py#CallerPropagationMiddleware (~L193)` |
| **AGENT-5** | **Every anticipated refusal in `app/tools.py` raises `ToolError`, and every gRPC-calling tool maps `AioRpcError` through `_grpc_error_message` (`except grpc.aio.AioRpcError as e: raise ToolError(_grpc_error_message(e, deadline_s=…)) from e`), passing `deadline_s` = the budget the call actually carries (`client._RPC_TIMEOUT_S`, `client._LONG_RPC_TIMEOUT_S`, or the tool's own config-driven deadline), plus `write=True` (or a verb-derived bool) in mutating tools — a new tool must do the same, and must also be added to `_PROBES` in `tests/test_tool_errors.py`.** The mapper returns `CODE: body`: details pass through for the closed set of caller-actionable codes, `NOT_FOUND` keeps the tool's literal plus the server hint, and every other code collapses to a fixed hint with the detail logged at WARNING on the agent; a call site allow-lists exact `UNAVAILABLE` strings via `pass_messages`. On a client-side `DEADLINE_EXCEEDED` a read says "upstream did not respond within Ns (deadline exceeded); retry shortly"; a write says "…; outcome unknown, verify before retrying", never "retry shortly". A server-set deadline detail (anything but grpc's client sentinel `"Deadline Exceeded"`) passes through verbatim. | The MCP SDK forwards only a `ToolError`'s text; any built-in exception (`RuntimeError`, `ValueError`, `PermissionError`) is masked to `Error executing tool <name>`, so the caller never sees why the call was refused. A client deadline does not prove a write failed, so "retry shortly" on a write invites a duplicate order/alert/signal. | `app/tools.py#_grpc_error_message (~L247)`, applied inside each tool's gRPC-calling body (the exact site list drifts on every tool addition, so it isn't enumerated); guards `tests/test_tool_errors.py::test_tools_py_raises_only_tool_error` and `::test_every_listed_tool_surfaces_a_backend_refusal_as_a_tool_error`, plus `tests/test_tool_deadlines.py` | `app/tools.py#_grpc_error_message (~L247)` |
| **AGENT-6** | **`JWT_SECRET` is the HMAC key signing the stateless OAuth `txn` blob (since feature 147, which removed the dedicated `MCP_AGENT_SECRET`)**. It is not sent as an outbound header. Inbound MCP auth requires `claims.aud == AGENT_PUBLIC_URL`. | Rotating the secret affects OAuth transaction integrity; the `aud`/`resource`/`AGENT_PUBLIC_URL` triple must stay aligned. `JWT_SECRET` is now shared between JWT verification and `txn` signing — rotate with that dual role in mind. | `app/oauth_server.py#JWT_SECRET = os.environ.get (~L36)`, signing `#_sign_txn (~L48-55)` | `app/oauth_server.py#JWT_SECRET = os.environ.get (~L36)` |
| **AGENT-7** | **`_account_to_dict` PINS every zero-value-omittable scalar (`is_paper`/`is_active`/`halted`) back onto the `MessageToDict` projection so its presence is uniform across every account.** `MessageToDict` follows proto3 JSON semantics: a scalar bool with no field presence is OMITTED at its `false` zero value. Left raw, a `false` field vanishes from some accounts and is present on others, so a tool-consuming agent cannot distinguish `false` from "field absent" (the reported list_accounts confusion). Any NEW zero-value-sensitive scalar added to `BrokerAccount` must be pinned here too — the `test_account_to_dict_covers_every_broker_account_field` F-12 parity guard forces this projection under review whenever a proto field is added. | A silently-absent `false` is read as unknown/missing by the model, not as `false`; uniform presence removes the ambiguity. | `app/client.py` `_account_to_dict` (the `for _bool_field in (...)` pin loop); guard `tests/test_broker_account_client.py::test_account_to_dict_covers_every_broker_account_field`; the same F-12 parity pattern guards the opportunity projection: `tests/test_opportunity_projection.py#test_opportunity_projection_covers_every_proto_field` | `app/client.py` (`_account_to_dict`) |

That swap does not reach the two lifespan `WatchConfig` watchers, which dial `grpc.aio.secure_channel` directly (not `client.mtls.secure_channel`) — stub their reads with `install_watcher` (AGENT-9). | `app/auth.py`, `app/oauth_server.py`, `app/oauth_metadata.py`, `app/main.py` (`AGENT_PUBLIC_URL`); `tests/conftest.py#set_env`; `app/config/watcher.py#ConfigWatcher.__init__` (`self._channel = grpc.aio.secure_channel(` ~L38) | `tests/conftest.py#set_env` |

## Gotchas & scars

- **The agent hand-maintains mirrors of ingest's and notify's enum maps** (`_TF_ALIASES`/`_TF_TO_ENUM`/`_FILL_MODE_MAP` mirror ingest; `_SEVERITY_MAP` mirrors notify's `AlertSeverity`). Adding a timeframe/fill-mode/severity upstream without extending these maps breaks the tool. Evidence: `app/client.py#_SEVERITY_MAP (~L184)`, `#_TF_ALIASES (~L1955)`/`#_TF_TO_ENUM (~L1956)`/`#_FILL_MODE_MAP (~L2057)`.
- **The trading/offline/broker RPCs also hand-encode proto enum *numbers* inline** (distinct from the string-alias maps above): `_OFFLINE_SIDE={"buy":1,"sell":2}` (`app/client.py#_OFFLINE_SIDE (~L2362)`), `#_OFFLINE_ORDER_TYPE (~L2363)`, `_BROKER_TYPE={"alpaca":1,"ibkr":2}` (`#_BROKER_TYPE (~L2367)`), and the magic literal `broker_type=3,  # common.v1.BROKER_TYPE_OFFLINE` (`#broker_type=3 (~L2402)`). These must stay in lockstep with the proto enum numbering — a proto enum renumber silently corrupts side/type/broker on every offline/broker RPC. Prefer the generated symbols (as the rest of the file does, e.g. `#WATCHLIST_ENTRY_SOURCE_MANUAL (~L469)`, `#SIZING_MODE_PORTFOLIO (~L698)`).
- **`manage_account resume` hand-rolls the `_require_admin` (`app/tools.py#_require_admin`) `scope & 0x04` check inline** (`if not (scope & 0x04): raise ToolError(…)`, `app/tools.py#manage_account` resume branch) instead of calling `_require_admin`, so the two must be kept in sync; both must stay in lockstep with the `x-access-scope` bit scheme. An agent copying a neighbor tool would omit the gate.
- **Hand-kept mirrors of other modules' logic (owner in parentheses).** `app/client.py#_effective_config_user_id` mirrors `services/xstockstrat-config/src/grpc/authz.ts#boundReadUserId` (code comment: "the two must change together"; it decides the `user_id` echoed by `get_config`, the server does the actual binding). `app/scopes.py#roles_to_access_scope` mirrors `services/xstockstrat-ui/src/lib/auth.ts#rolesToAccessScope` (viewer 1, trader 11, admin 15) — a role added in the UI and not here silently yields scope 0, i.e. denied. `app/tool_metrics.py#_BUCKETS_MS` must match `scripts/testdata/rpc-status-vectors.json`. And `app/auth.py#validate_bearer_claims` returns the **truthy** `IDENTITY_UNAVAILABLE` sentinel when identity stalls: only `app/main.py#handle_mcp` tests `is IDENTITY_UNAVAILABLE` before the boolean check, so a new `if await _authorized(...)` caller would treat identity-down as authorized.
