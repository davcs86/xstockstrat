## Rules (`AGENT-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **AGENT-1** | **Every backend RPC opens its own ephemeral `async with mtls.secure_channel(EP, "xstockstrat-<target>") as channel:` and discards it — no pooled/module-level channel or stub.** (Feature 210 swept the former `grpc.aio.insecure_channel(EP)` dials to the mutual-TLS factory `app/mtls.py` `secure_channel`; the connect-per-call shape is unchanged.) | Caching a persistent channel at import diverges from every call site and breaks the connect-per-call assumption the whole client layer follows. | `app/client.py` (69 `mtls.secure_channel` opens across client.py+auth.py — the exact line list drifts on every added tool, don't enumerate it); factory `app/mtls.py` | `app/mtls.py` |
| **AGENT-2** | **Import `gen.*` stubs *inside* each function body (`# noqa: PLC0415`), never at module top.** | The whole `client.py` follows the lazy-import contract (also keeps import-time light); a top-level `from gen.foo.v1 import …` trips the linter and breaks the convention. | first lazy `from gen.*` at `app/client.py#from gen.indicators.v1 import indicators_pb2 (~L129)`; the one top-level exception is `app/auth.py#from gen.identity.v1 (~L13)` (HTTP-transport path only) | `app/client.py#from gen.indicators.v1 import indicators_pb2 (~L129)` |
| **AGENT-3** | **The *real caller's* derived `x-access-scope`** — computed from the caller's roles by `app/scopes.py` `roles_to_access_scope` — is forwarded so the backend role check *verifies* admin rather than trusting an asserted constant. Since PR #994 it rides on EVERY outbound call via `CallerPropagationMiddleware` (AGENT-4), not just the management write tools; forwarding scope on an open read path is harmless (reads don't gate on it). The management write tools still *derive* the scope through `app/tools.py` `_caller_access_scope` for their own raise-if-missing-claims guard, and the client wrappers still pass an explicit `("x-access-scope", …)` that `_metadata()` de-duplicates against the middleware-bound context. *(Feature 092 removed the old hardcoded `("x-access-scope","7")` `_admin_metadata()` tuple.)* `manage_formula` relies on the indicators backend's author-ownership check, not an admin bit (see AGENT-3b). | Omitting the scope on a write path silently fails the backend role check. | `app/tools.py#_caller_access_scope (~L134)`; `app/scopes.py#roles_to_access_scope (~L39)`; `CallerPropagationMiddleware` | `app/tools.py#_caller_access_scope (~L134)` |
| **AGENT-3b** | **A sibling choke point, `_caller_user_id`, sits alongside `_caller_access_scope` — both route through the shared `_require_claims`** — and it must be used (never a plain claims dict-get) anywhere a tool needs the caller's *own* identity rather than their role. It raises rather than falling back to `""` on a missing `user_id`. | Notify's `EmitAlertRequest.target_user_id == ""` is the BROADCAST sentinel (`packages/proto/notify/v1/notify.proto#EmitAlertRequest.target_user_id (~L71)`; `#target_user_id = 7;    // empty = broadcast (~L45)`) — a silent empty-string fallback on identity lookup would silently broadcast an alert a caller meant to keep private. Introduced by feature 111 to close a real caller-identity-spoofing gap (see Gotchas & scars). | `app/tools.py#_require_claims (~L116)`, `#_caller_user_id (~L155)` | `app/tools.py#_caller_user_id (~L155)` |
| **AGENT-4** | **The agent is a platform EDGE and forwards the full propagation trio — `x-user-id` + `x-access-scope` + `x-trace-id` — on EVERY outbound backend gRPC (PR #994, reversing the old "originates, forwards nothing" stance).** A single `CallerPropagationMiddleware` (a `ServerMiddleware` registered in `register_tools`) binds the caller's identity onto `client`'s per-request contextvar (`client.set_caller`/`reset_caller`) for the duration of each `tools/call`, and `client._metadata()` reads that context — so every `client.*` helper forwards the trio with **no per-tool plumbing** (reads included, not just writes). Every header is sourced from the OAuth-verified claims `app/main.py` `_authorized` stamped on the request scope — **never** a caller-supplied parameter, so the feature-111 anti-spoofing guarantees still hold — and a fresh `x-trace-id` is **minted at the edge** when the claims carry none. `_metadata(*extra)` de-duplicates a legacy per-call header against the context, and returns only `extra` when no context is bound (stdio, the pre-token OAuth handshake, direct unit-test calls). PLAT-4 now applies to the agent like any other edge. | Downstream services resolve ownership/audit/trace from these headers; an edge that dropped them (the old stance) left reads unattributable and traces broken at the agent boundary. Sourcing from verified claims — not request params — keeps the forwarding safe. | `app/tools.py#CallerPropagationMiddleware (~L190)` + `#_claims_from_scope_state (~L178)`; `app/client.py#_metadata (~L59)`/`#set_caller (~L41)`/`#reset_caller (~L49)` | `app/tools.py#CallerPropagationMiddleware (~L190)` |
| **AGENT-5** | **Tool-layer gRPC error mapping is applied via `_grpc_error_message` + `except AioRpcError → RuntimeError` — a new tool must add it explicitly** (the older tools don't have it; see findings). `_grpc_error_message` maps `DEADLINE_EXCEEDED` to a "retry shortly" message for every tool; a tool that sets its own gRPC deadline passes `deadline_s` so the message names it. | Without the wrapper, raw `AioRpcError` leaks to the MCP client. | `app/tools.py#_grpc_error_message (~L223)` (`DEADLINE_EXCEEDED` branch ~L228-231), applied inside each tool's gRPC-calling body (a new tool must add it explicitly; the exact site list drifts on every tool addition, so it isn't enumerated) | `app/tools.py#_grpc_error_message (~L223)` |
| **AGENT-6** | **`JWT_SECRET` is the HMAC key signing the stateless OAuth `txn` blob (since feature 147, which removed the dedicated `MCP_AGENT_SECRET`)**. It is not sent as an outbound header. Inbound MCP auth requires `claims.aud == AGENT_PUBLIC_URL`. | Rotating the secret affects OAuth transaction integrity; the `aud`/`resource`/`AGENT_PUBLIC_URL` triple must stay aligned. `JWT_SECRET` is now shared between JWT verification and `txn` signing — rotate with that dual role in mind. | `app/oauth_server.py#JWT_SECRET = os.environ.get (~L35)`, signing `#_sign_txn (~L47-54)` | `app/oauth_server.py#JWT_SECRET = os.environ.get (~L35)` |
| **AGENT-7** | **`_account_to_dict` PINS every zero-value-omittable scalar (`is_paper`/`is_active`/`halted`) back onto the `MessageToDict` projection so its presence is uniform across every account.** `MessageToDict` follows proto3 JSON semantics: a scalar bool with no field presence is OMITTED at its `false` zero value. Left raw, a `false` field vanishes from some accounts and is present on others, so a tool-consuming agent cannot distinguish `false` from "field absent" (the reported list_accounts confusion). Any NEW zero-value-sensitive scalar added to `BrokerAccount` must be pinned here too — the `test_account_to_dict_covers_every_broker_account_field` F-12 parity guard forces this projection under review whenever a proto field is added. | A silently-absent `false` is read as unknown/missing by the model, not as `false`; uniform presence removes the ambiguity. | `app/client.py` `_account_to_dict` (the `for _bool_field in (...)` pin loop); guard `tests/test_broker_account_client.py::test_account_to_dict_covers_every_broker_account_field`; the same F-12 parity pattern guards the opportunity projection: `tests/test_opportunity_projection.py#test_opportunity_projection_covers_every_proto_field` | `app/client.py` (`_account_to_dict`) |

## Gotchas & scars

- **The agent hand-maintains mirrors of ingest's and notify's enum maps** (`_TF_ALIASES`/`_TF_TO_ENUM`/`_FILL_MODE_MAP` mirror ingest; `_SEVERITY_MAP` mirrors notify's `AlertSeverity`). Adding a timeframe/fill-mode/severity upstream without extending these maps breaks the tool. Evidence: `app/client.py#_SEVERITY_MAP (~L160)`, `#_TF_ALIASES (~L1771)`/`#_TF_TO_ENUM (~L1772)`/`#_FILL_MODE_MAP (~L1870)`.
- **The trading/offline/broker RPCs also hand-encode proto enum *numbers* inline** (distinct from the string-alias maps above): `_OFFLINE_SIDE={"buy":1,"sell":2}` (`app/client.py#_OFFLINE_SIDE (~L2158)`), `#_OFFLINE_ORDER_TYPE (~L2159)`, `_BROKER_TYPE={"alpaca":1,"ibkr":2}` (`#_BROKER_TYPE (~L2163)`), and the magic literal `broker_type=3,  # common.v1.BROKER_TYPE_OFFLINE` (`#broker_type=3 (~L2198)`). These must stay in lockstep with the proto enum numbering — a proto enum renumber silently corrupts side/type/broker on every offline/broker RPC. Prefer the generated symbols (as the rest of the file does, e.g. `#WATCHLIST_ENTRY_SOURCE_MANUAL (~L404)`, `#SIZING_MODE_PORTFOLIO (~L622)`).
- **Admin-gated tools check `x-access-scope & 0x04` CLIENT-side via `_require_admin`** (`app/tools.py#_require_admin (~L146)`, called ~L1772-1857: `manage_user`, `list_users`, `get_user`, `admin_get_user_metadata`, `admin_set_user_metadata`) — deliberate defence-in-depth on top of the server-side check. **`manage_account resume` hand-rolls the same check inline** (`if not (scope & 0x04): raise PermissionError`, `app/tools.py#manage_account` ~L2201) instead of calling `_require_admin`, so the two must be kept in sync; both must stay in lockstep with the `x-access-scope` bit scheme. An agent copying a neighbor tool would omit the gate.
