## Gotchas & scars

- **Node `getInt` does NOT have the Python zero-trap** — it uses `v?.intVal ?? def`, so a stored `0` returns `0`, and the producer round-trips `0` cleanly. The "0 reads as default" behavior documented in root CLAUDE.md is a **Python** property, not a Node one. An agent copying "0 means default" into Node code is wrong. Evidence: `services/xstockstrat-identity/src/services/configWatcher.ts#getInt` (~L113-116; ledger ~L112, notify ~L115 identical), `configServiceImpl.ts#buildConfigValue` (~L568). (Confirms root PLAT-6 gotcha + CF-N10.)
- **Snapshot values are encoded camelCase for ts-proto** (`string_val→stringVal`); consumers read camelCase. This is the contract that makes the request-decode bug (findings) detectable. Evidence: `configServiceImpl.ts#toProtoSnapPayload` (~L32; `stringVal` ~L49, `changedKeys` read ~L61).
- **`x-internal-caller` is a second, structurally separate authz channel from `x-access-scope`** (root PLAT-9) — a hardcoded per-`{callerID, namespace, key}` allowlist, direction-restricted (e.g. the trading reconciliation poller may only move `platform.trading_state` toward `REDUCE_ONLY`/`HALTED`, never back to `ACTIVE`), fails closed, and persists the caller id in a dedicated `caller_identity` column (`NULL` for ordinary human writes) rather than free-text `reason`; when no `x-user-id` is propagated, the grant id is also the audit `changed_by` (feature 241 — `request.author` is ignored). Already documented in this service's own CLAUDE.md item 7; recorded here because feature 102 postdates this constitution's original derivation. Evidence: `src/grpc/authz.ts` (`#HEADER_INTERNAL_CALLER` ~L56, `#INTERNAL_CALLER_ALLOWLIST` ~L66, `#hasInternalCallerAuthority` ~L82); `configServiceImpl.ts#setConfig` (hoisted `internalCallerAuthorized` ~L379-388, `callerIdentity` ~L407, `const author = callerUserId || …` ~L412); `migrations/014_config_caller_identity.up.sql:1-9` (column).
- **`GetSecret`'s read allow-list (`SECRET_CALLER_ALLOWLIST`) is a SECOND, structurally separate allow-list from the internal-caller WRITE allow-list** (both in `authz.ts`), and it supports **dynamic per-source secrets via `keyPrefixes` (`startsWith`), not just exact `keys`.** It now holds **two** grants: `marketdata` (exact `keys` — the four vendor credentials) and `ingest` (`keyPrefixes: ['mcp_credential.']`, feature 166; since feature 224 also `peerSan: 'xstockstrat-ingest'` — the mTLS peer must present that DNS SAN, so the `x-internal-caller` header alone no longer suffices). Granting a caller whose secret keys are dynamic (e.g. the per-user `mcp_credential.<uuid>`) via exact `keys` — impossible to enumerate — makes it fail closed on every read. Evidence: `src/grpc/authz.ts#SECRET_CALLER_ALLOWLIST` (~L114, `peerSan` ~L124), matcher `#hasSecretCallerAuthority` (~L149).
- **Seed values must equal the code default so a seed migration is a runtime no-op.** Migration `029` is a deliberate single-site exception: it flips the production `trading.risk.bracket_orders_enabled` seed from `'false'` to `'true'` (its header cites an operator sign-off in feature 189). Whether that belongs as a rule is an open question (see Candidate rules). Evidence: `migrations/029_heal_config_keys_full_dotted.up.sql`, `migrations/030_*.up.sql`.
- **`#884` — own-scope echo (see CONFIG-7).** Production bug: Save on a displayed row was silently refused because config-ui sent its *viewed filter's* scope instead of the row's own registered scope. The `trading_mode='all'`-vs-shadow duplication half of the original story was removed by feature 147; the echo-the-row's-own-scope discipline now applies to `user_id`.
