## Gotchas & scars

- **Node `getInt` does NOT have the Python zero-trap** — it uses `v?.intVal ?? def`, so a stored `0` returns `0`, and the producer round-trips `0` cleanly. The "0 reads as default" behavior documented in root CLAUDE.md is a **Python** property, not a Node one. An agent copying "0 means default" into Node code is wrong. Evidence: `src/services/configWatcher.ts:88-91`, `configServiceImpl.ts:565-580` (`buildConfigValue`). (Confirms root PLAT-6 gotcha + CF-N10.)
- **Snapshot values are encoded camelCase for ts-proto** (`string_val→stringVal`); consumers read camelCase. This is the contract that makes the request-decode bug (findings) detectable. Evidence: `configServiceImpl.ts:39-73` (`toProtoSnapPayload`, `stringVal` at `:58`), `:184` (`changedKeys` read).
- **`x-internal-caller` is a second, structurally separate authz channel from `x-access-scope`** (root PLAT-9) — a hardcoded per-`{callerID, namespace, key}` allowlist, direction-restricted (e.g. the trading reconciliation poller may only move `platform.trading_state` toward `REDUCE_ONLY`/`HALTED`, never back to `ACTIVE`), fails closed, and persists the caller id in a dedicated `caller_identity` column (`NULL` for ordinary human writes) rather than free-text `author`/`reason`. Already documented in this service's own CLAUDE.md item 7; recorded here because feature 102 postdates this constitution's original derivation. Evidence: `src/grpc/authz.ts` (`HEADER_INTERNAL_CALLER:93`, `INTERNAL_CALLER_ALLOWLIST:103`, `hasInternalCallerAuthority:117`); `configServiceImpl.ts:351-356,376` (consumption); `migrations/014_config_caller_identity.up.sql:1-9` (column).
- **`GetSecret`'s read allow-list (`SECRET_CALLER_ALLOWLIST`) is a SECOND, structurally separate allow-list from the internal-caller WRITE allow-list** (both in `authz.ts`), and it supports **dynamic per-source secrets via `keyPrefixes` (`startsWith`), not just exact `keys`.** It now holds **two** grants: `marketdata` (exact `keys` — the four vendor credentials) and `ingest` (`keyPrefixes: ['mcp_credential.']`, feature 166). Granting a caller whose secret keys are dynamic (e.g. `mcp_credential.<slug>`) via exact `keys` — impossible to enumerate — makes it fail closed on every read. Evidence: `src/grpc/authz.ts:109-120` (`SECRET_CALLER_ALLOWLIST`), matcher `hasSecretCallerAuthority:174-188`.
- **`#884` — own-scope echo (see CONFIG-7).** Production bug: Save on a displayed row was silently refused because config-ui sent its *viewed filter's* scope instead of the row's own registered scope. The `trading_mode='all'`-vs-shadow duplication half of the original story was removed by feature 147; the echo-the-row's-own-scope discipline now applies to `user_id`.
