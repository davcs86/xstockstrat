## Gotchas & scars

- **Snapshot values are encoded camelCase for ts-proto** (`string_val→stringVal`); consumers read camelCase. This is the contract that makes the request-decode bug (findings) detectable. Evidence: `configServiceImpl.ts#toProtoSnapPayload` (~L43; `stringVal` ~L60, `changedKeys` read ~L72).
- **Grant dynamic per-source secrets via `keyPrefixes`, never exact `keys`** — exact `keys` cannot enumerate per-user `mcp_credential.<uuid>`, so such a grant fails closed on every read (grants/`peerSan`: `CLAUDE.md` § Critical Invariants #6). Evidence: `src/grpc/authz.ts#SECRET_CALLER_ALLOWLIST`, `#hasSecretCallerAuthority`.
- **Seed values must equal the code default so a seed migration is a runtime no-op.** Migration `029` is a deliberate single-site exception: it flips the production `trading.risk.bracket_orders_enabled` seed from `'false'` to `'true'` (its header cites an operator sign-off in feature 189). Whether that belongs as a rule is an open question (see Candidate rules). Migration `031_heal_indicators_sandbox_keys_full_dotted` is a second exception: it overwrites `value_data` and `default_value` of the global bare `indicators.sandbox.*` rows with hardcoded literals (5000 / 134217728 / `numpy,pandas,math,statistics`) and leaves `config.config_values_premigration_031` behind as a permanent snapshot table (open question in findings). Evidence: `migrations/029_heal_config_keys_full_dotted.up.sql`, `migrations/031_heal_indicators_sandbox_keys_full_dotted.up.sql`, `migrations/030_*.up.sql`.
