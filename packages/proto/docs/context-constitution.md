## Rules (`PROTO-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **PROTO-1** | **`common/v1` is the only cross-package import — no service proto imports another service's proto.** Shared concepts are duplicated as separate messages or funneled through `common/v1`, never reused across packages. | Cross-service message reuse (e.g. importing `marketdata.Bar` or `trading.OrderSide` elsewhere) is architecturally disallowed here. | all imports are `common/v1` + google well-known (N=all 11); e.g. bespoke `analysis.proto:95` `CoverageGap` vs `common.TimeRange` | `packages/proto/common/v1/common.proto` |
| **PROTO-2** | **Never delete or renumber a field; there are no `reserved` ranges. Deprecate-don't-delete: keep dead members with `[deprecated = true]`.** | Field-number never-reuse is enforced by `buf breaking` + retaining deprecated members (the repo doesn't use `reserved`). Deleting/renumbering, or adding `reserved`, breaks the discipline. | `common.proto:85-91` (Timeframe numbered out-of-source-order — proof of never-renumber), `trading.proto:254` (`is_paper` field 3 `[deprecated]`), `marketdata.proto:58,89,102,120` (`string timeframe [deprecated=true]`); also `common.proto:62` `ENVIRONMENT_DEV [deprecated]`, `config.proto:85` `VALUE_TYPE_FLOAT_MAP [deprecated]` | `packages/proto/common/v1/common.proto:85-91` |
| **PROTO-3** | **`<NAME>_UNSPECIFIED = 0` is an active runtime convention meaning "no filter / server default"** (mirrored for scalars: empty string / 0 = "no narrowing"). Give a new filter field a zero sentinel; never make UNSPECIFIED an error or a non-zero "all". | Consumers rely on the zero value as the wildcard across ~32 enums. | `trading.proto:162-163` (`ListOrdersRequest.trading_mode`), `portfolio.proto:114` (`PositionRiskFlag`), `analysis.proto:75` (`BACKTEST_STATUS_UNSPECIFIED=0`), `indicators.proto:100` (`ParameterType`) | `packages/proto/trading/v1/trading.proto:162-163` |
| **PROTO-4** | **An `optional` numeric field that backs a config-governed platform default is three-way, not two-way**: unset → inherit the `<service>.<category>.default_*` config key; explicit `0` → hard-disable; explicit `N` → override. This is a stronger contract than "unset vs. `""`" (see the `account_id` gotcha below) — don't collapse it to a plain presence check. | A naive `value ?? default` (or Go zero-value) check can't tell "caller wants 0" from "caller wants the config default," silently picking the wrong one for a 0-meaning-disable field. | `analysis.proto:327` (`cooldown_days`), `:339` (`exit_cooldown_days`, "mirrors cooldown_days"), `trading.proto:126-128` (`confidence`, "Unset → confidence=1.0") | `packages/proto/analysis/v1/analysis.proto:327` |
| **PROTO-5** | **`ConfigKeyMeta.default_value` (field 3) and `.current_value` (field 9) are not interchangeable** — `default_value` is the seed/declared metadata `SetConfig` never touches; `current_value` is the live `value_data`. A consumer reading `default_value` for display/edit-prefill silently shows stale data after every write. | Exactly this bug shipped and was fixed in #901 (config-ui always re-displayed the seed default after a successful save, looking like a silent no-op). | `config.proto:159` (`default_value`, field 3), `:167` (`current_value`, field 9, added by commit `7b77447`) | `packages/proto/config/v1/config.proto:167` |
| **PROTO-6** | **A nullable scalar *inside a `repeated` field* needs a dedicated per-element wrapper message with a proto3 `optional` scalar** (e.g. `IndicatorValue { optional double value }`) — never a bare `google.protobuf.*Value` element. `*Value` gives presence only for a *singular* optional; as a repeated element an empty wrapper is byte- and JSON-identical to `0.0` (serializes to `0`), silently turning a gap into a real zero. | A warm-up-head / NaN / None point in an indicator series must read as "gap," not `0.0`; `repeated google.protobuf.DoubleValue` cannot express that (feature 125). Distinct from PROTO-4 (singular config-default optional). | `analysis.proto:709-711` (`IndicatorValue{optional double value}`, with the in-proto rationale comment); sibling `SparklinePoint{optional double close}` `:580-582` ("mirrors IndicatorValue") | `packages/proto/analysis/v1/analysis.proto:709-711` |
| **PROTO-7** | **A *singular* `optional` scalar means "value unavailable / not-yet-computed," never a fabricated `0.0` (omit-not-fabricate).** Distinct from PROTO-4 (config-default three-way) and PROTO-6 (repeated-element wrapper): this is the plain singular-optional-for-absence contract. **Exception:** `marketdata.Fundamentals`' 11 metric fields deliberately did NOT go `optional` (buf-breaking + approval cost); their absence is signaled by the `missing_metrics` list (field 18) instead — check it there. | A consumer that reads a plain `double`/`0` as a real datum renders/ranks a fabricated `$0` as a genuine reading (a $0 price, a 0 target). | `analysis.proto:564-567,575` (`Opportunity.live_price/change_pct/target_price/stop_price/signal_confidence`), `marketdata.proto:80,84` (`LatestPrice.last_price/prev_close`), `portfolio.proto:62` (`Portfolio.realized_pnl`, offline-only), `analysis.proto:582` (`SparklinePoint.close`); exception `marketdata.proto:181-189` (`Fundamentals` + `missing_metrics` field 18) | `packages/proto/analysis/v1/analysis.proto:564-567` |
| **PROTO-8** | **`BacktestResult` and `BarDiagnostic` wire bytes are persisted verbatim ("store what you serve," feature 068), so their fields are additive-only and must never be renumbered or retyped — a stronger constraint than the general `buf breaking` gate.** | A buf-breaking-clean edit (a field reshuffle/retype) that is nonetheless not purely additive silently corrupts previously-persisted `analysis.backtest_details` blobs on read. | in-proto NOTE `analysis.proto:108-111` | `packages/proto/analysis/v1/analysis.proto:108-111` |
| **PROTO-9** | **AIP-161 `FieldMask update_mask` partial-update convention (N=4): a mutation RPC that supports partial update carries `google.protobuf.FieldMask update_mask` with a consistent contract — mask ABSENT ⇒ FULL REPLACE (back-compat for the full-payload clients existing UIs send); mask PRESENT ⇒ merge only the masked paths (unlisted fields preserved); a masked path with an absent request value CLEARS that field (AIP-161 clear-semantics — the only way to erase a message/repeated field under proto3); and column/row-authoritative fields are mask-guarded (reject with `INVALID_ARGUMENT`).** Portfolio adds a **stricter variant**: `default_strategy_id` is writable ONLY via the masked path — a *no-mask* request carrying it is rejected `InvalidArgument` (the inverse of analysis's reject-when-masked guard). | Adding a new `Update*` RPC that treats an absent mask as "update nothing" (or unconditionally partial-merges) silently breaks the full-payload clients that rely on absent-mask = full replace — the back-compat guarantee all four call out. Writing a column-authoritative field from the body instead of erroring is the second trap. | `analysis.proto:386` (`UpdateStrategyRequest`, feature 070), `ingest.proto:197` (`ManageSignalSourceRequest`, feature 088), `indicators.proto:208` (`UpdateFormulaRequest`, feature 086), `portfolio.proto:294` (`UpdateWatchlistRequest`, feature 170); AIP-161 clear-semantics comment `analysis.proto:375-379`; column-authoritative reject `analysis.proto:385`; portfolio stricter variant `portfolio.proto:289-291` | `packages/proto/analysis/v1/analysis.proto:386` |

## Gotchas & scars

- **`#901` — `ConfigKeyMeta.default_value` vs `.current_value` (see PROTO-5).** Root cause of a real production bug: `ListKeys` only ever returned `default_value`, so config-ui's Value column and edit-prefill always re-displayed the untouched seed default after a save. Fixed by adding `current_value` (field 9). A future `ListKeys` consumer reusing the old field name would reintroduce it.
- **The field name `timeframe` denotes three different contracts**: (a) legacy `string timeframe [deprecated]` + sibling `Timeframe timeframe_enum` (marketdata Bar, ingest — 6 sites); (b) newer messages name the *enum* `timeframe`; (c) `indicators ComputeIndicatorRequest.timeframe` is a **plain non-deprecated `string`** that never migrated. Copying a neighbor can read/write the wrong type or a dead field. Evidence: `marketdata.proto:118,153`, `analysis.proto:97`, `indicators.proto:49`.
- **`config.ConfigValue` is the only `oneof` in the module** and *does* distinguish `int_val=0` from unset — so the Python "0 = default" consumer trap is a consumer choice, not a contract limit (CF-N10; see root findings). Evidence: `config.proto:61-67`.
- **`account_id` presence differs by service**: portfolio uses proto3 `optional` (7 messages) to distinguish unset from `""`; trading uses a plain field. Same logical field, different wire-presence contract. Evidence: `portfolio.proto:163,169` (7 sites `:163,169,176,190,195,201,205`); `trading.proto:111,160` (`Order.account_id:56`).
- **body `user_id` is a `[deprecated]` no-op on mutation RPCs (identity is the `x-user-id` header — root PLAT-11), but NOT universally.** These fields are deprecated + server-ignored: `trading.proto:110,133,153,189`, `portfolio.proto:161,166,172,186,198`, `analysis.proto:285`. These still carry a **live, read** `user_id` (filter/selector/owner-stamp, not identity): `ledger.proto:51` (`AppendEvent`, else metadata fallback), `trading.proto:322` (`SnapshotOfflinePositions`), `notify.proto:75,83,91` (`StreamAlerts/Acknowledge/ListAlerts`), `identity.proto:124,126` (`ListAuthorizedApps/RevokeAuthorizedApp`). Adding a new mutation RPC → omit `user_id` (or mark deprecated); never read it for ownership.
