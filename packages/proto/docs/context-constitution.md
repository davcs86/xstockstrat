| **PROTO-1** | **`common/v1` is the only cross-package import — no service proto imports another service's proto.** Shared concepts are duplicated as separate messages or funneled through `common/v1`, never reused across packages. | Cross-service message reuse (e.g. importing `marketdata.Bar` or `trading.OrderSide` elsewhere) is architecturally disallowed here. | all imports are `common/v1` + google well-known (N=all 11); e.g. bespoke `analysis.proto#CoverageGap (~L109)` vs `common.TimeRange` | `packages/proto/common/v1/common.proto` |
| **PROTO-2** | **Never delete or renumber a field; there are no `reserved` ranges. | **PROTO-3** | **On a request-side filter, `<NAME>_UNSPECIFIED = 0` is an active runtime convention meaning "no filter / server default"** (mirrored for scalars: empty string / 0 = "no narrowing"). | **PROTO-4** | **An `optional` numeric field that backs a config-governed platform default is three-way, not two-way**: unset → inherit the `<service>.<category>.default_*` config key; explicit `0` → hard-disable; explicit `N` → override. ## Gotchas & scars

- **`#901` — `ConfigKeyMeta.default_value` vs `.current_value` (see PROTO-5).** Root cause of a real production bug: `ListKeys` only ever returned `default_value`, so config-ui's Value column and edit-prefill always re-displayed the untouched seed default after a save. Fixed by adding `current_value` (field 9). A future `ListKeys` consumer reusing the old field name would reintroduce it.
- **The field name `timeframe` denotes three different contracts**: (a) legacy `string timeframe [deprecated]` + sibling `Timeframe timeframe_enum` (marketdata Bar, ingest — 6 sites); (b) newer messages name the *enum* `timeframe`; (c) `indicators ComputeIndicatorRequest.timeframe` is a **plain non-deprecated `string`** that never migrated. Copying a neighbor can read/write the wrong type or a dead field. Evidence: `marketdata.proto#string timeframe = 2 [deprecated = true] (~L117,130,148)` + `#Timeframe timeframe = 2 (~L162,175)`, `analysis.proto#Timeframe timeframe = 2 (~L111)`, `indicators.proto#ComputeIndicatorRequest.timeframe (~L60)`.
- **`config.ConfigValue` is the only `oneof` in the module** and *does* distinguish `int_val=0` from unset — so the Python "0 = default" consumer trap is a consumer choice, not a contract limit (CF-N10; see root findings). Evidence: `config.proto#oneof value (~L61-67)`.
- **`account_id` presence differs by service**: portfolio uses proto3 `optional` (7 messages) to distinguish unset from `""`; trading uses a plain field. Same logical field, different wire-presence contract. Evidence: `portfolio.proto#optional string account_id` (7 sites ~L163,169,176,190,195,201,205); `trading.proto#PlaceOrderRequest.account_id (~L130)`, `#ListOrdersRequest.account_id (~L179)` (`Order.account_id` ~L65).
- **body `user_id` is a `[deprecated]` no-op on mutation RPCs (identity is the `x-user-id` header — root PLAT-11), but NOT universally.** These fields are deprecated + server-ignored: `trading.proto#string user_id = … [deprecated = true] (~L120,143,163,199)`, `portfolio.proto#string user_id = 1 [deprecated = true] (~L161,166,172,186,198)`, `analysis.proto#string user_id = 2 [deprecated = true] (~L307)`. These still carry a **live, read** `user_id` (filter/selector/owner-stamp, not identity): `ledger.proto#falls back to the x-user-id metadata (~L51)` (`AppendEvent`), `trading.proto#SnapshotOfflinePositionsRequest.user_id (~L332)`, `notify.proto#StreamAlertsRequest/AcknowledgeAlertRequest/ListAlertsRequest.user_id (~L83,91,99)`, `identity.proto#ListAuthorizedAppsRequest/RevokeAuthorizedAppRequest (~L129,131)`. Also deprecated + server-ignored (feature 224): `indicators.proto#UpdateFormulaRequest.user_id` and `#DeleteFormulaRequest.user_id` (must match `formula.author` or `PERMISSION_DENIED`), and the visibility fields `RegisterFormulaRequest.is_public`/`author`, `UpdateFormulaRequest.is_public`, `ListFormulasRequest.include_public`, `FormulaDefinition.is_public`; template instantiation ignores the payload's `is_public`/`author` (`FormulaTemplate`). Adding a new mutation RPC → omit `user_id` (or mark deprecated); never read it for ownership. See PROTO-10 for the one sanctioned body-selector pattern.
