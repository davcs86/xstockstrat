## Rules (`PROTO-*`) — binding, easy-to-miss conventions

| ID | Rule | Why | Evidence | Example (canonical `path:line`) |
|---|---|---|---|---|
| **PROTO-1** | **`common/v1` is the only cross-package import — no service proto imports another service's proto.** Shared concepts are duplicated as separate messages or funneled through `common/v1`, never reused across packages. | Cross-service message reuse (e.g. importing `marketdata.Bar` or `trading.OrderSide` elsewhere) is architecturally disallowed here. | all imports are `common/v1` + google well-known (N=all 11); e.g. bespoke `analysis.proto#CoverageGap (~L109)` vs `common.TimeRange` | `packages/proto/common/v1/common.proto` |
| **PROTO-2** | **Never delete or renumber a field; there are no `reserved` ranges. Deprecate-don't-delete: keep dead members with `[deprecated = true]`.** | Field-number never-reuse is enforced by `buf breaking` + retaining deprecated members (the repo doesn't use `reserved`). Deleting/renumbering, or adding `reserved`, breaks the discipline. | `common.proto#enum Timeframe (~L85-91)` (numbered out-of-source-order — proof of never-renumber), `trading.proto#RegisterBrokerAccountRequest.is_paper (~L264)` (field 3 `[deprecated]`; note `BrokerAccount.is_paper = 4` (~L241) is live, NOT deprecated), `marketdata.proto#string timeframe = … [deprecated = true] (~L86,117,130,148)`; also `common.proto#ENVIRONMENT_DEV (~L62)` `[deprecated]`, `config.proto#VALUE_TYPE_FLOAT_MAP (~L85)` `[deprecated]` | `packages/proto/common/v1/common.proto#enum Timeframe (~L85-91)` |
| **PROTO-3** | **On a request-side filter, `<NAME>_UNSPECIFIED = 0` is an active runtime convention meaning "no filter / server default"** (mirrored for scalars: empty string / 0 = "no narrowing"). Give a new filter field a zero sentinel; never make UNSPECIFIED an error or a non-zero "all". **On a response-side annotation enum, UNSPECIFIED = 0 means "unknown", and such a label never gates a decision.** | Consumers rely on the zero value as the wildcard across ~32 enums; reading a response label's UNSPECIFIED as "all"/"none" (or branching a guard on the label) misreads a best-effort annotation. | `trading.proto#ListOrdersRequest.trading_mode (~L175)`, `portfolio.proto#PositionSide` (`ListPositionsRequest.side` ~L202), `analysis.proto#BACKTEST_STATUS_UNSPECIFIED (~L86)`, `indicators.proto#ParameterType (~L110)`; response-side: `portfolio.proto#PositionRiskFlag (~L128)` (`Position.flag`, an annotation, not a request filter), `portfolio.proto#MarkSource` (`Position.mark_source`, feature 240), `analysis.proto#FundamentalsGap (~L205-208)` ("UNSPECIFIED = label unknown", "never affects the guard decision"), `analysis.proto#SymbolDiagnostics.fundamentals_gap (~L241)` | `packages/proto/trading/v1/trading.proto#ListOrdersRequest.trading_mode (~L175)` |
| **PROTO-4** | **An `optional` numeric field that backs a config-governed platform default is three-way, not two-way**: unset → inherit the `<service>.<category>.default_*` config key; explicit `0` → hard-disable; explicit `N` → override. This is a stronger contract than "unset vs. `""`" (see the `account_id` gotcha below) — don't collapse it to a plain presence check. | A naive `value ?? default` (or Go zero-value) check can't tell "caller wants 0" from "caller wants the config default," silently picking the wrong one for a 0-meaning-disable field. | `analysis.proto#optional int32 cooldown_days (~L354)`, `#exit_cooldown_days (~L366)` ("mirrors cooldown_days"), `trading.proto#optional double confidence (~L136-138)` ("Unset → confidence=1.0") | `packages/proto/analysis/v1/analysis.proto#optional int32 cooldown_days (~L354)` |
| **PROTO-5** | **`ConfigKeyMeta.default_value` (field 3) and `.current_value` (field 9) are not interchangeable** — `default_value` is the seed/declared metadata `SetConfig` never touches; `current_value` is the live `value_data`. A consumer reading `default_value` for display/edit-prefill silently shows stale data after every write. | Exactly this bug shipped and was fixed in #901 (config-ui always re-displayed the seed default after a successful save, looking like a silent no-op). | `config.proto#string default_value = 3 (~L161)`, `#current_value (~L169)` (field 9, added by commit `7b77447`) | `packages/proto/config/v1/config.proto#current_value (~L169)` |
| **PROTO-6** | **A nullable scalar *inside a `repeated` field* needs a dedicated per-element wrapper message with a proto3 `optional` scalar** (e.g. `IndicatorValue { optional double value }`) — never a bare `google.protobuf.*Value` element. `*Value` gives presence only for a *singular* optional; as a repeated element an empty wrapper is byte- and JSON-identical to `0.0` (serializes to `0`), silently turning a gap into a real zero. | A warm-up-head / NaN / None point in an indicator series must read as "gap," not `0.0`; `repeated google.protobuf.DoubleValue` cannot express that (feature 125). Distinct from PROTO-4 (singular config-default optional). | `analysis.proto#IndicatorValue (~L835-836)` (`{optional double value}`, with the in-proto rationale comment); sibling `#SparklinePoint (~L657-658)` (`{optional double close}`, "mirrors IndicatorValue") | `packages/proto/analysis/v1/analysis.proto#IndicatorValue (~L835-836)` |
| **PROTO-7** | **A *singular* `optional` scalar means "value unavailable / not-yet-computed," never a fabricated `0.0` (omit-not-fabricate).** Distinct from PROTO-4 (config-default three-way) and PROTO-6 (repeated-element wrapper): this is the plain singular-optional-for-absence contract. **Exception:** `marketdata.Fundamentals`' 11 metric fields deliberately did NOT go `optional` (buf-breaking + approval cost); their absence is signaled by the `missing_metrics` list (field 18) instead — check it there. Where the metric stayed a plain `double`, absence is signalled by a sibling flag (`*_unavailable`) or a `missing_metrics` list — check it before treating `0` as data. | A consumer that reads a plain `double`/`0` as a real datum renders/ranks a fabricated `$0` as a genuine reading (a $0 price, a 0 target). | `analysis.proto#Opportunity` (`live_price/change_pct/target_price/stop_price` ~L621-624, `signal_confidence` ~L632), `marketdata.proto#LatestPrice` (`last_price` ~L108, `prev_close` ~L110), `portfolio.proto#optional double realized_pnl (~L62)` (offline-only), `analysis.proto#SparklinePoint.close (~L658)`, `marketdata.proto#EtfFlag.is_etf (~L398)` (`optional bool`: unset = unknown / not yet cached; `GetEtfFlags` is cache-only); exception `marketdata.proto#Fundamentals (~L218)` + `missing_metrics` field 18 (~L238) — the same `missing_metrics` signalling recurs in `marketdata.proto#HistoricalFundamentalsPeriod` (feature 198, `missing_metrics` field 21; metric fields are plain `double`, so check the list before treating `0.0` as data); further singular-`optional` sites: `analysis.proto#Opportunity` `composite_score` / `symbol_score`, `ingest.proto` `reliability_weight` | `packages/proto/analysis/v1/analysis.proto#Opportunity (~L621-624)` |
| **PROTO-8** | **`BacktestResult` and `BarDiagnostic` wire bytes are persisted verbatim ("store what you serve," feature 068), so their fields are additive-only and must never be renumbered or retyped — a stronger constraint than the general `buf breaking` gate.** | A buf-breaking-clean edit (a field reshuffle/retype) that is nonetheless not purely additive silently corrupts previously-persisted `analysis.backtest_details` blobs on read. | in-proto NOTE `analysis.proto#BacktestResult` (note: that comment says the message is guarded by `buf breaking`; this rule is the stronger statement — some edits are buf-clean yet corrupt persisted blobs, so do not rely on the in-proto wording) | `packages/proto/analysis/v1/analysis.proto#BacktestResult (~L119-123)` |
| **PROTO-9** | **AIP-161 `FieldMask update_mask` partial-update convention (N=4): a mutation RPC that supports partial update carries `google.protobuf.FieldMask update_mask` with a consistent contract — mask ABSENT ⇒ FULL REPLACE (back-compat for the full-payload clients existing UIs send); mask PRESENT ⇒ merge only the masked paths (unlisted fields preserved); a masked path with an absent request value CLEARS that field (AIP-161 clear-semantics — the only way to erase a message/repeated field under proto3); and column/row-authoritative fields are mask-guarded (reject with `INVALID_ARGUMENT`).** Portfolio adds a **stricter variant**: `default_strategy_id` is writable ONLY via the masked path — a *no-mask* request carrying it is rejected `InvalidArgument` (the inverse of analysis's reject-when-masked guard). | Adding a new `Update*` RPC that treats an absent mask as "update nothing" (or unconditionally partial-merges) silently breaks the full-payload clients that rely on absent-mask = full replace — the back-compat guarantee all four call out. Writing a column-authoritative field from the body instead of erroring is the second trap. | `analysis.proto#ManageStrategyRequest` (feature 070; `update_mask = 3`, applies only to `STRATEGY_OPERATION_UPDATE`; the former `UpdateStrategyRequest` no longer exists), `ingest.proto#ManageSignalSourceRequest.update_mask (~L228)` (feature 088), `indicators.proto#UpdateFormulaRequest.update_mask (~L243)` (feature 086), `portfolio.proto#UpdateWatchlistRequest (~L282)` (feature 170); AIP-161 clear-semantics comment and column-authoritative reject are in the `ManageStrategyRequest` comment block (`analysis.proto#ManageStrategyRequest`); portfolio stricter variant `portfolio.proto#UpdateWatchlistRequest.default_strategy_id (~L289-291)` | `packages/proto/analysis/v1/analysis.proto#ManageStrategyRequest` |

## Gotchas & scars

- **The field name `timeframe` denotes three different contracts**: (a) legacy `string timeframe [deprecated]` + sibling `Timeframe timeframe_enum` (marketdata Bar, ingest — 6 sites); (b) newer messages name the *enum* `timeframe`; (c) `indicators ComputeIndicatorRequest.timeframe` is a **plain non-deprecated `string`** that never migrated. Copying a neighbor can read/write the wrong type or a dead field. Evidence: `marketdata.proto#string timeframe = 2 [deprecated = true] (~L117,130,148)` + `#Timeframe timeframe = 2 (~L162,175)`, `analysis.proto#Timeframe timeframe = 2 (~L111)`, `indicators.proto#ComputeIndicatorRequest.timeframe (~L60)`.
- **`config.ConfigValue` is the only `oneof` in the module** and *does* distinguish `int_val=0` from unset. Evidence: `config.proto#oneof value (~L61-67)`.
- **`account_id` presence differs by service**: portfolio uses proto3 `optional` (7 messages) to distinguish unset from `""`; trading uses a plain field. Same logical field, different wire-presence contract. Evidence: `portfolio.proto#optional string account_id` (7 sites ~L163,169,176,190,195,201,205); `trading.proto#PlaceOrderRequest.account_id (~L130)`, `#ListOrdersRequest.account_id (~L179)` (`Order.account_id` ~L65).
- Body `user_id` rules → root PLAT-11; module-specific additions: Also deprecated + server-ignored (feature 224): `indicators.proto#UpdateFormulaRequest.user_id` and `#DeleteFormulaRequest.user_id` (must match `formula.author` or `PERMISSION_DENIED`), and the visibility fields `RegisterFormulaRequest.is_public`/`author`, `UpdateFormulaRequest.is_public`, `ListFormulasRequest.include_public`, `FormulaDefinition.is_public`; template instantiation ignores the payload's `is_public`/`author` (`FormulaTemplate`). Adding a new mutation RPC → omit `user_id` (or mark deprecated); never read it for ownership. See PROTO-10 for the one sanctioned body-selector pattern. **The deprecated-field inventory is wider than the above:** `portfolio.proto#Watchlist.symbols` (~L258) is deprecated while the request-side `CreateWatchlistRequest.symbols`, `UpdateWatchlistRequest.symbols` and `AddWatchlistSymbolsRequest.symbols` are not (still accepted as "legacy"); `ingest.proto#ManageSignalSourceRequest.operation` (~L226) is a string→enum migration via `operation_enum`; `config.proto#SetConfigRequest.author` (~L126) is deprecated (feature 241).
- `ledger.proto#QueryEventsRequest.owner_only` defaults to false = all users' rows; every user-facing reader must set it — see ledger CLAUDE.md item 5 / LEDGER-6 (the agent was not checked).
