## Swallowed / silenced errors

### D-39 ⚠ FMP/Finnhub transport errors carry the API key in the wrapped URL — SEV-2 · leverage H÷XS  *(new)*
- **Evidence:**
  - `services/xstockstrat-marketdata/internal/fmp/fmp_client.go:243`: `return fmt.Errorf("fmp: %s request failed: %w", path, err)`.
  - `services/xstockstrat-marketdata/internal/finnhub/finnhub_client.go:118`: `fmt.Errorf("finnhub: %s request failed: %w", path, err)`.
  - The `err` from `http.Client.Do` is a `*url.Error`, whose `Error()` embeds the full request URL. That URL carries `apikey=` / `token=` (`finnhub_client.go:110`).
  - The status branch in the same functions deliberately avoids this: "Never include the URL (it carries the apikey) in the error" (`fmp_client.go:254`, `finnhub_client.go:126`).
  - The error reaches callers as `connect.CodeUnavailable` with `%w` (`marketdata_service.go:1704`).
- **What it hides:** On a timeout, DNS failure or connection reset, the plaintext vendor key lands in gRPC status messages, analysis logs and any OTel exporter. The secret-at-rest design of feature 147 is bypassed at the network edge.
- **Benefit of fixing:** Closes a secret-disclosure path for 2 of the 4 vendor credentials.
- **LOE:** XS (estimate). Unwrap `*url.Error` and re-wrap only `.Err`, or redact the query. Two sites, plus one test each.
- **Trade-off:**
  - **Not fixing:** a key rotation every time a log is shared.
  - **Fixing:** the error loses the host and path context. Keep `path`, which is already formatted.

### D-47 Portfolio `processPositionSync` is `ackAlways` — offline sync write failures advance the cursor — SEV-2 · leverage H÷S  *(new)*
- **Evidence:**
  - `services/xstockstrat-portfolio/internal/service/portfolio_service.go:1117`: `s.consumeEventStream(ctx, "position sync", "account.positions.synced", ackAlways(s.processPositionSync))`.
  - `:1213-1231`: errors from `UpsertPositionFromSync`, `DeletePositionsNotInSync` and `UpsertOfflineRealized` are only `slog.Warn`ed.
  - The fill consumer was moved to a retrying handler when D-02 was fixed; this consumer was not.
- **What it hides:** A broker account heals on its next poll. An **offline** account is only re-emitted on the next ConfirmOrder or snapshot, so one DB blip leaves its positions, realized P&L and `recent_fills` stale indefinitely. The same applies to `ackAlways(s.processAccountDeregistered)` (`:1129`): a failed `DeleteOfflineRealized` keeps a deregistered account listed.
- **Benefit:** Offline-account books stay consistent with trading (feature 240).
- **LOE:** S (estimate). Return the error (a retryable handler), relying on the idempotent absolute upserts.
- **Trade-off:**
  - **Not fixing:** silent stale offline P&L.
  - **Fixing:** a poison event now blocks the stream, so it needs the same bounded-retry/park policy the fill path uses.
