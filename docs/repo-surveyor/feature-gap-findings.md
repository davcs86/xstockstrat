## Feature gaps

### G-01 Opportunity Snooze/Dismiss returns Unimplemented — SEV-2 · leverage H÷XS
- **Surface element:** `/insights/opportunities` actions (`services/xstockstrat-ui/src/app/insights/opportunities/page.tsx:121,155`) call `analysisClient.setOpportunityAction` (`src/hooks/useOpportunities.ts:63`).

## Inconsistencies

### I-01 ⚠ `manage-users.py` writes the DB directly and re-implements (or omits) identity's guards — SEV-1 · leverage H÷S
- **Sibling surfaces:**
  - CLI `reset-password` (`scripts/manage-users.py:177-185`) only `UPDATE`s `password_hash`. Server `UpdatePassword` also revokes refresh tokens (`identityServiceImpl.ts:818-820`).
  - CLI `update-roles` (`manage-users.py:371-377`) has no last-admin guard. Server `SetUserRoles` (`identityServiceImpl.ts:842-862`) and CLI `delete-user` (`manage-users.py:444-457`) both have one.
  - Every CLI write skips identity's admin-audit to ledger.
- **User impact:** an operator who resets a compromised account's password leaves the attacker's sessions alive for up to 30 days (SEV-1: "authentication" integrity). `update-roles` can also strip the last admin.
- **Fix trade-off both ways:** call the identity RPCs (mTLS client cert required), which gives one guard set and audit. Alternatively, mirror the guards and add the revoke. The second is faster but keeps the N-way drift.

### I-02 Money, prices and quantities are `double` everywhere; `common.Decimal` is unused — SEV-2 · leverage H÷XL
- **Sibling surfaces:**
  - `trading.proto:53-57` (Order qty/limit/stop/filled_avg) and `portfolio.proto:50-55,67-73,152-155`.
  - `common.Decimal{units,nanos,currency}` (`common.proto:28`) has 0 references.
  - This is already logged in `packages/proto/docs/context-constitution-findings.md:16`.
- **User impact:** float rounding in P&L and cost basis.
- **Fix trade-off:**
  - **Fixing:** a breaking proto migration across every service (2 owners + platform lead).
  - **Not fixing:** a bounded precision risk.
  - Recorded for completeness, not urged.

### I-03 Four pagination contracts — SEV-2 · leverage M÷L
- **Sibling surfaces:**
  1. `common.PageRequest`/`page_token` (`trading.proto:171`, `ledger.proto:65`).
  2. `page_size + page_offset` (`analysis.proto:404-405`, `indicators.proto:212-213`).
  3. Inline `limit + page_token` returning a bare `next_page_token` (`notify.proto:101-102,108`).
  4. `limit` only (`analysis.proto:256,850`).
- The response field is named `pagination` (`marketdata.proto:289`) versus `page` elsewhere.
- MCP mirrors the split: `limit`/`page_token` (query_bars, get_positions), `page_size`/`page_token` (`list_opportunities` `tools.py:1423`), and none (list_strategies, list_formulas, list_users, list_accounts).
- UI shows three paging UXs (prev/next at `positions/page.tsx:519`, load-more at `opportunities/page.tsx:371`, none elsewhere).
- **User impact:** every client re-learns paging, and the gaps in G-07 follow from it.
- **Fix trade-off:**
  - **Fixing:** converge on `PageRequest` incrementally, non-breaking (add new fields and deprecate the old ones).
  - **Not fixing:** each new list picks a fifth style.

### I-04 MCP parameter naming and default drift — SEV-3 · leverage M÷S
- **Sibling surfaces:**
  - Dates: `query_bars` `start_date/end_date` (`tools.py:339`), `query_fundamentals` `range_start/range_end` (`:374`), and `run_backtest` / `trigger_backfill` `start/end` (`:688`, `:1263`).

- **User impact:** the LLM caller and humans mis-name arguments, causing tool-call failures.
- **Fix trade-off:**

  - **Not fixing:** recurring argument errors.

### I-05 MCP error contract is split — SEV-3 · leverage M÷XS
- **Sibling surfaces:** `list_signal_sources` (`tools.py:454`), `ingest_signal` (`:580`), `emit_alert` (`:668`) and `screen_symbols` (`:808`) let a raw `AioRpcError` escape. Every other tool maps errors through `_grpc_error_message`.
- "No fields supplied" raises `ValueError` in some tools (`:967`, `:1748`) and `RuntimeError` in others (`:1087`, `:1198`, `:1614`).
- Unknown `operation` values are rejected client-side by 4 `manage_*` tools and passed through by 3. `operation` is typed as a bare `str` throughout, whereas `mode` and `value_type` use `Literal`.
- **User impact:** the agent receives inconsistent, sometimes raw, error text.
- **Fix trade-off:**
  - **Fixing:** a mechanical wrap, plus `Literal[...]` for `operation`, which also publishes the allowed values in the schema.
  - **Not fixing:** brittle agent recovery.

### I-07 ⚠ Authorization asymmetries at the edges — SEV-2 · leverage M÷S
- **Sibling surfaces:**
  - MCP `set_config` takes a free-text `author` from the caller (`tools.py:1535`) and records it in audit. By contrast, `manage_formula` derives the author from verified claims (`:1009-1013`).
  - `ingest_signal` always auto-broadcasts its alert (`target_user_id=""`, `:620`). `emit_alert` requires an explicit `broadcast` (`:646`).

- **User impact:**

  - One user's high-conviction signal alerts every user.
  - Non-admins hit error screens.
- **Fix trade-off:**
  - **Fixing:** derive `author` from claims, make auto-alerts user-targeted (or behind a config flag), and add `adminOnly` to the two nav items.
  - **Not fixing:** audit trust erodes.
  - → debt-radar D-31 covers the related cross-user config read.

## Product metrics to track  (what & why — recommendation-only; placement → signal-map)

### Opportunity queue (the home "Decide" surface)
- **Metric:** task success = share of viewed opportunities that receive TAKE, SNOOZE or DISMISS; error rate of `SetOpportunityAction`. Read from the BFF `insightsBff` analysis router and the `analysis.opportunity_actions` rows.
- **Why:** the queue only works if users act on it. G-01 means this rate is currently structurally 0, so the metric would have caught the regression.
- **→ signal-map:** a per-method BFF outcome counter (code, method).

### Backtest loop (strat-lab / MCP)
- **Metric:**
  - Funnel: `run_backtest` call → success → `set_strategy_live`.
  - Repeat-backtest rate per strategy.
  - p95 duration.
  - Read from MCP tool invocations (`tools.py:683`, `:1230`) and the analysis `RunBacktest` handler.
- **Why:** this measures whether research converts to live strategies. The repeat rate is the proxy for G-03's missing read-back.
- **→ signal-map:** an MCP tool-call counter + duration histogram labelled by tool and outcome.

### Order placement (trader)
- **Metric:**
  - Order-ticket submit → broker-accepted rate.
  - Rejection reasons by code.
  - Cancel/replace usage.
  - Read from trading `PlaceOrder` outcomes and the UI `OrderForm` submit.
- **Why:** this is the core trading task, and its reject reasons show UX friction (validation versus broker).
