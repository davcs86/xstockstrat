## Feature gaps

### G-11 First-run local boot needs `source scripts/mtls-dev-env.sh`, and no onboarding doc says so — SEV-2 · leverage H÷XS  *(new)*
- **Surface element:** `scripts/mtls-dev-env.sh:9-17` ("must be sourced"; it refuses to execute). `docker-compose.yml:22,457` defaults the `MTLS_*` PEMs to empty, and every service fails closed without them (feature 210).
- **The gap:** a grep for `mtls-dev-env` in `docs/setup/getting-started.md`, `README.md`, `scripts/bootstrap.sh` and `scripts/localenv-setup.sh` finds **0** hits. `localenv-setup.sh:104` runs `gen-dev-certs.sh` and then tells the user only to run `bootstrap.sh`. The step is documented only in `docs/patterns/inter-service-mtls.md:69-76` and the rollout runbook.
- **Trade-off:**
  - **Building it:** one line in three onboarding docs, or have `bootstrap.sh` source it.
  - **Not building it:** every new developer's stack crash-loops on its first `up`.

### G-18 A from-scratch prod recreate ships `YOUR_PROD_MTLS_*` placeholders — SEV-2 · leverage H÷S  *(promoted from NC-1, confirmed 2026-10-02; still untracked)*
- **Surface element:** `.github/workflows/prod-up.yml` and `scripts/do-inject-prod-secrets.py`. Neither has changed since `aa84f8b`, and a grep for `MTLS` finds 0 hits in either. `.do/app.yaml` holds the placeholders, and only `deploy.yml` fills them.
- **The gap:** the disaster-recovery path (recreate prod from spec) produces fail-closed services that crash-loop on `tls.X509KeyPair`.
- **Trade-off:**
  - **Building it:** inject the three `MTLS_*` values in the recreate path, reusing `mtls-provision.sh set-secret prod`.
  - **Not building it:** the DR runbook fails at the worst time.

### G-12 Templates show "update available" with no way to apply the update — SEV-3 · leverage M÷S  *(new)*
- **Surface element:** `TemplateOrigin.update_available` (`packages/proto/common/v1/common.proto:142`). It is shown as a badge on `insights/formulas/page.tsx:55` and `insights/strategies/[id]/page.tsx:228`, and documented to agents at `tools.py:1206-1207`.
- **The gap:** no RPC, tool or UI action diffs or re-syncs an instance (grep for `update_available|upgrade.*template|resync` finds no action). The only route is re-instantiating under a new id, which **loses the instance's evidence and grade**. Feature 224 scoped out *auto*-update (`224/product-spec.md:146`), not a manual pull.
- **Trade-off:**
  - **Building it:** an "apply update" that merges the new template payload into the instance. This needs a merge policy for user edits.
  - **Not building it:** the badge is a dead end that nudges users toward losing their history.

### G-13 A retired template cannot be listed or restored — SEV-3 · leverage L÷S  *(new)*

- **The gap:** grep for `unretire|restore|include_retired` finds nothing. A mistaken retire means re-creating the template under a new id, which orphans the `origin` link of existing instances.
- **Trade-off:**

  - **Not building it:** retire is irreversible in practice.

## Product metrics to track  (what & why — recommendation-only; placement → signal-map)

### Template catalog (feature 224 — new)
- **Metric:**
  - Funnel: `ListTemplates` view → `InstantiateTemplate` success → first backtest or first signal on the instance within 7 days.
  - Share of instances showing `update_available` for more than 30 days.
  - Read from the analysis, ingest and indicators `InstantiateTemplate` handlers, plus `origin` on reads.
- **Why:** this measures whether the catalog seeds real work. The stale-update share sizes G-12's cost.
- **→ signal-map:** an instantiate counter by kind and outcome.

### Offline books (feature 240 — new)
- **Metric:**
  - Confirm rate: confirmed / recorded offline orders, and median record→confirm latency.
  - Share of offline positions that are `MARK_SOURCE_NONE` at read time.
  - Read from trading `ConfirmOrder` / `RecordOrder` and portfolio offline valuation.
- **Why:** unconfirmed orders and unpriced marks are what make offline P&L wrong (I-15, debt-radar D-47/D-48).
- **→ signal-map:** a mark-source distribution at the valuation read.

### Opportunity queue (the home "Decide" surface)
- **Metric:** task success = share of viewed opportunities that receive TAKE, SNOOZE or DISMISS, plus the `SetOpportunityAction` error rate. Read from the insights BFF and `analysis.opportunity_actions`.
- **Why:** G-01 is fixed, but failures are now silent in the UI (debt-radar D-64), so the server-side error rate is the only signal.
- **→ signal-map:** a BFF per-method outcome counter.

### Backtest loop (strat-lab / MCP)
- **Metric:**
  - Funnel: `run_backtest` → success → `set_strategy_live`.
  - Repeat-backtest rate per strategy.
  - p95 duration.
  - **New:** the share of symbol-page runs that carry `strategy_id` (debt-radar D-45).
- **Why:** research→live conversion. The repeat rate proxies G-03.
- **→ signal-map:** an MCP tool-call counter and histogram.

### Order placement (trader)
- **Metric:** submit→accepted rate, reject reasons by code, and the nonce-mismatch reject count (I-20).
- **→ signal-map:** a reject-reason counter at `submitOrder`.

### Agent onboarding (OAuth → first tool call)
- **Metric:** authorize → first successful tool call within 24h, and distinct tools per active user per week.
- **→ signal-map:** a first-tool-call event.

### Signal ingestion
- **Metric:** signals per source per day, per-item failure rate, the share reaching an opportunity or alert, and **new:** mcp_client polls per cycle against active sources (a stall detector for debt-radar D-42).
- **→ signal-map:** a per-source, per-item outcome counter.

### Operator onboarding (local dev)
- **Metric:** `setup-env.sh` → `source mtls-dev-env.sh` → `docker compose up` → all healthchecks pass. Run it as a CI smoke job, not telemetry. G-11 is the current break.
