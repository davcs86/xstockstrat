> **ID scheme (CF-N5).** The repo already has an SDD Constitution (`docs/sdd/constitution.md`,
> prefixes `C-*`/`P-*`/`F-*`) that governs **process/workflow** (review gates, branch policy, the SDD
> pipeline). The rules below are **codebase/runtime invariants** — a different *kind* of rule — so they
> use a sibling namespace `PLAT-*` and cross-reference the SDD IDs where they overlap, rather than
> renumbering into the process scheme. Per-module constitutions use `<MODULE>-*`.

## Floor (`PLAT-*`) — never-do, non-overridable

| ID | Rule | Why | Evidence |
|---|---|---|---|
| **PLAT-F1** | Never persist a proto **enum integer** directly into a column whose stored form is a hand-mapped string (or vice-versa) — always route through the service's `*ToNumber`/`*FromJSON` / lowercase-string mapper at the DB boundary. | ts-proto `stringEnums` decodes enums to strings; binding the raw string into an `INTEGER` column throws `invalid input syntax for type integer`, and binding the raw int re-encodes to `UNRECOGNIZED`. Both shipped as bugs. | `services/xstockstrat-notify/src/grpc/notifyServiceImpl.ts:55` (`alertSeverityToNumber`), `:201` (`alertSeverityFromJSON`) + PR #698; Go string maps `services/xstockstrat-trading/internal/repository/trading_repo.go:350-460` (`sideStr`/`typeStr`/`statusStr`/`modeStr`, `parse*` `:414-455`) |
| **PLAT-F2** | Never let a `google.protobuf.Timestamp` reach a Node.js gRPC response (or a DB bind) as a `{seconds}` plain object, and never persist an Invalid `Date`. | ts-proto maps Timestamp to a JS `Date` and calls `.getTime()` during encode **after** the handler returns `callback(null,res)` — a plain object throws an uncatchable INTERNAL trailers-only error; a `new Date(undefined)` serializes to a NaN timestamp Postgres rejects. | PR #442 (identity), #443 (notify/ledger/config), #697 (ledger `toValidDate`); guard at `services/xstockstrat-ledger/src/grpc/ledgerServiceImpl.ts:299` |

## Gotchas & scars

- **Python config zero-trap (asymmetric with Node) — analysis has a per-key escape hatch, indicators/ingest don't.** The Python `ConfigWatcher.get_int/get_str/get_float` use `v.int_val or default`, so a stored `0`/`""`/`0.0` reads as the **default** — `get_bool` alone uses `HasField`. The Node getter uses `??` and correctly preserves `0`. Root CLAUDE.md documents this only for `analysis.scoring.shrinkage_days`, but it applies to *every* numeric/string Python key not opted out. `xstockstrat-analysis` added `get_int_present` (mirrors `get_bool`'s `HasField` check) as an explicit per-key opt-in for two 0-meaningful keys; `xstockstrat-indicators`/`xstockstrat-ingest` have no equivalent method yet, so every other numeric/string key across all three services is still trapped. The `config.ConfigValue` proto is a `oneof` that *does* distinguish 0 from unset, so this is a consumer choice, not a contract limit (also logged as a defect to fix, CF-N10). Evidence: `services/xstockstrat-indicators/app/config/watcher.py:93,101,117` (trap) vs `services/xstockstrat-analysis/app/config/watcher.py:103-114` (`get_int_present` escape hatch) vs `services/xstockstrat-config/src/services/configWatcher.ts:84-101` (Node, correct); oneof `packages/proto/config/v1/config.proto:61-67`.
- **SEV-1 scar behind PLAT-8: `WatchConfig` scope silently defaulted to dev/all for the lifetime of every backend service.** All six Go/Python `WatchConfig` clients declared `environment`/`trading_mode` fields on their request but never populated them — a purely additive-looking gap that produced no error, just the wrong config scope, indefinitely. Fixed as hotfix `fix-watchconfig-clients-omit` (commits `1eaf6c8`/`1413399`/`d7d185f`, PR #891). (The `trading_mode` half of the request was later removed entirely by feature 147.) The pattern to watch for: any new field added to a `WatchConfigRequest`-builder is easy to declare-but-forget-to-populate, and nothing catches it short of reading the server-side scope a request actually resolves to.
- **ts-proto is the strict path; protobuf-es tolerated the old shape.** The whole Timestamp/enum class of bugs (PLAT-F1/F2/1/2) stayed latent for as long as the frontends called backends over Connect-HTTP (protobuf-es), which tolerates `{seconds}`/ints; it surfaced *en masse* when everything moved to the gRPC path. When touching any Node gRPC (de)serialization, assume ts-proto's stricter rules. Evidence: PR #442 message body.
- **The proto `Timeframe` enum is not interval-ordered** (`15MIN=5, 1HOUR=3, 1DAY=4, 1MIN=1, 5MIN=2`); never infer bar duration from the enum number. Only `TIMEFRAME_1DAY` is requestable — `1MIN`/`5MIN` and, since feature 143, `15MIN`/`1HOUR` are all `[deprecated=true]`. Evidence: `packages/proto/common/v1/common.proto:85-92`.
