## Archive Synthesis — 2026-09-02 — /sdd-archiver

**What**: Flipped `services/xstockstrat-ui/src/middleware.ts` from the Edge runtime to Next.js 15.5's stable Node.js middleware runtime (`config.runtime = 'nodejs'`), so the near-expiry token refresh calls `refreshSession()` in-process (via `src/lib/identity.ts`) instead of the self-referential loopback `fetch()` to `/api/auth/refresh` that PR #925 had hardened as a TLS hotfix. `buildInternalRefreshUrl()` was deleted. No proto/config/DB/consumer-surface change — an internal auth-transport refactor. The feature's whole premise (that the Node runtime lifts the long-standing Edge ban on importing `@connectrpc/connect-node`) was treated as a hypothesis to disprove by build, not a given.

**Why (irrecoverable rationale)**: The Edge-only constraint was the original reason the fragile self-fetch existed at all; the Node runtime removes it, letting middleware talk to identity directly — the architecturally-correct transport the user flagged during the PR #925 writeup but deliberately deferred out of the hotfix.

**Rejected alternatives**: remove the `api/auth/refresh` matcher exclusion (what FR-5/AC-5 literally mandated) — lost because `authRedirect.ts:40` is a live browser caller (feature-153) with an expired token; matching it would redirect the browser's refresh POST to `/auth/login`, regressing feature-153 AC-5/AC-6 (C-16). delete `app/api/auth/refresh/route.ts` as redundant — lost, same live browser caller needs it. keep + further harden the loopback `fetch()` — lost, retains the self-fetch bug class the feature exists to kill. split a middleware-only `identityClient` module to shrink the bundle — lost as speculative (transports are lazy singletons; cost is a negligible cold-start import, not per-request).

**Scars & gotchas**: Deleting `buildInternalRefreshUrl()` silently broke compilation of an existing test block — `auth.test.ts` had a `describe` plus an `ORIGINAL_PORT`/`afterEach` PORT harness that had to be removed together or the suite won't compile (caught only by a repo-wide grep, not surfaced in recon). Stale in-file doc-comments beyond FR-6's two became actively false the moment middleware imports identity (`auth.ts:42-44` "must not be reachable from middleware … Edge runtime"; `identity.ts:1-6` "NEVER import from middleware.ts") — fixed inside the code step. AC-6 (the load-bearing feasibility gate) could not run its authoritative proof in-sandbox: Docker was unavailable, so it fell back to an offline `pnpm run build`, which passed emitting `.next/standalone/.../server.js` with no `node:http`/Edge bundling error — the true container-refresh proof was deferred to CI on the PR.

**Permanent deviations**: FR-5/AC-5 said *remove* the `api/auth/refresh` matcher exclusion → shipped *keeps* it → because `authRedirect.ts:40` is a live browser caller; the spec owner corrected FR-5's stale "browsers never call it directly" premise (C-15 append-only). FR-3 said behavior is "observably identical" → shipped is a strict improvement / latent-bug fix — the old Edge middleware discarded `refreshRes` and never forwarded the rotated `Set-Cookie`, so near-expiry rotation reached identity but the browser kept stale cookies; the in-process design now sets the rotated cookie on the `NextResponse`.

**Cross-feature signal**: The build **disproved** the standing ledger rule `insights.md:777-780` (`wire-fe-auth`: "middleware.ts must never import `@connectrpc/connect-node`") — for the Node runtime under `output:'standalone'`. `serverExternalPackages` (documented for route handlers only) turned out to cover the Node-runtime middleware chunk too; no `next.config.js` change was needed. The `frontend-auth.md` "Edge-runtime trap" section is now a historical/superseded banner.

**Deferred follow-ons**: extend `e2e/auth.spec.ts` to cover the now-rotated near-expiry cookie path (the FR-3 latent-bug fix, currently proven only at the unit layer). The v16 Middleware→Proxy rename (defaults middleware to Node) was explicitly deferred — repo is on 15.5.21.
