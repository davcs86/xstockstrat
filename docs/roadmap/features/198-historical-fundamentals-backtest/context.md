## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: A separate point-in-time (PIT) fundamentals lane beside the latest-snapshot cache. Marketdata stores SEC EDGAR as-reported periods in the plain table `marketdata.fundamentals_history`, each carrying `filed_date`; `pe_ratio` and `market_cap` come from a price-join against stored OHLCV. Ingest `TriggerBackfill` gained a `data_kind` axis; analysis gained `COMPONENT_KIND_FUNDAMENTAL`, resolved in backtest and live as a carry-forward join (latest filing with `filed_date < bar_date`); agent and `/insights` UI expose it. Shipped behind default-OFF gates `analysis.backtest.fundamentals.enabled` and `marketdata.fundamentals.history.enabled`; FMP ratio enrichment is a guarded seam with its own default-OFF flag — NOT a wired source (the user's "EDGAR primary + FMP Free ratios" premise was never delivered by 198). Launched 2026-09-24 via PR #1169. Nothing in 198's own sessions exercised real EDGAR data or applied a migration.
**Why (irrecoverable rationale)**: EDGAR over FMP: the user first accepted "FMP primary + Finnhub fallback", then disclosed they hold only FMP Free (250 req/day, ~5 years annual / 5-8 quarters, US-only, as-reported/`acceptedDate` depth and bulk endpoints paid-gated) — too shallow for a universe-scale PIT backfill, so they chose EDGAR primary. EDGAR is keyless (a non-secret `User-Agent` only) and FMP reuses the feature-147 credential, so no new secret row (avoids the feature-129 deploy-wiring scope-creep by construction). Three user decisions at the design gate: price-derived metrics via a PIT price-join (not a vendor ratio); full live parity (not backtest-only); T+1 availability (`filed_date < bar_date`), because SEC filings are often accepted after the close — the T+1 sign-off authorized rewording `@AC-3`/`@AC-4` from same-day (they were not yet promoted, so no C-16 amendment). v1 universe is the operator-supplied `TriggerBackfill.symbols` list (default: the feature-168 fundamentals universe); FMP's 250/day cap bounds only the optional enrichment pass.
**Rejected alternatives**: FMP primary + Finnhub fallback (user holds only FMP Free). A Timescale hypertable on `filed_date` — reads filter `period_end`, it forces `filed_date` into the unique index (breaking the `@AC-1` triple-PK idempotency) and re-imports the ledger-153 chunk-lock-OOM surface (recon had recommended it; the adversary overturned it; `feature.md` Reviewers rows still say "hypertable partitioning" — stale, not a decision). EDGAR as a `marketdata.fundamentals.provider` value / reusing the snapshot `FundamentalsSource` (the feature-154 FMP-cap gate keys on provider name). FMP `ratios-ttm` for historical rows (a current snapshot on a past filing date is look-ahead). `fundamentalsQuota()` for enrichment (dispatches on the snapshot provider, counts the snapshot table, so `@AC-5` would never fire). Backtest-only operand (breaks feature-152 `@AC-7` parity). Restatement/amendment history (reintroduces the `@AC-1` duplicate-key problem). Same-day availability (`<=`). EDGAR-native vocabulary only (user wanted `pe_ratio`). Per-site gate reads at 6+ evaluate sites (single chokepoint instead).
