## Execution Summary

Fork (a) from the approved `design.md`: consolidate the `/trader/positions/[symbol]` `#overview`
OHLCV price chart and the indicator overlay panels onto a **single lightweight-charts v5 chart
instance** with native multi-pane layout, and drop `recharts` from the symbol page. Order is
verify-before-build: **Step 1** pins lightweight-charts v5 and confirms its pane/series/whitespace
API against the *installed* typings (the feature-014 trap — a spec written against a newer API than
the version that ships; `insights.md:659-663`). **Steps 2–3** land the two pure `src/lib` helpers the
design makes the correctness backbone (the unset→whitespace point mapper with strictly-ascending-time
normalization, and the oklch→rgb token resolver) with vitest coverage. **Steps 4–6** migrate the
shared `useCandlestickChart` hook to v5 panes, build the indicator panes on that same instance
(replacing recharts), and migrate the hook's other consumer `ChartPanel.tsx` in lock-step. **Step 7**
rewrites the e2e that asserted recharts internals. **Step 8** rewrites the CLAUDE.md sanctioned
exception and fixes the stale doc-drift.

**Consumer surface (C-14):** the only surface is the UI `/trader` segment symbol page
(`/trader/positions/[symbol]`) `#overview` section — an **existing, already-registered** route
(`page.tsx:381-401`). It is not a new page, so **no `PLATFORM_SUBNAV` nav registration** is required
(the C-10(a) nav-reachability rule applies only to new routes). The change is delivered by Steps 4–6
(the chart surface) plus Step 7 (its e2e). No Agent surface; no backend/proto/config/DB surface
(`recon.md:76-83`).

**No proto / config / DB steps.** The `GetIndicatorSeries` / `ComponentSeries` / `IndicatorValue`
data contract is unchanged (`recon.md:78-80`); the warm-up/gap "unset, never 0.0" guarantee is already
proven at the wire layer by `services/xstockstrat-analysis/tests/test_analysis_servicer.py:5530`
(`test_none_maps_to_unset_indicator_value_not_zero`) — this feature does not touch it.

### Step 2 — service: Add the pure indicator-point mapper (unset→whitespace, strictly-ascending time)

**Status**: `pending`

- `services/xstockstrat-ui/src/lib/indicatorChart.test.ts` — create (vitest)

**Reviewers**: `xstockstrat-ui` service owner — analytics display accuracy (indicator correctness: gaps never fabricated to 0)

**Codebase Evidence**:
- Today's gap semantics to preserve exactly: `IndicatorPanels.tsx:63-67` — `s.values[i]?.value ?? null`
  maps only `undefined`/`null` → a gap; a genuine `0` reading is kept — with recharts
  `connectNulls={false}` (`:88`). Design (`design.md:39-45`) maps that to a lightweight-charts
  **whitespace point `{ time }`** (unset) vs `{ time, value }` (real, incl. `0`).
- Fixture shape the mapper must consume: `e2e/fixtures/indicatorSeries.ts` — `INDICATOR_SERIES_AAPL`
  with `times: [{seconds: bigint, nanos}]` and `series[].values[]` where `{}` = UNSET, `{value:n}` =
  real. The `macd` component has a 2-point warm-up head (`GAP, GAP, V(1.2)...`).
- Parity time source: `page.tsx:204-208` (`withTime = res.bars.filter((b) => b.time)`,
  `times: withTime.map((b) => b.time!)`) → carried to `useIndicatorSeries.ts:10-28`. Proto time is
  `{ seconds: bigint, nanos }` (`chart.ts:32-33` `RawBar.time`, `mapBars` uses `Number(b.time.seconds)`).
- v5 crash surface the design flags (`design.md:44-45`): v5 `setData` throws on non-monotonic/duplicate
  time — the integer-index recharts version (`IndicatorPanels.tsx:59,76` `dataKey="i"`) never had this.
- Existing `src/lib` vitest pattern to mirror: `src/lib/chart.test.ts`, `src/lib/protoTime.test.ts`
  (node env, `src/**/*.test.ts`, `vitest.config.ts`).

**TDD**: `red-green required`

**Instructions**:
1. Create `src/lib/indicatorChart.ts` exporting a pure function that maps one `NamedSeries`
   (`values: IndicatorValue[]`) plus the shared `times` array to lightweight-charts line-series data:
   for index `i`, `values[i]?.value === undefined` → `{ time }` (whitespace, breaks the line — the
   design's gap); otherwise `{ time, value: values[i].value }` (a genuine `0` is kept). Convert each
   proto time `{ seconds: bigint, nanos }` to the lightweight-charts `Time` (Unix seconds `number`,
   matching `chart.ts:45` `Number(b.time.seconds)`).
2. In the same module, **normalize/assert strictly-ascending unique `time`** before returning (the v5
   `setData` precondition): reuse `chart.ts`'s ascending sort convention (`mapBars` sorts ascending,
   `:52`) and reject/deduplicate out-of-order or duplicate timestamps deterministically. Decide, and
   document in the function's doc comment, the resolution for a duplicate/out-of-order input (the
   vitest test asserts whichever you choose).
3. Write `src/lib/indicatorChart.test.ts` asserting: (a) an UNSET value → a `{ time }`-only point (no
   `value` key); (b) a genuine `0` → `{ time, value: 0 }` (not dropped); (c) the `macd` warm-up head
   yields two leading whitespace points; (d) duplicate / out-of-order `time` input is normalized per
   the documented rule. Import the shape from `e2e/fixtures/indicatorSeries.ts`'s `INDICATOR_SERIES_AAPL`
   where practical, **not** an inline re-declaration (C-13: this fixture already has ≥2 consumers, so
   reuse the canonical home; scenario one-offs like the dup/out-of-order case stay inline).
