**What**: SEV-2 bug fix (debt-radar D-04, D-62), `xstockstrat-trading` only, no proto/migration/config. Four discarded `UpsertOrder` results (broker-timeout, broker-reject, cancel-final, replace-final) now go through `persistOrderBestEffort` (`trading.go:3659` at execute time, `:3791` at HEAD), which logs `slog.Error("order state write failed", order_id, user_id, status, path, error)`. Three discarded reactive `ReclaimOrphanIntent` results now go through `reclaimStaleIntent` (`order_intent.go:146`), which logs on failure and fires an async `order_intent.reclaimed_unknown` ledger event (triggers `reactive_place|reactive_cancel|reactive_replace`). The sweeper adopted the shared `reclaimedUnknownPayload` (`order_intent.go:137`). The operator widened scope mid-design: all 32 request-reachable `context.Background()` sites in `trading.go` became `context.WithoutCancel(ctx)` so `x-trace-id` reaches the ledger/notify clients. Only the two background-only watchdog sites (`:2858`/`:2906` at execute time, `:2947`/`:2995` at HEAD; `:2859`/`:2907` before the 2026-10-29 main-dev merge) keep `Background()`. RPC return codes and "still pending" messages are unchanged.

**Why (irrecoverable rationale)**:
- D-04 is log-only, not surfaced as an RPC error: every one of the four writes happens AFTER the broker side effect (SubmitOrder `:681`, CancelOrder `:1322`, ReplaceOrder `:1519`), so returning an error invites a client retry against an order the broker already holds, and would reopen PRESERVE guarantees `@AC-1`/`@AC-3 @feature-202` and `@AC-1 @feature-192`. The reconciliation poller already repairs divergence. (context.md 2026-10-21 design Decisions.)
- Only the reclaim branch was extracted, not the four-way intent-lookup switch (`classifyIntentLookup` callers `:586/:789/:1285/:1482`): the three reclaiming copies return different types/messages, and the fourth (`recordOfflineOrder`, `:789`) has NO reclaim at all (`:800-803`), so it was never a D-62 site. C-18 cost of generic plumbing > DRY gain.
- Binding operator rule (2026-10-21): every request-derived write/emit uses `context.WithoutCancel(ctx)`, never a fresh `Background()` and never a C-03 waiver. Rationale: `WithoutCancel` keeps ctx values, and `UnaryServerInterceptor` stores PropagationData as a ctx value (`middleware/propagation.go:35-39`) which the ledger conn's `UnaryClientInterceptor` (`trading.go:184` at execute time, `:215` at HEAD; `propagation.go:45-52`) turns back into outgoing metadata, so no header code is needed. Forwarding headers changes no stored owner: ledger `AppendEvent` takes the owner from `req.userId` and falls back to `x-user-id` only if empty (`ledgerServiceImpl.ts:37-39` at execute time; now `:76-78` after `parseSequenceToken` was added above it); notify uses `req.targetUserId`.
- Persist timeout bound = existing `ledgerEmitTimeout` (`trading.go:3657` at design time, `:3749` at HEAD), NOT `brokerCallTimeout()`: the latter is operator-tuned for broker REST latency and retuning it would silently change the DB-write deadline (F-07, spec-session decision).
- Sweeper ledger payload goes nil -> populated: operator ACCEPTED this at the round-3 gate; no `@AC-*` guards it. Step 3 found no downstream reader of `order_intent.reclaimed_unknown` outside `order_intent.go` (only a trading findings doc row).
- Reactive emit `user_id` comes from the resolved owner (`accountEntry.userID` set `:627`/ownership-gated `:433`; `order.UserId` gated `:1256`/`:1429`), never the header, because the header is empty on the flatten path.

**Rejected alternatives**:
- Surface D-04 failure as RPC error (Internal/Unavailable) — lost: post-side-effect retry collision; reopens PRESERVE ACs (above).
- Retry the D-04 write once on `Background()` — lost: adds error-path latency; `WithoutCancel` + timeout removes the cancel-caused failure mode more cheaply.
- Extract the full four-way intent-lookup switch — lost: C-18 (see Why).
- C-03 waiver with new emits on `context.Background()` — lost: operator rejected 2026-10-21.
- Reuse the sweeper's payload literal for the reactive sites (design r3) — lost: it holds a `time.Time`, `structpb.NewStruct` rejects it, and `emitLedgerEvent` discards the error (`p, _ :=`), so the event reaches the ledger with nil payload; AC-4/8/9 trigger assertions could never pass. See fails.md:3064-3067 (2026-10-21 entry).
- Fix serialization generically inside `emitLedgerEvent` (convert time.Time / log NewStruct error) — lost: touches a shared hot helper beyond D-04/D-62; logged as a finding instead, hardening left as an operator candidate.
- Route the sweeper through the new async helper (design r1) — lost: would change sweeper emit timing, shutdown cancellation and log text, no AC covers them. The sweeper kept its own ctx, synchronous emit, user `""`, log text and `continue`s; it adopts only the payload builder.
- `reclaimStaleIntent` returning `(record, bool)` with the emit inlined at each site (r2) — lost: trigger literal + emit repeated three times, copy-paste mismatch risk. Helper emits instead.
- Make the reclaim CAS async — lost: races a tight client retry. Synchronous reactive emit with a short timeout — lost: adds latency to the FailedPrecondition response.
- Emit `user_id` from `middleware.FromContext(ctx).UserID` — lost: empty on background flatten.
- Thread a trigger param through `submitOrder` for a `reactive_flatten` label — lost: widens an 11-parameter signature (`:550-561`) for a rare case; payload is open so it can be added later.
- Bufconn wire test for trace propagation — lost: real client interceptor through a fake invoker covers value->metadata; mTLS already has a wire test.
- Keep request ctx at `:1367`/`:1550` and stay log-only by choice — lost: conflicts with the binding WithoutCancel rule.
