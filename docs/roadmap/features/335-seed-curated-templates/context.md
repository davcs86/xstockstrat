## Archive Synthesis — 2026-11-18 — /sdd-archiver

**What**: Four hand-written seed migrations: indicators 008 seeds 9 formula templates, analysis 028 seeds 14 strategy templates, analysis 029 seeds the `fundamentals_macd_blend` strategy owned by `admin@localhost`, ingest 016 seeds 4 source templates plus the system `fundamentals` signal source. Every `created_by='system'` template is read-only through `ManageTemplate` in all three services (`TemplateMeta.read_only`, "System" badge in config-ui). Seeds were written from agent-tool output and proven against a raw staging export only afterwards; the first parity run found 6 differences (fixed or operator-allowlisted). There was no post-deploy behaviour check.

**Why (irrecoverable rationale)**:
- Operator chose migrations over config-ui payload files and over a new MCP `manage_template` tool: "Low risk, as they are templates and don't execute anything." Story-time scope: strategies = all non-junk ones, deliberately not just the 3 `live_enabled`; formulas: probes and near-duplicate z-score/ER variants dropped. Excluded as junk: `zz_fscore_probe`, `dbg_regime_voo_inverted`, `diag_formula_probe`, `jjjjjjj`, `bbbb`, `aaaa`, `rsi20` (the seeds show what was included, not what was left out).
- Range-mean-reversion version kept by operator rule (keep the live version; if none live, keep the one with best results). None was live; a staging comparison backtest (8 megacaps, 2024-07..2026-06, portfolio sizing, next_bar_open fills) picked v2: v1 made 1 trade in two years, v3 lost money; the margin is thin (one window, one basket) — it ranks, it does not validate. `rolling_zscore_v2` and `kaufman_efficiency_ratio_v2` are in the 9 formulas; `zscore_close_20` and `kaufman_er_close_10` are out. The first attempt was rejected by the 730-day span cap (started 2024-01-01); the three runs left backtest evidence rows in staging.
- System templates became read-only because the operator declined the C-10(c) waiver: retiring a shared formula template would make every dependent strategy template impossible to instantiate. The guard widened to all system templates, so catalog changes ship only as version-guarded migrations (`UPDATE`/`retired_at`), never `DELETE` (D-14/D-19/R-4/O-8). A guard get-then-check has no race because `created_by` is written only at CREATE (D-17).
- Operator constraint: "Formulas, Strategies, Watchlists, and Signal sources are strictly user-owned." The `fundamentals` source is the one recorded exception ("Seed as system anyway") because the producer already registers and feeds it as the system identity (D-16); it cannot be a source template because its slug is reserved for the system, so a user copy could never be instantiated or fed (FR-5). `created_by='system'` rather than a seed user id (OQ-5): indicators migrations have no `SEED_USER_ID`, so using one would force a `-- requires-env` header and break verbatim copying; it also marks rows for the guarded down.
- The blend belongs to `admin@localhost`, not `SEED_USER_ID`: `SEED_USER_ID` is the operator's own committed literal id (`.do/app.yaml:689`); keying on it would do nothing in staging and seed an orphan blend on every fresh DB (O-15/P-2, D-30). Operator: "my current user is not the default admin@localhost, but that's intentional." The blend starts "active, not live" — template instances are created inactive, so the proposer's reason for `active=TRUE` was false; "active" was the operator's explicit choice, made with the irreversibility stated in the option text (the blend can never be deactivated through the API; D-33, O-16/P-3). `user_id` is embedded in the blend `definition_json` (`|| jsonb_build_object('user_id', …)`) so the fingerprint survives the first masked edit (D-34) — do not delete it as redundant.
- The blend template's default id is `fundamentals_macd_blend_copy`: a non-admin instantiating with the default gets FAILED_PRECONDITION; an admin taking it gets the protected, never-deactivatable blend (O-9/D-31). The composite formula template is deliberately separate from, and never linked to, system formula `d1ff5e6b-…` — operator: "fundamentals_macd_blend and referenced formulas are system special cases to preserve integrity… Duplication is acceptable"; its parity reference is the code module because staging's row is itself the boot-upserted system formula (D-12/D-28).
- Post-deploy behaviour check dropped: instantiating and backtesting would leave 14 permanent copies in the operator's account, add backtest evidence that could move grades in the live queue, and block every promotion to `main` until done (O-17/D-32). The CI substitute (D-36) explicitly does not prove, before production, the deployed indicators saga on seeded rows, the asyncpg JSONB read, or numeric backtest equality. The pre-existing `tpl-*` check in production was waived (production never used); the collision guard is the only protection.
- Strategy-template payloads must not carry `user_id`/`origin`/`warnings` (O-2/D-9): otherwise the operator's own user id would leak into every environment's catalog — which is why the blend *strategy* embeds `user_id` on purpose (D-34) but the *templates* must not. The checker's absence assertion catches a regression. The collision guard (O-12/D-20) exists because `ON CONFLICT DO NOTHING` skips silently when an environment already has an admin-authored row under a `tpl-*` id, which would then stay editable and non-system in place of the catalog entry. The `fundamentals` slug is hard-coded though `analysis.fundsignal.source_slug` is configurable and the producer is off by default (O-10/D-24): if an environment changes the slug, the seeded system row becomes a dead reserved source nobody can use — safe today only because the operator confirmed every environment uses `fundamentals` (context.md 2026-11-12). The seeded blend was checked on purpose to carry none of the operator's personal curation (`signal_eligible: true`, empty `signal_params`, no `denied_symbols`; `signal_eligible` kept in both template and seeded strategy). Deliberate non-goal: no back-fill of `origin_template_id` — the operator's existing staging instances stay unlinked to the new templates (not an oversight). The checker's dollar-quote parsing is the trust boundary of parity (seed SQL is hand-written): its good/bad parser test, including a trailing-newline case, is load-bearing — simplify it away and parity still reports green while proving less.
- Blend down is a no-op: a seeded row looks identical to an untouched manual REGISTER and backtests never bump `updated_at`, so a "delete if untouched" down would delete a backtested seed and orphan its scores (D-35/R-7). Rule: a down may delete only rows it can prove it wrote.
- The analysis→identity read is the only migration-time cross-schema read; allowed where feature 276's runtime read was rejected (276-fix-legacy-formula-authors/context.md:24) because it is operator-mandated and one-shot at migration time (D-37). The deploy window is accepted with no release split: PRE_DEPLOY applies seeds minutes before guarded images start; during it only admins can change a seeded row and older UI/agent builds ignore proto field 9 (D-27).
- Parity method: `md5(jsonb::text)` is not stable, so JSON columns are compared structurally; formula `source`/`description` were exported as md5 only, so their text was transcribed via MCP `get_formula` and the md5 proves it byte for byte (D-21).

**Rejected alternatives**:
- Committed generator + data file + "SQL == generator output" check — F-01 freezes applied output (permanent pinned liability) and parity would be circular (R-1).
- Adding seeds to `REPLAYS` — redundant, pass 3 of `migration-rerun` already downs and re-ups them (R-2, C-18). New per-service `local_pg` tests — only analysis has the fixture and `migration-rerun` covers all schemas (R-3).
- A shared `scripts/` seed parser imported by service tests — cross-tree dependency for a grammar F-01 freezes (R-5/D-23). Rewriting `platform.feature @AC-15 @feature-224` in place — promoted scenarios are never rewritten; superseded by comment (feature 302 precedent; R-6).
- Reading `config.config_values` for the blend id — one row per environment in the same DB, SQL cannot pick one without an env var, and a second cross-schema read (R-8). Agent-transcribed snapshot as parity reference — snapshot and seed can share one copy error and `extractor_module` cannot be read via MCP (O-1).

**Scars & gotchas**:
- Strict `ParseDict` in indicators (`servicer.py:835,864`, no `ignore_unknown_fields`): one unknown or deprecated key (`isPublic`, `author`) in a seeded payload breaks `ListTemplates` for every user; seeds bypass every write-time validator, which is why the validity tests exist. No cross-schema FK exists, so the whole-catalog formula-reference test is the only check that strategy templates reference existing formula templates. "golang-migrate wraps a file in one transaction" was only inferred; the collision guard raises after the INSERT and relies on it (CI assertions run in their own BEGIN…ROLLBACK and do not prove it).
- `migration-rerun` runs every assertion file against the final state (`scripts/migration-rerun.py:1119-1120`): each new seed migration must delete its predecessor's "has seed rows" assertion in the same commit; `analysis/tests/test_strategy_templates_real_pg.py` failed as soon as another up-file mentioned `strategy_templates` (re-keyed to `CREATE|ALTER TABLE`, D-11); the ingest guard broke three tests on a `MagicMock()` db (guard skips an empty id so the NOT_FOUND path is unchanged); admin-absence states are built by renaming the admin's email.
- psql `\set seed_error :LAST_ERROR_MESSAGE` must be quoted (`:'LAST_ERROR_MESSAGE'`) or spaces are stripped and the match never hits (first expected-failure assertion block in the repo; its first real execution was CI); export needs `psql -q` or `BEGIN`/`ROLLBACK` tags land in the JSON.
- Staging stores empty `extractor_module` for the four mediated sources (seeds had guessed `app.extractors.noop`; fix = omit the key, the stored form since proto3 defaults are dropped; the system `fundamentals` row keeps `noop`). Staging strategy rows still store four dead feature-097 `signal_params` keys (`signal_sources`, `signal_weight`, `technical_weight`, `min_conviction`) because the service strips them on read, not in storage — a raw-DB parity check must strip them staging-side only.
- Cross-service Python test trap: the analysis test could not build its fake `GetFormula` from the indicators code module (importing `indicators/app/formulas/fundamentals_value_quality.py` makes `app.formulas` resolve to the analysis package). It is built from the seeded composite template payload instead, which the indicators drift test pins to the module field by field (D-36(c) shipped differently).
- A privacy guard refused to write the operator's email into the SEC User-Agent (placeholder decision); Step 23 was committed with the AC-35 parity test deliberately red so CI, not a note, enforces the pre-merge gate (departs from F-05's letter; id cross-check mutation-proven); e2e under `pnpm dev` exceeds the 10 s `warmup.setup.ts` timeout, so specs ran in CI mode; intermittent `test_sandbox_watchdog.py::test_ac8_fork_bomb_…` fails without this feature's tests too; the operator's "`fundamentals_macd_blend` in both cases" conflated the blend-id key with `fundsignal.source_slug` (an agent read caught it).
- Step order: guards before seeds (seed validity tests assert `read_only` through real row mappers); indicators before analysis (the analysis test parses the indicators seed).
