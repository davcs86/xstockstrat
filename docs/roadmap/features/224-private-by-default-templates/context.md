# Context: private-by-default-templates  (archived 2026-11-04)

**Feature**: ./feature.md
**Status**: launched — archived by /sdd-archiver; verbose specs pruned (recoverable via git history).

## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: Removed the concept of "public" from every user-authored object. Formulas, strategies, signal sources and the signals ingested into them are now owner-private. `system` is a reserved, SAN-bound identity that owns the fundamentals source and the seeded `SYSTEM_AUTHOR` formulas. Added an admin-curated, per-service template catalog (indicators = FORMULA, ingest = SIGNAL_SOURCE, analysis = STRATEGY) whose `InstantiateTemplate` makes an independent private snapshot copy (origin id + version recorded, "update available" computed on read). Strategy templates deep-copy their referenced formula templates through an analysis-orchestrated saga. Per-user secrets in config replace global `mcp_credential.<slug>`, and the analysis-side `InternalCallerInterceptor` was removed (Step 16) while the indicators-side `_INTERNAL_FORMULA_READERS` bypass stayed for N, now bound to SAN `xstockstrat-analysis`. Shipped as **release N, expand-only and header-tolerant** (41 steps, 37 `@AC-*`, launched 2026-10-08 via #1233). Enforcement and contract are the named follow-up feature 225 `private-by-default-enforce-contract` (also launched).

**Why (irrecoverable rationale)**:
- Operator decisions, verbatim (2026-10-05, binding):
  1. Signals: "Both sources and signals per user." Two users following the same newsletter each ingest their own copy.
  2. Templates: "Admin catalog, snapshot copy." Only admins or seeded code author templates; the UI may show "template updated" but never mutates the copy.
  3. Migration: "Just make everything private." No templates are seeded, so the catalog starts empty. System objects (`SYSTEM_AUTHOR` formulas, the blend-strategy id convention) stay special-cased.
  4. References: "Deep copy, remove bypass." Analysis runs formulas only as the strategy owner, and the PR #1219 `x-internal-caller` bypass is removed.
- OQ answers (2026-10-06, "Go with both"):
  - OQ-1: backfill global signal sources, signals and dedup keys to `SEED_USER_ID` (the feature-133 precedent).
  - OQ-2: the fundamentals producer emits under a `system`-owned, read-all, immutable source (a third system special case, with `SYSTEM_AUTHOR` formulas and the blend id).
  - OQ-3: admins get a read-only, audited view of foreign objects and lose the update/delete override on formulas.
  - OQ-4 (templates per-service, not a central service) was settled in design.
- The rollout shape was decided by the round-3 gate. A single release that both threads owner identity and enforces it fails at the RPC layer on a rolling deploy or an analysis-only rollback: headerless calls would darken the fundamentals blend and reject fundsignal (`@feature-160/168/190`). The operator chose the two-phase cutover (release N tolerates headerless calls; 225 enforces).
- Operator override of feature 147: config secrets may now be per-user (`GetSecretRequest.user_id=4`, exact-scope resolution, no cross-scope fallback). Feature 147's 3-guard model is kept: encrypted at rest, redacted on every edge, decrypted only through `GetSecret` for allow-listed callers. The ingest `GetSecret` grant is additionally bound to mTLS peer SAN `xstockstrat-ingest`, because any mTLS client with the header could otherwise decrypt secrets and per-user secrets widen that.
- `GetBacktest` denies **every** non-owned or ownerless run, admins included, with no audit event (impl-spec D-9, operator decision 2026-10-07). FR-13's admin read view covers formulas, strategies, signal sources and signals only. A missing run is still `NOT_FOUND`.
- Legacy backtest runs with an ambiguous owner go to `SEED_USER_ID` (round-1 gate; the operator accepted that the seed user receives that history). The alternative of leaving them NULL and unreadable was rejected.
- Blend guard: `ManageStrategy` REGISTER and `InstantiateTemplate` both require the ADMIN bit to create the *currently configured* `analysis.engine.fundamentals_blend_strategy_id`; others get `FAILED_PRECONDITION`. Round 3 found that the `@feature-186` REGISTER guard did not exist: only DEACTIVATE and set-non-live were guarded, and the blend is user-registered rather than seeded. A guard on the template path alone would have given no parity. This is classed EXTEND (a new guard, nothing weakened).
- Bounds are fixed invariant caps, not config keys (round-5 gate, F-07): audit append concurrency 4, a per-page foreign-owner ceiling of 100 (neither analysis nor ingest has a max page size, so 100 is the platform default page size), boot recompute 50 pairs per pass, `_INTENT_STALE_SECONDS=900` and `_INTENT_SWEEP_SECONDS=300`. A gate prompt once mis-stated the last two as 300/60; the operator re-confirmed 900/300.
- `audit.admin_read` goes on both streams: 1 event on the admin's stream carrying all foreign ids, plus K events (one per distinct foreign owner, that owner's ids only). A page of the admin's own objects emits 0. Any append failure fails the read closed with `UNAVAILABLE`. Ledger `DB_POOL_MAX=1` serializes the appends, which is why the cap exists.
- OQ-5 (resolved by promotion into FR-9): a strategy template must reference formula **templates** by template id, never live formula ids, "or deep copy has nothing stable to copy".
- Reserved slugs exist because (round-1 objection 2) a user who registers the slug `fundamentals` would poison the blend and the `{slug: weight}` maps. Reserving the string `system` is safe because identity ids are UUIDs (identity `001:7`), so no real user can collide.
- `LEGACY_GLOBAL` was designed (round-2 objection 4) because a legacy global credential ref could exfiltrate the seed user's bearer token to a user-controlled URL. The reset trigger had to watch `config_json.mcp_endpoint` and `credentials_ref`, not `url` (round-3). If `mcp_client` rows ever exist before an exact-scope migration, this risk returns.
- The headered `IngestSignal` change `INVALID_ARGUMENT` → `NOT_FOUND` (AC-10) is deliberate: missing and foreign slugs become indistinguishable, so nobody can probe for other users' slugs.
- `GetAttribution` filters to the caller-visible own + system source set because pre-feature `order_snapshots.signals` were captured unscoped, and without the filter AC-12 fails on legacy rows. The impl-spec reviewer accepted the legacy-slug edge for pre-feature data.
- Nav entries are mirrored into `PLATFORM_SUBNAV` only to satisfy C-10(a)'s wording; it is legacy and inert (the real registration is `NAV_GROUPS`). The duplicate entries are intentional, so do not "fix" them.
- The `GetTemplate` RPC named in the product spec was cut as YAGNI: `ListTemplates` serves every read, so each service has three template RPCs.
- The D-4 rule "`derived` ⇒ `system`" was verified on staging only, where exactly one `derived` source (`fundamentals`) existed. A future `derived` producer would also be classed `system` on a migration replay.
- Contract migrations went to a named follow-up (C-14 deferral form) rather than being left as a doc note, gated by a `merge-order.md` row plus a new CI `migration-contract-gate`.
- Prod did not exist at execute time (operator note 2026-10-07), so the two prod pre-merge checks were dropped, not discharged: the prod `analysis.fundsignal.scoring_formula_id` check (design.md Open Risks) and the prod `mcp_client` count (answered "0" while no prod existed).

**Rejected alternatives**:
- Big-bang enforcement in one release — lost: rolling deploy or analysis-only rollback sends headerless calls (see Why).
- Keep the old PKs and expand around them — lost: `@AC-8/9/35` are impossible in N. The `signal_sources` PK is swapped in N, and the two N-1 `ON CONFLICT` targets (ingest dedup, analysis scores) move to new owner-keyed tables `signal_dedup_claims` and `strategy_scores_v2`, leaving the old tables for N-1.
- Headerless reads return system rows only in N — lost: silent data loss for the headerless pnl snapshot and live-loop drain (`@feature-042/029/176`).
- N-1 owner-fill trigger "system, else `SEED_USER_ID`" — lost: files other users' private signals under the seed user on a rollback. The shipped trigger resolves the unique slug holder, else RAISEs, so N-1 fails closed.
- A literal reserved-slug list in ingest — lost: ingest cannot read `analysis.fundsignal.source_slug`. "Reserved" means "slug already held by `system` in the DB".
- AST "passes `metadata=`" CI check — lost: it accepts `metadata=()`, which is exactly the headerless bug at the old `main.py:148`. A runtime client-interceptor test requires a non-empty `x-user-id` on every ingest and indicators stub call.
- A single interceptor stamping verified identity — lost: grpc.aio interceptors cannot reliably reach the auth context pre-handler. One shared `peer_identity.py` helper per service instead.
- One central template-catalog service (OQ-4) — lost: a new service and schema, and formula/source instantiation would need the same cross-service copy the strategy saga already pays for.
- Shared Python package for `admin_audit.py`/`peer_identity.py` — lost: `packages/` holds only `otel` and `proto`, and the services are separate deployables. Per-service copies mirror the existing per-service `mtls.py`/`telemetry.py`, and the jscpd duplication is accepted.
- Evaluator returns all-None for an unreadable formula in backtest — lost: it becomes a buffered zero-trade cell that counts as evidence (fails.md:616-619). A post-evaluation `unreadable_formulas` filter was also rejected (needs a per-symbol reset on a shared evaluator).
- Per-object audit events (1 per foreign object) and config keys for the bounds — both rejected by the operator.
- Global per-slug MCP credentials, or a config secret-write grant — rejected by the operator in favor of per-user secrets in config.
- Template-only blend guard — lost: no parity with REGISTER.

**Scars & gotchas**:
- **Design rounds each refuted the previous round's "complete" claim by reading code.**
  - Round 3 refuted "release N reads and writes only owner-keyed structures": `backtest_run_symbols.fetch_eligible` was keyed by `strategy_id` plus fingerprint with no owner, and template instances share a fingerprint, so grades would have pooled across users (`@AC-21`). The in-memory `_strategies`/`_recompute_locks`/`hydrate_scores`/`ListStrategies` filter were also bare-keyed. `ListBacktests` and `GetStrategyAnalytics` called `list_by_strategy` with a bare `WHERE strategy_id = $1`. `_persist_backtest_run` had never written `backtest_runs.user_id` at all, and the `backtest_details` retention DELETE could evict another owner's rows.
  - Analysis→ingest call sites: rounds 1-2 had missed `entry_backfill.py:96` (the round-3 proposer added it), round 4's list lacked `servicer.py:3458` (the round-5 proposer added it), and round 5 found the eight analysis→indicators sites had never been listed. (Recorded at fails.md:2658-2659; note that entry words it as "Round 3 missed" / "round 4 missed".)
- **Peer-SAN API had no repo precedent.** Step 5 spiked it before anything depended on it. grpc.aio: `peer_identity_key()=="x509_subject_alternative_name"` plus an exact element match in `peer_identities()`. grpc-js: `call.getAuthContext().sslPeerCertificate.subjectaltname` is a comma list with `DNS:` prefixes. The cert-parsing fallback was not needed. Helpers must fail closed on non-SSL or mock contexts. Config `hasSecretCallerAuthority` had to take the call object. Unit tests for the config SAN grant call handlers against an in-memory store, because insecure loopback gRPC cannot present a peer certificate.
- **`db-migrate.sh` dirty recovery re-runs from 001, and about 14 already-applied up-files are not idempotent** (e.g. `indicators/001_formulas.up.sql:3`, `ingest/001_newsletter_signals.up.sql:8`). The planned full-chain replay in CI failed before any 224 assertion, and F-01 forbids fixing applied files. Operator decision: CI replays only the three new files (indicators 007, ingest 013, analysis 026) via `psql -1 -f` on the migrated schema, and also checks that the N-1 trigger count is unchanged. The pre-existing defect is filed at `docs/reports/2026-10-07-db-migrate-dirty-recovery-replay-unsafe-defect.md` (sidecar `open`, not yet triaged as of this archive). Pass 0 refuses to run on an already-migrated DB, because `goto` would run down-files.
- **New up-files must be safe on both the expanded and contracted schema:** triggers are created only inside the one-shot "column absent" branch (otherwise a post-contract dirty replay re-creates them). Files embedding `SEED_USER_ID` carry an **unconditional** unrendered guard (the feature-133 guard raised only when `missing>0`). The analysis-013 hardcoded envsubst branch in `db-migrate.sh:72-89` is untouched (editing an applied file breaches F-01). New files declare `-- requires-env: SEED_USER_ID`, handled by `scripts/render-migrations.sh`.
- **Deploy-image gap (D-2):** `db-migrate.sh` began calling `scripts/render-migrations.sh`, but the migrator image (DO prod and dev PRE_DEPLOY jobs, and compose `db-migrator`) COPYs only `db-migrate.sh`. Every deploy's migrator would have failed. One `COPY` line was added to `scripts/Dockerfile.migrate` (operator-approved scope expansion), and a structural test pins it.
- **Ingest 013 N-1 rollback window (D-19, accepted):** the owner-fill trigger covers `newsletter_signals` inserts only. During a rollback, an N-1 instance that REGISTERs a new source without `user_id` fails the NOT NULL, and an N-1 `mark_source_*` UPDATE by slug touches every owner's row with that slug. Registration is admin-only and N-1 has no `ON CONFLICT (slug)`. The risk disappears once N is fully rolled out. Down 013 refuses to run once any slug or dedup key has more than one owner.
- **Indicators 007 rollback note (D-14, accepted):** after `is_public=FALSE`, an N-1 `ListFormulas(include_public=true)` no longer returns system formulas. N-1 `GetFormula`/`ExecuteFormula` still read them via `author=='system'`. The impact is list discovery only. The N-1 seed also re-upserts the fundamentals formula's `is_public`.
- **`NOT_FOUND` from indicators is overloaded.** Before this feature it meant "data unavailable" and triggered a 300s retry. It now also means "formula not readable by owner". The mapping is per surface: backtest raises `FormulaExecutionError` (symbol gets FORMULA_ERROR and is excluded from `backtest_run_symbols` evidence; preserves ANALYSIS-2/3); the other five surfaces record it as "component skipped + warning", never the `"unavailable"` marker (`@feature-185 @AC-1`). `_formula_outputs` swallows NOT_FOUND, so the AC-30 warning must be computed first and the `INVALID_ARGUMENT` message names the unreadable formula before the "unknown series" reason. REGISTER and UPDATE now make one extra `GetFormula` per referenced formula.
- **Fundsignal scoring fail-closed (AC-6/AC-37):** an empty `scoring_formula_id` uses the built-in scorer and never calls `ExecuteFormula`, so the original AC-6 could not be observed. The Given was amended to "set to system formula `d1ff…`", and AC-37 covers a non-system value (nothing emitted, ERROR plus notify, no fallback). The per-symbol `_builtin_score` fallback was deleted deliberately (C-18). The pre-flight runs after the `dry_run` return and before the `force` DELETE. A headered `NOT_FOUND` from `IngestSignal` as `system` aborts the cycle; the triggering symbol's `fundsignal_emitted` claim row remains (same as any failed emit, not fixed).
- **Status-code changes recorded on purpose:** a headered `IngestSignal` to a slug the caller does not hold, or to an own **inactive** source, changed from `INVALID_ARGUMENT` to `NOT_FOUND` (AC-10, D-21; no durable `@AC-*` pinned the old code). A headerless call with 0 holders stays `INVALID_ARGUMENT` (round-4 amendment 5 proposed `FAILED_PRECONDITION` and was reversed in round 5); more than 1 holder gives `FAILED_PRECONDITION`. Agent `client.py:240-244` passes codes through.
- **Strategy fingerprint must exclude `origin`** (`_FINGERPRINT_EXCLUDED_KEYS`, D-28): otherwise a masked UPDATE of an instantiated strategy folds origin into the definition fingerprint and resets its evidence (ANALYSIS-3). `_row_to_strategy_definition` clears any `origin` from a request body so origin always comes from columns.
- **Saga details:**
  - The PENDING→COMMITTED CAS and the strategy insert share one transaction.
  - The sweep resolves `ABORTING`/`COMMITTED` intents of any age and `PENDING` only after 900s; the indicators resolve call is idempotent. Pending rows are never cached, and an abort evicts the indicators cache.
  - Request path and sweep use a dedicated SAN-bound `analysis-template-saga` caller id (the `analysis` read-bypass id is rejected on the saga path). The sweep sends the intent owner's `x-user-id` with a fresh trace id.
  - A retired or missing formula template fails the whole saga `NOT_FOUND` before anything is inserted.
  - Strategy-template validation reads indicators `ListTemplates` for outputs and fundamental inputs and never calls `GetFormula` (named outputs such as `z.upper` validate).
  - The blend guard runs on the final `_N`-suffixed id.
  - `template_intents` has no default for `intent_id`, so writers must supply the UUID.
- **Boot recompute (D-8):** `list_unscored_pairs` selects only ambiguous pairs that have no v2 score and have owner-evidence cells. Otherwise pairs that can never score would consume the 50 slots on every boot and the rest would never be reached. A `RunBacktest` with no caller id is still stored ownerless, and the owner-filtered retention DELETE never matches it.
- **Reverse slug race fails loudly on purpose:** round 3 asked that a reconfigured system slug that a user already holds "fail loudly". Shipped: `system` REGISTER of a user-held slug returns `FAILED_PRECONDITION` (reserved-slug rule, under an advisory lock), and a register `FAILED_PRECONDITION` aborts the fundsignal cycle with an ERROR alert. So pointing `analysis.fundsignal.source_slug` at a slug some user already holds aborts every fundsignal cycle until fixed.
- **Single-instance assumption:** design time verified `instance_count: 1` for indicators, ingest, analysis and config in both `.do/app.yaml` and `.do/app.dev.yaml`. The reason is unstated in the sources; the saga cache eviction, never-cached pending rows and the in-memory `(user_id, strategy_id)` maps are per-process. Assumption verified, reason unstated.
- **Un-granted `x-user-id: system` in analysis resolves to owner `""`** (owns nothing, reads empty, writes `PERMISSION_DENIED` via the existing empty-caller guard) rather than the `PERMISSION_DENIED` the design specified for ingest and indicators. This is a documented divergence (Step 7, design §2). A failed `ListSignalSources` in `GetAttribution` yields an empty visible set and no attribution, not a raw-slug fallback (D-5).
- **Admin override on formulas removed:** `UpdateFormula`/`DeleteFormula` keep the body `user_id` fallback in N only. `is_public` is stored `false` on every update, not only on full replaces (D-15). `ExecuteFormula` on a formula the caller cannot read returns `PERMISSION_DENIED` for an admin and `NOT_FOUND` for everyone else (AC-28).
- **Template response limitation (D-26, ingest):** `ManageSignalSource`/`InstantiateTemplate` responses report origin without `latest_version`. Only `ListSignalSources` does the batched version lookup. Template payloads are built from a whitelist (`_template_payload`) so no credential or owner data can leak. Unspecified ingest status codes (D-26): duplicate template create `ALREADY_EXISTS`, headerless instantiate `FAILED_PRECONDITION`, no slug on request or template `INVALID_ARGUMENT`, updating a retired template `NOT_FOUND`. Unspecified indicators codes (D-27): headerless `ListTemplates` `UNAUTHENTICATED`, user-path instantiate with an empty or `system` owner `PERMISSION_DENIED`, duplicate template id (incl. retired) `ALREADY_EXISTS`, non-UUID `intent_id` `INVALID_ARGUMENT`, retiring an already-retired template idempotent, a repo-less instance `UNAVAILABLE`.
- **Empty-value secret** decrypts as `found:true ''`, so the ingest poller treats `''` as missing ("bearer not configured"). The agent writes an `mcp_client` bearer as a per-user secret under opaque `mcp_credential.<uuid4>` (the UI BFF forces `userId`, `isSecret:true`, `createKey:true` and accepts only `ingest`/`mcp_credential.*` keys). `ManageSignalSource` has no DELETE verb (`ingest.proto`), so FR-4 "delete" maps to DEACTIVATE; no verb was added (C-18).
