## Chosen Approach

An indicators refusal of a formula the caller cannot read — `NOT_FOUND` or `PERMISSION_DENIED` — becomes a first-class **"formula not readable"** state on every analysis surface that traces readiness, instead of "indicators outage" (opportunities) or an unhandled abort (readiness). Paths that do not trace readiness (backtest, live loop, `GetIndicatorSeries`, write-time validation) keep their current mappings.

### Marker and contract

- `bool formula_unreadable = 25` on `Opportunity` and `bool formula_unreadable = 6` on `SymbolReadiness` (`packages/proto/analysis/v1/analysis.proto:603-654`, `:673-679`; no `reserved` statements; additive only). One `SymbolReadiness` field serves `EvaluateReadiness` and `GetWatchlistReadiness` (`WatchlistReadinessRow.readiness = 4`). A bool follows the sibling mutually exclusive markers `data_unavailable = 20`, `muted = 12`, `fundamentals_unavailable = 23`; C-04 targets closed value sets carried as strings, and a reason enum would churn the three existing fields (C-18, recorded trade-off).
- Persistence: provenance token `"formula_unreadable"` on `analysis.opportunities` (authoritative for `Opportunity`; the SQL floor needs `?`) and the key `"formula_unreadable"` in `readiness_json` (authoritative for `SymbolReadiness`; `readiness_cache` has no provenance column). No migration. The two stores are kept equal (the evaluator is not called under `fund_skip`/`fund_unknown`, so the trace never carries the key when the provenance token is absent).
- The verdict is a real, RESOLVED 0-of-0 result with a genuine `bar_epoch >= 0` — never the `bar_epoch = -1` UNKNOWN sentinel (`@AC-2 @feature-181`; `readiness.py:66-95`, classifier `servicer.py:4186-4203`).
- It is **terminal until the next recompute**: daily refresh, stale-read recompute, new bar / TTL on the readiness cache (24 h backstop; 30 s on `EvaluateReadiness`), or a definition change. The 300 s heal selector stays keyed on `"unavailable"` (`servicer.py:4948-4952`), so it never re-selects these rows — which also fixes today's endless 300 s re-stamp (the heal's `except grpc.RpcError` at `:5129` catches PERMISSION_DENIED as an outage). A formula-visibility change is not a fingerprint input (YAGNI); a repaired formula can keep showing the marker up to ~24 h (accepted).

### Fundamentals gate — global `_formula_fundamentals` classification (user-confirmed C-16 CHANGE of FR-5 with the gate ON)

## Rejected Alternatives

- **`raise_unreadable=True` on the read paths** — raises `FormulaExecutionError`, which propagates by design and aborts `EvaluateReadiness` / the recompute (`evaluator.py:262-269`).
- **A `FormulaExecutionError` subclass, or catching the refusal at 5–6 servicer `except` arms** — repeats the "fourth caller omits the kwarg" trap, loses the whole candidate instead of one component, cannot tell referenced from unreferenced.
- **Reading `unreadable_formulas` after the call** — one evaluator is shared across concurrent candidates; cannot attribute a refusal.
- **A constructor flag `flag_unreadable` (+ guards, `for_owner` plumbing)** — mechanism protecting against callers that do not exist; replaced by the private sink (user decision).
- **Scope-dependent marker (PERMISSION_DENIED only)** — the daily refresh/materializer (`owner_metadata`, no admin bit) overwrite it with a quiet skip valid ~24 h; non-admin owners never see it (fails.md 2026-10-22 "map every status code for one refusal to one outcome").
- **Propagating the admin bit into scheduled passes** — breaks the feature-225 `owner_metadata` contract, leaves non-admins silent.
- **A reason enum (`OpportunityDegradedReason`)** — churns three existing markers; out of scope.
- **Marking any unreadable component** — blanks an entry trace for a formula used only in the exit rule and can suppress a held REDUCE; replaced by referenced-only.
- **A partial 0/N result** — a rule with a missing operand is not honestly evaluable (P-03); contradicts AC-2/AC-3.
- **Retrying unreadable rows on the 300 s heal** — a permission/visibility refusal is permanent until the formula is repaired; endless loop.
- **Fundamentals fix scoped to opportunities + heal only** — adversary/proposer recommendation, overridden by the user (global), with the before/after above signed off.
- **Zeroing both axes for held rows** — would remove a genuine sell-signal REDUCE on a held position; replaced by the held rule.
- **Never caching refusals in `_formula_fundamentals`** — adds per-candidate `GetFormula` calls on the opportunities/heal/kick paths even with the gate OFF.
- **A `readiness_cache` column / the `-1` sentinel** — unneeded (the marker rides `readiness_json`); `-1` classifies UNKNOWN and re-kicks every 300 s.
- **A characterization test pinning the batch-loss behaviour** — would pin a bug; filed as a defect report instead.
