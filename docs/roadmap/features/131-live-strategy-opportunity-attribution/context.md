## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: Shipped a read-side attribution change in `xstockstrat-analysis._compute_opportunities` so a held position or active signal whose symbol is covered by a live-enabled strategy's `signal_params.symbols` now surfaces that strategy's readiness trace, instead of falling to unattributed (`strategy_id=""`, `0/0`) unless coincidentally watchlist-bound. A one-index add ballooned into a three-cap fan-out control problem: because `curated` rows bypass `max_universe_size` truncation, every new curated-injecting path had to be independently bounded. Final shape = a shared SQL predicate constant + three new config caps + a `_capped_live` helper, landed as a per-user (owner-scoped) compute stacked behind features 133/134.

**Why (irrecoverable rationale)**: The live loop's coverage was re-traced independently rather than read from `live_loop`'s in-memory `_last_state`, because main.py never hands the servicer a `LiveEvaluationLoop` reference — reaching into another module's lock-guarded mutable state was rejected as the weaker option before design. Three *separate* config caps (not one shared `max_universe_size` budget) because they bound different-cost dimensions: `max_live_strategies_per_symbol` (per-symbol, zero-marginal), `max_live_only_symbols_per_compute` (signal-only distinct symbols, zero-marginal), `max_live_held_symbols_per_compute` (held symbols, capital/fill-gated); conflating them let one dimension silently starve another and caused an overshoot bug. Cap tiebreak is `created_at` ascending, NOT lexicographic `strategy_id` (an alphabetical slug rewards whoever named a strategy earliest, unrelated to relevance). Held-symbol ranking uses summed `abs(Position.market_value)` — the only cleanly-aggregable, economically-meaningful field `ListPositions` returns (`opened_at` doesn't aggregate across multi-account holdings).

**Rejected alternatives**: Shared `StrategiesRepository` method call from live_loop.py (DRY's literal preference) — disproportionate blast radius on a tested cooldown/transition-bearing production loop for a one-line predicate; resolved with a shared *constant* `LIVE_ENABLED_PREDICATE_SQL`. Re-declared-string / behavioral parity test — the string test proves nothing about live_loop.py's actual query; the behavioral test needs heavy mocking for a one-line predicate. `_capped_live(sym, exclude=existing)` (exclude-before-slice) — PROVEN wrong: excluding before the top-cap slice re-opens the ranking window past cap and can push a symbol past `max_live_strategies_per_symbol` (5 held + 3 = 8); only `_capped_live(sym)` with no exclude then filter-for-newness composes correctly across both call sites. Making step 6 is_held-aware — excluded held_norm from step 6's domain entirely: an is_held-blind step 6 would emit a wrongly entry-traced duplicate ENTER row for a position the user already owns. Truncating the shared `live_by_symbol` index uniformly — it has 3 consumers but only 2 cost compute; truncating for tagging-only reads strips "live_strategy" from existing curated rows at zero savings (AC-3 violation). Symbol-level "already curated" exclusion — violates FR-4 by dropping a genuinely new (symbol, strategy B) pair; fixed with per-(symbol,strategy) newness check `_new_live_strats`. Cross-pass hysteresis for cap-boundary flapping — `replace_for_user` is a stateless DELETE+INSERT; carried state for a ~daily cosmetic risk violates the write-minimum bias.

**Scars & gotchas**: `list_live_enabled`'s return annotation had to be quoted `-> "list[dict]"` because the class's own `list()` method shadows the builtin in class scope (unquoted `list[dict]` evaluates `<method>[dict]` → TypeError). Mandatory harness break: `_materialized_svc` stubbed `_strategies_repo` as a bare AsyncMock; once Step 3 calls `list_live_enabled()` the bare mock returns a non-iterable MagicMock → TypeError breaking all 12 existing `TestListOpportunitiesMaterialized` tests (must default `list_live_enabled → []`). Second harness break: the ListPositions mock built `SimpleNamespace(symbol=s)` with no `market_value`, so summing `abs(Position.market_value)` raised AttributeError on every held test until the mock carried a value. The raw-vs-normalized symbol-key mismatch bug recurred THREE times in one feature (`live_by_symbol`, `held_value_by_symbol`, screener membership test) — each silently no-ops a mixed-case-configured symbol; `signal_params.symbols` has no write-time case validation. Fix pattern: normalize at construction/source, not at read sites.

**Permanent deviations**: design said widening `_drain_held_symbols` to a normalized-keyed dict "leaves both call sites dict-compatible with zero other changes" → shipped ALSO changed the screener membership test to `if _normalize_symbol(r.symbol) in held:` (D-3). design/spec said read the per-symbol cap "alongside `max_universe_size`" → shipped defines `max_live_strats`/`_capped_live` BEFORE the attribution loops because `_capped_live` is consumed inside the held loop (D-4). design/spec assumed a global `list_live_enabled()` → shipped owner-scoped it with an optional `user_id` param because feature 133 merged first and made `_compute_opportunities` per-user; a global query would cross-attribute another user's live strategy (IDOR) (D-1).

**Cross-feature signal**: 131 sits in a tightly-coupled cohort all editing `_compute_opportunities` (servicer.py:2144-2168); merge order 133 → 134 → 131 → 132. Feature 132 layers on top and replaces `strategy_symbols` with a shared `resolve_universe` helper and adds an orthogonal `muted` flag reusing 131's `− held_norm` domain guard — a future editor of this function must read 132's design too. The "spec written before a security-model feature lands must be re-owner-scoped at execute time" pattern (D-1) is a reusable cross-feature ordering hazard.

**Deferred follow-ons**: Attributing a position to the *specific* live strategy that historically opened it — out of scope; needs `trading.Order.strategy_id` (recorded at fill) to propagate into `portfolio.Position` (portfolio.proto:43-63 has no such field). Reusing the live loop's in-memory in_position/entry-time belief instead of re-tracing — a future feature may revisit if re-tracing proves too expensive. Multi-strategy-per-symbol behavior (FR-4) ships with NO dedicated test — an explicit user-directed scope waiver; if that behavior regresses, this suite gap is why it wouldn't be caught.

**Runtime-invariant recommendations (→ /context-constitution)**: ANALYSIS-* — in `_compute_opportunities`, `curated` candidates (is_watchlist||is_held||is_live) are NEVER subject to `max_universe_size` truncation, so any new code path injecting a curated candidate must carry its own independent per-request cap or it creates unbounded synchronous compute-on-read cost (bar fetch + `evaluate_conditions_traced`) — the root invariant behind all three of 131's config caps. ANALYSIS-* — all `*_by_symbol` indexes in `_compute_opportunities` are keyed by `_normalize_symbol(...)`; `signal_params.symbols` has no write-time case validation, so any new index built from strategy config must normalize at construction.
