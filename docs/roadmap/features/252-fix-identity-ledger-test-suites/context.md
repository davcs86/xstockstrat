The impl tests now execute against the real `IdentityServiceImpl`/`authz` and `LedgerServiceImpl`/`EventNotifier`; the swallowed `before()` import, the proto try/catch and 105 `if (!x) return` guards (identity 67 on the #1262-inclusive base, ledger 31 + 7 = 38; design had counted 103 = 65 + 38, +2 on #1262) are gone, replaced by a bare throwing `before()` import, a 2-line constraint comment and one harness case per file. Observed in-tree on Node v24.20.0: identity 79/79 tests (aggregate 81.88% lines), ledger 47/47 (73.7%), zero fail/cancelled/skipped/todo (old context.md@1ed63958:264,291). **Rejected alternatives**:
- `tsx` loader — lost: adds a devDependency and changes the root lock (Dockerfile `--frozen-lockfile` vs CI `--no-frozen-lockfile`), and does not type-check.
- `--experimental-transform-types` with explicit `.ts` imports — lost: needs extension rewrites in runtime files, keeps the `.nvmrc` 22 vs CI 24 split, no type-check.
- `tsconfig.test.json` — lost: no Node service uses it; drifts from config/notify.
- `rewriteRelativeImportExtensions` / `allowImportingTsExtensions` — lost: change production compiler options for every file to fix 6 test specifiers.
- Static import plus `as any` casts (notify precedent) — lost: bigger diff, and once the subject is typed, bare pool objects and `{}` do not satisfy `Pool` / `ConfigWatcher` and `FakeClient` does not satisfy `() => Client` (`eventNotifier.ts:33`), so casts are needed at those call sites (recon.md:210-213). The design/recon also named `ledgerServiceImpl.test.ts:586` a `protected` override needing a cast (design.md:173,203; recon.md:212), but Step 4 found it "a property assignment on `impl`, not a `protected` override" (old context.md@1ed63958:281) — that reason did not hold; the typing reason survives. A bare `before()` import plus harness case plus constraint comment (no casts, `any` bindings) is the minimum; the cost of the `any` bindings: a renamed export still fails `tsc` (TS2339 at the unannotated `mod`), but constructor and call shapes go unchecked (design.md:173).
- Relying on `tsc` TS2307 alone as FR-3 evidence — lost: identical result with and without the runtime hardening; AC-6 exists for this.
- AC-1 mutation via the `aud` binding, or removing the whole claim UPDATE on the #1262 base — lost: the first moves AC-1 off the rotation rule the bug was found on; the second makes the test fail through the `invalid_grant` path (a different cause).
- AC-6 via a stub subject that throws at load — lost: a new fixture to maintain (C-13).
- AC-6 with only a negative Then, or pinned to `# tests`/`# fail` counts — lost: the first is unattributable, the second over-specifies the mechanism; a positive control plus the exit code plus `# pass 0` suffices (design.md:209).
- A literal "zero `catch`" grep gate — lost: too broad; scoped to `catch` wrapping subject/proto imports, equivalent on both verified bases because the only other `try {` is the `APPLICATION_ENV` try/finally at identity `:143` pre-change (old context.md@1ed63958:162) / `:127` post-change (:264); design.md:212.
- AC-1 with line-number anchors in `acceptance.feature` — lost: the anchors depend on the base (main-dev vs #1262) and F-09 freezes them, so the AC uses behavioural wording and the base-specific mutations live in step Verification (design.md:213). AC-2 kept its anchors (design.md:169 "stay as written"), which is why they went stale (see Permanent deviations and Deferred follow-ons).
- Counting the buggy-base "control step fails" ("Could not find") as AC-6's RED — lost: that is an unmet Given (the control run's precondition fails), recorded as context only; only the end-of-Step-A run that deletes the compiled subject while the catch is still in place (exit 0, unchanged `# pass N`) discriminates (design.md:48,210).
- Permanent `--test-timeout` / `--test-force-exit` / `--test-reporter=tap` in scripts — lost: diverge from config/notify; reporter flag only in AC-6's ad-hoc command. `--test-force-exit` as the probe's pass condition also rejected: it masks event-loop hangs (CI `node-test` has no `timeout-minutes`).
- Exact `# tests` pins in a frozen step Verification — lost: F-09 makes them uncorrectable if #1262 or 248 lands mid-execution; a relative formula (pre-count + harness cases) was used.
- Editing the working-tree main-dev `acceptance.feature` — lost: splits main-dev from the feature branch.
