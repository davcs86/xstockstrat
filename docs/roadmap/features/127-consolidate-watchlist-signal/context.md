## Archive Synthesis — 2026-08-26 — /sdd-archiver

**What**: Shipped a per-user, `system_managed`-flagged "Signals" watchlist that the MCP agent auto-populates as a best-effort post-commit side effect of `ingest_signal(direction="watchlist", not deduplicated)`, mirroring the existing auto-alert. What began as an agent-only change (recon assumed "no proto / no schema / no UI") expanded mid-design into four coordinated surfaces: the agent side-effect; portfolio proto + migration (`system_managed` flag, `EnsureSignalWatchlist` RPC, per-entry `source`, `FAILED_PRECONDITION` delete-guard); and a UI undeletable-affordance + signal badge. The two previously same-named-but-unlinked "watchlist" concepts (inert ingest label vs. real portfolio watchlist) are now one.

**Why (irrecoverable rationale)**: The central "whose watchlist?" fork was resolved to *the calling user's own* via propagated `x-user-id` — no system-owned/owner-less watchlist was introduced, keeping the resource user-owned (C-10(c)). Identification moved from a reserved *name* to a *flag* because `UNIQUE(user_id,name)` lets a user co-opt the name and find-by-name is rename-fragile (this half already recorded at insights.md 2026-08-19).

**Rejected alternatives**: reserved-name identity, a `CreateRequest.system_managed` boolean, server-side name disambiguation, a config-key for the name, and a `PERMISSION_DENIED` delete guard — all already captured at insights.md 2026-08-19; not re-emitted.

**Scars & gotchas**:
- `CreateWatchlist` collapses a `UNIQUE(user_id,name)` collision to `CodeInternal` — indistinguishable from a DB outage (`portfolio_service.go:1238-1241`), so a caller *cannot* match on `ALREADY_EXISTS`; the atomic find-or-create (`EnsureSignalWatchlist`) is the only correct path, and best-effort failure logging must surface the **original** gRPC code/details or a real misconfig (PERMISSION_DENIED/UNAVAILABLE) becomes undiagnosable.
- **`normalizeBindings` silent field-drop** (execute-phase discovery, Step 4): the service-layer `normalizeBindings` (`portfolio_service.go:1139`) reconstructs every `WatchlistBinding` as `{Symbol, StrategyId}`, and **every** write path (`AddWatchlistSymbols`, `CreateWatchlist`, `UpdateWatchlist`) funnels bindings through `requestBindings`→`normalizeBindings` before the repo sees them — so a `source`-tagged binding is silently reset to `0` at that choke point *before* insert, defeating FR-10, even though the migration column and `insertBindingsTx` were correct. The spec never named `normalizeBindings`; it was found only by doing. Fix: `Source: b.GetSource()`. The trap (a central binding-normalizer silently zeroes any newly-added `WatchlistBinding` field rather than failing to compile) is exactly what the next feature adding a `WatchlistBinding` field will hit unless it knows to touch `normalizeBindings`.
- UI watchlists e2e (Step 10) had to run against a production `next start` build: dev-mode warmup timed out on cold compile + a blocked Google-Fonts fetch; `JWT_SECRET` set to the e2e `TEST_JWT_SECRET` so the auth cookie validates.
- Codegen Docker image build failed at the NodeSource apt step (egress not routed inside the Docker build); host-toolchain fallback used, validating an **empty** `gen/` diff on the unedited proto *before* editing (byte-for-byte reproduction). Recurring per `codegen-toolchain-host-setup.md`.

**Deferred follow-ons**: per-entry `source` is **first-writer-wins** (`ON CONFLICT (watchlist_id,symbol) DO NOTHING`): a symbol added manually then re-signaled stays `MANUAL` (and vice-versa) — a provenance *hint*, not authoritative; any future feature treating the badge as ground truth must revisit. The empty-but-undeletable system list (after `RemoveWatchlistSymbols`/`UpdateWatchlist`) is deliberate and self-healing via `EnsureSignalWatchlist` — not a defect.

**Runtime-invariant recommendations (→ /context-constitution)**: (1) PORTFOLIO-* — `CreateWatchlist` maps a `UNIQUE(user_id,name)` violation to `connect.CodeInternal` (identical to a DB outage), so callers cannot distinguish "already exists" from a real failure — the atomic `EnsureSignalWatchlist` exists specifically to avoid depending on a distinguishable error code (`portfolio_service.go:1238-1241`).
