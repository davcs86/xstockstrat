## Execution Summary

Proto first (enum + user_id + deprecated trading_mode + GetSecret), then the config DB migration,
then the config service (crypto → authz → servicer), which unblocks marketdata's GetSecret
resolution. The agent (MCP_AGENT_SECRET→JWT_SECRET), the config-ui consumer surface, the remaining
WatchConfig client edges, the deploy-file env-var sweep, and the governance-doc rewrite follow.
Security-bearing behavior ships with config-service tests proven RED-before-GREEN with non-zero
assertions (feature-074 trap).

### Step 2 — migration: config 017 scope re-model + encryption columns + collapse

**Status**: `done`
**Service**: `xstockstrat-config`
**Files**:

- `services/xstockstrat-config/migrations/017_config_secrets_and_scoping.down.sql` — create

**Reviewers**: DBA — migration numbering/up+down/index correctness; `xstockstrat-config` owner — scoping.

**Codebase Evidence**:
- Last config migration `016`; schema/unique from `001_config_tables.up.sql` + `002_config_environment.up.sql`; audit triggers `config.audit_config_change()` (001) + `config.audit_config_insert()` (`010_config_audit_insert_trigger.up.sql:20-21` inserts `NEW.trading_mode`); `config_audit` has `trading_mode` (002).

**TDD**: N/A (migration)
**Covers**: — (behavior asserted by Step 4 AC-12)

**Instructions** (up.sql, single transaction):
1. `ALTER TABLE config.config_values ADD COLUMN value_encrypted BYTEA, ADD COLUMN user_id TEXT;` `ALTER TABLE config.config_audit ADD COLUMN user_id TEXT;`
2. `CREATE TABLE config.config_values_premigration_017 AS SELECT * FROM config.config_values;` (audit/faithful-down snapshot).
3. `UPDATE config.config_values SET environment='staging' WHERE environment='dev';` same for `config_audit`. Drop old `environment` CHECK, add `CHECK (environment IN ('staging','production'))`.
4. FR-10 collapse (winner env-matched-mode > `all` > opposite; `production`←`live`, `staging`←`paper`): for each `(namespace,key,environment)` set the surviving row's `trading_mode='all'`→null-user global, delete losers. Header comment documents the rule + AC-12 example.
5. Drop unique `(namespace,key,environment,trading_mode)`; `ALTER TABLE ... DROP COLUMN trading_mode;` on both tables; `CREATE UNIQUE INDEX config_values_scope_uniq ON config.config_values (namespace, key, environment, COALESCE(user_id,''));`.
6. `CREATE OR REPLACE FUNCTION config.audit_config_change()` and `config.audit_config_insert()` without `trading_mode`, carrying `user_id`; keep copying `value_data`, never `value_encrypted`.
7. Seed the 4 vendor secret rows for `staging`+`production` (global): `marketdata.alpaca.api_key`, `marketdata.alpaca.api_secret`, `marketdata.fmp.api_key`, `marketdata.finnhub.api_key` — `is_secret=true, value_encrypted=NULL, value_data='[redacted]', consuming_service='xstockstrat-marketdata'`, `ON CONFLICT DO NOTHING`.
- down.sql: re-add `trading_mode TEXT DEFAULT 'all'` + old CHECK on both tables; restore rows from `config_values_premigration_017`; restore the old trigger bodies + unique constraint; drop the new columns/index/premigration table. Header notes the collapse is inherently lossy but faithfully restorable from the snapshot.

**Verification**:
- `ls services/xstockstrat-config/migrations/017_*.up.sql services/xstockstrat-config/migrations/017_*.down.sql`; read both — every `ADD/CREATE/ALTER/DROP` in up has an inverse in down (offline, no DB).

**TDD**: red-green required
**Covers**: — (paired test Step 4)

**Instructions**:

**TDD**: red-green required
**Covers**: `AC-1, AC-1b, AC-2, AC-3, AC-4, AC-5, AC-10, AC-11, AC-12, AC-13, AC-14, AC-16`

**Instructions**:
- `buildConfigValue`: if `row.is_secret` → return `{ string_val: '[redacted]', is_secret: true }` regardless of `value_type`.
- `setConfig`: extend the existence-gate SELECT to read the existing row's `is_secret`; when secret, `encryptSecret(plaintext)` into `value_encrypted` and force `value_data='[redacted]'` in the upsert (row-authoritative — ignore request `is_secret` except when `create_key`+`is_secret=true` mints a new secret key). Upsert `ON CONFLICT (namespace,key,environment,COALESCE(user_id,''))`. Never log plaintext.
- New `getSecret(call, callback)`: gate `hasSecretCallerAuthority`; `SELECT value_encrypted FROM config.config_values WHERE namespace/key/environment AND user_id IS NULL`; row-absent/NULL → `{value:'',found:false}`; present → `decryptSecret` (on throw → `callback({code:13})` INTERNAL, never partial).
- `authz.ts`: `SECRET_CALLER_ALLOWLIST = [{callerID:'marketdata', keys:[4 marketdata.* names]}]`; `hasSecretCallerAuthority(md, ns, key)` fail-closed, mirroring `hasInternalCallerAuthority`.
- Scope: `resolveEnv` maps `STAGING`+`DEV`→`'staging'`, `PRODUCTION`→`'production'` (string branch + numeric `ENV_MAP`); remove `resolveMode`/`requestMode` fan-out; cache key `ns:env`; per-user overlay: subscriber record + `getConfig` overlay global rows with the caller's `user_id` rows (both via `buildConfigValue`, so redacted); rebroadcast per-user subscribers on `pg_notify`.
- Bind `GetSecret` in `serviceDefinition.ts`; drop the `platform.trading_state` per-mode assumption (now per-env).

**Verification**:
