## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: Every inter-service gRPC hop runs flag-day, fail-closed mutual TLS: the 10 backends, the UI BFF and the agent (12 identities, 10 servers). No plaintext listener, no permissive mode, no verification-disabling flag in any environment. Trust in the `x-user-id`/`x-access-scope`/`x-trace-id` trio now rests on "the peer holds a platform-CA leaf", NOT on "which service is calling" — per-RPC identity authorization was descoped. Larger than the spec: after launch, CI-minted leaves were added (`.github/workflows/deploy.yml:87-104`, `scripts/mtls-provision.sh`), recorded only in the runbook, the workflow and `docs/setup/digitalocean.md:359-375`.
**Why (irrecoverable rationale)**: Two hard platform constraints: DO App Platform injects env vars only (no file mount, daemonset or socket; recon.md:55,94), ruling out SPIRE/cloud-CA and leaving env-PEM from a self-signed CA; and `xstockstrat-config` serves WatchConfig, so it cannot receive its own channel's credentials over that channel (hence cert material never goes through config; F-07 honoured by external config). DO internal networking is L4 raw TCP with no TLS termination or re-origination (context.md decision 3, 2026-10-01, confirmed by WebSearch and DO docs) — the precondition that makes end-to-end mTLS work on DO production at all, independent of feature 084's droplet; the only surviving trace is the `.do/app.yaml:9` comment "internal_ports for TCP (any protocol, including gRPC H2C)" (stale-reading). Flag-day beat a permissive window: a client-cert-optional server in the prod spec collides with FR-4/`@AC-4`, CI cannot guard that window until the second release, and its only benefit (zero failed calls on the fire-and-forget ledger-emit edge) is matched by a mandatory flat-book precondition.
**Rejected alternatives**: SPIFFE/SPIRE or a cloud-managed CA (DO has no mount/daemonset/socket). Per-RPC peer-SAN authorization (the C-16 CHANGE option; lost by operator decision 2026-10-01 — the `x-internal-caller` gates in features 147/154 authorize on a forgeable header, so handshake-only auth leaves the DT-3 impersonation hole open; round-1 adversary finding; accepted residual: any holder of any platform leaf can forge `x-internal-caller`; the old `@AC-3` is retained `@descoped`). Model A (two-release `MTLS_REQUIRE_CLIENT_CERT` permissive window). Go `InsecureSkipVerify` with manual chain verify (native `tls.Config.ServerName` pinning instead). Dial-host == SAN (DO dials `${svc.PRIVATE_DOMAIN}`, not the SAN). Multi-SAN leaves carrying the DO FQDN (DO-generated, differs dev/prod, unstable at cert-gen time). A shared cross-service mTLS library (the platform has no shared cross-service libs; jscpd hard-blocks only in `xstockstrat-ui`, so 12 per-service helper copies pass). An `@grpc/grpc-js` stub fallback for the UI (not needed: connect-node `nodeOptions` is `http2.SecureClientSessionOptions`). Accepted trade-offs: a single leaf carrying both EKUs (C-18), per-service helpers, the bounded-loss ledger-emit residual, and the CA signing key living in CI (runbook:61-65).
**Scars & gotchas**: POST-LAUNCH: the first `main-dev` deploy pushed literal `YOUR_*` placeholders and DO rolled back the release (runbook:55-59 is the ONLY evidence; "every service crash-looped" is the runbook author's inference, not logs). Authority-pinning bug class (R4): compose dials the bare name and in-process loopback tests pass, so a DO `PRIVATE_DOMAIN` ≠ SAN mismatch is invisible except at the DO deploy; only a valid-CA/wrong-SAN negative test catches it in-process (implemented in all four test families). **Permanent deviations**: Design said static per-service leaf, restart-only rotation, leaf stored as env → shipped a CA-only secret (`DEV_MTLS_CA`/`PROD_MTLS_CA`) with all 12 leaves re-minted every deploy off the byte-stable CA, because the operator chose zero per-deploy manual steps and automatic leaf rotation over keeping the CA key off CI; the dev CA is also the local compose CA. "Load MTLS_* at import" → loaded at call inside `_load()` for the agent (importable under pytest without global MTLS env). Spec FR-4 still demanded a "documented relaxed/dev-cert mode"; NONE shipped (dev runs full mTLS, Model B; `@AC-4` was rewritten, the FR-4 text never edited). Design-promised tests did not ship and the Deviation Log never recorded it: "HALTED refuses PlaceOrder" and "snapshot self-heals" (shipped only `TestEmitLedgerEventFailSoftOneShot`, `ledger_emit_mtls_test.go:36-58`), and a stream surviving a rotated-leaf reconnect with replay (shipped a single rotated-leaf handshake, `ledger/src/__tests__/mtls.test.ts:149-156`); the design's "Step 6" is the spec's Step 4; no shipped test opens ANY stream under mTLS (trading's `StreamOrderUpdates` has no C-16 guard). `@AC-5`'s "Node AsyncLocalStorage" names a mechanism feature 175 removed. `@AC-6`'s "no service downtime" is not literally true (restart-only rotation; the runbook reads it as reconnect-without-data-loss, runbook:157-160).
**Cross-feature signal**: mTLS authenticates "a platform service", but the features 147/154 `x-internal-caller` gates remain header-only; wiring the peer SAN into them is a C-16 CHANGE for another feature. Feature-174 app-layer WatchConfig `client_id` prefixes (`ingest-`, `analysis-`) are a separate mechanism from cert SAN identity — never conflate them. The deploy-file overlap with feature 084 (droplet + Caddy) was rebase-only; Caddy is the external edge. `recon.md:81`: the design must not reintroduce a shared inter-service secret even as a relaxed-dev fallback (MCP_AGENT_SECRET; `platform.feature @AC-8 @feature-147`).
