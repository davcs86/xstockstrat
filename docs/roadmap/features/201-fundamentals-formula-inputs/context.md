## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: A `COMPONENT_KIND_CUSTOM_FORMULA` strategy component whose formula declares `fundamental_inputs` (a new closed `FundamentalMetric` enum persisted by indicators migration `006`) runs as a fundamentals-only operand: fed only those metrics (never `close`), scored once per filing-boundary epoch (point-in-time on backtest, `GetFundamentalsMulti` snapshot elsewhere), its scalar outputs broadcast across the span. It started as a mis-scoped "formula signal producer loop" that the user rejected; the shipped feature is a no-loop, no-emission evaluator wiring plus a persisted declaration. Launched 2026-09-24 via PR #1169.
**Why (irrecoverable rationale)**: Disjoint formula kinds instead of an in-formula blend (user steer at the R2 gate): a fundamentals-only formula never receives `close[]`, so an epoch value cannot depend on bar position and look-ahead is structurally impossible; indicator-only formulas stay byte-identical; blends compose at the rule level; the seeded producer formula reads no `close`. The declaration lives on the formula, not on `StrategyComponent`, because the `input_schema` activation idea was empty on the seeded formula, had no authoring surface, was unvalidated/mutable and was not fingerprinted (it would regress feature-152 `@AC-6`). Partial rows OMIT absent metrics rather than zero-fill (user option b, R4/R5): zero-filling would match the producer but penalise non-reporting symbols and skew early-window backtest scores against live. Execution is one `ExecuteFormula` per epoch (a span where the tuple of per-metric as-of values is constant), O(filings) not O(bars); all-`None` epochs skip the call and hold `None` because the seeded formula returns a neutral 0.5 on no metrics and would fabricate a score. No C-16 CHANGE: holding a filing forward from its as-of date looks like the forward-fill feature-152 `@AC-3` forbids, but the design resolved it as a new branch, not a reinterpretation.
**Rejected alternatives**: `input_schema` as the routing signal (see above); a `StrategyComponent`-side routing field (user picked the formula-side field and accepted the fingerprint residual); `repeated string fundamental_inputs` validated against the analysis allow-list (proposer R3 recommendation; the user declined twice and kept the closed enum for C-04 proto safety, accepting a 4th representation of the metric vocabulary plus one enum-to-key lowering site); proto-zero partial-row parity (option a); an in-formula `fundamentals + close` blend (a deferred `HYBRID` kind is the only path); per-bar recompute (multiplies `ExecuteFormula` volume against feature-176 `@AC-5`); a second snapshot config gate (value_type-immutability seed gap, C-10(b)/F-11 — one key is read at two sites instead); snapshot-first or stack-on-198 sequencing (moot once 198 merged).
**Scars & gotchas**: Persistence was the late discovery: recon and context said "no proto, no indicators change, Migration: NONE", and only design round 4 saw that `GetFormula` did not map the new field — without migration `006` plus the Register/Update/Get mapping the routing map is always empty and every fundamentals formula dies with `FormulaExecutionError`. The routing map must exist before `_needs_eval_dates` at every surface, else `eval_dates=None`, nothing is broadcast and the strategy holds silently; the backtest prefetch therefore covers all formula components, not only rule-referenced ones. Post-execute regression, unrecorded in the old context: the backtest PIT loader `_load_fundamentals` recognised only a feature-198 operand, so a formula-only strategy ended `ENTRY_NEVER_TRUE` with 0 trades (silent hold); fixed by the guard at `servicer.py:1571-1577` (regression tests `test_fundamentals_formula_servicer.py:223-262`); the fix depends on callers passing `formula_fund_map`, and the `_load_fundamentals` docstring still says "SINGLE chokepoint". Bare `<ref>` resolves to `value`, not `composite` (headline is `<ref>.composite`); `_compute_component` used to drop scalar outputs. CI break: the agent `TestFormulaBuilderParity` failed after Step 1 because `fundamental_inputs` was neither covered nor opted out; the step's Files omitted `test_formula_builders.py`. Test traps: `make_servicer` stubs no `get_bool` (fails.md:1395); real `Bar` on `bar.time` (fails.md:727); assert the mid-window transition (fails.md:1853); `MessageToDict` rejects NaN so a non-finite scalar becomes `FormulaExecutionError`; growing the evaluator signature broke fixed-signature stubs in three test files (widen to `**_kw`); `GetIndicatorSeries` now fetches each formula once and needed a `GetFormula` stub; a source-only revert of `ComponentEditor.tsx` cannot give RED against an `E2E_PREBUILT` bundle — revert AND rebuild.
**Permanent deviations**: A separate `formula_fundamentals_data` evaluator channel (defaulting to `fundamentals` on backtest) instead of one shared channel, because on a non-backtest surface a co-occurring feature-198 operand must stay PIT while the formula needs the snapshot (operator-approved mid-Step-8; touched `evaluator.py` and `readiness.py`, outside the step's Files). `_decode_formula_output(formula_id, resp)` (no `expected_n`), and the OR guard on both loaders shipped only after the regression. `@AC-5` text ("formula error gives None/hold, evaluation does not abort") is contradicted by shipped behaviour: a genuine formula failure raises `FormulaExecutionError` (`evaluator.py:132-133,536`, test `test_ac5_formula_error_raises`) — the backtest skips that symbol with `NO_TRADE_REASON_FORMULA_ERROR` (`servicer.py:934-948`), `GetIndicatorSeries` isolates faults per component (`:3748-3750`), opportunities propagate (`:4063`); only a whole-row-missing span holds `None`. An unreachable `GetFormula` routes the formula as indicator-only (fed `close`, raises); `_formula_fundamentals` caches `[]` in the shared per-pass cache (`servicer.py:1633-1636`), so one transient error can poison a whole pass (inference, no test).
