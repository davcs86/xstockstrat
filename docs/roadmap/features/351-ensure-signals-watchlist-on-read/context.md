## Archive Synthesis — 2026-11-18 — /sdd-archiver

**What**: `PortfolioService.ListWatchlists` now idempotently creates the caller's system-managed "Signals" watchlist (feature 127) the first time that user lists watchlists, so users who never ran an agent `ingest_signal(direction="watchlist")` (the origin report: Homelab staging, whose lists were only "DB workload test" and "Test") have one. Shape: list first; only when `page_token == ""` and the loaded page has no `system_managed` row, call the existing `EnsureSystemManaged`, then re-list once (skipped when the ensured id sorts after the last returned id); an ensure or re-list failure is fail-open (WARN, original page returned). No proto, config, migration, UI or agent-contract change; agent `list_watchlists` text lost "(read-only)". Shipped with zero code deviations; two process deviations (below). The work landed on the harness session branch `ccr-1305a9de-7x1t7v` and integration PR #1561 (squash commit `8b472521`); `feature/ensure-signals-watchlist-on-read` never existed on origin (execute context: "the harness forbids other branches"; no code impact). Promoted to main by #1573 (`dd41417d`).

**Why (irrecoverable rationale)**:
- Origin and mechanism choice. The operator report was "system watchlist 'Signals' missing on Homelab staging; migrator didn't create it". Investigation found migration `011` only adds the column and indexes, and the only ensure caller was the agent side effect; Loki (30 d) showed no "Watchlist auto-add failed" or portfolio ensure errors, so it was a design gap, not a failed side effect. Operator decisions at story time (AskUserQuestion): mechanism = lazy ensure on `ListWatchlists`; process = SDD story + design quick (not bug-triage). Rejected there: a cross-schema migration (portfolio has no users table; a migration stays inside its schema) and identity→portfolio ensure-on-create plus a backfill job.
- Depth escalation. The product-spec review recommended `quick`; after Phase 0 recon the operator chose "Upgrade to full" because the rubric fires on 2+ services (named consumer surfaces count) or any overlap finding, and both did. The design ran 4 full rounds (round 3 and round 4 were operator-requested at the gates; round 4's pre-mortem focus was orchestrator-chosen). No Floor (F-11) breach in any round. Design approved by the operator at the round-4 gate, 2026-11-16T20:49:25Z (design.md header); P-1 and P-2 were declined, not reopened.
- Why list-first with a conditional ensure (D-1, D-2, D-8), not ensure-always: the steady state stays at the same 2 round trips as before (Signals already on page 1); ensure-always (R-1) would add about 6 round trips and a write attempt to every analysis drain and UI load. `EnsureSystemManaged` always runs INSERT…ON CONFLICT plus SELECT plus GetByID plus listBindings, so it is never free. The skip rule compares ids, never the token value, so it keeps working after the token fix; it exists because the ensured row's uuid position is random (`ORDER BY watchlist_id`), so presence on the first response is only deterministic via a re-list. The cheap check on data already loaded beat a new store method (R-4: interface + two implementers change, +1 round trip and a write attempt in the common case; remains the remedy if write load ever shows).
- Fail-open (D-3) was first an author assumption (product-spec Open Questions marked it so; the spec review round 2 carried it to the design gate as "NOT operator decisions"). It was operator-confirmed at the round-2 gate (D-10(b), AskUserQuestion). WARN is silent when `ctx.Err() != nil` so a cancelled request is not read as a degraded store; no telemetry counter and no ledger event on creation (`EnsureSignalWatchlist` emits none; no consumer of `portfolio.watchlist.created`); WARN-only is the in-service pattern (`refuseUnservable`).
- Concurrency needs no transaction (D-4): the partial unique index `watchlists_user_system_uidx` is the `ON CONFLICT` target shared with the agent's `EnsureSignalWatchlist`, so exactly one system list per user under READ COMMITTED and PgBouncer transaction mode. The AC-2 concurrency clause is proven at repository level (5 concurrent `EnsureSystemManaged` in a dbtest) and sequentially at service level only, because the unit fake store is a mutex-less map and a concurrent unit test would fail under `-race` (accepted, D-9).
- Operator decisions with consequences recorded so they are not rediscovered as defects:
  - **No UI change** (recorded as an operator decision in the 2026-11-16 design-phase-0 session; no question text is recorded for it).   - **Token bug split out** (round-1 gate, AskUserQuestion): the `ListByUser` look-ahead-token skip (`nextToken = wls[pageSize].WatchlistId` while the next page filters `> token`) is a separate defect, not bundled (R-5): it keeps 351's diff to the ensure and avoids silently widening the analysis symbol universe under a watchlist-row feature. The `ListPositions` twin got its own report (round-1 gate decision: "file report and launch a fix session"). Both fixes shipped as features 354 (`fix-listwatchlists-page-token`, #1566, commit `149351de`) and 353 (`fix-listpositions-nextpagetoken-skips`).

**Rejected alternatives**:
- R-1 always ensure before listing — ~6 round trips + write attempt on every first page for nothing in steady state.
- R-2 ensure then merge/append the ensured row onto page 1 — breaks `page_size`, and the row reappears on a later page when its uuid is past the token (duplicate).
- R-3 `ORDER BY system_managed DESC, watchlist_id` with a compound opaque token (guarantees Signals on page 1, would also remove the UI's 51st-list loss without UI code) — viable but the spec's Out of Scope excludes pagination order and it changes every caller's token format; recorded as the road not taken.
- R-4 new "ensure-only / existence-check" store method — interface + `WatchlistRepo` + `fakeWatchlistStore` change, +1 round trip and a write attempt in the common case; wins only for users with more lists than `page_size`.
- R-5 bundle the `ListByUser` token fix (and a new FR-8 token contract) — operator split it out (D-6).
- R-6 `CountByUser … AND NOT system_managed` — operator accepted 49 (D-7).
- Story-time: cross-schema migration; identity→portfolio ensure-on-create + backfill job (see Why).
- UI alternatives (recon.md:81,92; not chosen): a screener `systemManaged` filter on the Add-top-N picker, and/or auto-select + empty-state handling, each with e2e/mock updates; the operator chose "no UI change".
- O-18 (not a design change): a zero-code interim remedy for the Homelab symptom exists — `ingest_signal(direction="watchlist")` at low conviction then remove the symbol (the emptied list stays), or `EnsureSignalWatchlist` over mTLS; side effects: a stored signal row and an alert if conviction >= `agent.signal.alert_threshold` (0.6).
