**Why (irrecoverable rationale)**:
- Cancel guards are in-memory-set-only on purpose. `CancelBackfill` is the sole `CANCELED` writer in `app/` and does `_canceled_jobs.add` before the `CANCELED` write; ingest is `instance_count: 1` (design.md@1ed63958:87-92). The set check is synchronous with no `await` before the write it guards, because any awaited DB re-read between check and write reopens a missed-cancel window (design.md@1ed63958:165-166, rejected r1 `_is_canceled`). The one persisted check is `_resume_job`, because after a restart the set is empty (design.md@1ed63958:79-81).
- Pinned `last_error` markers (the strings AC-4/AC-7/AC-8 and the `/config-ui` health list depend on): `GetSecret deadline exceeded`, `ambiguous result`, `all <N> items failed` (design.md@1ed63958:32, :63-64; context.md@1ed63958 sdd-design "Pinned last_error markers").
- FR-1 amendment (operator, design gate r2, 2026-10-22, "APPROVED as synthesized"): a partial failure only logs the skipped count; when EVERY parsed item fails, including a one-item batch, the summary log is emitted first and then the poll raises so the source is marked errored. Reason recorded in the old context: the design behaviour contradicted product-spec FR-1's original "a skipped item alone does not mark the source errored" (adversary O-1, P-03/C-15). The adversary rated O-1 non-blocking; the synthesizer escalated it to blocking because C-15 makes `acceptance.feature` the single source of acceptance truth, so the spec/design contradiction had to be fixed before approval (old context.md@1ed63958:400); fixed by amending FR-1 and appending `@AC-8 @FR-1` (context.md@1ed63958:427-435, :260-265). Why total failure must escalate is not separately recorded beyond that spec-consistency reasoning (reason not recorded).
- Operator standing rule 2026-10-21 (verbatim, context.md@1ed63958:82): "x-trace-id must be propagated as much as possible; no C-03 waiver — request-derived emits/writes use context.WithoutCancel(ctx) (Go) / the inbound metadata (Python/Node), never a fresh background context; only work with no originating request (background sweepers/loops) may mint its own context, and it should still carry a trace id when one is available." Applied here as: request-derived cancel-skip paths keep the inbound `propagation_meta`; `_resume_job` (no request) mints one uuid4 per resumed job.
