# Context: stop-loss-bracket-orders  (archived 2026-08-16)

**Feature**: ./feature.md
**Status**: launched — archived by /sdd-archiver; verbose specs pruned (recoverable via git history).

## Archive Synthesis — 2026-08-16 — /sdd-archiver

**What**: Stop-loss bracket orders built as a persisted, per-order state machine inside `xstockstrat-trading` (`NONE→SUBMITTING→PENDING_VERIFY→ACTIVE→CANCELING→CANCELED/FAILED`), with a protection-window watchdog that can flatten and then halt a broker account if bracket submission cannot be established within a configurable deadline. Alpaca attaches brackets atomically at entry-order submission time; IBKR submits stop and take-profit as a linked two-order array after fill confirmation. Portfolio stores bracket leg IDs as display-only columns, populated asynchronously via a new `order.bracket_updated` ledger event. Delivered as the fourth in a stacked-branch sequence `100→101→023→030`, branching from `feature/position-sizing-engine`.

**Why (irrecoverable rationale)**: A live-capital safety review elevated this to P0 and imposed six requirements including: automated halt must survive a redeploy; protection window must re-arm at every resize transition; flatten must reuse `PlaceOrder`'s existing approval/dedup machinery (not a bare broker call). A `SetConfig` halt fallback was discarded because `StartFillPoller`'s background ticker carries zero propagated metadata, so `SetConfig` returns `PERMISSION_DENIED` in exactly the unattended scenario the fallback exists for (design session round 2). `CancelOrder` is deliberately not gated by the halt check — it is the operator's sole manual de-risk tool once `PlaceOrder`/`ReplaceOrder` are frozen. `max_unprotected_seconds` defaults to 30s (not the P0 review's example of 5s) because IBKR's conid-resolution plus the two-call bracket submission path makes 5s operationally unrealistic.

**Rejected alternatives**: `SetConfig`-based automated halt (trading's background poller carries no `x-access-scope`; returns `PERMISSION_DENIED` in the unattended path). Gate bracket hook on `order.StopPrice` (field collides with STOP/STOP_LIMIT entries' own real broker-trigger price). Synchronous `SetPositionBracket` portfolio RPC (trading already persists leg IDs locally; portfolio display-only fields populate via ledger events, preserving portfolio's "all state sourced from ledger" invariant). Hold halt mutex across DB write (blocks `PlaceOrder` for unbounded DB round-trip; set-map-then-release-then-bounded-DB-write is correct). Reuse feature 100's halt mechanism (100 was only `spec-ready` at design time). Ship `bracket_orders_enabled=true` in prod (pending feature 103 broker-failure-simulator). Two separate protection-window config keys (one global key covers both initial arm and resize transition). Reduce-only carve-out for `ReplaceOrder` on a halted account (no precedent; `CancelOrder` is the operator's tool).

**Scars & gotchas**: `submitOrder` extraction required 11 params (not 6) to satisfy 101's pre-sizing dedup-hash requirement and 023's sizing outputs simultaneously. `pollFills` dedup gate `if newStatus == order.Status { continue }` silently skips a second `PARTIALLY_FILLED` event with a larger cumulative `FilledQty` — changed to also compare `order.FilledQty == brokerOrder.FilledQty`. `TradingRepo` is a concrete type, blocking `flattenAndHalt` full round-trip tests; `s.repo.UpsertOrder` fires before any broker call inside `submitOrder`. Any test that reaches a success path calling `go s.emitLedgerEvent(...)` on a hand-constructed `TradingService` with a nil ledger client will crash the entire test binary — `recover()` cannot catch an async goroutine panic. Fake gRPC clients must use `...grpc.CallOption`, not `...interface{}` — the mismatch compiles but causes runtime panic. `ReplaceOrder` halt gate ordered before `checkTradingStateForReplace`: a zero-value `config.Watcher`'s fail-closed HALTED default would fire first otherwise, masking the halt gate. Alpaca `GetOrder` must also return bracket leg IDs (not just `SubmitOrder`) because brackets can fill asynchronously. `xstockstrat-portfolio` `go.mod` was silently stale after a Dependabot grpc bump; surfaced only by `golangci-lint run --modules-download-mode=mod`. IBKR `SubmitOrder` never sent a `cOID` — a real pre-existing bug discovered because this feature's bracket mechanism requires child orders to reference the parent's `cOID`. IBKR Client Portal Web API uses linked-array bracket submission (`isSingleGroup`/`parentId`/`cOID`), NOT a client-settable `OCAGroup` field.

**Permanent deviations**: design.md said IBKR uses client-settable `OCAGroup` string → shipped linked-array submission with `isSingleGroup: true` and `parentId` = parent `cOID`. Product-spec said `bracket_orders_enabled` defaults to `true` in prod → shipped `false` (pending feature 103). design.md said `trading.proto` bracket field shape was an open risk → shipped with `trading.proto` entirely unchanged; bracket/OCA fields live only in internal `trading.order_brackets` table.

**Cross-feature signal**: 030's per-account `broker_accounts.halted` and feature 100's planned platform-wide halt gate are orthogonal and must both remain — they are NOT the same axis. Feature 100's `/sdd-design` must record 030's `broker_accounts.halted` as prior art. `config.Watcher` hoisting-as-params (hoist the resolved config value as an explicit call parameter) has now converged across four consecutive features (100/101/023/030) as the lightweight testability pattern for single-knob config reads.

**Deferred follow-ons**: Feature 103 (broker-failure-simulator) — required before flipping `bracket_orders_enabled=true` in prod. 023's `ComputePositionSize` return signature widened by 030 to add a 4th return value (current entry price proxy for take-profit formula) during 030's own execution.
