## Archive Synthesis — 2026-09-02 — /sdd-archiver

**What**: Shipped a read-only `GetAttribution` RPC in `xstockstrat-analysis` that aggregates feature 042's already-persisted `analysis.pnl_positions` + `order_snapshots.signals` into per-source win-rate/avg-return/total-P&L, plus an end-to-end additive per-fill `fees` seam (trading fill emit → portfolio `fees_accum` → analysis `fees_total`) so the win test is net of fees. The original producer-side plan (stamp a weight vector on `trading.orders` at `PlaceOrder`, migration 010, cross-schema join) was entirely dropped in design. The fee value is a **hard 0 in production today** — the seam is correct but unpopulated pending a named follow-up.

**Why (irrecoverable rationale)**: 042 already writes exactly 029's inputs, so a producer-side rebuild would duplicate a launched consumer's capture and add two runtime gRPC edges; trading also has no causal weight vector to stamp (`PlaceOrderRequest` carries no signal linkage). FR-3's "highest input weight" was realized as **highest ingest conviction-at-order-time — a deliberate proxy** (no analysis-score→order per-source weight is persisted anywhere); a future reader must know conviction is a knowingly-accepted proxy, not the intended source-reliability-weighted metric. `realized_pnl` is kept gross/authoritative; net is `realized_pnl − fees_total` at read time only — folding fees into `realized_pnl` was rejected because 042's launched pnl page + `GetPnL` surface that figure as gross (mutating it = C-10(b)/C-16 regression).

**Rejected alternatives**: producer-side stamping (dup of 042, no causal weight exists); a **gross-only win definition** (win = gross `realized_pnl > 0`, skip the fee seam) — offered and **rejected under operator decision #2 which required net-of-fees semantics** (this is the load-bearing justification for shipping a fee seam that subtracts a hard 0 in prod); subtract fees into `realized_pnl` (changes 042's gross semantics + diverges from `GetPnL`); aggregate over `pnl_pattern_samples` (stores only `signal_present=true`, drops conviction, double-counts per factor); extend `QueryPnLPatterns` (symbol-scoped ranked-factor, not date-range per-source); a typed proto field for fees (ledger payload is `Struct`, an additive map key is more non-breaking); source Alpaca fees now (EOD-aggregated, not per-fill).

**Scars & gotchas**: The fee seam ships correct but always subtracts 0 — Alpaca/IBKR expose no per-fill fee; US equities are commission-free and SEC/TAF regulatory fees live only in the Account Activities API (EOD-aggregated), which trading does not integrate. So `net == gross` in prod, proven only by unit tests injecting a fee — a future agent must not read the never-changing `net = realized_pnl − fees_total` as dead code or a bug. Portfolio fee-fold is not unit-drivable (`UpsertPosition` uses a concrete `*pgxpool.Pool`, no live-DB harness); `fees_accum` shipped as a byte-parallel of `realized_accum`, compile-checked only. Trading/portfolio `internal/service` and portfolio `internal/repository` are coverage-excluded.

**Permanent deviations**: design pointed the fee stamp at `trading.go:731-732` (submit path, emits `order.broker_submitted`) → shipped at `:1712`/`:1728` (the real `order.filled` emit sites in `pollFills`). design registered the insights nav in `PLATFORM_SUBNAV` → shipped in `NAV_GROUPS` only (`PLATFORM_SUBNAV` is dead post-083).

**Cross-feature signal**: 029 is a template for "read-side aggregation over a prior feature's already-shipped persisted capture" (reinforces C-10(b) no-second-realized-P&L-formula). The dead-`PLATFORM_SUBNAV` / register-in-`NAV_GROUPS` correction recurred across 029/043/167 (already a binding ledger rule via feature 156, fails.md).

**Deferred follow-ons**: named follow-up — source per-fill regulatory fees (SEC §31 / FINRA TAF) from Alpaca's Account Activities API; only then does net-of-fees become real (UI labels P&L "net of fees (broker regulatory fees pending)" until then). `avg_return` is a v1 approximation (percent over `|earliest order_snapshot price × qty|`). Inherited 042 limitations: synthesized-`position_id` window sharing, `realized_accum` inexactness for shorts; `fees_accum` inherits the same window semantics.
