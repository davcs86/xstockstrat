## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: A UI-only `xstockstrat-ui` consolidation that migrated the insights charts onto shadcn's `ui/chart.tsx` (`ChartContainer`), bumped `recharts` v2→v3 repo-wide, extracted a shared `RepeatableRowList` composite, and adopted the shadcn `Questionnaire` primitive for `StrategyWizard`. The shipped outcome diverged materially from the approved design in the Questionnaire work: the primitive turned out architecturally unable to model the wizard's externally-owned step index, so Steps 2–4's "native shell" was abandoned and Step 1's sub-screen nav was rebuilt from plain `Button`s. Execution also surfaced a genuine pre-existing product bug (edit-mode strategy-ID gate) latent because no prior test path exercised it. All 15 steps landed green (43/43 e2e).

**Why (irrecoverable rationale)**: The `Questionnaire` primitive derives `Next`/`Previous`/`Submit`/`Progress` visibility purely from `Item`s registered inside the same `Root` (`Next` = `total>1 && !last`, `Submit` = `total>0 && last`). Because the wizard renders one step's content at a time and owns its own `step` state, any naive shell `Root` registers exactly one (or zero) items, so the primitive's own nav is structurally wrong — it can only track the real 4-step model via the controlled `item`/`onItemChange`/`FormData` answer model that the design explicitly forbade adopting for the outer shell. This is why shipped code uses plain buttons and a zero-item `Progress` Root, contradicting the literal design prose.

**Rejected alternatives**:
- Bump `recharts` vs. hand-author `chart.tsx` against installed v2 — bump chosen (user override) because a future `apply --preset` would silently overwrite a hand-authored file with the registry's v3 version anyway; hand-authoring just carries that overwrite hazard as permanent debt.
- Replace `lightweight-charts` with a recharts candlestick — rejected: no first-party OHLCV geometry, 3 shared `useCandlestickChart` consumers, e2e coupled to the `.tv-lightweight-charts` injected DOM class (already ledgered insights.md:1309).
- Flatten the wizard to 7 top-level screens — rejected to keep the outer "Step 1 — Identity" heading valid (12 e2e assertions) via nesting (already ledgered insights.md:1304).

**Scars & gotchas**: The `Questionnaire` primitive cannot represent an externally-owned multi-step index without its controlled `item`/`onItemChange`/`FormData` model; a lone-item `Root` hides `Next`/`Previous` and shows `Submit` instead (caught by source-inspecting the installed `@shadcn/react@0.3.0` compiled dist before writing broken code). `@shadcn/react@0.3.0` declares `peerDependencies: react >=19` but the repo is React 18.3.1; verified safe by grepping the compiled `dist/questionnaire/index.js` for React-19-only APIs (`use()`/`useActionState`/`useFormStatus`/`useOptimistic`) — zero matches; the `>=19` range is a demo-app default. `npx shadcn@latest add chart` silently reset `package.json`'s `recharts` from the live-verified `^3.10.1` back to the registry item's `^3.8.0` (reverted), and re-prompts to overwrite `button.tsx` (must answer `n` to preserve the `buy`/`sell` variants). `ChartTooltipContent`'s `payload` prop type (`Payload[]`, needs `graphicalItemId`) does not overlap loose custom `TooltipEntry[]` shapes — required a cast through `unknown`; `next lint` passed, only the full `pnpm build` type-check caught it (both verification commands are load-bearing). The recharts v3 bump's real code change was tiny — one mechanical `CartesianGrid xAxisId={0} yAxisId={0}` in the two existing charts (already ledgered insights.md:1314); `EquityCurveChart`'s `Scatter` uses `data`/`dataKey`/`shape`, not the removed `points` prop.

**Permanent deviations**: design said Step 1's 4 sub-screens each keep their own `Questionnaire.Next`/`Previous` via the native model → shipped uses a plain-`Button` `IdentityNav` helper for sub-screen nav (keeping `Questionnaire`/`QuestionnaireItem` only for fieldset semantics) plus a defensive `onSubmit={e=>e.preventDefault()}` → because a single-item `Root` permanently hides `Questionnaire.Next` and renders `Submit`. design said Steps 2–4 get a minimal `Questionnaire.Root`/`Item` shell and FR-11 renders `Questionnaire.Progress`/`Next`/`Previous`/`Submit` → shipped wraps Steps 2–4 in no shell Root at all, and `Questionnaire.Progress` wraps a zero-item Root whose `children` prop drives all rendering from the outer `step`/`STEPS` state; the existing `Back`/`Next`/`Create Strategy`/`Save Changes` buttons were left untouched → because the primitive's registered-item architecture cannot reflect an externally-owned 4-step index without the forbidden controlled model. Both used the implementation spec's own built-in escape hatches, but net Questionnaire adoption for Steps 2–4 is `Progress`-only.

**Cross-feature signal**: Third instance of the "verify a fast-moving external dependency right before use" discipline (trader-chart-panel, then this feature's `recharts` and `@shadcn/react`) — a stronger variant: verify against the installed/compiled source or declared peer range, not just the docs/registry, since both the Questionnaire nav architecture and the React-19 peer range were only knowable from the shipped package's own dist.

**Deferred follow-ons**: `useCandlestickChart.ts`'s hardcoded dark-theme hex literals (`#22c55e`/`#ef4444`/…) → swap for the app's CSS custom properties for partial theming consistency (out of scope). `StrategyWizard`'s `canAdvance` `step===1` branch is now dead code (outer nav row hidden for `step===1`) but was deliberately left in place as out-of-scope for Step 13's narrow fix — a future touch of this file can remove it.
