**What**: Release N+1 of feature 224 (`private-by-default-templates`), launched 2026-10-14 via promotion PR #1242 (commit `9def6259`). It made the ownership model fail-closed in analysis, indicators and ingest and contracted 224's expand-only schema. Headerless owner-scoped calls now fail `UNAUTHENTICATED` (analysis 22 RPCs, indicators 10, ingest 7, each behind an `owner_scoped` decorator, with descriptor-walk completeness tests). An inbound `x-user-id: system` without a SAN-bound grant fails `PERMISSION_DENIED`. The indicators `analysis` formula-read bypass and the ingest slug-holder / body-`user_id` fallbacks are gone. analysis `027_contract_owner_dimension` (backfill + `SET NOT NULL` on `backtest_runs.user_id`, drop `strategy_scores`) and ingest `014_contract_signal_ownership` (drop N-1 trigger/function/`signal_dedup_keys`) shipped with raising down-files, plus a `db-migrate.sh` contract-floor dirty-recovery guard (`scripts/migration-dirty-guard.sh`) and a `QueryPnLPatterns` owner filter that was not in the original story.

NULL/unowned positions are excluded.

This is by design (product-spec FR-1 addendum); the spec-time drain fix realises it. A skipped system-owned unit is not a bug.

**Scars & gotchas**:
- Design said live-loop drains sit under the per-pair `try`; that `try` wraps only `_eval_pair`. The drains run from the record-building loop (`live_loop.py:370-382`) with only the cycle-level `except` (`:325-328`) above them, so one ownerless strategy would have aborted every owner's cycle. Caught at /sdd-spec, confirmed by impl-spec review; Step 6 builds `owner_metadata` before each drain's inner `try` and adds a per-row `except ValueError: continue` in `_run_cycle`. Round-3 fix B is the same class: the template-sweep `meta = self._saga_sweep_meta(...)` was built before the per-intent `try` (`servicer.py:5657-5658`), so it was moved inside so `schedule.advance` still runs.
- The decorator must `return None` after `await context.abort(...)`: test contexts use a non-raising `AsyncMock` abort, so without the `return` the body runs and the gate only appears to work.
- ingest grants are per RPC: the decorator passes `fn.__name__` and bodies use `_owner(context)` backed by a `_CURRENT_RPC` contextvar, so a body cannot re-resolve under a different grant key (tests: inside QuerySignals `_resolve_owner` is called with `"QuerySignals"` by both gate and body; `analysis-system-read` + SAN on IngestSignal -> `PERMISSION_DENIED`).
- golang-migrate marks a version dirty *before* running a down, so a raising down leaves the schema dirty at the expand version; `db-migrate.sh` dirty recovery was `force 0` (replays non-idempotent pre-224 up-files) and `psql -f` exit checks are vacuous without `ON_ERROR_STOP`. Recovery for both reachable dirty states is `migrate force <n-1>` (use raw `migrate`, never `db-migrate.sh force`, which forces to the highest version). `db-migrate.sh` has no `down` command; refused downs are reachable only through raw `migrate`.
- `set_config('lock_timeout', ..., true)` must sit *outside* the exception block in 027's DO block (a `set_config` inside a failed subtransaction is rolled back), and the prior value is restored after the `LOCK` so later UPDATE/ALTER/DROP queue normally.
- CI `migration-rerun` bind-mounts the repo over `/repo` (`ci.yml:657`), which would hide a missing `COPY scripts/migration-dirty-guard.sh` in `scripts/Dockerfile.migrate`; hence the no-mount smoke step `docker run --rm --entrypoint test ... -x /repo/scripts/migration-dirty-guard.sh`.
- `ingest-013.sql` ended in an N-1 trigger probe that cannot pass after 014; removing it must ship in the same push as Step 4 or `migration-rerun` is red.
- indicators upsert/update SQL was inline (`formulas_repository.py:144-158`, `:226-234`); it had to be hoisted to `_UPSERT_SQL` / `_UPDATE_SQL` module constants (closing `"""` at column 0) so the awk-extracting AC-11 harness and the routing test could reach it. The harness fails loudly if a constant's highest `$n` differs from the supplied param count.
- Test churn is large and must be classified before fixing: rule (i) tests asserting removed behaviour change or are deleted (ingest: 9 deleted, covered by per-RPC headerless -> `UNAUTHENTICATED` completeness cases); rule (ii) incidental contexts gain `OWNER_HEADERS`. Red-run counts: analysis 19 failed / 1006 passed, indicators 24 failed / 252 passed (+ 7 failed / 261 passed and 1 collection error after the `is_public` change), ingest 37 failed / 299 passed. Several ingest tests had been green on an `UNAUTHENTICATED` abort for the wrong reason (fails.md feature 074 class).
- `test_strategy_templates.py` imports `test_owner_header_guard.py` at module load, so helpers from the former must be imported inside the one test that uses them (top-level import is circular).
- AC-5, AC-7, AC-10, AC-15 are characterization tests, green on first run by design; AC-17 and the sweep needed no code beyond Steps 6/8. Not a TDD-gate failure.
- No database was started during execution (hard constraint): migration steps 3-5 and 16 were verified offline (shellcheck/shfmt, libpg_query/pglast parse, guard matrix against real dirs); the first live proof is CI `migration-rerun` on the integration PR. `envsubst` was absent on the host, so the `render-migrations.sh` render was not exercised locally.
