## Archive Synthesis — 2026-09-02 — /sdd-archiver

**What**: Shipped Web Push as a third, disjoint, best-effort fanout channel in `xstockstrat-notify` (a `WebPushDispatcher` mirroring the feature-020 `FanoutDispatcher`, wired via a second `queueMicrotask` in `emitAlert`), plus PWA plumbing (`public/manifest.webmanifest` + a hand-written `public/sw.js` + icons) making `xstockstrat-ui` installable, and a Settings-group `/accounts/notifications` enable toggle. Backed by a `notify.push_subscriptions` table, additive `Register/UnregisterPushSubscription` RPCs, a `notify.push.min_severity` config seed, and VAPID keys wired as deploy secrets. Push is inert in production until an operator sets the VAPID GitHub Actions secrets.

**Why (irrecoverable rationale)**: The dispatcher is deliberately **disjoint** (not an extension of `FanoutDispatcher`) because the two share no state — fanout holds an in-memory dedup Map + stateless sends; push holds DB-backed subscriptions + a prune side-effect. That structural disjointness is the guard that keeps every `notify-external-fanout` `@AC` (C-16) intact. Unregister is **by endpoint only** (no `user_id` in the delete) because the register upsert can reassign an endpoint to a new user, so a user-scoped delete would silently no-op and fail AC-3 (accepted risk: any valid session could delete a subscription by replaying an endpoint — worst case a user loses a push they were unsubscribing anyway). VAPID subject is validated at startup fail-loud/disable — a keys-present-but-malformed subject logs ERROR once and disables, rather than throwing per-send where the top-level catch would swallow it to WARN forever. The push send loop is deliberately **sequential** (one row per installed device, already off the hot path in a microtask) — bounded-concurrency was the considered-and-rejected fork. No push content-dedup in v1 (rely on OS `tag`-coalesce). The VAPID public key crosses server→browser via a `VapidKeyContext` copying the `AgentUrlContext` force-dynamic pattern, never `NEXT_PUBLIC_*`.

**Rejected alternatives**: extend `FanoutDispatcher` with a push channel (forces DB-backed state + prune into a stateless class; any edit risks the C-16 fanout AC); reuse fanout's content-hash dedup (a private method; sharing couples the two dispatchers for low-harm OS-coalesced duplicates); `Unregister{endpoint,user_id}` + a user-scoped DELETE (reassigned endpoints make it silently no-op → fails AC-3); a dedicated `/accounts/api` NotifyService BFF surface (duplicates one-line `forward()` registrations for zero isolation gain); `next-pwa` / a build-time SW toolchain (a push-only SW is a small hand-written file).
