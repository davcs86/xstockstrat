## Archive Synthesis — 2026-11-18 — /sdd-archiver

**What**: A watchlist symbol that stays unservable (feature-282 meaning: `NOT_TRADABLE` or `OTC`) for the confirmation window (config `marketdata`/`assets.delisting_confirmation_trading_days`, default 5 trading days, bounds [1, 30]) is flagged delisted in a new platform-wide `marketdata.symbol_profile` table (migration `010`; companion `watched_symbol` union table). Marketdata's asset-load hook is the only decider (reset, start, flag, recover). Portfolio pulls on its existing signal-prune tick (`SyncWatchlistDelistings` / `AckDelistingAlerts`), removes flagged symbols from system-managed lists (never-waiting deleter beside the 281 one), sends one at-least-once alert per symbol and marks bindings `delisted` on every watchlist RPC; `ListAllWatchlistSymbols` drops them; analysis skips them. Backfills report per-symbol `empty|skipped|failed` (`symbol_results` on both marketdata responses and on `BackfillJob`, ingest migration `018`); a flagged symbol's source error is `skipped`, not `failed`, so a job no longer ends `PARTIAL` for it. Agent tools and the `/insights` row show the state. Launched 2026-11-17 (`**Launched date**`; integration PR #1574, squash commit `4f14f897`; promotion PR #1576, `37d41f42`). Origin: the 2026-11-16 DO-staging fundamentals backfill that feature 348 diagnosed (below).

- **Single decider is the design's spine.** Rounds 1–2 had portfolio's sync and marketdata's asset-load hook both writing profile state, which produced a stream of ordering/race objections (O-9, O-10, O-24, O-27). The operator's round-2 steer (debate D-19) made the hook the only writer and reduced the sync to supplying the watchlist union, claiming and acknowledging alerts and reading flagged state; the persisted `watched_symbol` union (D-20) was the price, so that a load alone can start a row (AC-21) and the union survives a restart. (Generalized in insights.md:4635-4638; not repeated.)
- **Pull, not push (R-1).** Portfolio already calls marketdata; marketdata → portfolio would be a new edge against the dependency graph (insights.md:423), need `PORTFOLIO_ENDPOINT` in three deploy files and an `authz.go` grant, and require retry state for a portfolio outage. Classification stays server-side in marketdata so a caller cannot forge unservability.
- **Why the flag alert is sent by portfolio, after removal (spec D-12 / debate D-10, operator at round-1 gate).** Marketdata cannot know which system-managed lists a symbol was removed from and would alert before anything is removed (O-3). Once-only comes from a conditional update on the profile row, delivery is at-least-once via claim → 10-minute lease → separate `AckDelistingAlerts` (D-18, D-22, operator at the round-2 gate). Acknowledgement is a separate RPC, not a field on the next sync, because the lease would have to exceed the prune interval, which can be 86 400 s (R-13). Removal is tied to alert state (nothing is removed while `PENDING`; only `CLAIMED`/`REDELIVERY`/`REPORTED` and "unservable in the handler's current asset set" remove), because an untied removal could report "removed from 0 lists" in a burst, a SKIP LOCKED skip or a second instance (O-31) and a relisted symbol's fresh signal entry could be removed before the hook recovers it (O-33).
- **Fixed values and why (operator approved all five at the round-3 gate as invariants, not config keys — F-07 precedent, P-04):** hook limit 30 s; flag-alert lease 10 minutes; sync/ack/per-alert-send deadline 15 s (not the 500–4000 ms insert-path key `portfolio.marketdata.servability_timeout_ms`, wrong budget for a background write of up to 20 000 rows — R-14, O-25); 20 000 symbols per sync (about 1.5× the roughly 13 500-symbol active universe, since inserts are servability-gated; a constant in marketdata only, so portfolio carries no cap and takes the error path on `InvalidArgument`); 100 claims per sync (O-36: 1000 alerts could outlast the lease and delay the 281 prune). The operator acknowledged at the round-4 gate that the approved 15 s value also bounds each alert send and that portfolio stops sending at the first failed alert, the rest re-sent after the lease.
- **Window arithmetic.** The hook's day is the New York calendar date of now (`DayStart`), a trading day iff `IsTradingDay`; the existing `SessionDate` is not used because it adds 6 h and would turn a Friday-evening load into Saturday (O-49, D-26; tested at 17:59 and 18:01 New York). The cutoff is `DayStart` stepped back N−1 times with `PrevTradingDay`, computed in Go and re-checked inside the H4 statement (a per-row trading-day test cannot run in SQL, and a precomputed symbol list is unsafe with a second instance — O-57, D-29). The stored reason is the one observed when the row started; H4 does not refresh it (O-55). The calendar is rule-based and moved to `packages/proto/marketsession` (the `pnl/` carve-out precedent); one-off closures are not modelled (R-3: Alpaca `/v2/calendar` adds a client and failure modes for one day of precision).
- **Empty-union and reset guards come from the ledger.** A reset of unflagged rows that left every watchlist never runs on an empty symbol list (D-13, insights.md:4308); an empty, error-free union clears `watched_symbol`, but with an empty union the hook starts nothing, resets nothing for leaving watchlists and flags no unflagged row (D-20). A stale cache after an RPC error removes nothing (D-12, O-17).
- **Backfill outcome model.** `failed_symbols` keeps today's meaning and never holds a skipped symbol, so ingest's PARTIAL rule and the 8-key webhook payload (334 `@AC-30`) stay unchanged (R-6). Only an error from the data source turns a flagged symbol into `skipped`; a failure writing to our own DB stays `FAILED` (D-9, O-12; typed `backfillSourceError` at `FetchHistorical` in fundamentals and at `src.GetBars` in bars, never at `InsertBars`). Ingest stores `symbol_results` per chunk as JSON text (asyncpg has no JSON codec here) with replace-on-attempt, merged at read failed > skipped > empty (D-29).
- **Deliberate non-goal — analysis `GetWatchlistReadiness` is unchanged and still evaluates flagged bindings** (impl-spec review round 1, W23, impl-spec:1401: left unchanged and documented; design authorised only the two drains `_drain_watchlist_bindings` and `_drain_watchlist`). The UI replaces that cell with the delisted badge and passes only unflagged pairs to `useWatchlistReadiness`, so it is not an oversight.
- **Accepted limit that looks like a bug — a held flagged symbol is valued only within the lookback.** FR-6 "still valued from its last stored close" holds only until the last close is older than `marketdata.last_close_lookback_days` (21); after that offline valuation reads `MARK_SOURCE_NONE` (existing behaviour, `offline_valuation.go:287-300` per recon, not caused or fixed here).
- **Feature-291's bar-ingest dead-symbol hold (`stream.bar_ingest_backoff_ms`) is deliberately unchanged** (product-spec Out of Scope); it is a different state from the 352 flag.
- **Expiry rows of removed symbols are deleted with a plain `DELETE` under the parent lock, not `SKIP LOCKED`** (O-30/D-17: SKIP LOCKED there would be dead mechanism). insights.md:4638 says a new deleter copies the 281 deleter's lock order and SKIP LOCKED shape "exactly"; that applies to the parent and binding locks, not the expiry-row delete — do not "fix" it.
- **Operator did not pursue stored-data deletion or auto-removal from user lists.** FR-4 keeps and marks a flagged symbol on user-created lists, and (R-10) a replace-all `UpdateWatchlist` (including a name-only agent update that re-sends the stored symbols) still drops it into `refused_symbols`.
