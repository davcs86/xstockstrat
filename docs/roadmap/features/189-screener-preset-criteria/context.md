## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: UI-only control on `/insights/screener`: a controlled shadcn `Select` loads the typed preset "Fundamentals Signal" into the criteria builder through the existing `setCriteria`. Five rows: four rank-only (`pe_ratio`, `pb_ratio`, `roe`, `debt_to_equity`) plus an `eps > 0` hard filter — a static copy of the backend fundamentals-scoring constants. No proto/config/migration/backend change. The code merged (PR #1139, `173bab6`) before its spec existed; only the e2e (Step 4) was genuinely authored in the execute phase.
**Why (irrecoverable rationale)**: Preset thresholds are the *bad endpoint* of each `_BUILTIN_BANDS` band (35 / 5 / 0.05 / 2) — where the backend's linear interpolation returns 0.0 — so they are rank-only cut-offs and the screener's own normalization does the scoring; deliberately not the good endpoints (10 / 1 / 0.25 / 0.3). `eps` is a hard filter because the backend uses it as a binary gate (`1.0 if f.eps > 0 else 0.0`, `fundsignal_loop.py:395-396`). The comment at `screenPresets.ts:12-13` names the bad endpoint but not why, and carries no "keep in sync with" pointer.
**Rejected alternatives**: Factory function per preset (static constant + shallow copy at the call site is simpler; also tree-shakeable). Separate `PresetSelector` component (~15 lines tightly coupled to the page's `setCriteria`; no reuse). Uncontrolled Radix `Select` (keeps its own selection so the same preset cannot be re-selected). Confirmation dialog on load (reversible by editing). Scope boundary with no rationale recorded: the preset populates criteria rows only, never `symbolsText`.
