## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: Offline (`BROKER_TYPE_OFFLINE`) accounts now get broker-parity P&L. Trading persists per-order cumulative `fees`, freezes a per-snapshot lifetime carry in a new `offline_snapshot_headers` table, and widens its absolute `account.positions.synced` payload (fees, carry, a 10-day `recent_fills` list). Portfolio alone owns the NYSE calendar (`internal/marketsession`) and values every read at read time through one shared step (`valueRead` → `valueOffline` / `applyAccountPnL`): broker-style Day P&L, Total P&L and return % over Σ|cost_basis|, a stale-flagged last-close mark (`MarkSource`), and a platform-wide short-% fix. Marketdata `BatchGetBars` gained an opt-in `allow_partial` flag. Surfaced on the four `/trader` surfaces and the MCP agent tools (no new tool; count stays 45). Integration commit `45356952` (#1266, per `git log`), promoted in #1271 (`107761265f`, feature.md:23). All 54 `@AC-*` are already promoted into durable suites.

**Why (irrecoverable rationale)**:
- Read-time computation is forced, not preferred: the session rolls over with no event, offline per-session fill data never reached portfolio, and a portfolio→trading read edge would create a boot cycle (trading→portfolio already exists). So trading pushes raw, calendar-free, bounded inputs on the existing absolute-sync payload and portfolio interprets them where the clock lives. Trading cutting fills by session at emit time was rejected (couples producer to calendar, its clock, and the cutting-logic version). (context.md design Phase 0 R1; round 1)
- Lifetime realized rides alongside the feature-163 since-snapshot figure instead of replacing it: explicit operator override of 163's rejected alternative "carry realized forward across snapshots", but 163 AC-14 (snapshot resets since-snapshot to 0) is preserved. (Session 2026-10-19 sdd-story)
- Total P&L uses LIFETIME realized (round-3 review N1, reverses the round-1 basis) so Total P&L does not drop when a snapshot is taken.
- Return % denominator is open cost basis `Σ|cost_basis_i|` (absolute value so a mixed long/short book never nets to a 0 denominator); no capital-base ledger exists.
- `GetPnL` and the persisted `portfolio.snapshots` series are deliberately untouched (cashless MTM, fails.md 172; feature 229 `@AC-5` UNAVAILABLE on missing quote preserved). Aggregates/insights offline P&L was offered at story time and NOT selected.
- Operator chose "fallback wins" (D-1): for offline positions only a two-sided quote from the reference session counts as live; everything else falls to the daily close within `portfolio.marketdata.last_close_lookback_days` (default 21, bounds 5..60). Why "fallback wins" (implementation-spec.md:61-73): FR-5 provenance stays honest (a stale close is never labelled `QUOTE`); no second close lookup is needed; 231 `@AC-1`/`@AC-13` values are preserved because the bar-derived close is the same stored `ohlcv` row (now labelled `MARK_SOURCE_LAST_CLOSE` with its real date); it extends the operator's FR-5 sign-offs over 229/178 to 231. The alternative that lost: capping the offline fallback at `marketdata.quotes.mark_close_max_age_hours` (default 168h, impl-spec :52-53,76-77) — it would have preserved 231 `@AC-6` but narrowed the operator-chosen 21-day lookback.
- Six fixed invariants stay code constants, not config keys (design.md:383-390, approved at the round-5 gate; context.md:282-283 calls them "five fixed invariants plus a coalescing interval"; feature-229 precedent of fixed quote-retention invariants, F-07):
  - `barsPartialMargin` 250ms: reply headroom inside the caller's own deadline, not a policy; operator rejected a configurable margin and `marketdata.bars.batch_timeout_ms` (round 2).
  - `recent_fills` window 10 days: must cover the longest NYSE session gap (~4.5 days) plus slack and only limits payload size; portfolio's calendar decides what counts, too small just drops the oldest fills.
  - `pnl.QtyEpsilon` 1e-9: float-equality tolerance that already existed as three literals (`pnl.go:77,84,89`); exported, not tuned.
  - Session calendar (NYSE rule holidays, Good Friday, 09:30-16:00 ET): a fact of the exchange, not an operator choice; its gaps are limitation 3.
  - Bars coalescing interval 1 minute (`end = now.Truncate(time.Minute)`): cache-key granularity giving a stable singleflight key so concurrent reads share one cold fetch; the bar it can miss is at most one ingest interval old.
  - `SessionDate` +6h offset: encodes how stored bar timestamps map to session dates; pinned by the blocking golden test, not tuned at runtime.
  Homes: marketdata, trading, portfolio (x3) and `packages/proto` CLAUDE.md respectively.

**Rejected alternatives**:
- Portfolio→trading RPC for fills — boot-order cycle.
- Trading computing Day P&L at emit time / putting the calendar in trading or `packages/proto` — couples producer to the clock; calendar lives in portfolio.
- `BatchGetLatestPrice.prev_close` for previous close — not session-aware (second-newest 1d row, shifts depending on whether today's bar is stored; recon R3).
- Constant lookback — replaced by the config key; deriving previous session `P` from the batch's own bars — rejected, `P = PrevTradingDay(ref)` from the calendar.
- Universal `BatchGetBars` degradation, `unavailable_symbols`, an analysis consumer change, and a `marketdata.bars.batch_timeout_ms` key (round 2) — would have starved analysis's 400-day cold fetches and regressed `@AC-1 @feature-185`; replaced by opt-in `allow_partial`. Also rejected: one singleflight key for both modes (strict closure on a cancellable ctx would take down partial waiters), per-waiter `DoChan` deadlines, a configurable 250ms margin.
- Detached no-deadline partial fetch "bounded by the 30s HTTP timeout" — premise false: `GetBarsMulti` keeps paging (`alpaca/client.go:411-454`), so no-deadline partial runs on the caller's ctx.
- Documenting the `filled_at` default ("defaults to now") instead of preserving the stored value on re-confirm (design.md:458) — preserving designs out the frozen-window double-count (an un-confirm/re-confirm pair moving a frozen-window order into the current window) and keeps `@AC-10 @feature-157` intact.
- `PermissionDenied` gate on `GetPortfolio` (leak fixed by user-scoping every account-keyed read, fields omitted for non-owned accounts, so brand-new accounts still render).
- `FAILED_PRECONDITION` on confirms inside the frozen snapshot window — kept feature-163 behaviour (accept and ignore).
- Clearing fees or `filled_at` on un-confirm (operator, rounds 3-4) — both kept internally, hidden while NEW; masking in the handler or cache (handler gets the shared `s.orders` pointer, masking there corrupts it) — masked in the service on clones/fresh scans at 5 live response sites.
- Deriving the carry from rows without a header table; recomputing later carries when an `as_of` is edited (known limitation 12); a portfolio-side close-price memo; re-emitting syncs at boot (limitation 2); sharing the `DISTINCT ON` fragment with the feature-206 `NetFilledQtyBySymbol` query.
- Bar-date mappings "+12h UTC" and "NY date of t" — only "NY date of t+6h" maps the real stamps (00:00 America/New_York = 04:00Z EDT / 05:00Z EST).

**Deferred follow-ons**:
- Account-level figures (Total P&L/%, lifetime realized, fee totals, net realized) are UI-only; no agent tool reads account-level `Portfolio`.
- Out of scope and still open: offline realized in the `GetPnL` aggregate / `/insights` P&L Patterns (`portfolio.position.closed` for offline closes); cash/capital ledger; dividends/corp actions/FIFO lots/options; fees on snapshot baselines; per-position realized P&L history or a P&L time series (product-spec.md:184); the out-of-repo `trade-confirm-ingest` skill update for the `fees` argument; `StreamPortfolioUpdates` carries no offline P&L.
- Accepted limitations worth remembering (design.md §12:406-427): (1) adjusted bars: with `adjustment=all` an ex-dividend/split day can carry a re-adjusted `pc`, offline quantities are not split-adjusted; (2) no re-emit at boot; (3) early closes/one-off closures not modelled; (4) one `filled_at` per order — partial confirms on different sessions need an explicit `filled_at`, and orders un-confirmed before deploy carry the un-confirm time; (5) a snapshot whose `as_of` is inside or after the reference session counts that session's fills as overnight shares; (6) after the close the reference bar can lag one ingest interval, and the quote mark is used until it arrives; (7) torn read between positions and offline-state writes (written separately under `positionsMu`, reads don't take it); (9) symbols with no stored bars are fetched cold on every read within the budget, coalesced per minute; (10) a coalesced waiter with a shorter deadline can time out at portfolio, treated as a bars failure, and a no-deadline partial leader can hold up a deadline-bound waiter — safe only because portfolio always sends a deadline (design.md:260); (11) `GetPortfolio` Equity is Σ market value while broker Day P&L is on broker equity — product-spec OQ-8 (product-spec.md:308-312) asked design to settle it and design accepted the mismatch; (12) later snapshots' carries are not recomputed when an earlier non-latest snapshot with the same `as_of` is resubmitted; (13) LAST_CLOSE risk fields use the stale close; (14) the `GetPortfolio` aggregate leaves realized/fees unset, so the UI sums `ListPortfolios`; (16) a symbol with some stored bars is never backfilled (ingester looks back only 48h `minIngestLookback`; cold = zero bars), so a missing previous-session bar stays missing and overnight terms are 0.
