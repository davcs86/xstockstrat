**What**: SEV-2 bug (debt-radar D-12, D-24; defect report `docs/reports/2026-10-21-portfolio-snapshot-surface-defect.md` (pruned 2026-11-04; git show 9892b610:docs/reports/2026-10-21-portfolio-snapshot-surface-defect.md)). `broadcastSnapshot` now fans out only to subscribers whose owner `userID` equals the snapshot owner (strict equality, an empty owner receives nothing), and the gRPC `StreamPortfolioUpdates` adapter rejects an empty `x-user-id` with `InvalidArgument` before it subscribes. The two stream paths share one `streamSnapshots` helper behind an unexported `snapshotHub` interface. The never-called `StartSnapshotWriter` was deleted and `portfolio.snapshot.interval_minutes` retired by config migration `034_retire_portfolio_snapshot_interval`. Merged as #1345 (`9bd923f3`), staging-verified, launched 2026-10-30 via #1368 (`df521ff5`). No proto change; no UI/agent consumer exists.
**Why (irrecoverable rationale)**:
- Filtering was put at the producer (`broadcastSnapshot`) rather than the handlers so every future consumer inherits isolation; the producer was already live per fill (`portfolio_service.go:383` at HEAD) and only "leaked to nobody" because no consumer subscribed. The leak was latent, not absent.
- D-12 resolved by deleting (branch b), not wiring (branch a): wiring needed a new all-users query, a clock seam and periodic PgBouncer writes (F-06), and nothing consumes the rows; periodic rows would also have forced a decision on `GetSnapshot` semantics, since insights 2026-08-26 (feature 157) relies on it being an "absolute snapshot" (`recon.md@1ed63958:186-187`, `:224-225`; `old context.md@1ed63958:162`). Operator signed off the @AC-4 deletion and @AC-5 rewording at the design gate r2 (2026-10-22, "APPROVED as synthesized").
- Triage recommended `quick` design depth and said to escalate to full if design chose the delete branch, since that adds a config-service migration and a second service (`old context.md@1ed63958:38-40`); the delete branch was chosen, which is why design ran full rounds (r2 gate 2026-10-22).
- The operator's standing 2026-10-21 decision kept `x-trace-id` propagation with no C-03 waiver: persist and emit stay on the fill ctx; the only background path was deleted rather than re-contexted.
**Rejected alternatives**:
- Filter in the handler instead of the producer — lost: every user's snapshot would still reach every channel and each consumer would re-implement the check.
- Trading-style empty-means-all filter (`trading.go` `sub.userID != "" && ...`) — lost: portfolio needs fail-closed and has no internal cross-user subscriber (`design.md@1ed63958:143-144`). Trading's version is documented as intentional for trusted internal callers (`services/xstockstrat-trading/CLAUDE.md`, `StreamOrderUpdates` exception).
- Exported `(*PortfolioService) SubscriberCount()` as a test seam — lost under C-18 (production symbol that exists only for tests); the unexported consumer-side `snapshotHub` + test-local fake gives the same "zero Subscribe calls" proof.
- Handler tests on `newQuoteSvc`/a real service — not buildable: `newQuoteSvc` is in a `package service` _test file, `NewPortfolioService` dials mTLS deps, `broadcastSnapshot` is unexported, a bare struct panics on its nil map.
- Nil-service panic as the "never registered" proof — lost: on RED it crashes the whole `internal/handler` test binary instead of failing one named test.
- `subKey any` helper parameter — lost under C-18; `subID string` built after validation suffices.
- Defense-in-depth `snap.PortfolioId == userID` check inside the helper — lost as DRY/YAGNI.
- Deleting the unmounted Connect `StreamPortfolioUpdates` and dropping @AC-3/@AC-6 — lost as scope creep; FR-3 was operator-fixed and the shared helper makes keeping it cheap.
- Reserving migration 033 with a one-sided ">= ours" gate — lost: 033 was the likely landing spot for the 244/248 `032` double-claim, and a one-sided gate misses 264 merging first and silently skipping peers' lower numbers.
