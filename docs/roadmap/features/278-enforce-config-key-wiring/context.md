## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: A zero-dependency Node check (`scripts/check-config-wiring.mjs` plus the stdlib-`ast` helper `scripts/config-wiring-py-reads.py`) joins the config-migration stored set against every Go/Python/TS reader and reports four finding kinds (`form-mismatch`, `seeded-unread`, `read-unseeded`, `dynamic-read`). State lives in `scripts/config-wiring.json` (`findings` baseline, `registry`, `policy`). CI job `config-wiring` is wired into `ci-gate`; `/sdd-execute` Phase 3 (step-time mode) and the all-steps-done / integration-PR gate (`--final`), an `/sdd-review` B2 row and the `/sdd-story` declared-key format enforce it; `docs/patterns/config-governance.md` has the rule section. 19 steps, 47 tests at completion. The shipped baseline is 124 entries, all owned `feature 278` (19 `form-mismatch`, 5 `seeded-unread`, 100 `read-unseeded`, 0 `dynamic-read`), plus one non-baselined `REPORTED:` env-scoped line.

**Why (irrecoverable rationale)**:
- Origin: the operator demoted `277-fix-ingest-seeded-config-keys` at its round-4 design gate and asked for a follow-up that enforces, in the execution/validation loop, that every new config key is actually implemented as planned (old context.md@1ed63958:12). The ingest defect report was then marked `wont-fix` (ref `feature:277-fix-ingest-seeded-config-keys`), so the 18 known findings had no open owner; they lived only in 277's `context.md` and FR-4's baseline had to name 277 or 278, never a defect report (old context.md@1ed63958:19).
- Baseline, not fix-first: nothing else would fix the existing findings (277 canceled, report wont-fix), so FR-4 baselines them with a mandatory owner; the check is read-only and never heals or rewrites a seed (product-spec.md@1ed63958:75-79).
- Stored form is the live snapshot key `values[row.key]` (the migration `key` column, raw), never normalized, so a bare seed read dotted is a `form-mismatch` (product-spec.md@1ed63958:76).
- Gate shape: a single completion-time `--final` instead of per-key "last step touching K", because impl-specs already written (243, 244, 261) cannot satisfy step-body quoting and F-09 forbids editing step bodies; step time checks only `form-mismatch`, `dynamic-read`, unmodelled-rewrite and non-missing-side declared-key findings, and missing-side legs are `PENDING:` until the completion gate (design.md@1ed63958:28, :43).
- Accepted tradeoff of that shape: the completion-gate `--final` finds a missing reader or seed only at the last step, so a wrong-side defect can survive several steps; the step-time `form-mismatch` and `dynamic-read` checks bound it (design.md@1ed63958:61; old context.md@1ed63958:124, :163).
- Gate placement: `config` and `migration` steps skip the TDD gate (`.claude/skills/sdd-execute/SKILL.md:285-288`), so for them the wiring check is the only gate; @AC-10 therefore needs detection of a migration inserting into `config.config_values`, not the step category alone (recon.md@1ed63958:104).
- Language choice: Node because `node --test` already runs in CI (`ci.yml:723-724` at spec time) and bash 3.2 cannot parse three languages (design.md@1ed63958:14, :47).
- Declared-key format pinned in `/sdd-story`: `## Config Key Changes` was free-form and the overlap-check regex matches only three-segment dotted keys, so extracting declared keys needed a format rule (recon.md@1ed63958:106).
