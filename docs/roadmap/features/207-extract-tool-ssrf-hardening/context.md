## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: The agent's two content tools, `extract_website_content` and `extract_email_content`, now refuse to fetch non-public targets. They share one fetch helper, so one hardening covers both: a `not is_global` IP validator, an httpx transport subclass that pins the connection to a validated IP, and a manual redirect loop with a byte cap. Tool surface unchanged (43 tools, same `{raw_text}`); a blocked fetch raises the generic `RuntimeError("content fetch refused by egress policy")`. Launched 2026-10-01 via PR #1205. The design's central fail-closed guard against a silently missing pin shipped weaker than designed (see Scars).
**Why (irrecoverable rationale)**: Audit finding (M-list, DT-2 §150): a prompt-injected agent can use the fetch as a pivot to cloud metadata, loopback and private gRPC services. The operator chose a fail-closed deny-by-range core and deferred the domain allowlist. Deny-ranges are stdlib-derived, not configured, a deliberate security-invariant choice (product-spec FR-5 wanted them config-sourced); F-07/C-05 apply only to the four scalar limits. This closes fetch ingress; feature 214 closed DB egress; they are independent. Out of scope: a container/pod NetworkPolicy or egress firewall (product-spec: "complementary defense-in-depth, tracked separately if pursued") — SSRF is therefore NOT closed at every layer.
**Rejected alternatives**: `is_private` or an enumerated flag list as the primary gate (fails open for CGNAT `100.64/10`); pre-resolve and validate then pass the hostname to httpx (httpcore re-resolves at connect: DNS-rebind TOCTOU); a from-scratch `AsyncBaseTransport` (round 2: may drop connect-timeout/SNI extensions and leak pooled connections — subclass instead); `follow_redirects=True` with only the connect-layer pin (no per-hop scheme check, no hop bound); a blocking `getaddrinfo` in `connect_tcp` (stalls the event loop); `c.get()` + `r.text` (buffers the whole body, defeating the byte cap — needs `client.stream()` + `aiter_bytes()`); a domain allowlist in v1 (could break legitimate public extraction; named hook `agent.extract.domain_allowlist`); pick-one-of-resolved-IPs (replaced by reject-if-any, since a mixed public+private answer is itself the rebind signal); an OTel span for FR-6 (no tracer wrapper; `telemetry.py` is init-only).
**Scars & gotchas**: 1) The "fail-closed identity assertion" is tautological: `egress.py:138` assigns `self._pool._network_backend = self._pinned_backend` and `:140` reads the same attribute back with `is not`; on a plain-attribute rename in httpcore the assignment creates a dead attribute, the read-back passes and the pin is silently absent (a total bypass — design open risk). It would still fail closed if the attribute became a property/`__slots__` entry, and a rename of `httpx.AsyncHTTPTransport._pool` raises at `:138`. The shipped test (`test_egress.py:139-147`) repeats the tautology and never simulates a revert (impl-spec Step 4 instr.5 promised one); the only real guard is incidental — `test_tools.py:2008-2069` patches `httpcore.AnyIOBackend.connect_tcp` at class level and asserts it is not called (DO NOT WEAKEN). 2) DEV-1: `AutoBackend` is not a public httpcore export, so `AnyIOBackend`; DEV-2: swap `_network_backend` on httpx's built pool instead of rebuilding it, to preserve ssl/http2/limits (this is what made the assertion tautological). 3) `respx` patches above the pin, so block tests must monkeypatch `socket.getaddrinfo` and the held `AnyIOBackend.connect_tcp`; `EgressBlocked` propagates unwrapped from `connect_tcp` and both the `except` and the FR-6 no-leak guarantee depend on that. 4) DEV-4: acceptance `@AC-5` required a re-validated rejection, so the loop re-validates literal-IP redirect targets at the app layer (`tools.py:2312-2318`); hostname targets rely on the connect pin; `@AC-5` is tested only through respx. 5) Teardown also had to update `config-governance.md:120-131` and `mcp-tools.md:174,203`. 6) Passing `transport=` to `AsyncClient` disables env-proxy mounts (`allow_env_proxies = trust_env and transport is None`), so `HTTP_PROXY` cannot route around the pin — a future `proxy=`/`mounts=` would.
**Permanent deviations**: Pool revert-guard → a swap + read-back that cannot fail. `AutoBackend` → `AnyIOBackend`. Extra literal-IP redirect check in the loop. The credential strip pops only the exact-case keys `Authorization`, `Cookie`, `cookie`, `Host`, `host` (`tools.py:2321`), so lowercase `authorization`, `Proxy-Authorization` and custom headers (`X-Api-Key`) survive a cross-origin hop; both callers pass `password=None` (`tools.py:511,545`; feature 093 has-credentials-raises gate), so the Bearer path is dead and only operator-supplied `request_headers` are exposed. `extract_website_content` takes its URL from the admin-registered source `config_json.url`; only `extract_email_content` takes caller-supplied `urls` (`tools.py:523`). `connect_tcp` uses only `ips[0]` (`egress.py:108-109`; the design said "pick one validated IP"). `httpx.Timeout(read_timeout, connect=connect_timeout)` also sets write/pool timeouts to the read value. The config fallback (`tools.py:2258-2271`) uses the hardcoded defaults on a config-read failure — it does NOT fail closed. NOT SHIPPED: the design-mandated tests for the cross-origin credential strip and per-hop scheme redirect (dropped between design and impl-spec Step 6, never flagged by review), a total wall-clock deadline (a slow-drip host holds a request until `max_bytes`; redirect hops reset the read timer), the pre-request/per-hop scheme gate's end-to-end test (`@AC-4` is covered only by the pure-validator parametrize, `test_egress.py:81`); `@AC-8` deny ranges "read from configuration" and "no hardcoded literal in the helper" are untrue (defaults 5/5_000_000/10.0/30.0 are in `_fetch_url`, `tools.py:2285-2288`).
**Cross-feature signal**: The only outbound HTTP path in the agent (`httpx.AsyncClient(` appears only at `egress.py:150`; no `requests`/`aiohttp`/`urllib.request`/`http.client`) and `services/xstockstrat-agent/docs/` has no egress invariant, so a later bare client would bypass the protection. 214 removed DB egress; 207 closes fetch ingress; 210 (mTLS) covers outbound gRPC only.
**Deferred follow-ons**: VERIFIED RESIDUAL (static trace; not executed): an error-text oracle breaks FR-6/`@AC-7`. `PinnedValidatingBackend.connect_tcp` (`egress.py:98-100`) runs `getaddrinfo` in a thread; for a nonexistent name it RAISES `socket.gaierror` (an `OSError`), never returning `[]`, so the `if not ips: raise EgressBlocked("unresolvable host")` branch (`:102-103`) is dead code; httpcore exceptions derive from `Exception` not `OSError` (`_exceptions.py:18-72`) and `map_httpcore_exceptions` (`httpx/_transports/default.py:96-118`) only maps httpcore types, so the raw `gaierror` propagates; `_fetch_url` (`tools.py:2334`) catches only `EgressBlocked` and neither caller wraps it. A name resolving to an internal address gets the generic refusal while a non-resolving name gets a raw resolver error (`[Errno -2] Name or service not known`, no hostname), letting a prompt-injected caller enumerate internal/split-horizon DNS names (e.g. `xstockstrat-config`). No test covers an unresolvable host; the MCP SDK's last hop (`isError` with `str(exc)`) is unverified. Fix: catch `gaierror`/`OSError` in `connect_tcp` → `EgressBlocked("unresolvable host")`, add a catch-all in `_fetch_url`, add the test. Other follow-ons: harden the credential strip (case-insensitive, `Proxy-Authorization`, allowlist forwarding); decompression expansion (`aiter_bytes()` yields decoded chunks and the cap runs after decoding, `tools.py:2328-2331`); a total deadline; a dual-stack fallback across validated IPs; the domain allowlist; a network-layer egress policy; replace the read-back with a discriminating guard on any httpx/httpcore bump. FR-6 shipped as a plain `log.warning` with a static reason code — no metric, span, alert hook or target detail, so blocked attempts cannot be attributed. Public-host content exfiltration (a prompt-injected agent sending data to arbitrary public hosts, chiefly via `extract_email_content`'s `urls`) is explicitly accepted. The deployed image is Python 3.13 (`Dockerfile:1`) while the local venv is 3.12.
**Runtime-invariant recommendations (→ /context-constitution)**: Candidate AGENT-*: every outbound HTTP fetch of a caller-influenced URL must go through `egress.build_pinned_client` plus the bounded manual redirect loop (no bare `httpx.AsyncClient`, never `follow_redirects=True`); `PinningTransport` swaps the private `httpcore.AsyncConnectionPool._network_backend` — on any httpx/httpcore bump re-run the `test_tools.py` block tests and treat failure as pin loss, do not rely on the read-back; `EgressBlocked` messages and logs must stay static reason codes.
