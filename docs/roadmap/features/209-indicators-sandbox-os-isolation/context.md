## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: Feature 209 contains the blast radius of an escapable formula sandbox; it does not fix the escape. The audit C-3 / DT-1 escape (`().__class__.__base__.__subclasses__()` against a builtins/import blocklist) is still reachable at the language level. Formulas now run in an unprivileged OS-isolated child: a distinct UID (nobody, 65534) dropped from a root parent, `NO_NEW_PRIVS`, expanded rlimits and a post-import seccomp allowlist with default `ERRNO(EPERM)`. It runs on DO App Platform with no added privileges. Launched 2026-10-01 via PR #1205; a SEV-2 on 2026-10-03/05 forced a second pass that removed all file-open syscalls.
**Why (irrecoverable rationale)**: DO App Platform grants no `CAP_SYS_ADMIN`, userns or privileged mode (`.do/app.yaml` has no `security_context`/`cap_add`/seccomp fields); the operator chose to stay on App Platform rather than re-host to a jailer, ruling out netns, nsjail and bubblewrap. A same-UID seccomp filter cannot stop `process_vm_readv` or a read of `/proc/<parent>/environ` (round-1 SEV-1), so the distinct UID is the control that actually delivers "an escape reaches no secrets"; seccomp then shrinks what the nobody child can do. Real platform secrets are `GetSecret` RPC config rows, not files in the container, so env-strip plus a UID boundary suffices for FR-2. `ioctl` is deliberately absent from the allowlist: the `isatty`/`TIOCGWINSZ` probes tolerate `EPERM` identically to the `ENOTTY` they already got (verified; no comment in code — do not add it while chasing a numpy EPERM). `clone`/`clone3` stay allowed for numpy/BLAS threads; a forked child is inert because `execve` is denied and `RLIMIT_NPROC` bounds the count. `RLIMIT_FSIZE=0` is safe only because stdout is a pipe.
**Rejected alternatives**: A jailer (nsjail/bubblewrap/gVisor); seccomp on the same UID; a seccomp DENYLIST (fails open: io_uring, the 32-bit/x32 ABI, pidfd — an allowlist fails closed and its FR-4 fragility is testable via the golden); `preexec_fn` (unsafe with threads; the lockdown runs in the wrapper, in a single-threaded post-execve child); per-slot UIDs (kept as the O-2 escape hatch); `SCMP_ACT_KILL` default (a mis-scoped filter would SIGSYS-kill a legitimate formula; EPERM lets libraries probe and fall back, at the cost of a generic `runtime_error`); flag-filtered `openat` (fragile; replaced by env fix + `RLIMIT_FSIZE=0`, later by a full deny); new `indicators.sandbox.*` leaves or a `seccomp_enabled` kill-switch (YAGNI; a kill-switch would let prod disable the primary control — reverses recon's recommendation); `RLIMIT_AS` (rejects numpy's virtual reservations, INDICATORS-2); attribute-filtered module proxies (post-launch; the operator preferred the seccomp deny and the reason is NOT recorded); a raw `ctypes` seccomp instead of `pyseccomp` (recon R4 posed it; design never records why `pyseccomp` won — do not invent one). Firecracker/microVM isolation is out of scope "unless the design finds the container-level mechanism insufficient" — keep as an explicit escalation trigger now that the language-guard escape is still unfixed and one file-read incident has happened.
**Scars & gotchas**: `mbind` is missing from small traces (a 200×200 matmul missed it; 800×800 hit it) so the allow-set must be derived from realistic array sizes; `statx`/`getdents64` were added defensively for the `python:3.13-slim` glibc (probably vestigial now that `openat` is denied — unverified). A global uv-tool pytest breaks subprocess tests (child `sys.executable` lacks numpy/pyseccomp; fails.md:2393). The execute sandbox was root so the full stack was verified locally; CI is non-root so the setuid tests are `skipif`'d, but `ci.yml:373-379` installs `libseccomp2` so CI still enforces the real filter. Post-launch SEV-2: `_safe_import` checks only the top-level name and returns the real module and `getattr` is a safe builtin, so attribute traversal (`numpy.lib._datasource.os`, `pandas.io.common.os`) reaches the real `os`; with `openat`+`read` allowed a formula read `/etc/passwd`, listed `/etc` and read app source and the venv. Once `openat` is denied numpy's lazy `fft`/`rec`/`ma` fail with EPERM on first access, so the wrapper resolves every `dir(mod)` lazy attribute before the filter loads (~55 ms per child). `killpg` is load-bearing beyond timeouts: a `fork()+sleep(∞)` grandchild survives both the SIGKILL and `RLIMIT_CPU` and would hold a uid-65534 NPROC slot forever. Wrapper ordering constraints exist only in code comments and one test: `tempfile.gettempdir()` before `RLIMIT_FSIZE=0` (it probes by writing), `import pyseccomp` before `RLIMIT_NPROC` (`find_library` forks `ldconfig`).
**Permanent deviations**: Design said `openat` is allowed and "read-used" → shipped `open`/`openat`/`openat2`/`open_by_handle_at` all absent (`sandbox.py:59-60,64-115`, structural test `test_sandbox_isolation.py:304-307`) because attribute traversal bypasses the import guard. The shipped allowlist has 50 names (the design's 51 included `openat`). AC-2 was reinterpreted down at /sdd-spec (P-03) to "world-readable non-secret files stay readable by design" and that is SUPERSEDED: file reads are denied, so the acceptance wording "reads outside scratch are denied" was right all along. Design lockdown order `setgid → setgroups → setuid → prctl → setrlimit → eager-import → seccomp.load` shipped as eager import with lazy resolve → builtins/`json.loads` → `gettempdir()` → `setuid` (if euid==0) → `prctl(38,1)` → `import pyseccomp` → rlimits → filter load (`sandbox.py:212-292`), so the eager import, `json.loads` and `gettempdir()` run as ROOT before `setuid` (the heap counts toward `RLIMIT_DATA`, applied after; import-time code of allowed modules runs as root — operator-trusted; context.md logged "Deviations: none"). FR-1 and acceptance AC-1/2/3 promised a netns, a "dedicated scratch/tmpfs area", dropped capabilities and "address-space" termination; shipped is seccomp EPERM on `socket`, no scratch area (`HOME`/`TMPDIR=/nonexistent`), a non-root nobody with `NO_NEW_PRIVS`, and `RLIMIT_DATA` — that stale wording persists in the retained `acceptance.feature` (lines 10,18,24) and the promoted suite (lines 15,23,29). `@AC-5` is tested only sequentially (not concurrent) and `@AC-6` mixes live config (timeout/memory/`max_concurrent` read per call, `servicer.py:171-172,197`) with an `asyncio.Semaphore` read once at `__init__` (`:65`). The `try/except Exception: pass` at `:288-291` swallows ANY `add_rule` failure (not only unknown names) so a typo'd name passes the tuple-only structural test and is inert in prod; `.load()` is unwrapped (a failure surfaces as `runtime_error`).
