## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: `time_in_force` on `Order`, `PlaceOrderRequest` and `ReplaceOrderRequest` went from a free-form string to a closed `TimeInForce` enum, an in-place wire-breaking conversion with no dual-field transition. Broker-edge validation is a hardcoded per-broker matrix and `UNSPECIFIED` is rejected for non-offline accounts. `/trader` gained a TIF select on the place form; the replace dialog always sends a concrete TIF. Before 202 the UI never sent TIF: the broker got `"day"` from the `buildBrokerRequest` default and the DB stored empty/NULL (hence migration 010's backfill to `day`). Launched via PR #1177.
**Why (irrecoverable rationale)**: Operator R2: "Remove unspecified. There are no old callers to care about" — killing both the additive-field strategy and any `UNSPECIFIED→DAY` default. Operator R4: Edit Order "must have a value, not undefined", so no "leave unchanged" option. The user overrode the 5-round grilling cap to reach SOUND at R6. Original request was "add to the roadmap: order timing", narrowed via AskUserQuestion to TIF enum + per-broker validation; explicitly OUT of scope: scheduled/deferred/"not-before" submission, order-lifecycle timing telemetry (intent→submit→fill latency), auto-cancel/expiration guardrails beyond native broker TIF, any new broker or order type.
**Rejected alternatives**: Additive new-field + deprecation (no old callers). `UNSPECIFIED→DAY` fallback (implicit defaults hide misconfigured callers). Config-driven TIF matrix (deployment-time-fixed; mirrors the `orderTypeToIBKR` constant map). `optional TimeInForce` with absence = DAY (reintroduces an implicit default). A DB CHECK constraint (second source of truth that breaks on enum growth; `order_type` has none). Moving `validateTIF` ahead of the offline early-return (offered at R6; would break the agent — see Scars).
**Scars & gotchas**: The offline carve-out is load-bearing and its recorded rationale is wrong: the design said "No agent tool places orders (confirmed)" and "UI always sends a concrete value", but the agent's `record_offline_order` (`manage_offline_account`, `client.py:2142-2150`) calls `PlaceOrder` with no `time_in_force`; it works only because the offline return (`trading.go:451-453`) precedes `validateTIF` (`:472`). The `OFFLINE` row of `allowedTIFs` (`tif_validation.go:49-55`) is unreachable; an offline order with `UNSPECIFIED` is stored as `day` (`tif.go:22-23`) while the in-memory return value keeps `UNSPECIFIED`. `ReplaceOrder` validates AFTER claiming the intent: `InsertIntent` `:1392`, PENDING `:1426`, `validateTIF` `:1436-1438` returns `InvalidArgument` with no `FinalizeIntent`/revert, so an identical retry hashes the same and gets "still pending" `FailedPrecondition` until the staleness sweeper reclaims it (PlaceOrder validates before hashing, `:472` vs `:478`); no test touches it. Tests cover helpers (`tif_validation_test.go:14-93`), not handler wiring; the Replace dialog has NO automated test and recon's "202's own @AC-5 covers Replace Order TIF" is false. `UpsertOrder`'s `ON CONFLICT DO UPDATE` set (`trading_repo.go:77-85`) excludes `time_in_force`, `qty`, `limit_price`, `stop_price`, and there is no other writer — a `ReplaceOrder` change reaches `s.orders` and the intent response but never the DB (pre-existing; 202 inherits it). `AC-4`'s example string `good_till_cancel` is rewritten to `gtc` by migration 010, so it only reads back `UNSPECIFIED` for unaliased strings. The IBKR matrix (DAY/GTC/IOC/FOK; OPG/CLS rejected) rests on Client Portal docs and was never verified; the pre-deploy `latest_response` unmarshal check was never tested; TIF×order-type coupling was never resolved; F-C-10 protection is partial (`EditOrderDialog.tsx:130-135` hand-lists six items; `OrderForm.tsx:43-58` keys on a string union; only `TIF_LABEL` is exhaustive). E2E: the new TIF combobox broke six bare `getByRole('combobox')` sites (`.first()`); mock responses use numeric enums while the request assertion is the NAME-string; `mock-backend.ts` `placeOrder` must return `timeInForce: 1`. Docker Hub 429 forced host-native codegen (`analysis.pb.go` drift reverted; fails.md:2378); `AGAINST_BRANCH=__skip_breaking__` skips the local `buf breaking`.
**Permanent deviations**: A `# TEMPORARY … remove in the integration PR` `--exclude-path trading/v1/trading.proto` is STILL in `.github/workflows/ci.yml:123-126` (the `proto-lint` job's `buf breaking`), silently disabling the breaking-change gate for the whole file; the baseline is now post-202, so removal is safe. impl-spec Step 6(c) `selectedTif || undefined` shipped as an always-concrete pre-filled `PbTimeInForce` with `UNSPECIFIED` mapped to `DAY` (every replace, even qty-only, re-sends and re-validates TIF). "`buildBrokerRequest` dead fallback" was actually live for UI-placed orders. OrderForm TIF is hidden in offline-record mode but still sends `DAY`. `UNSPECIFIED` is "always rejected" for broker accounts only. The adversary over-predicted fixture breakage (design said every fixture must add explicit TIF; only one cosmetic edit, `order_intent_test.go:39-41`, was needed).
**Cross-feature signal**: 202 chose "always reject UNSPECIFIED", the opposite of the fails.md:326-340 lesson (grep the zero-value's existing resolution first); the operator overrode it knowingly, and the one place the old default survives is the offline/agent path. 203/204/205 ran sequentially after 202 and share the host-native codegen path (their `buf breaking` checks are local, not CI). Agent consumers of order RPCs were missed by the C-14 enumeration.
**Deferred follow-ons**: Remove the CI `--exclude-path`; move `validateTIF` above `InsertIntent` in `ReplaceOrder` (or finalize/revert on failure) and add handler-level tests; decide whether the offline path validates TIF (then the agent must send `DAY` first); persist replaced TIF/qty/prices; per-(TIF × order type) validation; verify the IBKR matrix and add the legacy `latest_response` test; `scripts/integration-test.sh` PlaceOrder bodies (`:427-434,528-535,563-570,585,606`) carry no `time_in_force`. A deploy note: in-flight intents hashed under the old wire type stop matching for about the staleness window (`stale_multiplier` × broker timeout, ~30s); cleanup `DELETE … state IN ('PENDING','UNKNOWN') AND created_at < <deploy-ts>`; deploy outside trading hours. The wire-breaking change needed 2 owners + platform lead and no approval was recorded.
**Runtime-invariant recommendations (→ /context-constitution)**: Candidate TRADING-*: `PlaceOrder`'s offline path precedes all validation gates including `validateTIF`; the agent's `record_offline_order` depends on that by sending `UNSPECIFIED`; moving the TIF gate above the offline return breaks `manage_offline_account`. Candidate TRADING-*: in `ReplaceOrder` the intent claim precedes `validateTIF`, so a rejected TIF leaves a PENDING intent.
