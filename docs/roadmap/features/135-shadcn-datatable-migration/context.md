## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: Every table across all four `xstockstrat-ui` segments (finally 16 sites, not the 15 recon found) migrated onto one shared `ui/data-table.tsx` composite (`@tanstack/react-table` headless state wrapping the existing shadcn `Table` primitive). Shipped three genuine bug fixes it wasn't scoped to make — a composite `onRowClick` self-match bug, a pre-existing keyboard mis-fire, and dead-code removal — and its own scope grew mid-flight when sibling feature 125's merge planted a 16th table one import-hop from an already-checked file. No proto/config/DB/migration surface; a pure presentation-layer refactor.

**Why (irrecoverable rationale)**: The single-composite-with-CSS-`meta.className` approach (not a JS `useIsMobile()` hook) was chosen because the codebase already had working multi-tier Tailwind breakpoint disclosure (feature 083's 3-tier `hidden sm:/md:/lg:table-cell` on the 19-column Exposure table); a `matchMedia` hook would have regressed that to a binary threshold plus hydration flicker. Row-click safety was built as one row-level `isInteractiveTarget` guard rather than per-cell `stopPropagation()` because non-Actions interactive cells (Symbol links, the Trade button) would otherwise be silently missed.

**Rejected alternatives**: JS `useIsMobile()`-driven column visibility — post-hydration flicker + collapses row 2's working 3-tier breakpoint disclosure into one threshold. Pagination always-on — conflicts with row 2's existing server-side keyset Prev/Next (two unsynchronized controls) and violates FR-3's justify-chrome-by-count rule. Per-cell `stopPropagation()` — must be re-applied at every Actions site, misses non-Actions interactive cells, and (as first scoped) guarded only `click` not `keydown`. TanStack built-in row-selection API — real needs are navigate/select-one, not multi-select; a selection-state + checkbox column is unused scaffolding. Auto-tagging the composite's own Actions-cell renderer with a marker attribute — rejected because the Actions trigger is already a real `<button>` (feature 124's DropdownMenuTrigger), so the native-`<button>` branch of `isInteractiveTarget` covers it with no special case; `[data-row-click-ignore]` is deliberately RESERVED for genuinely non-semantic future cell content the composite can't predict (e.g. a bare `<div onClick>`), not for elements already carrying a semantic interactive role.

**Scars & gotchas**: Shared per-cell components (`OrderSymbolCell`/`OrderSideCell`/`OrderStatusCell` in orderShared.tsx) each returned a full `<TableCell>`, not bare content — unusable as a `ColumnDef.cell` (would nest `<td>` in `<td>`); forced substituting the bare-content `OrderSideBadge`/`OrderStatusBadge` and inlining the Symbol `Link`; the three wrappers became dead code, removed Step 33. The composite sets `role="button"` on every `onRowClick` row for a11y, overriding the native `row` ARIA role — every e2e locator using `getByRole('row',{name})` on a migrated table broke and had to become `getByRole('button',…)`; the same fact caused the shipped `onRowClick` self-match bug. Same-route header collisions: two migrated tables on bare `/trader` (OrderBook + LiveStrategiesPanel) both render a "Status" columnheader; added `tableTestId="order-book-table"` and scoped by getByTestId. The composite's `meta.className` is STATIC-per-column (read as `cell.column.columnDef.meta?.className`, fixed at column-definition time), and design deliberately added NO per-row cell-styling hook ("adding one for a single call site would be scope creep"); 5 of the 19 Exposure columns computed cell className dynamically per row via `pnlClass(...)` (sign-dependent P/L color), which meta.className structurally cannot express — the fix moved the dynamic class onto an inner `<span>` inside the cell renderer (impl-spec Step 29 deviation). An automated no-overflow assertion is only meaningful against a fixture whose values are wide enough to actually force overflow: the row-3 Sheet fill-lineage overflow test proved nothing until a 65-character `order_id` stress fixture replaced the default `mock-order-001` ("would have passed vacuously") — high-value because the whole feature exists to close an overflow regression. AC-2's literal "exactly 2 files import `@tanstack/react-table`" was mechanically false (16 files) but satisfied in intent: every non-composite import is `import type { ColumnDef }` only; the runtime API has zero matches outside the composite — a future audit grepping the literal AC will wrongly read a violation.

**Permanent deviations**: design said the LiveStrategiesPanel keyboard bug was a "double-fire" → shipped/verified reality is a single mis-fire: pre-migration the row's `onKeyDown` called `preventDefault()` on the bubbling keydown, cancelling the browser's native "Enter activates focused button", so keyboard-Enter fired ONLY the row handler and never the button's mutation → the migration's shared guard fixes it to fire only the button (caught because the RED test didn't reproduce design's predicted failure; the corrected mechanism lives only here now). design mandated replacing the old `StrategyRow` component (one `useStrategyAnalytics(strategyId)` call read across 6 cells) with a small `AnalyticsCell` that each of 6 columns renders independently, each calling `useStrategyAnalytics(strategyId)` itself → because a `ColumnDef.cell` renders every cell independently so a per-row wrapper can't survive the migration; the fix relies on React Query deduping the identical concurrent query by key so it stays one round-trip (companion to the static-`meta.className` limitation). Once specs are gone, shipped code showing 6 identical `useStrategyAnalytics` calls on one page reads as a perf regression rather than a deliberate, safe choice. design granted row 3 (nested-Sheet fill-lineage table) a deliberate design-level exception — migrate for consistency but sort-only, no pagination/filter/column-visibility, because a full composite is disproportionate to a single-position drill-down; its no-overflow test needs bespoke Sheet-open-then-measure code the generic `mobile-overflow.spec.ts` sweep structurally can't reach (it never clicks).

**Cross-feature signal**: Capstone of the shadcn table-migration arc — siblings 119-124 had already normalized all raw `<table>` markup onto the `Table` primitive, which is why recon found zero raw `<table>` and no prior table library; 135 was the next rung (primitive → TanStack DataTable), not a duplicate. Large in-flight sibling features editing the same UI files (feature 125, "unified Symbol page," 795-line diff to positions/[symbol]/page.tsx, merged mid-execution) repeatedly forced re-spec/re-grounding and even planted a wholly new table — a recurring cost when two features touch the same surface concurrently.

The re-spec-gate lesson (re-run the *unbounded* discovery sweep, not just re-verify known sites) is already flagged as a candidate binding note for reference/sequential-mode.md (fails.md:1217).
