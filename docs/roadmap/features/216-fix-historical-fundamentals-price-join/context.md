## Archive Synthesis — 2026-10-14 — /sdd-archiver

**What**: Marketdata-only write-path fix. Historical fundamentals rows now recover their five price-derived columns (`price`, `market_cap`, `pe_ratio`, `pb_ratio`, `dividend_yield`) when daily bars arrive after the fundamentals backfill. Before, `InsertHistoricalFundamentals` was insert-only (`DO NOTHING`) and the price-join ran once at insert. Shipped design: keep `DO NOTHING` for new rows; for existing rows read the stored price state, derive the five columns, merge in Go, and write through a dumb fixed-5-column `UPDATE`. `overwrite` is wired into marketdata for the first time as an operator force-refresh. Ingest, agent, UI, proto, config, migrations unchanged.

**Why (irrecoverable rationale)**:
- The report's framing was wrong: `overwrite` reached nothing in marketdata (`BackfillFundamentals` never read it; bars are unconditionally upserted). Do not reuse the report's "overwrite governs the bars fetch" idea.
- A write-path fix is necessary and sufficient. Bars-before-fundamentals ordering in ingest is caller sequencing across two single-`data_kind` `TriggerBackfill` calls — it can never recover rows that already exist, and would only help the forward case for new symbols (optional, "likely deferred", not rejected outright).
- The central correctness question was the NIL-CLOBBER hazard: a naive `DO UPDATE SET price=EXCLUDED.price` on a no-bars re-run would overwrite a good price with nil — hence the monotonic rule (never value→nil).
- The 5-round debate (11 proposer/adversary passes) caught: (a) a latent fabricated-0 `dividend_yield` (dividend fetch window ~2y vs periods up to 10y: an empty fetch divided by price gives 0); (b) SQL-merge logic a mock cannot execute; (c) recovery that breaks when the re-fetched `filed_date` drifts; (d) write amplification and PIT drift; (e) an `overwrite` path that would wipe a stored dividend yield; (f) a pre-211 currency fabrication; (g) a C-15 gap on the signed-off `overwrite` val→val′ capability (→ `@AC-4`).
- C-16 CHANGE signed off 2026-09-27: with `overwrite=true` a backfill may overwrite the 5 derived columns of an existing row (narrows feature-198 `@AC-2` "no earlier period row overwritten by a later fetch"). As-reported fields and the earliest `filed_date` are never touched, structurally (fixed SET list + triple-PK WHERE). Default stays fill-if-null. The user was offered "leave `overwrite` unwired" (recommended) and chose "wire force-recompute". Of the three trigger options (a) re-derive only on `overwrite=true`, (b) default fill-if-null + `overwrite` force-recompute, (c) hybrid — (b) won because it recovers the existing AAPL/MSFT/KO nil rows without an operator flag.

**Rejected alternatives**:
- Single `INSERT … ON CONFLICT DO UPDATE SET x=COALESCE(EXCLUDED.x, t.x)` — merge lives in SQL a mock cannot execute (`fails.md` 722/757/727-729), COALESCE cannot set-null per column, and it cannot cleanly skip the write when nothing changed.
- Read-time projection — breaks the stored PIT contract (feature-198 `@AC-4`), must persist for `@AC-1`, and re-plumbs every read path + the snapshot lane.
- Guard on incoming `filed_date` equality — drift-fragile, leaves the permanent gap; the `period_end` mitigation is unsound (same `period_end` on a 10-Q and a later comparative 10-K reintroduces look-ahead).
- Widen the dividend fetch to `max_lookback_years` (10y) — ~5× Alpaca cost for a fail-closed metric.
- `dividendAuthoritative` value→nil to clear a persisted fabricated 0 — the coverage guard is wall-clock-relative, so it would wipe legitimate yields for periods older than ~1y on every re-run; a fabricated 0 is indistinguishable from a real 0 on an uncovered period. Abandoned Round 4→5. A `dividend_yield_source`/coverage marker column — schema change for a marginal cleanup (YAGNI, C-18, SEV-3).
- Recovering `debt_to_equity` — as-reported/formula-derived (feature 211), not price-join.
- Testing: "no testcontainers for a SEV-3" (C-18) — merge logic in a stateful Go fake, UPDATE SQL pinned with pgxmock, a real-Postgres dev smoke (backfill without bars → store bars → re-backfill `overwrite=true` → confirm `query_fundamentals` stops reporting the 5 metrics missing) as the stand-in. The smoke is not recorded as run.
