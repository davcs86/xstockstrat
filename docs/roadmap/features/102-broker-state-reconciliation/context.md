**Feature**: ./feature.md
**Status**: launched — archived by /sdd-archiver; verbose specs pruned (recoverable via git history).

## Archive Synthesis — 2026-08-16 — /sdd-archiver

**What**: A lightweight periodic reconciliation poller added inside `xstockstrat-trading`, reusing existing `alpaca.go`/`ibkr.go` broker clients and the already-dialed `portfolio` client, that compares open orders and positions against broker truth per tick, self-heals propagation-delay-class drift silently, halts per-account on genuine mismatches via 030's `broker_accounts.halted` mechanism, and escalates to 100's platform-wide kill switch on systemic failures via a new structurally separate `x-internal-caller` authz channel in `xstockstrat-config`. FR-6 resolves 101's `UNKNOWN` order-intent state — Alpaca-only via `ListOrders` scan; IBKR excluded because IBKR's `SubmitOrder` never sends a `ClientOrderID`/`cOID` key in its request body.

**Why (irrecoverable rationale)**: Feature was initially demoted (no automated trading path — only the human trader UI calls `PlaceOrder`) and then revived because the *cheap* version (existing clients, no new service, no new engine, ledger events + notify reuse) is proportionate even for a solo maintainer. "Re-scope before demoting — the cheap version of a control can be worth building now even when the expensive version should wait." The halt was split per user-approved AC-3/FR-4 amendment: ordinary per-account findings route to 030's per-account circuit breaker; only a systemic failure (N% of accounts erroring/unprotected, threshold `trading.reconciliation.systemic_threshold_pct` default 0.5/50%) escalates to 100's gate, because escalating every ordinary finding would be operationally noisy. The internal-caller channel was kept structurally separate from `x-access-scope` because the human-role bitmap check has no caller-identity component — any code path in the calling binary could construct the same header — whereas the new `x-internal-caller` + `{callerID, namespace, key, allowedTargetValues}` allow-list is narrow and caller-identity-checked. Direction restriction (`allowedTargetValues: ['REDUCE_ONLY', 'HALTED']` — never `'ACTIVE'`) prevents a buggy caller from silently un-halting the platform. `caller_identity TEXT` added as a structural DB column (not folded into freetext `author`) because a `WHERE caller_identity IS NOT NULL` filter is structurally guaranteed for incident review. `x-trace-id` propagation on the new `trading → config` outbound edge was SHIPPED in Step 13 (design.md Open Risk #6 resolved) — NOT deferred.

**Rejected alternatives**: Brand-new parallel halt mechanism (invented a third circuit-breaker axis when 030 already owns the same per-account concern). Reusing `x-access-scope` for service self-assertion (wrong trust primitive — any binary code path can construct it). Escalating all ordinary per-account findings to 100's platform gate (user-approved wording amendment: disproportionate). Deferring platform-wide escalation entirely out of v1 (explicit fork offered and explicitly not chosen). Folding `caller_identity` into freetext `author`/`reason` (convention-only distinction insufficient for incident review). Unbounded-authority internal-caller check (adversary found round 2's version lets a bug silently un-halt the platform — fixed with `allowedTargetValues` in round 3). mTLS/SPIFFE cryptographic caller verification (inconsistent with platform precedent).

**Scars & gotchas**: `config.Watcher`'s unexported `client` field blocks fake gRPC injection for the *outbound* `SetConfig` call — required extracting a `configSetConfigForwarder` interface and swappable `TradingService.configSetter` field. "Unprotected/impossible" mismatch bucket is architecturally unreachable — an order/position under an account ID absent from `s.brokers` cannot occur; named as a NOTE in tests rather than fabricating an unreachable test path. Two test-fake naming/signature collisions with 030's own fakes in the shared `internal/service` test package. Playwright `getByText('Exposure')` without `.first()` triggers strict-mode violation (breadcrumb + nav link + heading all contain "Exposure"). `page.route()`-fulfilled raw JSON in Playwright e2e is parsed browser-side by `fromJson()`, which expects standard proto3 JSON flattened oneof shape (`{stringVal: 'REDUCE_ONLY'}`) — NOT the server-side `create()`-style wrapped shape (`{value: {case: 'stringVal', value: 'REDUCE_ONLY'}}`); wrapped shape silently fails to parse, leaving hook data `undefined`. 5-feature stacked-chain squash-merge retargeting: after each squash-merge to `main-dev`, downstream feature PRs required manual retarget + `git merge origin/main-dev` (NOT rebase — rebase rewrites already-integrated content as new commits because squash creates a synthetic commit with no ancestry to pre-squash history). 101's `implementation-spec.md` never actually emits `order_intent.late_response_conflict` in any of its 25 steps — only a forward-reference note at `:55`. This means FR-6's "first check" branch in this feature can never match if 101 ships without adding that emit instruction.

**Permanent deviations**: design said position quantity comparison uses "remaining quantity (`Qty - FilledQty`)" → shipped uses `FilledQty` directly (`BrokerOrder` has no total `Qty` field). design's UI section implied server-side prefix filtering of reconciliation events → shipped uses `stream_key` exact-match filter + client-side event-type prefix filtering (`QueryEvents.event_type` is a single exact-match filter, not prefix). design's FR-6 described IBKR `ListOrders`-scan fallback → shipped is Alpaca-only (IBKR `SubmitOrder` never sends `cOID` in the request body). design's UI section assumed `QueryEvents` returns newest-first → shipped `ledgerServiceImpl.ts` uses `ORDER BY recorded_at ASC`; `useReconciliationStatus.ts` indexes from the end of the array.

**Accepted open risks (irrecoverable)**: `GetPosition` account_id scoping gap in `xstockstrat-portfolio` (`portfolio_service.go:462-466`): `repo.GetPosition` has no `accountID` parameter, so `GetPositionRequest.account_id` is silently dropped at the service layer. `ListPositions` and `ListPortfolios` honor `account_id` correctly. Feature deliberately routed around it. IBKR `ListOrders` `accountId` filter unverified against real IBKR API — whether IBKR's bulk-orders endpoint actually scopes by `accountId` was never verified; if the broker ignores the param, a multi-sub-account session could return orders from other sub-accounts. Implementation-spec explicitly instructed "Flag in PR description; do not claim as proven" — not a code comment.

**Cross-feature signal**: The `config.Watcher` unexported-field testability pattern for outbound `SetConfig` calls is a new sub-class (distinct from the config-read limitation hit across 100/101/023/030). Each future feature adding a new outbound call from a service holding a `config.Watcher` will need the same extraction pattern. 030 and 102 are the SAME per-account halt axis — feature 100 is the platform-wide axis; they are orthogonal and both must remain.

**Deferred follow-ons**: Extend IBKR's `SubmitOrder` to forward a `cOID` — enables FR-6's broker-side scan for IBKR `UNKNOWN` intents. Operator-facing "checked N times, human must intervene" signal for unbounded inconclusive `UNKNOWN` intent retries. Constitution gap: no F-* Floor item in `docs/sdd/constitution.md` addresses authz self-assertion for internal automated callers.
