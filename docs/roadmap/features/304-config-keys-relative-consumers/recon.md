## Objective

Feature 296 made every stored config key namespace-relative and kept a server-side alias (`relative_keys_v1`) so prefixed reads still resolve. 304 rewrites every production read, `GetSecret`/`SetConfig` key and key constant in the 11 consumers to the relative spelling of the namespace the reading watcher subscribes to, respells every test double / fixture / mock that models those reads (C-12/C-13), updates consumer docs, and drains the gate baseline (`prefixed-read`, owner `feature 304`, 180 entries) so the alias can be retired. With the alias OFF a rewritten reader must still return the stored value (FR-6).

## Patterns to REUSE

- **Respell tests through the existing double, not new ones**: Python `snapshot_watcher(**values)` (analysis `tests/conftest.py:62`, indicators `tests/conftest.py:164`, ingest `tests/conftest.py:71`); agent `install_watcher` (`tests/test_config_watcher.py:41`); portfolio `fakeConfig` (`watchlist_service_test.go:259`) and `newTestWatcher` (`config_test.go:78`); marketdata `NewSnapshotWatcher` (`config.go:134`).
- **Trading two-namespace double**: trading needs one new shared double in `internal/testdata/` (C-12/C-13). `NewSnapshotWatcher` (`config.go:117`) is single-namespace. Register it in the service's fixture catalog if one exists.
- **Key-set guard tests** `tests/test_config_read_classification.py` in analysis (`FR3_KEYS` :25, `HONOUR_KEYS` :64, `ZERO_IS_LEGIT` :106), indicators (:26-33) and ingest (:26-44) AST-scan `app/` and compare to hard-coded sets; they ARE the lockstep check: respell sets and `app/` in the same commit. `rule6` also demands each FR3 key appear as a quoted literal in some *other* test file.
- **Read-evidence assertions that follow the key for free**: ledger `configWatcher.test.ts:19,95,142-157` (`readKeyLine` derives from `KEY`), indicators `test_config_watcher.py:403-417`: respelling `KEY` yields FR-7 / AC-12 (`config.read_key ns=ledger key=export.enabled`) with no other edit.
- **Constants over literals**: tests that import the constant (`signalPruneIntervalKey`, `RESOLVE_TIMEOUT_KEY`, `FactorMapKey`) follow a rewrite for free; prefer extending this to `assetRefreshHoursKey` / `barIngestBackoffKey`, whose test copies `bhKey` (`bar_hold_test.go:22`) and `config_test.go:172` otherwise drift.
- **Display-only FQN helper already relative-safe**: Go `fqn`, Python `_fqn` (`watch_core.py:175-177`), Node `fqn()` (`configWatcher.ts:173-175`) return the key if it already starts with `<ns>.`, else `<ns>.<key>`: WARN text keeps the FQN after the rewrite with no core edit.
- **Gate**: reuse `validateState` + `excluded()` + `attribute()` rather than a new check; docs gate reuses `DOC_RULES`/`DOC_BANNED`.
- **Config service bounds registry needs no change**: `lookupScalarBounds` builds `${namespace}.${canonical(namespace,key)}` (`configServiceImpl.ts:184`), so its FQN-keyed `SCALAR_BOUNDS_REGISTRY` (:115, e.g. portfolio entries :155-176) already matches relative keys.
