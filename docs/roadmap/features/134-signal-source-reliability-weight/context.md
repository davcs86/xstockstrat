## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: Reliability weighting moved from the analysis-owned `analysis.signals.source_weights` config blob onto `ingest.SignalSource` as a first-class `reliability_weight` field (persisted `NOT NULL DEFAULT 1.0`, `CHECK [0,1]`). Both the opportunities queue (`_compute_opportunities` `signal_axis`) and the screener (`ScreenSymbols`) now read it through one new `_drain_source_weights` → `ListSignalSources` call; the config blob was left registered but is read by no code path. The config-ui Sources weight cell became inline-editable end-to-end. Shipped clean and launched; the only real defect was caught post-PR by CI (agent projection parity, below).

**Why (irrecoverable rationale)**: The decisive fork FR-4 was resolved as a *genuine replace, not an override layer*, because reliability is a property of the source, not an analysis-owned shadow copy — an override would recreate the "two silently-independent, possibly-disagreeing numbers" the requirement existed to forbid. Validation was made *reject-at-write* (`INVALID_ARGUMENT`), deliberately mirroring ingest's own `conviction` precedent rather than the read-time clamp of the config blob it replaced. `optional` presence was load-bearing, not stylistic (zero-value bug).

**Rejected alternatives**: FR-4 override layer (config wins when present) — reinstates the dual-source anti-pattern FR-4 forbids. Register-path `None` relying on the DB `DEFAULT` — a bound `NULL` on a `NOT NULL` *named* column does not fall through to `DEFAULT` in Postgres; crashes every UI registration (already insights.md:1464). Cosmetic "deprecate the config key via description text, leave `ScreenSymbols` reading it" — ships the exact dual-source anti-pattern. Reusing `NamespaceEditor.validateFloatMap` for the scalar cell — it validates a JSON map, would make every edit unsavable. Dropping the DB `CHECK` as dead-code (round 3) — re-litigated and kept round 4: insurance against write paths outside `ManageSignalSource`.
