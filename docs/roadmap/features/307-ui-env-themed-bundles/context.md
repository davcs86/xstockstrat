# Context: ui-env-themed-bundles  (archived 2026-11-18)

**Feature**: ./feature.md
**Status**: launched — archived by /sdd-archiver; verbose specs pruned (recoverable via git history).

## Archive Synthesis — 2026-11-18 — /sdd-archiver

**What**: Production now ships its own dark palette and staging keeps Nocturne. The theme is picked at build time by a `UI_THEME` Docker ARG and stamped on the image as a label; deploy paths refuse an image whose label does not match the target; a token-aware bundle checker (checks a/b/c) runs on every `pnpm build`; and promotion automation changed so dev and prod never build the same SHA (main-dev is fast-forwarded onto main's promotion commit, so the main→main-dev sync became a serialized `--no-ff` merge and the promote gate three-dot). It began as a small `globals.css` split; two operator scope widenings and that SHA discovery made it a 19-step change across UI, CI, deploy and promotion. Design ran 9 adversarial rounds and impl-spec review 9 iterations.

**Why (irrecoverable rationale)**:
- Operator story-time choices: build-time ARG, one image per deploy workflow, tags unchanged; unset `UI_THEME` means staging (fail-safe so a non-prod build never looks like prod). Two-images and runtime-switch were rejected by the operator here.
- C-11 round-cap override (Commandment, recorded here per root CLAUDE.md): operator, 2026-11-10 (round 5), "Override round cap, do as many as you need to converge." Convergence rule the orchestrator then applied: stop at a round with 0 BLOCKER and 0 FIX-IN-SPEC, then send approval back to the operator. Design therefore ran 9 rounds.
- C-16 sign-off: operator signed the CHANGE to feature 279 @AC-19 on 2026-11-10 — a manual redeploy now requires a matching theme label. Unlabelled pre-307 images pass silently on staging and with a warning on production, so that rollback to a pre-307 SHA still works. At launch the operator chose "Promote, trim the AC-12 line" (2026-11-11): the durable `services/xstockstrat-ui/acceptance/ui-env-themed-bundles.feature` omits AC-12's third clause (`src/components/ui/sidebar.tsx` no longer contains `hsl(var(--sidebar-border))`) because it was a one-time fix assertion; `src/styles/noColorLiterals.test.ts:31` still enforces it as a unit test. The durable suite and `acceptance.feature` differ here on purpose.
- Execute-phase governance records: the operator gave a "no checkpoints" override for /sdd-execute — checkpoint reports were still printed but did not gate, only blockers (§5.7) stopped for a decision, so all 19 steps ran without checkpoint gates by sign-off, not by skipping. Fixing Deviation D-1 (the two `tsc` errors in `e2e/insights/backfills.spec.ts:135-136`, a file outside every declared Affected Services area) inside 307 was an operator-approved scope expansion, "Option A", 2026-11-11: a type-only fix (`let triggered = null as Record<string, unknown> | null;`) committed separately before Step 1.
- Contrast is fixed only in the production palette (`--primary` ~0.62 L with dark foreground; production chart-1..5 reach 3:1 on card). Staging values are frozen, so staging shortfalls are recorded as deviations, not fixed. `--chart-grid` is exempt from the 3:1 rule as decorative (WCAG 1.4.11); `ui-ux-governance.md` §5 omits it from the pair list without saying why — it is not an oversight. Smallest ΔE_ok between adjacent production chart entries is 0.092; a helper result >0.05 off an AC pin was a stop-and-re-pin condition.
- Operator widened scope to "tokenize everything now" (~28 /insights literals, per-theme manifest and themeColor), accepting that staging /insights colours move to Nocturne tokens. Staging PWA chrome (`themeColor`/manifest) went `#0a0e14` → `#0c0a09`, operator-confirmed at the round-3 gate: the old value never equalled Nocturne `--background` and FR-12's single-source rule forced the change.
- Check (b) is symmetric across both themes and runs in every build; the `ui-theme` CI filter was left narrow on purpose. A production-only check would let a shadcn `src/components/ui/**` PR pass PR CI and then break deploy-prod; the always-run staging `e2e-build` carries the guarantee instead (round 6 F3, round 7 item 4).
- The re-theme preflight is a separate job the build matrix `needs`, so a push is all-or-nothing. Threat it guards: `homelab-images.yml` can rebuild any ref under the same `<sha>` tag and would overwrite a production-themed image with the default staging theme, and a manual staging `deploy-homelab` pointed at a `main` SHA would pull a prod-themed image (recon). That is also why homelab-images takes a required theme choice instead of deriving it. `deploy.yml` got `require-match` as defense in depth beyond bring-up paths.
- One tree-identical `--no-ff` merge commit per promotion was accepted as the price of distinct SHAs.
- Why stone/emerald utilities are landmines: the frozen Nocturne staging tokens are Tailwind default-palette values (`--background` = stone-950, `--primary` = emerald-800, `--muted`/`--accent`/`--chart-5` = stone-800, `--sidebar-primary` = emerald-500). Any stone-*/emerald-* utility, or a `var()` of one, therefore fails both builds. The docs deliberately avoid naming palette families (no-self-matching rule), so the cause is not findable there.
- Check (b) margin is tight: the smallest is Δ5, between `#fff` (the white declaration and `--tw-ring-offset-color`) and staging `--foreground`. If either moves slightly every build fails. Escape hatch: move the colour into a theme token, or nudge the value by ≥2 per channel (Open Risk 11). UI CLAUDE.md documents the ±1 trap but not the margin or the nudge.

**Rejected alternatives**:
- In-leg re-theme guard — leaves a version-skewed partial push.
- `docker/login-action` on deploy paths — `scripts/sops-secrets.test.sh:1031-1032` pins prod-up's exact `uses:` list and `:1083` forbids `uses:` after resolve in deploy-homelab; GHCR login is a `run:` step.
- Grepping the build log for the checker's OK line — Docker cache hits skip `Dockerfile:20`; the CSS is re-checked after extraction from the image.
- Production-only palette self-check / widening the `ui-theme` filter to `services/xstockstrat-ui/**` — unnecessary given symmetric (b) in the always-run staging build.
- Asymmetric leak set — a pre-computed translucent fallback such as `bg-white/10` → `#ffffff1a` equals staging `--border`, so it would pass staging CI and fail deploy-prod.
- Check (a) on every token-name declaration — shadcn `sidebar.tsx` `[--radius:var(--radius-xl)]` would fail every build. Narrowing (b) to token names — (a)+(b) together cover every declaration.
- Classifying token declarations by value — minifiers rewrite values (`oklch(1 0 0/10%)` → `#ffffff1a`), never property names. Scanning selectors/at-rule preludes — `chart.tsx` escaped `\#ccc` and `@supports (… red, red)` paint nothing.
- Folding the `color-mix` % into alpha — Tailwind ≥4.1 already emits the pre-computed fallback, which (b) sees. Accepted blind spots: a bare `color-mix(…, #fff 10%, transparent)` with no fallback is compared at α1, and named colours are skipped by (b) (C-18 trade-off; (a) rejects them in theme-token declarations). Other accepted C-18 trade-offs: `--color-warning` deliberately duplicates the paper value (distinct role); the Node colour parser differs from the browser canvas path at `chartColors.ts:24`.
- An `hsl(var(` ban across all of `src` — matched the feature's own fixtures; only the sidebar assertion kept.
- `test.skip` on @AC-10 — a mis-themed image would skip instead of fail; each run asserts staging and the production job uses `--grep-invert`; AC-10 runs cannot be compared across processes, so each asserts the pinned bg.
- Two-dot / commit-count promote gate — `--no-ff` sync commits always count as "ahead". Re-merging inside the sync retry loop — serialization via `concurrency` chosen instead.
- `build/` dir (outside guard rails), layer-order assertion and per-theme GHA cache (YAGNI), enumerated `@source not` list (`source('..')` beats a deny-list), a second self-map fallback (dead — the `--font-sans` self-map already builds), lockfile in the `ui-theme` filter (dropped round 4).
- Moving only the `noColorLiterals` test to a later step — S6 would ship with AC-12 unasserted (the one-line `layout.tsx:20` edit was the smaller move). Checker CLI only from S5 — S4's `ui-prod-image-build` needs `--css-dir`. Keeping (b′) as its own code path — (a) and (b) already cover every occurrence. Registry via `github.repository_owner` or a per-workflow `REGISTRY` env — lost to a single `UI_IMAGE_REPO` constant with a prefix drift test (round-4 L5, round-5 item 4).
- Named rejected with no reason recorded anywhere: an aria `pathTemplate` override (dropped round 3), a Tailwind `@import` resolver, an `/app.webmanifest` rename, extracting the sync to a script, lab/lch support up front, the full e2e suite per theme, placement asserts in `ui-theme-label.test.sh`, reading Tailwind's `theme.css` to recognise palette literals.
- Runtime switch, two images per build, theme-suffixed tags, prebuild copy (runner-up), `[data-theme]` scoping, `app/manifest.ts`, skipping deploy-dev on the main SHA, a prerequisite split — named rejected, reasons lived only in non-repo round scratchpads (only the operator's story-time rejection of two-images/runtime-switch is on record).

**Scars & gotchas**:
- Webpack persistent cache does not follow an alias-target or `next.config` `env` change: a production build after a staging build in one tree emitted staging tokens. Fix: `config.cache.version` gains `|ui-theme:<theme>`. Only check (a) would have caught it.
- Tailwind 4.3.3 prunes unreferenced `@theme inline` vars (`--color-paper`, `--color-warning` never emitted; buy/sell survive only because `chartColors.ts` names them). Fallback: unlayered `:root` plus self-maps. Shipped side effect: the no-`color-mix` fallback for `bg-buy/20`-style utilities is now solid `var(--color-buy)` instead of a translucent `oklab()` literal (pre-2023 browsers; judged acceptable; the `@supports` path is unchanged).
- A bare `var(--color-stone-950)` string anywhere Tailwind scans emits the palette declaration and fails both builds: scan scope is `source('..')` plus `@source not` for tests and theme files; fixture names are concatenated.
- `next lint` lints `.cjs` (needed a `no-var-requires` override); `vi.resetModules` does not clear CJS `require.cache` (delete entries explicitly); `pkill -f "next start"` misses Next's retitled process (kill by `$SERVER_PID`, else a stale staging server answers the production curl — a false GREEN); `run-e2e.sh` mounts no volume (goldens via `docker cp`); host `pnpm test:e2e` starts `pnpm dev` and `warmup.setup.ts` exceeds the 10 s local timeout (specs ran with `CI=true`); shadow colours compose from vars in Tailwind v4 (grep `--tw-shadow:`); one combined AC-7 aria test overran 30 s so it was split into three; sops 3.10.2 gives different refusal text and fails `sops-secrets.test.sh` (needs pinned 3.13.3); a `: ` inside a plain YAML scalar in the homelab-images summary needed rewording; sandbox Docker builds needed a scratch harness (proxy/apt/corepack/Docker Hub 429).
- Local verification traps: after a standalone build a local `pnpm start` only prints a warning — local checks must prefix `NEXT_DISABLE_STANDALONE=1` (SD-3, accepted round 9); emitted CSS bytes differ from hand-computed palette hex because lightningcss gamut-maps (blue-500/20 emits `#3080ff33`, not the hand-computed `#2b7fff33`), so check-(b) collisions must be judged against the emitted CSS, never against values derived from Tailwind's `theme.css`.
- Self-matching scans recurred four times (the `hsl(var(` ban, the FR-10 `APPLICATION_ENV` scan hitting its own tests, a `next.config.js` comment containing the needle, check (a) failing Step 2 fixtures) — fixed by a spec-wide "no self-matching scans" convention block; review converged (14 warnings at iteration 4 → 0 at 9).
- Accepted risks that look like bugs but are not: preflight-vs-push has a TOCTOU gap that needs a concurrent homelab-images dispatch; a conflict-resolved sync PR counts as promotable under the three-dot gate (real content, acceptable); under `concurrency` without cancel-in-progress GitHub keeps only one pending run, so a third push inside the sync window cancels a pending run (real trap of the serialized-sync choice, accepted at round 5); MERGE_COUNT is cosmetic after `--no-ff`; `git diff` exit ≥2 is ruled out by fetch-depth 0.
- Deliberate action-pin mismatch: the new `ci.yml` jobs keep `ci.yml`'s `build-push-action@v6`/`setup-buildx@v3` pins while `docker-build.yml` uses v7/v4 (design §1 E) — do not "fix" it as drift. Reading `APPLICATION_ENV` for config scope (`traderBff.ts:27`, `insightsBff.ts:29` via `nativeConfigEnvironment`, `deploymentEnv.ts:8`, `telemetry.ts:47`) does not violate FR-10: its static test scans only the theme-selection files and `APPLICATION_ENV` never feeds styling; do not widen that scan. The checker depends on the CSS shape Tailwind 4.3.3 / Next 15.5 emit (`@theme inline` pruning, `color-mix` and fallback forms, minifier rewrites): any Tailwind or Next upgrade needs the checker re-validated, and if `source('..')`/`@source not` stop behaving, the recorded fallback is an enumerated `@source not` list (Open Risk). Homelab gets no theme of its own because homelab deploys reuse the image built by whichever workflow calls them; FR-14 guards the pairing.
- Steps 15–18 (deploy guards) were sequenced after the UI steps so the image label (Step 6) exists before any deploy path requires it.
- UI e2e specs are type-checked by nothing in CI (`next build` covers the app only): two `tsc` errors in `e2e/insights/backfills.spec.ts:135-136` shipped unnoticed and blocked the baseline.

**Cross-feature signal**:
- Any SHA-keyed artifact that differs per environment depends on main-dev never fast-forwarding to main; `--no-ff` sync, `concurrency` and the three-dot gate encode that (fails.md:3976) and future promotion-automation edits must keep it.
- Feature 342's series palette depends on check (b)'s `nonSharedTokens`: `--series-*` must stay byte-identical across both themes to stay out of (b). 307's N-set semantics are now load-bearing for 342.
