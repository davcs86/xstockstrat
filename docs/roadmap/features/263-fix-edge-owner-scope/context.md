## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 cross-tenant-read fix (debt-radar D-25, D-31; defect report `docs/reports/2026-10-21-edge-owner-scope-defect.md` (pruned 2026-11-04; git show 9892b610:docs/reports/2026-10-21-edge-owner-scope-defect.md)). Two seams now bind identity server-side. (D-25) The trader BFF `queryEvents` (`services/xstockstrat-ui/src/lib/traderBff.ts`) takes one of three branches: `copilot:` key is rewritten to the caller's own key; `account:<id>` is ownership-checked via trading `ListBrokerAccounts` (unowned/empty id -> PERMISSION_DENIED, trading error code passed through, owned -> forwarded unfiltered); every other key (incl. none) forces `ownerOnly:true`, an additive `bool owner_only = 7` on `ledger.v1.QueryEventsRequest` (`packages/proto/ledger/v1/ledger.proto:69`) enforced by a ledger predicate shared with `exportEvents` (`callerUserId`). (D-31) Config `boundReadUserId` (`services/xstockstrat-config/src/grpc/authz.ts`) rebinds a non-admin header caller's foreign body `user_id` to the caller on `GetConfig`/`ListKeys`; the agent echoes the effective id (`client.py:_effective_config_user_id`). 12 steps, launched 2026-10-30 via PR #1368 (df521ff5).

**Why (irrecoverable rationale)**:
- Config-side bind (not agent-only) because it closes all four edges in one two-line helper: agent, trader `getConfig` forward (`traderBff.ts`), insights forward (`insightsBff.ts`), and config-ui non-admin `ListKeys`. Config-ui admin view is safe because `backendHeaders` sets the 0x04 bit from the admin role (`bffShared.ts` / ui `auth.ts`) and config tests the same bit.
- Ledger filter is a typed opt-in proto field, not "scope when `x-user-id` is present", because internal Go callers (portfolio `GetPnL` `portfolio_service.go:534/:751/:796`, trading `trading.go:2222`) read `order.filled` history written with NULL `user_id` and would silently lose it; historical rows are NULL and UPDATE is denied on `ledger.events`, so no backfill was possible.
- `account:<id>` streams are NOT user_id-filtered: trading writes `reconciliation.*` rows NULL-owned (`trading.go:1930`, `:3669`), so a predicate would empty `useReconciliationStatus` for the legitimate owner. Ownership is decided by the account list, owned -> unfiltered.
- Per-call `ListBrokerAccounts`, no cache: a cache risks a stale ownership set; the extra trading RPC per `account:` poll (doubles BFF->backend fan-out per tick) was accepted.
- Trading error is passed through (UNAVAILABLE / DEADLINE_EXCEEDED), not relabelled PERMISSION_DENIED: still fail-closed (no ledger call, no fall-through) but does not report an outage as "forbidden".
- Agent echo fix exists because config returns no effective scope: `client.py` echoed the *requested* `user_id`, so a bound result would be labelled with the foreign user and an LLM would misreport whose data it was. Fixed locally from `_CALLER` + `scopes._ADMIN` (no proto change, no ctx plumbing, ctx-less tests keep passing). It was the only blocking objection left at design round 2 and the operator approved "as synthesized, including the agent echo fix" (the echo is kept, not dropped).
- An empty body `user_id` from a non-admin is never bound (stays "global"): recon raised it as a C-11 fork and kept empty as global because the spec binds only a *foreign* id, AC-6 passes the caller's own id, and it preserves `@AC-13 @feature-219` (`recon.md@1ed63958:232-234`, `design.md@1ed63958:258-259`).
- Locus reversed between recon and design: recon recommended the agent-tool bind as primary, config-side only as optional defence-in-depth "weighed against YAGNI", and leaving `client.py` untouched to avoid 247/273 (`recon.md@1ed63958:276-282`). Design round 1 moved the fix to config (`design.md@1ed63958:276-279`); the adopted echo fix then touched `client.py:2034-2080` anyway, re-creating the 247/273 collision recon was avoiding.

**Rejected alternatives**:
- Agent-tool-only bind via `ctx` — lost: closes only the agent edge, leaves BFF `getConfig` forwards and config-ui non-admin path open, and breaks ctx-less `tests/test_config_tools.py:78/:320/:328`, and `TestSdkWiring` / `test_config_tools_expose_no_environment_parameter` must keep `ctx` out of the tool schema (`recon.md@1ed63958:229-231`).
- Minimal BFF `userId` pins as `listOrders` does — lost: three edits, agent edge still needs its own fix, config-ui `listKeys` becomes a follow-up.
- Refuse a foreign `user_id` with PERMISSION_DENIED — lost: operator override 2026-10-22 (bind, not refuse); no Floor breach to justify reopening.
- Proto `effective_user_id` on `ConfigSnapshot`/`ListKeysResponse` — lost: correct but a second proto change + approval gate; local computation is lower rework.
- Copy the `exportEvents` predicate verbatim into `queryEvents` — lost: two copies drift (C-18); shared `callerUserId` helper instead.
- Ledger filter keyed on `x-user-id` presence — lost: hides NULL-owned `order.filled` from portfolio GetPnL and reconciliation rows (above).
- Ledger `user_id` filter on `account:<id>` streams — lost: hides owner's NULL-owned reconciliation rows, breaks AC-3.
- Gate on `x-internal-caller` header or peer-SAN instead of a typed field — lost: untyped header is easy to drop; no evidence ledger can read SAN identity. Kept only as the escalation fallback if the C-09 proto gate stalled; the C-09 outcome is not recorded (still open at Step 1, old context.md@1ed63958:472), launch implies it cleared.
- BFF-only post-filtering — lost: short/empty pages with an opaque `next_page_token`, and other users' rows pulled into BFF memory.
- Owned-order branch for NULL `order:<id>` rows — lost: YAGNI, no consumer; recorded as accepted limitation.
- Cache `ListBrokerAccounts` per poll — lost: YAGNI / stale ownership risk.
