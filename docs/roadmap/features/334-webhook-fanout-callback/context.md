**Feature**: ./feature.md
**Status**: launched — archived by /sdd-archiver; verbose specs pruned (recoverable via git history).

## Archive Synthesis — 2026-11-18 — /sdd-archiver

**What**: Publisher side of the three-repo `webhooks-mcp` project. `trigger_backfill` takes an optional `callback_url`; notify checks it before any job row exists via a `validate_only` call of `FanoutWebhook` that fails closed. When the job ends, ingest hands it off once from a single sweep loop that every terminal write wakes; notify stores it in `notify.webhook_deliveries` and a worker on notify's one shared DB connection delivers at-least-once. Verified locally during a GitHub Actions outage, green in CI on PR #1523, launched 2026-11-13 via #1525. Left outside the feature: the staging end-to-end (upstream S7, waits on the live listener) and setting the allowlist in any environment.

**Why (irrecoverable rationale)**:
- The owner fixed the RPC name `FanoutWebhook`, the wire format, "delivery lives in notify" and "no ledger tail / no notify→ledger dependency"; changing any means stop and report. Only two points were delegated: how to reject up front and whether to add an `x-internal-caller` gate.
- `quick` design depth was kept despite recon's escalation signals (proto change, migrations, four services) because the architecture was already debated and approved upstream (webhooks-mcp design §4/§5/§8 at commit `ad7e0ec`); the owner's "start the full implementation" served as the confirmation for in-scope SDD steps, so P-04 and checkpoint gates were not re-prompted.
- Notify has one pooled DB connection shared by every handler; holding a claim across an HTTP call would stall `EmitAlert`. So the worker uses single `pool.query` statements, an in-memory in-flight set as its claim (valid only because notify runs one instance) and computes `next_attempt_at` in SQL (recon:226-227; D-8, R-9).
- One hand-off path in ingest: terminal writes sit at 7 sites in 5 paths with no shared helper; T6 (restart reconcile) emits nothing and T6→T7 can give one job two terminal statuses. A path that selects by row state, woken by an `asyncio.Event`, covers all by construction and keeps every notify call off the backfill path (D-11).
- Once per job, no `error` in the payload: re-publishing per status change would turn the restart re-drive defect into contradictory webhooks; `error` is written only by T1/T6 so a stale reconcile error could ship inside a COMPLETED payload; `str(e)` can carry internal gRPC hostnames off-platform. The agent reads the error via `get_backfill_status` (O-1/O-7/D-12/D-13).
- Sweep default stays 60 s: a sweep-only design would have contradicted FR-3 / upstream §8.1 ("call at terminal state") and silently changed the default 60→30 (O-2). `callback_url` is not on `BackfillJob` (INGEST-11: `GetBackfillStatus`/`ListBackfillJobs` return every job to any caller; echoing it would expose minted capability URLs; D-16).
- `PERMISSION_DENIED` at trigger maps to `FAILED_PRECONDITION` + ERROR log (certificate/allowlist misconfiguration, not transient; `UNAVAILABLE` would be retried forever by the sweep; O-6). The dead-letter alert body carries idempotency key, attempts and error because notify's 300 s dedup (feature 020 @AC-5) would otherwise collapse two dead rows into one alert. The `dead` metric and ERROR log are recorded before the alert insert so a failed alert insert is not lost silently (O-16).
- No signing or authentication of the outbound POST, by decision (product-spec Out of Scope): reachability of the target is the listener's control. Also excluded by decision: `callback_url` on any other long-running RPC such as `RunBacktest`, and any UI for it (UI-started backfills carry no callback). An unsigned webhook is intended, not a security bug.
- Surfaced decisions (within delegated latitude): fifth field `validate_only` (upstream §8.2 lists four); fail closed (`UNAVAILABLE`, no job) when notify is down; comma-separated string allowlist; publish once per job with no `error`; `occurred_at` is notify's accept time with `completed_at` inside `data`. AC-20's treatment of `INVALID_ARGUMENT` at job end as terminal plus one WARNING alert is this feature's own extension — upstream says only "the publisher must not retry it".
- Accepted incompleteness: a payload rebuilt from the row (D-11) can differ from one built at the write site — T4's "all chunks failed" text and T1's failed symbols are never written to the job row, so a T1-FAILED webhook can carry an empty or partial `failed_symbols`; this is the accepted cost of D-11, not a bug (the `error`-column half is above). Accepted head-of-line risk in the sweep (O-10 closed by D-14): the cycle picks the oldest job first and stops on any code other than OK or `INVALID_ARGUMENT`, so an old job that keeps failing with an unclassified code delays every later hand-off until notify answers it; `INVALID_ARGUMENT` has its own terminal marker and other codes are treated as notify-wide outages — do not "fix" it by skipping failed jobs (that loses stop-on-outage).
- Redirects kill the delivery instead of being followed (`redirect: 'manual'` plus 3xx → dead) because the story read FR-5's "allowlist enforced on every delivery" so: following a redirect would reach an origin the allowlist never checked (product-spec OQ; notify CLAUDE.md records the behaviour, not the reason). Owner-fixed: "Ledger events are unchanged (audit only, no `callback_url` stamped on them)" — adding `callback_url` to the backfill ledger events would break an owner-fixed constraint. `occurred_at` is the row's `created_at` so it stays identical across retries (every retry sends an identical envelope; do not switch to send time, D-4).
- Why the seed could not land in one unit with its readers: D-15 fixes one migration for six keys read at three sites; a unit is capped at four steps; a reader before its seed fails as `read-unseeded`, so no ordering avoids `seeded-unread`; two `config-wiring.test.mjs` tests assert the `--final` exit code. Hence one temporary baseline entry per key, each removed in the commit that adds that key's reader (a leftover fails `--final` as `STALE`).
- "Artifact generation is not verification": `/sdd-execute` bans starting a database, intended for step verification. `scripts/config-wiring-stored.json` can only be produced by applying migrations to a real Postgres (it hashes the generator's own sources, `inputs_sha256`), so a short-lived scratch Postgres to generate it was used — an orchestrator decision under the owner's standing authorization, flagged for the owner (sdd-spec "Step 3 needs a scratch Postgres"; impl-spec Deviation Log Step 3), NOT an explicit owner sign-off and not a general exemption from the database ban; the JSON is never hand-written, and if no Postgres is reachable the step is blocked. This recurred at integration (#1517 conflicted only on `inputs_sha256`; fix = regenerate on a scratch TimescaleDB, not hand-merge).
- The delivery-time `displayOrigin` is safe: a stored row passed the URL rule at accept, so its host was operator-allowlisted then; the rule module returns no origin on rejection, hence the local `hostname:port` derivation.
- `index.ts` casts the implementation to `grpc.UntypedServiceImplementation`, so a missing handler compiles and fails only at runtime with `UNIMPLEMENTED` — that is why a "method exists on the impl" test exists. The ingest caller-gate detail deliberately ends "no job was created"; `FAILED_PRECONDITION` is already a pass-through code so the agent never reports "outcome unknown" for it (mcp-tools.md).

**Rejected alternatives**:
- R-1 ingest reads notify's namespace and runs the allowlist — two parsers in two languages break notify as the single enforcement point (FR-5). R-2 separate `ValidateWebhookUrl` RPC — more surface for the same check. R-3 accept job when notify is down, decide at job end — silently breaks FR-2's trigger-time guarantee.
- R-4 `x-internal-caller` header — self-asserted, adds nothing over the verified certificate SAN. R-5 leave `FanoutWebhook` ungated like `EmitAlert` — the agent reaches notify and holds user input, so it would be a POST relay; the gate also makes `source_service` unforgeable.
- R-6 JSON-array allowlist with a new `getJson` — the watcher file is byte-identical across three services and a proto Struct cannot be a bare array. R-7 inline call at each terminal site with the sweep as safety net — seven sites, two payload builders (live vs row) that can disagree, a notify call on the backfill path. R-8 re-hand-off on status change — externalizes the restart re-drive defect. R-9 persisted claim column / `FOR UPDATE SKIP LOCKED` — YAGNI at one instance and a row lock needs a held connection notify cannot spare.
- Per-step scratch-Postgres verification (design O-9) — conflicts with the executor's database ban; upgraded to a CI assertion file (see deviations).

**Scars & gotchas**:
- `buf breaking` baseline must be `origin/main-dev`, not the feature branch — comparing against the feature branch compares the change with itself once committed; the spec template got this wrong.
- `migration-rerun` pins each service's clean end state as a literal (`ingest:14`); recon missed it and any new ingest migration breaks the job; it recurred when main-dev ported `migration-rerun.sh` to `.py` (#1520) mid-PR (accept the deletion, carry the one-literal change into the `.py`).
- `context.abort` must stay OUTSIDE the `try` that classifies the RPC error: it raises (in production and in the test fake), and inside the `try` the `except` would turn a notify `INVALID_ARGUMENT` into `UNAVAILABLE`. The whitespace/control-character check runs on the raw string before parsing because WHATWG parsing strips those characters — moving it onto the parsed URL would silently weaken the SSRF guard.
- Worker tick period, slot cap, batch size, size limits and the 5 s timeouts are code constants, not config keys, by repo precedent (`fanout.ts:14`; design C-05/F-07); D-8 fixed only that they are constants — the values (5000 ms, 4 in flight, batch 50) were proposals, not deliberate. The 5 s validate-call timeout was sized to stay inside the agent's 45 s `TriggerBackfill` deadline (@AC-5/@AC-10 @feature-273). The temporary `seeded-unread` baseline entries contradicted the spec's "Do not add a `findings` entry" (Step 3 instruction 4); the orchestrator decided under the owner's standing authorization.
- Governing upstream source: `docs/superpowers/specs/2026-11-11-webhooks-mcp-design.md` (§4/§5/§8) and §7 of `docs/superpowers/plans/2026-11-11-orchestration.md` (brief, step order, S7 check) in the public `webhooks-mcp` repo, branch `main` — feature.md names only "webhooks-mcp". Adding an RPC to `NotifyService` needs no Go test change: the Go fakes of `NotifyServiceClient` in trading and marketdata tests embed the interface.
- URL-rule edges: a `*.host` entry is a literal host, not a wildcard; an upper-case `HTTPS://` prefix or an entry with a path, query, userinfo or whitespace is malformed and matches nothing; a URL containing a backslash is judged by the host the WHATWG parser lands on, so delivery must POST the parsed `href`, never the raw string. Each weakened comparison (`endsWith`/`startsWith`/`includes`, host-only) was shown to fail a named test; removing the five `_webhook_wake.set()` calls, alert-before-marker ordering or `error` in the payload fails 18 tests.
- `MagicMock` `TriggerBackfill` requests return a truthy mock for an unset `callback_url` (each needs `callback_url = ""`); an agent test reading ingest's `servicer.py` runs only if that file is in the agent's CI path filter (PLAT-18; added to `ci.yml`); notify's `tsc` compiles tests so a RED run needs stubs of the new exports first; no telemetry-test change was needed because notify's telemetry tests check label keys only and enumerate no channel/outcome values — `'webhook'`/`'dead'` are pinned only by the worker test; local tooling stand-ins (dockerd for codegen, scratch migrator image, host golangci-lint v2.5.0 refuses go 1.27).
- A flaky indicators test, `test_sandbox_watchdog.py::test_ac8_fork_bomb…`, fails under host load when run in parallel with other suites and passes alone — unrelated to this feature; route to indicators findings.

**Permanent deviations**:
