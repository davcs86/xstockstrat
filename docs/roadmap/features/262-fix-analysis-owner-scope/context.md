## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 Track C bug fix (debt-radar D-44, D-55, D-60; defect report `docs/reports/2026-10-21-analysis-owner-scope-defect.md`), all inside `services/xstockstrat-analysis`. The boot entry-backfill (`app/engine/entry_backfill.py`) now sends trading `ListOrders` with the row owner as both body `user_id` and `owner_metadata(user_id)` plus one per-pass `x-trace-id`, so one owner's fills no longer seed another owner's live entry state. `run_once` now honours its "never raises" contract: strategies read, blend-universe resolve, system-signal drain, row parse, held/watch prep, owner-signal drain and `resolve_universe` are each isolated, and `gather(..., return_exceptions=True)` results are logged. The dead owner-agnostic `StrategiesRepository.get_by_id` / `.update` were deleted and ~30 stale test mocks removed. No proto, migration, config, trading or `main.py` change. Launched 2026-10-30 via PR #1368 (commit df521ff5).

**Why (irrecoverable rationale)**:
- The body `user_id` is load-bearing and the header alone is not enough: trading adds no owner predicate when `user_id` is empty (`services/xstockstrat-trading/internal/repository/trading_repo.go:229-232`). Both are sent so the call stays correct if trading later scopes non-admin `ListOrders` by `x-user-id` (open sibling report `docs/reports/2026-10-19-trading-listorders-body-user-id-filter-defect.md`, sidecar `open`). Rejected "header only" for this reason (`design.md@1ed63958:133`).
- Failure isolation was split by scope on purpose. Only a held/watchlist prep failure poisons an owner (`failed_owners`); a malformed row, a `resolve_universe` failure or an owner-signal drain failure is row-scoped, because poisoning on a parse failure would silently drop that owner's other valid strategies (`design.md@1ed63958:53-62, 121-122`; `old context.md@1ed63958:416-418`).
- Why an owner-signal drain failure does not mark the owner failed: if it shared the held/watch `try` and added the owner to `failed_owners`, that owner's earlier rows would already be queued while its later rows were dropped, so FR-3 would hold only halfway (`old context.md@1ed63958:271`, round-2 objection). It gets its own `try` and falls back to `system_signals` (`design.md@1ed63958:60-61`). Product-spec FR-3 (`product-spec.md@1ed63958:44-46`) listed the owner-signal drain among the failures after which "that owner's rows are skipped"; the design narrowed that so only held/watch prep poisons the owner, and the shipped fallback is `own_cache[owner]=set()` unioned with `system_signals` (`app/engine/entry_backfill.py:166-177`). No promoted scenario covers an owner-signal drain failure.
- The `x-trace-id` is minted per pass because the boot backfill has no originating request; the operator's standing trace-id decision of 2026-10-21 ("as much as possible", rationale per `old context.md@1ed63958:204` and `:419-420`) beat "record that no trace id exists" (`design.md@1ed63958:125-126`). Full standing wording is recorded in `docs/roadmap/features/265-fix-identity-auth-code-race/context.md:72`: x-trace-id must be propagated as much as possible; no C-03 waiver; only work with no originating request (background sweepers/loops) may mint its own context, and it should still carry a trace id when one is available.
- Scope was fixed by the operator on 2026-10-21 (grouped by service+theme from the 2026-10-20 debt-radar scan, Track C for all SEV-2 per precedent #1264; scope is D-44/D-55/D-60 only, trading-side `ListOrders` report stays separate) (`old context.md@1ed63958:14, 52-54`). Reason for Track C beyond precedent not recorded.

**Rejected alternatives**:
- Mechanically renaming `get_by_id` to `get_by_owner_and_id` in test mocks (round-2 rules for sites 684/799/4500) — lost because every site already set `get_by_owner_and_id` on the next line, so a rename creates duplicate assignments where the later silently wins, and step bodies are immutable once approved (F-09) (`design.md@1ed63958:113-116`).
- Atomic cache writes without `failed_owners` — lost because `system`/empty owners would re-drain and re-warn on every row (`design.md@1ed63958:117-118`).
- One `try` around the whole per-row body (recon's first cut) — lost because it cannot tell a malformed row from a failed owner prep (`design.md@1ed63958:119-120`).
- Failing the owner on a parse failure — lost (drops the owner's other valid strategies) (`design.md@1ed63958:121-122`).
- Per-pair trace id — lost because a boot pass is one unit of work; per-pass plus logging is enough (`design.md@1ed63958:123-124`).
- Copying `live_loop.py:522` into an `AsyncMock` side effect for `@AC-3` — lost because the copy goes stale silently; the real `LiveEvaluationLoop` helper existed (`design.md@1ed63958:127-128`).
- Scoping the blend-universe guard out to a follow-up — lost because it leaves a whole-pass abort when one `try` reusing the existing empty-universe skip fixes it (`design.md@1ed63958:129-130`).
- Owner-scoping `get_by_id`/`update` instead of deleting — lost to C-18 duplication of `get_by_owner_and_id`/`update_locked` and 0 callers in `app/` (`design.md@1ed63958:131-132`).
- Catching only `ValueError` — lost because FR-3/`@AC-8` require any drain failure to be isolated; `except Exception` still lets `CancelledError` (a `BaseException`) propagate (`design.md@1ed63958:135-136`).
- Rewording `@AC-8` to match the implementation — lost as rework with no behavior gain, because the test already drives a raising `_drain_held` (`old context.md@1ed63958:203`, r1 synthesis; not in design.md). Consequence: the promoted `@AC-8` "portfolio RPC error" wording stays slightly inaccurate (`recon.md@1ed63958:191-197`; see Scars) -- do not "fix" it later without this context.

**Scars & gotchas**:
- `@AC-8` says "portfolio RPC error", but the real `_drain_held`/`_drain_watchlist` already catch their RPC errors and return a partial set (`app/engine/live_loop.py:534-536`; `_drain_signals_with` `:501-503`; `recon.md@1ed63958:191-196`). The scenario therefore holds only against a mocked drain that raises; the production value of the broad `except` is unexpected errors such as `owner_metadata`'s `ValueError`. The `_drain_system_signals` guard likewise can fire only in tests, so no comment may claim it protects production (`design.md@1ed63958:50`, `old context.md@1ed63958:120`).
- A partially filled cache is a trap: if `held_cache[owner]` is set but the watchlist drain then raises, a bare `continue` leaves the next row of that owner hitting `KeyError` at the `resolve_universe` read. Held and watchlist are drained into locals and committed together (`recon.md@1ed63958:185-190`; `design.md@1ed63958:57-59`).
- Keep the blend skip ahead of `resolve_universe` and any `ListOrders`: that ordering is what preserves 193 `@AC-3` (`design.md@1ed63958:63-64`, `:178-181`).
- `LiveEvaluationLoop.__init__` defaults `cooldowns_repo=None` and `_write_entry_cooldown` returns early on `None`, so the real loop is safe to build in the `@AC-3` test (`old context.md@1ed63958:487-489`).
- The test helper moved to `tests/conftest.py` as `real_live_loop(ingest, indicators, rows, *, config_watcher, marketdata_stub)` with its two dependencies injected, so conftest never imports a test module; the header-guard file keeps a one-line `_live_loop` wrapper (`old context.md@1ed63958:450-455`). The collision fallback with 244/246 was not needed because their helpers were already in conftest (`old context.md@1ed63958:530-531`).
