## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug fix (triaged from `docs/reports/2026-10-19-agent-get-config-value-no-deadline-defect.md` (pruned 2026-11-04; git show 9892b610:docs/reports/2026-10-19-agent-get-config-value-no-deadline-defect.md), flagged by feature 227). `client.get_config_value` in xstockstrat-agent now passes `timeout=_CONFIG_READ_TIMEOUT_S` (fixed 3.0 s module constant in `app/client.py`, read at call time) on `GetConfig`, so a config service that accepts connections but never answers makes `extract_website_content`, `extract_email_content(urls)`, `ingest_signal`'s alert-threshold read and `/oauth/register` fall back (they already caught `Exception`) instead of hanging to the MCP client's timeout. The `except` was narrowed to `grpc.aio.AioRpcError as e` and now logs `e.code().name` (`get_config_value: GetConfig %s for %s.%s`), then re-raises. Callers unchanged. Single service (agent); no proto, migration or config key. Integration PR #1338; promoted to main via PR #1368 (commit df521ff51091a86e813950b34afff09ac4e8821b), launched 2026-10-30.

**Why (irrecoverable rationale)**:
- D is a fixed constant, not an `agent.*` config key, because a config read cannot bound itself (circular); precedent `_POLICY_READ_TIMEOUT_S` (design.md "Rejected": D as a config key; F-07). D is also not a literal in `_fetch_url` (preserves `@AC-8 @feature-207`).
- Deadline lives in the helper (one site) rather than at the four callers, because per-call-site deadlines would be four edits and would put D as a literal in `_fetch_url`.
- The feature-227 `asyncio.wait_for` (`tools.py`, `_POLICY_READ_TIMEOUT_S`) was KEPT. Reason: removing it is a C-16 CHANGE to `@AC-2 @feature-227` with no operator decision covering it, and it breaks the pinned tests `test_list_opportunities_deadline.py:78-88`. Third reason: removing it drops the guard against a future increase to D. Not for channel setup (the gRPC deadline already covers connect/handshake/call). The two 3.0 s constants are deliberately NOT aliased (two different test seams: outer tool bound vs RPC deadline); the DRY duplication was accepted (How-to-Act #3).
- Serial reads were left serial ("option (a)"): `_fetch_url` = 4 x D, DCR = 2 x D, `extract_email_content` = N x 4 x D. The right remedy (one `GetConfig` snapshot per tool call; `config.proto:49` already returns the whole namespace) adds a client helper, changes the AC-2 bound and is Out of Scope (performance), so it was deferred rather than done.
- Status code in the warning (`DEADLINE_EXCEEDED` vs `UNAVAILABLE`) was added so a stall and config-down become distinguishable; `tools._grpc_error_message` was not reused because client importing tools is an import cycle.

**Rejected alternatives**:
- Deadline at each of the four call sites — lost: four edits, D literal in `_fetch_url` violates `@AC-8 @feature-207`.
- D as a config key — lost: circular (F-07).
- Per-call `timeout=` kwarg on `get_config_value` — lost: C-18 YAGNI; all four callers want the same D, the one differing caller (`get_config`) is excluded.
- `asyncio.wait_for` around the stub call — lost: raises `TimeoutError` not `AioRpcError` (breaks the feature-093 contract that `None` means only "key absent"), sends no `grpc-timeout` to the server, skips the client log.
- Removing the 227 `wait_for` — lost: uncovered C-16 CHANGE; breaks pinned tests.
- `asyncio.gather` over `_fetch_url`'s four reads — lost: layers concurrency on four duplicate RPCs/handshakes (the anti-pattern at insights.md:2240-2244).
- Fail-fast in `_fetch_url` (use defaults after the first `DEADLINE_EXCEEDED`) — lost: changes callers, overlaps the snapshot follow-up, email stays unbounded for large N.
- Single snapshot read in this feature — deferred (see follow-ons).
- Deadline on `client.get_config` too — lost: different caller shape (operator-supplied namespace/user_id, surfaces its error; ledger fails.md:2936-2951 rule: enumerate caller shapes before changing a shared RPC's failure behaviour) and Out of Scope.
- Fail-closed DCR (503 on config read failure) — lost: contradicts FR-2 / AC-4 (201).
- Leaving the false comment at `oauth_server.py:102` and logging it only in findings — lost: a false security invariant on a path this feature widens; one-line comment fix is cheaper.
- `grpc.aio.server` test harness — lost: the `TestClient` portal-thread event loop used by AC-4 cannot service a pytest-loop-bound aio server; `httpx.ASGITransport` for AC-4 also lost (skips ASGI lifespan).
- AC-1 at a patched D — lost: the kwarg pin proves wiring, not end-to-end expiry at the production value; AC-1 therefore runs at the real 3.0 s (adds ~3 s to the suite).
