## Archive Synthesis — 2026-10-14 — /sdd-archiver

**What**: Marketdata treats SEC EDGAR as the single fundamentals source for the backtest point-in-time (PIT) path and the live snapshot. The EDGAR aggregator is unit-aware and captures the real reporting currency; D/E uses financial debt; P/B and P/E are currency-consistent at the filing boundary; a PIT dividend yield comes from Alpaca corporate-actions. The snapshot has a live-read `snapshot_source` axis (`vendor` default, flipped to `edgar` at rollout). FMP and Finnhub are disabled by config only, not deleted. Triggered by a BABA/AXP backtest-vs-live divergence on `fundamentals_macd_blend` (composite ~0.35 PIT vs ~0.70 live) that was a source/methodology mismatch, not a fundamentals change.

**Why (irrecoverable rationale)**:
- The seeded `fundamentals_value_quality` bands (`de_bad=2.0`, `pb_bad=5.0`) assume the financial-debt D/E convention; EDGAR total-liabilities/equity gave ~4.64 for BABA.
- Full EDGAR-canonical was required, not optional: a PIT-only fix leaves the ROE convention split (EDGAR ending-equity ~52% for BABA vs vendor TTM ~7%) and re-opens the @AC-9 divergence. (This describes the 211-era convention; feature 222 later made quarterly-row ROE trailing-twelve-month — do not read it as current.)
- Operator decisions: dedicated `snapshot_source` axis; P/B and P/E option (b) (prefer a USD-unit fact, else missing); Alpaca dividend feed (no new fundamentals vendor). Two C-16 CHANGE sign-offs (2026-09-26): repointing the snapshot at EDGAR overrides the feature-198 doc contract "provider never takes edgar / EDGAR is a separate PIT lane"; "stop hardcoding USD" is a currency-semantics change — consumers must never cross-currency-aggregate absolute fields.

**Rejected alternatives**:
- Overload `marketdata.fundamentals.provider` with `edgar` — couples client construction, config namespace and quota shape; forces `if provider==edgar` at every read site and leaves the fallback accidentally `default→fmp` (feature-129 fallthrough trap).
- PIT-only fix ("(Y)") — fails @AC-9 on the ROE split and does not retire the vendor.
- P/B option (a) (absent on any mismatch) as the sole rule — option (b) gives real P/B for ADRs that dual-report USD; (a) stays as fallback. Option (c) historical FX feed — a second data-source integration beyond scope.
- Keyless always-on EDGAR gate — leaves no rollout lever; a real `marketdata.edgar.enabled` kill switch was chosen.
- Uncached live `GetHistoricalFundamentals` + `CloseAt` per call — N scans/N ohlcv reads per screener call would re-open feature-141 "out of shared memory" (F-06); write-through cache chosen. A bounded-lookback reuse of `GetHistoricalFundamentals` was also rejected as "more robust … would miss a slow filer"; the dedicated `LatestHistoricalFundamental` single-row read serves both reasons.
- One-time cutover cache purge — source-aware self-heal keeps cutover instantly reversible (purge kept as fallback). Boot-bound `snapshot_source` — a live-read axis gives instant reversible cutover.
- Dividends from EDGAR or FMP — EDGAR rarely carries clean per-share cash-dividend facts; FMP is being disabled.
- Cache invalidation by plain string inequality — rejected for a mapping: `edgar`→edgar axis; `fmp`,`finnhub`→vendor axis; `edgar+fmp`→edgar axis.

**Scars & gotchas**:
- BABA's only recent financial-debt tag is `ConvertibleDebtNoncurrent` (USD 8,098M); `DebtCurrent`/`ShortTermBorrowings` stop after FY2018/19. Do NOT sum `SeniorNotes` (stale in AXP, FY2015 only; double-counts `LongTermDebt`). BABA/AXP/AAPL all report under `us-gaap`; the `ifrs-full:*` branch was dropped (non-us-gaap filers are a separate future feature). Debt tags must be verified against live SEC companyfacts, never guessed.
- BABA dual-reports `StockholdersEquity` in CNY (1,060,886M) and USD (153,796M), which makes option-(b) P/B work; the aggregator stashes `stockholders_equity_usd`. The aggregator originally kept a first-seen value over a nondeterministic Go-map range and discarded the XBRL unit key; fixed by keying `metric→unit→value` and picking currency by vote (most monetary facts; per-share/share units excluded; lexical tiebreak — @AC-1 passes only because BABA's CNY and USD fact counts tie and "CNY" wins lexically). Currency is pinned to the earliest-filing unit set so a re-backfill cannot flip a stored period; a later-amendment restatement is an accepted residual needing manual purge + re-backfill.
- The `ratioEnricher` seam warns TTM ratio sources are a PIT look-ahead risk, which is why D/E comes from filing tags and P/B from price-at-filing.
- CI-caught: making an unknown `provider` boot-fatal (`os.Exit`) broke the always-non-nil canary `TestNewFundamentalsSource_AlwaysNonNil`; Step 11 verification ran `./internal/...` only. Fixed to WARN + FMP fallback. Unknown `snapshot_source` likewise WARNs and fails safe to `vendor`; the config service has no allowed-values check for string keys.
- `GetBool` returns `false` for a missing key, so `marketdata.edgar.enabled` needs an explicit `true` default, and a test omits the key to prove it. The edgar snapshot builder sets `Source="edgar"` explicitly because the repo defaults an empty source to `'fmp'`. FR-8 provider-keyed-literal audit: TTL reads in `resolveFundamentals`/`GetFundamentalsMulti` use `marketdata.<provider>.cache_ttl_hours` (edgar needs its own); `enrichmentUnderCap()` reads `marketdata.fmp.daily_request_cap` in the backfill lane (feature 198) and the `edgar+fmp` mapping depends on it; `newFundamentalsSource` reads `finnhub.base_url`/`fmp.base_url`/`fmp.metrics` — vendor clients are always built and gated only at use. Keys are read before migration 030 seeds them, mitigated by in-code defaults.
- Dividend semantics: feed present with no payments → `dividend_yield=0`; feed absent/errored/disabled/unentitled → nil ("—"); never conflated; a post-filing `ex_date` must not count. As built in 211 the fetch lookback (default 2y, seed `dividends.enabled=false`, `backfill_lookback_years=2`) is shorter than the history backfill (10y), so periods filed >~1y before the fetch start computed a false 0; the 3→2 seed alignment was NOT a fix — feature 216 later added the guard (`marketdata_service.go:1997-2001`). `FUNDAMENTAL_METRICS` already had pb_ratio/dividend_yield/debt_to_equity from feature 204, so FR-6 UI work was only provenance (currency/source), CSV columns and a USD-basis hint. Two pre-existing tsc errors sit in `e2e/insights/backfills.spec.ts` and `src/middleware.test.ts`.
- Numbering: PR #1186 (this feature) and #1185 (security batch 207–210) both merged as `207`; this feature was renumbered 207→211, leaving a stale `@feature-207` tag in Steps 15/16 that the impl-spec review flagged (corrupts C-16 traceability).

**Permanent deviations (shipped contradicts design/spec)**:
- IFRS/`ifrs-full:*` allow-list → shipped us-gaap only with the grounded tag set (direct SEC fetches).
- Non-USD P/E via native or USD-unit EPS → shipped P/E only when `Currency=="USD"` (Step 2 stashed only `stockholders_equity_usd`, no `eps_usd`); consequence: after the live-flip every non-USD filer has NO P/E, where the vendor path gave one.
- Snapshot "latest filing + live price-join" → shipped `edgarSnapshotFromPeriod` (`marketdata_service.go:1569-1592`) overlays the live mid on `Price` only; `MarketCap`, `PERatio`, `PBRatio`, `DividendYield`, `DebtToEquity`, `ROE` and `AsOf` (the filing date) are copied from the stored period (parity with PIT for the same filing was chosen over live recomputation; this explains the open @AC-12 "Last refreshed" thread). Price falls back to the filed-date close when no live quote exists.
- `GetHistoricalFundamentals`+`filterAsOf` for the latest period → dedicated `LatestHistoricalFundamental` (`marketdata_repo.go:773-780`), which orders by `period_end DESC` across annual AND quarterly rows with no period-type preference, so a quarterly row can supply single-quarter EPS (and pre-222 ROE) to the snapshot where the vendor gave TTM.
- Unknown `snapshot_source` fails loud / unknown `provider` boot-fatal → shipped WARN + safe default (above).
- Dividend currency: the spec-time research note claimed "currency ≠ trading currency → dividend_yield missing"; design.md:54 actually assumed USD/USD, and `alpaca/client.go:264` hardcodes `Currency: "USD"` and parses only `ex_date`/`payable_date`/`rate` (never `currency`/`foreign`/`special`). UNGUARDED assumption, not a decision; contradicts the "stop hardcoding USD" sign-off for ADRs. The dividend table PK `(symbol, ex_date)` (`marketdata_repo.go:526-531`) collapses same-day regular+special dividends (undercounted T12M). The window filters `ex_date <= asOf` only (`marketdata_repo.go:551`); `pay_date` is stored but unused; `SumDividendsInWindow`'s "has any row" bool is discarded (`marketdata_service.go:1991-1992`) and the zero-payer-vs-missing-feed distinction rests only on `dividendsFetched`.
- Alpaca entitlement was UNVERIFIED at build (no creds/egress); operator signed off, post-deploy audit logs are the verification; a 403 would force descoping FR-4/@AC-5. The `iex` feed assumption is an inference (the corporate-actions request sends no `feed` param). Docs-confirmed (not live-tested): `GET data.alpaca.markets/v1/corporate-actions`, records carry `currency` (empty = USD) and `foreign`.
- @AC-2 figures corrected to real FY2026 values with operator sign-off (BABA financial debt ≈ USD 8,098M, D/E ≈ 0.05 vs ≈ 0.74 for total liabilities, Liabilities USD 113,555M).
- Price basis: `CloseAt` is an ADJUSTED daily close (`marketdata_repo.go:822-823`, `adjustment=all`); market_cap = adjusted close × as-reported shares, and P/B, P/E, yield divide by it while EDGAR shares/EPS are as filed and the Alpaca dividend `rate` is raw — after a later split/dividend older periods are biased, uneasy with FR-7's no-look-ahead claim. Pre-existing `CloseAt`; durable open risk.
- Verification weaker than specs: @AC-9 is validated only by checking the PIT period and the EDGAR snapshot for the SAME filing carry identical `debt_to_equity`, `pb_ratio`, currency — the composite is never recomputed, ROE convention argued not tested, band retuning out of scope. The @AC-5 window runs against a Go fake that replicates the SQL; no repo-level `SumDividendsInWindow` test and no idempotent `UpsertDividends` test (Step 9); the @AC-6 snapshot test uses USD, not BABA's CNY; no test asserts the zero-history WARN (Step 11).
- Zero-history WARN: spec says "CIK-known-but-zero-history WARNs"; shipped `getEdgarSnapshot` (`marketdata_service.go:1529-1537`) does no CIK lookup and logs `reason=zero_history|no_core_metrics` for EVERY unproducible symbol, so a non-SEC filer and a backfill gap are indistinguishable.
- No-op surfaces are deliberate (C-14): analysis passes marketdata values through verbatim and its formula bands are tunable params; agent `query_fundamentals` is a deliberate no-op (no proto field added, so the feature-134 descriptor-parity test cannot break); no strat-lab plugin update was owed. Disabling FMP makes the feature-154 fundsignal `max_symbols` cap (applies only when `provider==fmp`) inapplicable — intended.
