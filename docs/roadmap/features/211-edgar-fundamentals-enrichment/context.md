## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: Marketdata uses SEC EDGAR as its single fundamentals source for the backtest point-in-time (PIT) path, and for the live snapshot once `snapshot_source` is flipped to `edgar`. The aggregator is unit-aware and records the real reporting currency; D/E uses financial debt; P/B and P/E are currency-consistent at the filing boundary; a PIT dividend yield comes from Alpaca corporate-actions. FMP and Finnhub are disabled by config only — code not deleted. Trigger: a BABA/AXP backtest-vs-live divergence on `fundamentals_macd_blend` (composite ~0.35 PIT vs ~0.70 live) caused by different sources and methods, not real fundamentals change.
**Why (irrecoverable rationale)**:
- Seeded `fundamentals_value_quality` bands (`de_bad=2.0`, `pb_bad=5.0`) assume the financial-debt D/E convention; EDGAR total-liabilities/equity gave ~4.64 for BABA.
- A full EDGAR-canonical switch was required: a PIT-only fix leaves ROE computed two ways (EDGAR ending-equity ~52% for BABA vs vendor TTM ~7%) and re-opens the @AC-9 divergence. (211-era ROE; feature 222 later made quarterly-row ROE TTM.)
- Operator decisions: a dedicated `snapshot_source` axis; P/B and P/E option (b) (prefer a USD-unit fact, else missing); Alpaca dividend feed (no new fundamentals vendor). Two C-16 CHANGE sign-offs on 2026-09-26: repointing the snapshot at EDGAR overrides feature-198's "provider never takes edgar / EDGAR is a separate PIT lane"; "stop hardcoding USD" changes currency semantics, so consumers must never aggregate absolute fields across currencies.
- Product spec's leading option was extending `provider` with an `edgar` value because the overlap scan showed feature 198 owns that selector; design reversed it.
- Live-reading `snapshot_source` is safe because the EDGAR builder constructs no client (stored history + live quote); that is why only this axis is live-read while `provider` stays boot-frozen.
- `marketdata.dividends.enabled` is seeded `false` deliberately so the migration does not start unexpected Alpaca corporate-actions cost before entitlement is confirmed; the @AC-5 unit test uses a fake dividend source so coverage does not depend on the gate.
- Corporate-actions is market data, not a broker/order concern, so no IBKR lane was mirrored and broker-symmetry does not apply.
**Rejected alternatives**:
- Overload `marketdata.fundamentals.provider` with `edgar` — couples client construction, config namespace and quota shape, forces `if provider==edgar` at every read site, leaves the fallback as an accidental `default→fmp` (the feature-129 fallthrough trap).
- PIT-only fix — fails @AC-9 on the ROE split and does not retire the vendor.
- P/B option (a) (absent on any currency mismatch) as the only rule — (b) gives a real P/B for dual-reporting ADRs; (a) remains the fallback. Option (c), a historical FX feed — a second data-source integration beyond scope.
- Keyless always-on EDGAR gate — no rollout lever; a real `marketdata.edgar.enabled` kill switch chosen.
- Uncached live `GetHistoricalFundamentals` plus `CloseAt` per call — N history scans plus N ohlcv reads per screener call would re-open the feature-141 "out of shared memory" failure (F-06); write-through cache chosen.
- Reusing `GetHistoricalFundamentals` for the latest period — pages oldest-first (`ORDER BY period_end, fiscal_period ASC`) so the newest filing is on the last page and reaching it scans the whole history; a bounded-lookback variant "would miss a slow filer". Dedicated `LatestHistoricalFundamental` (DESC LIMIT 1, `filed_date < asOf` in SQL) chosen.
- One-time cutover cache purge — source-aware self-heal keeps cutover instantly reversible; purge kept as the sanctioned fallback.
- Boot-bound `snapshot_source` — a live-read axis gives instant, reversible cutover with no dark window.
- Dividends from EDGAR or FMP — EDGAR rarely carries clean per-share cash-dividend facts; FMP is being disabled.
- Cache invalidation by plain string inequality — explicit mapping instead: `edgar`→edgar axis; `fmp`,`finnhub`→vendor axis; `edgar+fmp`→edgar axis.
- @AC-2 correction had two options: real FY2026 figures, or a relaxed direction-only assertion ("≪ de_bad"); real figures chosen with sign-off.
**Scars & gotchas**:
- Debt tags: BABA's only recent financial-debt tag is `ConvertibleDebtNoncurrent` (USD 8,098M); `DebtCurrent`/`ShortTermBorrowings` stop after FY2018/19. Do NOT sum `SeniorNotes` — stale in AXP (FY2015 only) and double-counts `LongTermDebt`. AAPL: `LongTermDebtNoncurrent` (78,328M) + `LongTermDebtCurrent` (12,350M) = `LongTermDebt` (90,678M), so the sum takes components when either is present, else `LongTermDebt` (AXP shape), never both; `CommercialPaper` (7,979M) is a separate addend. Verified ratios: AAPL ~1.34; AXP ~1.73 (total-liabilities D/E would be ~7.96 and break `de_bad`); BABA ~0.05. All three acceptance filers report under `us-gaap`; the `ifrs-full:*` branch was dropped. Verify debt tags against live SEC companyfacts; never guess them.
- Currency: BABA dual-reports `StockholdersEquity` in CNY and USD, which makes option-(b) P/B work. The aggregator originally kept first-seen over a nondeterministic Go-map range and discarded the unit key; it now keys `metric→unit→value` and picks currency by vote (monetary facts only; exclude per-share and share units; tie → lexical). @AC-1 passes only because BABA's CNY and USD counts tie and "CNY" < "USD". Currency is pinned to the earliest-filing unit set; a later-amendment restatement is an accepted residual needing manual purge + re-backfill.
- The `ratioEnricher` seam warns TTM ratio sources are a PIT look-ahead risk — that is why D/E comes from filing tags and P/B from price-at-filing.
- Unknown config values: making an unknown `provider` boot-fatal broke the canary `TestNewFundamentalsSource_AlwaysNonNil` (features 082/129); `os.Exit` is untestable besides. Caught in CI because the local check ran `./internal/...` only. Fixed to WARN + FMP fallback. Unknown `snapshot_source` WARNs and defaults to `vendor`: it is read live on a serving RPC, so failing it on a config typo would take fundamentals serving down platform-wide. The config service has no allowed-values check for string keys.
- golangci-lint could not lint go1.27 (pre-provisioned binary built on go1.25; `go install` of v2.13.1 caps at go1.26); every Go step used `go vet` + `gofmt -l` locally and the real gate ran in CI.
- `GetBool` returns `false` for a missing key, so `edgar.enabled` needs an explicit `true` default and a test that omits the key. The builder sets `Source="edgar"` because the repo defaults an empty source to `'fmp'`. FR-8 literal audit: TTL reads use `marketdata.<provider>.cache_ttl_hours`; `enrichmentUnderCap()` reads `fmp.daily_request_cap` in the backfill lane and the `edgar+fmp` mapping depends on it; vendor clients are always built, gated only at use. Keys are read before migration 030 seeds them; in-code defaults cover the gap.
- Dividends: a responded-empty feed gives 0; an absent, errored, disabled or unentitled feed gives nil; a post-filing `ex_date` must not count. As built, the 2-year fetch lookback was shorter than the 10-year history backfill, so periods filed more than ~a year before the fetch start computed a false 0; the 3→2 seed alignment was not a fix; feature 216 later added the guard (`marketdata_service.go:1997-2001`).
- `FUNDAMENTAL_METRICS` already carried the three metrics (feature 204), so FR-6 UI work was provenance, CSV and the USD hint only. Two pre-existing tsc errors: `e2e/insights/backfills.spec.ts` and `src/middleware.test.ts`.
- PR #1186 and #1185 both merged as `207`, so this feature was renumbered 211; a stale `@feature-207` tag was left in Steps 15/16.
**Permanent deviations**:
- Design: IFRS/`ifrs-full:*` allow-list + `DebtLongtermAndShorttermCombinedAmount` fallback → shipped us-gaap only with the grounded 7-tag set, because a direct SEC fetch showed no acceptance filer uses IFRS (YAGNI).
- Design: non-USD P/E via native or USD-unit EPS → shipped P/E only when `Currency=="USD"`, because Step 2 stashed only `stockholders_equity_usd`, not `eps_usd`, and Step 6 was file-scoped. After the live-flip every non-USD filer has no P/E where the vendor path gave one.
- Design: "latest filing + live price-join" → shipped `edgarSnapshotFromPeriod` (`marketdata_service.go:1569-1592`): overlays live mid on `Price` only; `MarketCap`, P/E, P/B, yield, D/E, ROE and `AsOf` (filing date) are copied from the stored period (parity with PIT for the same filing over live recomputation). This is why the @AC-12 "Last refreshed" thread is open. With no live quote, `Price` falls back to the filed-date close.
- Design: `GetHistoricalFundamentals` + `filterAsOf` → shipped `LatestHistoricalFundamental` (`marketdata_repo.go:773-780`) because of oldest-first paging. It orders by `period_end DESC` across annual AND quarterly rows with no period-type preference, so a quarterly row can feed single-quarter EPS (and pre-222 ROE) to the snapshot where the vendor gave TTM.
- Design: unknown `snapshot_source` fails loud, unknown `provider` boot-fatal → shipped WARN + safe default (see Scars).
- Dividends: design counted "ex/pay ≤ filed_date" → shipped filters `ex_date <= asOf` only (`marketdata_repo.go:551`); `pay_date` stored but unused. Design assumed USD/USD; the spec-time "currency ≠ trading → missing" guard was never built — `alpaca/client.go:264` hardcodes USD and never parses `currency`, `foreign` or `special` (unguarded assumption, not a decision). The `(symbol, ex_date)` PK collapses a same-day regular and special dividend. `SumDividendsInWindow`'s has-rows bool is discarded (`marketdata_service.go:1991-1992`), so zero-payer vs missing-feed rests only on `dividendsFetched`.
- Alpaca entitlement was UNVERIFIED at build: Step 8's "first action" direct check never ran (no credentials/egress). Operator signed off with post-deploy audit logs as verification; a 403 would force descoping FR-4/@AC-5. The `iex` feed assumption is an inference.
- @AC-2 figures: original "714,121M liabilities, ~45,000M debt, D/E ~0.3" corrected with sign-off to real FY2026 values: debt USD 8,098M, D/E ~0.05, liabilities USD 113,555M.
- Price basis: `CloseAt` is an adjusted close (`marketdata_repo.go:822-823`) while EDGAR shares/EPS are as-filed and the Alpaca `rate` is raw; after a later split or dividend, older periods are biased. Uneasy with FR-7; a durable open risk.
- Alpaca corporate-actions facts, confirmed from docs but never live-tested: endpoint `GET data.alpaca.markets/v1/corporate-actions`; records carry `currency` (empty = USD) and `foreign`; the request sends no `feed` param, which is why the `iex` assumption is only an inference. Design assumed dividends are USD/USD because Alpaca reports an ADR's actual USD distribution — a stated belief, not an oversight; a future fix for the unguarded currency gap should start from those fields.
- Financial-debt D/E did not make the two sources agree: for BABA the vendor snapshot gave ~0.25 vs EDGAR ~0.05.
- BABA D/E contrast: financial-debt D/E ~0.05 vs total-liabilities D/E ~0.74 on the FY2026 USD figures, while the spec cites ~4.64 for total-liabilities D/E; the source does not explain the discrepancy between the two total-liabilities numbers (older period or mixed currencies is likely). Treat ~4.64 as unreproduced.
- The `provider` key still selects only the vendor lane; EDGAR reaches the snapshot via `snapshot_source`, so feature 198's "EDGAR is a separate PIT lane" holds in that narrow sense.
- ROE convention was argued, not tested, and band retuning was explicitly out of scope: `roe_good`/`roe_bad` (and the D/E and P/B bands) were never confirmed to behave under EDGAR ending-equity ROE; ROE was left unchanged and @AC-9 validated by shared inputs, not by touching the formula.
- Verification is weaker than specified: @AC-9 is validated only by checking the PIT period and the snapshot for the same filing carry the same D/E, P/B and currency (composite never recomputed); @AC-5 runs against a Go fake (no repo-level `SumDividendsInWindow` test, no idempotent-upsert test); @AC-6 test uses USD not CNY; no test asserts the zero-history WARN.
- Spec said "CIK-known-but-zero-history WARNs" → shipped `getEdgarSnapshot` (`marketdata_service.go:1529-1537`) does no CIK lookup and logs `reason=zero_history|no_core_metrics` for every unproducible symbol, so a non-SEC filer and a backfill gap look the same.
- No-op surfaces are deliberate (C-14): analysis passes values through; agent `query_fundamentals` gets no proto change (feature-134 parity test safe); no strat-lab plugin update owed; feature-154 `max_symbols` cap becomes inapplicable once FMP is off, as intended.

**Runtime-invariant recommendations (→ /context-constitution)**: MARKETDATA-*: EDGAR rows carry native reporting `currency` and absolute fields must never be compared across currencies (`market_cap` and `price` are always in the trading currency, USD, even inside a CNY-labelled row — `currency` labels only the native absolute facts); P/B and P/E come only from same-currency or USD-unit facts, never FX-fabricated; `snapshot_source` is a live-read axis failing safe to `vendor` with a WARN; the edgar builder must set `Source="edgar"`; `marketdata.edgar.enabled` defaults `true`; missing dividend data is nil never 0; the EDGAR snapshot's ratios and `AsOf` are filing-date values, only `Price` is live; `CloseAt` is adjusted-basis.
