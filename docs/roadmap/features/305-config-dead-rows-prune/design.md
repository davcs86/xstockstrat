### 1. Migration (`NNN_config_dead_rows_prune.{up,down}.sql`, max+1 at merge; 046 today)

- **One top-level statement** (data-modifying CTE chain), not a DO block: on failure golang-migrate records no partial write. **No lock** (removes 044's lock-exhaustion RAISE that leaves config dirty — recon: `044:38-49`), **no data-dependent RAISE** (F-01), **no `contract-of` header** (it would break the unique R discovery, `migration-rerun.sh:52-58`), **no number in content or actor**: actor `system:config-migration-feature-305`; a merge-time renumber renames the up/down/`config-NNN.sql` files and regenerates the stored JSON — nothing else.
- Signed block `(VALUES …) AS dead_rows_305(namespace,key,environment,value_sha256)` between `-- dead_rows_305:begin/end` (idiom `041:239-282`, sha match `041:371-373`). Marker lines are not part of the compared text; tuple count rule = `migration-rerun.sh:77`.
- **Latch**: every CTE runs only while no marker `dead_rows_305` exists; the marker INSERT is itself gated on the latch (`config.config_markers.name` is the PK, `040_config_markers.up.sql:3`, so an ungated insert would raise on the AC-6 replay).
- `DELETE … WHERE user_id IS NULL AND NOT is_secret AND (ns,key,env) match AND sha256(value_data) match … RETURNING` is the snapshot image → `config_values_premigration_296` (columns `044:182-191`), one audit row per deleted row (`044:203-206`, `new_value` NULL, `changed_at = clock_timestamp()`), `dead-row-deleted` report rows with `run_at = now() =` marker `set_at`, `unmatched-signed-tuple` report rows (reason prefix `feature 305:`) for tuples with no deleted row — reported, never raised (`044:236-241`). `pg_notify('config_changed', {namespace, environment})` per touched pair in a CTE that the final SELECT reads. Per-user rows are excluded by the predicate and probed, not deleted.
- DELETE fires no audit trigger (only BEFORE UPDATE `001:49-51` and AFTER INSERT `010:27-29`), so the explicit audit CTE does not double-write. Concurrency: the DELETE re-checks each row's hash at lock time, so a concurrently updated row is reported unmatched; `SetConfig` is an upsert (`configServiceImpl.ts` ~:898-909) but a global write on a missing key without `create_key` returns NOT_FOUND, so re-creation needs `create_key=true`.
- **Down** (mirrors `041_*.down.sql`): joins the marker's `dead-row-deleted` report rows (`run_at = marker.set_at`) to `config_values_premigration_296` rows with the same `(ns,key,env)`, `user_id IS NULL`, `snapshot_at >= run_at`, `DISTINCT ON … ORDER BY snapshot_at ASC` (the shared snapshot table also holds 296's rename images; the first image at/after `run_at` is 305's), re-inserts without `id` with `updated_by` = actor and `update_reason = 'feature 305: down restores a dead row'`, explicit conflict target `(namespace,key,environment,COALESCE(user_id,''))` `DO NOTHING`, notifies each restored pair, deletes the marker. The AFTER INSERT trigger attributes the restore audit to the 305 actor (`017:87`).

### 2. Evidence + evaluator (`scripts/check-config-wiring.mjs`, `scripts/config-heal/`)

- Exported pure functions `loadEvidence(text)`, `subscribersOf(receivers)`, `deadRowVerdict({ns,key}, evidence, subscribers)`; `run()` never calls them (so they cannot suppress a `seeded-unread` finding — 278 @AC-2/7/8, 295 @AC-19); `membership()` is **unchanged**. Normalisation: `canonical(ns, loggedKey) === canonical(ns, key)` (`canonical` adds the prefix; equality is equivalent to FR-3's strip rule).
- Verdict order: `kept:read-hit` → `kept:missing-coverage` → `kept:ui-reader` → `kept:list-receiver` → `dead`; each of AC-3/4/5 holds under this order (AC-4's ui fixture has zero hits and full coverage).
- **Evidence = metric queries** (operator decision), `scripts/config-heal/dead-row-evidence.tsv`, tab-separated, column 1 the row kind: `window <W0> <W1> 21600 deployment_environment="staging"` (exactly one; W0/W1 UTC on a 6 h boundary 00/06/12/18Z, W1−W0 = k·6 h); `subscriber <service> <ns> <single|list|ui>` (frozen; limited to receivers on the signed namespaces: analysis→analysis, analysis→marketdata, marketdata→marketdata — `analysis/app/main.py:43,49`, `marketdata/cmd/server/main.go:64`); `coverage <service> <ns> <bin_end> <count>` (`bin_end` on the grid W0+i·6 h, i=1..k; Loki samples are left-open `(t−6h, t]`, so the k bins tile `(W0, W1]`; **absence = missing**; count<1 rejected); `read-hit <service> <ns as logged> <key as logged> <count>` (superset: every key of the two namespaces, both spellings); `keys <service> <ns> <N>` (the `keys=N` of that pair's last coverage line). The loader throws on a wrong header/cell count, unknown or duplicate kind, off-grid or out-of-window row, a second window, or zero subscribers.
- **Positive control (operator-chosen `keys=` cross-check)**: for every `single`/`list` pair (`ui` exempt) the distinct canonical read-hit keys must be ≥ its `keys=N`; every tick re-emits every read key (`watchcore.go:302-305`, `watch_core.py:171-173`), so a key silently dropped by the export for a service with other hits is detected (fails.md 2026-11-05: a liveness signal must exercise the component that can fail).
- **Pinned queries** (text in `signoff.md`): Go emits slog attributes `ns`/`key`/`keys` (`marketdata/internal/config/watchcore.go:301,304,323`), Python/Node put `config.read_* ns=… key=…` in the body (`watch_core.py:170,173,193`, `configWatcher.ts:166,169,190`) → two disjoint families per signal (`|= "config.read_coverage ns="` vs `|= "config.read_coverage" != "config.read_coverage ns="`), `sum by (service_name, ns[, key]) (count_over_time({deployment_environment="staging", service_name=~"analysis|marketdata"} … [6h|R]))`, coverage as a range query (step 6 h, start W0+6 h), read-hits as an instant query at W1. `service_name` is the short-name stream label (`observability.md:22-24`). **Operator pre-checks** (unverifiable from the repo): Go attributes arrive as queryable structured metadata; Python/Node bodies carry the formatted text; R-wide instant query within `max_query_length`/retention; sample timestamps on the grid; `deployment_environment="staging"` maps to exactly one deployment. Empty bin → `kept:missing-coverage` → **halt**: shift W0/W1 by Δ<6 h and re-export, never edit the evidence.
- **Halt rule (P-03)**: any `kept:*` verdict for a signed tuple halts execution and re-scopes the spec; S2 assumes exactly 4 `dead`.
- Permanent FR-4/AC-7 test `dead 2` in `scripts/config-wiring.test.mjs`: block has exactly 4 tuples; each is `dead` against the committed evidence and its **frozen** subscriber rows (never the live registry — it would go red on unrelated PRs); every signed `ns` has ≥1 `single` subscriber (blocks a vacuous `dead`); every signed sha equals its row in `inventory-fresh.jsonl` after `canonical()` (keeps `config-044.sql:145`'s unscoped `unmatched-signed-tuple` count at 0 on CI with a 305 message, not a misleading 296 one); the migration is found by slug glob `*_config_dead_rows_prune.up.sql` (exactly one) and contains the block byte-for-byte; evidence and block sha256 equal `signoff.md`'s. The one-time "frozen set == `subscribersOf(registry.receivers)`" proof is a pinned command run at P1, output recorded in `signoff.md` — not permanent code.

## Rejected Alternatives

- Keep the 044-style `LOCK TABLE` retry loop — rejected: lock exhaustion leaves config dirty (stalled migrator, fails.md 2026-11-08); a single statement's DELETE re-check gives the same snapshot guarantee.
- Natural idempotence (`NOT EXISTS` on prior report rows) instead of a latch — rejected: per-tuple dedupe, fuzzy down→up semantics, report rewritten on replay.
- A down that RAISEs "irreversible" (044.down) — rejected: FR-1/AC-6 require a restoring down. Down selected by `id` or by a time-window heuristic — rejected: 296's rename snapshots keep the same ids / prefixed keys and share the table.
- Line-level Loki export with per-line timestamps (`line_format`, `__timestamp__`, literal tabs, truncation guard) — rejected by the operator for metric queries (unverified template pieces, entry limits).
- Per-service "≥1 hit" positive control — rejected for the `keys=` cross-check (a dropped key for a service that has other hits slips past it).
- Permanent test comparing the frozen subscriber set with the live `registry.receivers` — rejected: red on unrelated PRs, pressure to edit the merged block (F-01 trap).
- Narrowing `membership()` to 306 / removing the `305` regex branch — rejected: rewrites the gate-7 fixture and baseline-3 for no behaviour gain; cleanup fits 306.
- Owner of the kept ledger entry = a defect report — rejected: `OWNER_RE` allows it but baseline-3 (`SWEEP_277`) goes red and `membership()` stops checking it. Leaving owner `feature 305` — rejected: a launched feature would own an entry nobody settles.
- Scoping `config-044.sql:145` by reason — rejected: edits 296's assertion; the fresh-sha equality guard makes it unnecessary.
- Local Docker/Timescale verification of S2 and step-branch pushes — rejected: forbidden by sdd-execute HARD CONSTRAINTS; integration-PR CI is the live check.
- A new CI workflow/label check for sign-off — rejected: the `dead 2` + file-sha tests in the required `config-wiring` job, the draft-PR rule and operator-authored commits suffice.
- Partial-resolution notes in defect-report bodies — rejected (`defect-filing.md:28-42`).

## Open Risks

- [ ] **False-zero read-hit export**: if Go `ns`/`key` attributes are not queryable structured metadata, or a Python/Node body differs, hits vanish and the verdict says `dead`; the `keys=` control catches a dropped key per pair but not a key logged under an unexpected namespace — P1 pre-checks must be run on real lines — P1 (operator).
- [ ] **Sha drift across five data sets** (four live DBs + CI fresh DB): drift between P1 and deploy turns 4-deleted into reported-unmatched (safe on live, fails P2/P3) — mitigated by the fresh-sha guard, P2 rehearsal and file-sha pin — P2/S5.
- [ ] **Production tuples rest on "same code" + static evidence** (staging services never read `environment=production` rows) — accepted assumption, recorded in `signoff.md` — P1.
- [ ] **Rollback asymmetry**: a 305.down-restored `sparkline_bars` row has no bounds entry (removed in S4); harmless (no reader) — S4.
- [ ] **Shared harness/number race with 306/280**: pass 3's `refuse_down` chain also runs any later config down; `must_be_dirty config 43` breaks if a later down raises before 044 — covered by the proposed merge-order row — at rebase.
- [ ] **Indicators coverage** after removing a 241-line module + 19 tests (≥50% gate) — measure in S3 — S3.
- [ ] **Loki log retention** must cover the window start; not knowable from the repo (`grafana-cloud.md` states trace retention only) — P1 pre-check.
- [ ] **306 must take the kept ledger entry** (its own `/sdd-review` is still pending); if it never does, the entry stays owned by an unsettled feature — 306 review.
