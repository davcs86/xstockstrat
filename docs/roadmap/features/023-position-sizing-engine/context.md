# Context: position-sizing-engine  (archived 2026-08-16)

**Feature**: ./feature.md
**Status**: launched — archived by /sdd-archiver; verbose specs pruned (recoverable via git history).

## Archive Synthesis — 2026-08-16 — /sdd-archiver

**What**: Added a risk-adjusted position-sizing engine to `xstockstrat-trading` that intercepts any `PlaceOrder` call arriving with `qty <= 0` and computes a safe quantity from broker-authoritative account equity (`ListPortfolios`), true Wilder ATR(14) computed in-process from `GetBars` OHLCV data, and signal confidence. Wired a new `trading → marketdata` gRPC dependency, seeded four new `trading.risk.*` config keys, and added `optional double confidence = 16` to `PlaceOrderRequest`. The confidence field ships consumed correctly but unpopulated by any live caller; UI wiring and `ExternalSignal.conviction` plumbing are deferred to feature `110-wire-signal-confidence-to-position-sizing`.

**Why (irrecoverable rationale)**: `ListPortfolios` was chosen over `GetPortfolio` for equity because `GetPortfolio` sums open-position market values and returns `$0` for a flat, freshly-funded account — exactly the AC-1 scenario. Wilder ATR was computed in-process (not via `xstockstrat-indicators`) because `indicators._atr` is a close-only rolling mean (not true Wilder high/low/close), and routing through it would require trading to fetch bars from marketdata first anyway. `ComputePositionSize` is fail-closed while the existing `checkPortfolioRisk` stays fail-open because they are asymmetric: `checkPortfolioRisk` is advisory (warn-only log); `ComputePositionSize` is the sole source of quantity for an auto-sized order. The two concentration limit keys (`max_position_pct` warn-only, `max_concentration_pct` enforcing) coexist because they cover disjoint populations: the enforcing cap applies only to auto-sized orders. The request hash (feature 101's exactly-once dedup) must run before `ComputePositionSize` mutates `req.Qty` because ATR/quote can drift between genuine retries — hashing post-mutation would cause the same original request to hash differently on a retry, producing a spurious dedup rejection. `checkPortfolioRisk` is fail-open despite `ComputePositionSize` being fail-closed because of the single-instance no-HA topology: a portfolio-service blip would block ALL new orders if `checkPortfolioRisk` were fail-closed. This asymmetry is a deliberate HA decision — a future agent hardening `checkPortfolioRisk` to fail-closed is reversing it.

**Rejected alternatives**: Route ATR through `xstockstrat-indicators` (close-only approximation, not Wilder; still requires bar fetch). Extend indicators proto to fix `_atr` there (proto change governance overhead). Fail-open on missing portfolio/price/ATR data (`ComputePositionSize` is the sole quantity source). Wire `Opportunity.conviction` as confidence source (proto comment says "deterministic ordinal… NOT a probability"). Mutate `req.Qty` via a separate local variable (more code for no extra safety). Run `checkPortfolioRisk` before sizing (`req.Qty` is 0 pre-sizing → `orderNotional = 0 × price = 0`, guard structurally never fires). Hardcode `confidence = 1.0` permanently (user decided at round 3 gate to add the proto field now). Ship full UI confidence wiring in this feature (three blocking gaps found by round-5 adversary).

**Scars & gotchas**: `internal/handler/trading.go:35-37` rejected `qty <= 0` with `InvalidArgument` before `TradingService.PlaceOrder` ever ran — the entire `qty <= 0` auto-size trigger was unreachable at the handler layer; only Phase 0 recon caught this. `resolveAccount`'s single-broker convenience path discarded the resolved account ID; signature had to be widened to return `(string, brokerPoolEntry, error)`. `GetBars` with `ORDER BY time ASC LIMIT` returns the oldest-N bars in the window; use explicit tight `Range: {Start: now-45 days, End: now}` with `PageSize: 40`, then take the last 15 bars from the ascending result slice. `GetLatestQuote`'s live-fetch path returns a real Go error (`nil` response), not an empty-but-valid response — check `err != nil` before any field access. `Quote` proto has no single current-price field — only `ask_price`/`bid_price`; convention: `(ask+bid)/2` when both > 0. Feature 101's `NewTradingService` added a 6th parameter before this spec; canary test template had wrong arg count. `fakePortfolioClient` name collided with feature 100's fixture; renamed to `fakeSizingPortfolioClient`. `Order.stop_price` is semantically overloaded for MARKET auto-sized orders: set to the computed sizing stop as "informational only" — NOT submitted to the broker as a real trigger price.

**Permanent deviations**: Product-spec said "No proto changes required in V1" → shipped `optional double confidence = 16` on `PlaceOrderRequest` → user explicitly decided at round-3 gate. design.md pseudocode declared `ComputePositionSize(ctx, req, mode, equity, confidence)` returning `(sizedQty, stopPrice, dollarRisk, err)` → shipped as `ComputePositionSize(ctx, req, equity, confidence)` (mode dropped, return order: `qty, dollarRisk, stopPrice, err`). Spec placed `equity <= 0` guard in `PlaceOrder` only → shipped also inside `ComputePositionSize` to enable independent unit testing. Request hash computed before sizing → decided at execute time (unspecced).

**Cross-feature signal**: The three-feature stacked build (100 → 101 → 023) required a manual three-way merge of `PlaceOrder`'s statement sequence at execute time — sizing gate interleaved with 100's trading-state gate and 101's dedup/hash/finalize logic. The request-hash-before-sizing ordering was an unspecced dependency created by 101 landing first. Fixture name collisions in the same Go package across stacked features is a real risk; prefix fixture names per feature (`fakeSizing*`).

**Deferred follow-ons**: Feature `110-wire-signal-confidence-to-position-sizing` (wire `ExternalSignal.conviction` to `PlaceOrderRequest.confidence`). V2 risk-control requirements: maximum gross/net exposure limits, per-symbol concentration limits, buying-power validation, minimum/maximum stop-distance bounds, rejection of zero/negative/NaN/stale prices, environment-scoped limits, persisted `RiskDecision` record, concurrency safety.
