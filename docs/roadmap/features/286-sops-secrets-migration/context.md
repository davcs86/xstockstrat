**What**: Deploy-time secrets for DigitalOcean App Platform and the homelab VM moved out of GitHub secrets / 1Password into per-environment age-encrypted SOPS files (`secrets/{staging,production}.enc.yaml`, namespaces `common` / `digitalocean` / `homelab`). Each file has exactly two recipients: the environment key (`SOPS_AGE_KEY` in the GitHub Environment) and an operator key (`vars.SOPS_OPERATOR_AGE_RECIPIENT`). One KEYS table in stdlib-only `scripts/sops_secrets.py` drives three consumers: the unified DO renderer `scripts/do-render-app-spec.py` (imports it, resolves and renders in one process, replaces `do-inject-prod-secrets.py` and the inline python in `deploy.yml`), a homelab `resolve` CLI, and a `build` CLI used by the new `sops-bootstrap.yml` (matrix seed -> ciphertext artifacts -> one PR to main-dev). Resolution is dual-read: SOPS first, then per-key fallback to legacy GitHub secrets via `LEGACY_<NAME>` step env vars, fail-closed only when a required key is in neither store. The DO app ID is no longer stored, it is resolved by spec name. Homelab dropped 1Password. 21 steps, PR #1405, launched 2026-11-04 via promotion PR #1406. Rollout steps 3-7 (operator-driven, see Deferred) were NOT recorded as completed in context.md.

**Why (irrecoverable rationale)**:
- Three namespaces instead of two (operator, post-spec-ready): `common` = the app needs it regardless of hosting, `digitalocean` = DO-only, `homelab` = homelab-only. On a common-key conflict between DO and homelab sources DigitalOcean wins; this is enforced by rendering the common tail LAST in the homelab APP_ENV and by refusing a common key inside `homelab.app_env` (@AC-23). Homelab is not live yet, so this was non-disruptive. (old context.md@1ed63958:49-58)
- MTLS_CA unified into `common` from DO's CA, reversing `docs/patterns/inter-service-mtls.md:105` ("a separate CA from DO's"). Operator decision; the reason is not recorded beyond that. Staging and production still keep distinct CAs, only DO<->homelab share within an environment (see D-2). (old context.md@1ed63958:55-56, 96; implementation-spec.md@1ed63958:1136-1142)
- DO app ID resolved by spec name at deploy time (FR-11) instead of stored: removes the stale-ID-after-prod-up-recreation hazard outright. (old context.md@1ed63958:68-71)
- 1Password dropped from the bootstrap (operator, round-1 gate): YAGNI for a non-live homelab. Bootstrap seeds only `common` + `digitalocean`; homelab values are filled by hand with `sops set`. This retired @AC-3, @AC-4, @AC-19 (kept IDs, own pre-launch ACs) and rewrote @AC-2; @AC-23 was added (old context.md@1ed63958:102); @AC-20 dates from the operator revision (:63). Whether it was rewritten at this gate is not recorded. (old context.md@1ed63958:94, 100-102)
- `GITHUB_ENV` export of the 6 homelab values accepted as an operator waiver: TS_AUTHKEY / DEPLOY_SSH_KEY are infra creds like the DO token, resolution is by first-party same-repo scripts, no third-party `uses:` runs after resolve, whereas the DO token already goes to a floating-tag third-party action. Re-confirmed at the round-3 gate. (old context.md@1ed63958:132-135)
- `production` GitHub Environment has required reviewers (operator correction at the round-1 gate); binding the DO prod deploy and prod-up to it puts every main push and every prod-up run behind approval. Operator accepted. (old context.md@1ed63958:98-99, product-spec.md@1ed63958:188)
- Fail-closed on an undecryptable file (never a per-key fallback): per-key fallback would silently hide a broken key/file and resurrect stale values. (design.md@1ed63958:383)
- Values pass through with NO normalisation (no strip, no newline change); asserted with `"trail-v \n"` end to end, because CONFIG_SECRETS_ENCRYPTION_KEY, BROKER key and JWT_SECRET must be delivered byte-identical or stored config secrets turn INTERNAL, IBKR credentials turn INVALID, and the JWT stops matching between agent and identity. (design.md@1ed63958:44, 320; recon.md@1ed63958:16-17, 100, 102, 106)
- Platform credentials stay native GitHub secrets because `DIGITALOCEAN_ACCESS_TOKEN` is account-wide and is used by `prod-down.yml`, which runs with no environment. (old context.md@1ed63958:58; product-spec.md@1ed63958:47-48)
- Legacy fallbacks are read with `secrets[format('{0}_K', env.P)]`, not `cond && secrets.PROD_X || secrets.DEV_X`, because that expression falls through to DEV when PROD_X is empty. (design.md@1ed63958:121)
- Operator override recorded: the operator chose `feature/sops-secrets-migration` plus a single squash PR, overriding the harness "push only to main-dev" directive. (old context.md@1ed63958:29-30)
- Deliberate prod-up behaviour changes (design C5): a missing required key now hard-fails (was a warning at `do-inject-prod-secrets.py:63-64`); MTLS is required and minted; an absent optional key renders `''` (used to leave the literal placeholder); VAPID + MTLS now included (FR-9, @AC-16). (design.md@1ed63958:132-135, old context.md@1ed63958:396)

**Rejected alternatives**:
- Bash resolver — lost: JSON handling, per-line masking, SHA compares fragile in bash 3.2; stdlib Python already a deploy dependency (design.md@1ed63958:377).
- `resolve -- exec child` mode — lost: same single-process guarantee as an in-process import with more to build (design.md@1ed63958:378).
- `toJSON(secrets)` into one step — lost: exposes every repo secret incl. platform credentials to one process; per-key `LEGACY_*` is least-privilege and statically pinnable (design.md@1ed63958:379).
- Explicit caller passthrough / `LEGACY_DO_*` rename — lost: keeps the 14-line DRY hazard and, in an env-bound job, same-named environment secrets can shadow passed values (the round-1 O1 silent CA swap). `secrets: inherit` + `secrets[format('{0}_K', P)]` makes shadowing structurally impossible (design.md@1ed63958:380).
- Same-named homelab fallbacks for common keys — lost: contradicts FR-10 / DO-wins (round-2 C1) (design.md@1ed63958:381).
- Resolving at the image commit (after detach) — lost: a rollback would run old tooling and old secrets; old commits lack the script and action (round-1 O2) (design.md@1ed63958:382).
- Golden rendered-spec files — lost: leaves are re-minted every deploy and goldens become tautological after the first spec edit; reverse substitution against the real spec is permanent (design.md@1ed63958:384).
- Per-env bootstrap input — lost: YAGNI; matrix + per-env guard is one dispatch, later single-env re-seed done locally with `sops` (design.md@1ed63958:385).
- 1Password reads in the bootstrap — lost: YAGNI for non-live homelab (design.md@1ed63958:386).
- prod-up running `sops set` and opening a PR to update a stored APP_ID — lost: "leaves main stale until merge + promotion"; resolving by name removes the hazard (design.md@1ed63958:387, old context.md@1ed63958:70-71).
- Per-name 0600 files instead of `GITHUB_ENV` for homelab — waived by operator, not technically rejected: more plumbing for infra creds (design.md@1ed63958:388).
- Inline pins in each workflow — lost: 5 copies of version + SHA; one composite action `.github/actions/setup-sops` is the single home (design.md@1ed63958:389).
- Hand-editing `docs/sdd/business-rules/platform.feature` @AC-8 — forbidden by `docs/sdd/business-rules/CLAUDE.md:51`; extension moved to own @AC-24, promoted at launch (design.md@1ed63958:390, old context.md@1ed63958:154).

**Scars & gotchas** (build-time, found only by doing):
- Round-1 adversary blocker O1: binding a reusable workflow job to an Environment makes the env secret `MTLS_CA` (homelab CA) silently shadow the caller-passed `MTLS_CA` (`DEV_/PROD_MTLS_CA`), swapping DO's CA at rollout step 1 with no error (formats match). Existing insights.md:3779 covers this (DUP).
- Round-1 O3: a depth-1 checkout has no `origin/main-dev`, so a naive existence check for the SOPS file fails open and would overwrite an existing file. Fix: explicit `git fetch --depth=1 origin main-dev`, and a fetch failure is an error, never 'absent' (old context.md@1ed63958:85, 110; code `scripts/sops_secrets.py:260-263`).
- `build` pipes JSON into sops because Python's stdlib has no YAML emitter: it sends JSON with `--input-type json --output-type yaml` and asserts every leaf is a string. (old context.md@1ed63958:115)
- Round-2 C1: homelab legacy fallbacks (its own `MTLS_CA` env secret, JWT etc. via the APP_ENV blob) contradicted FR-10 / FR-5(a2) — an intra-spec contradiction; fix: homelab common-key fallbacks also read `DEV_/PROD_`, and the legacy APP_ENV blob is stripped of common keys (regex mirrors the `owned` regex at `homelab-release-env.sh:34`), DO values appended last. (old context.md@1ed63958:113-114, 131-132; design.md@1ed63958:56)
- Round-2 C3: "byte-identical rendered spec" is false because leaf PEMs are re-minted per deploy; parity = identical after normalising leaf `yaml_pem` blocks. (old context.md@1ed63958:116-117)
- Round-3 major: the AC-22 static test must pin the RIGHT-HAND side of every `LEGACY_` line and the `P` expression, otherwise a crossed fallback deploys wrong values and is then seeded permanently into SOPS. (old context.md@1ed63958:149-150)
- Real sops 3.13.3 wrong-key stderr is `identity did not match any of the recipients`, NOT `no matching keys` (see D-1). Found by the gating Step 1 smoke test. (old context.md@1ed63958:278)
- `docker compose config --format json` re-escapes `$` as `$$` in its output, so the AC-5 assertion decodes `$$`->`$` before comparing; single quotes keep `p$w #1 "x"`, `j$t`, `tr ail ` literal. (old context.md@1ed63958:281)
- Explicit `--age` overrides a repo `.sops.yaml` even with cwd inside the repo; `build` still runs with `cwd=$RUNNER_TEMP` as belt-and-braces. (old context.md@1ed63958:277, 326-327)
- sops 3.13 lists `enc:` BEFORE `recipient:` in each `sops.age` entry, so the self-verify recipient regex needs an optional `- `; the first green `build` failed self-verify on this and the test's AC-1 recipient check caught it. (old context.md@1ed63958:328-329)
- GitHub unescapes `::add-mask::` command data, so `%`, `\r`, `\n` must be escaped (`%25`, `%0D`, `%0A`) or a value containing `%` (e.g. percent-encoded OTEL headers) registers the wrong mask and stays visible (`scripts/sops_secrets.py:85-95`). (old context.md@1ed63958:311-312)
- Masking floor: values shorter than 4 chars are not masked (documented; they are non-secret flags and masking would blank unrelated log text). (design.md@1ed63958:40)
- Local tooling traps: system `age` 1.1.1 was shadowed by a pinned v1.3.2; system `yq` 0.0.0 was a different implementation from mikefarah v4 (workflow YAML is parse-checked with mikefarah yq; runner image ships it). (old context.md@1ed63958:272, implementation-spec.md@1ed63958:44-70 (finding 5))
- `git check-ignore -q` with several paths exits 128 ("--quiet is only valid with a single pathname"); the Step 18 check was made per-path, plus an assertion that `.sops.yaml` is not ignored. (old context.md@1ed63958:257-260)
