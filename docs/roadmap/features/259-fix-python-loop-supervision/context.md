**What**: SEV-2 bug fix (debt-radar D-07, D-08, D-56; Track C from `docs/reports/2026-10-21-python-loop-supervision-defect.md` (pruned 2026-11-04; git show 9892b610:docs/reports/2026-10-21-python-loop-supervision-defect.md)) across analysis, indicators and ingest. Analysis got one shared helper, `app/supervision.py` (`spawn`, `_on_done`, `retry_until_ok`, `run_supervised`). The eight `main.py` boot tasks are retained through `spawn`, and the four `*_forever` loops seed via `retry_until_ok` then tick under `run_supervised` (any exception: ERROR log, 30 s backoff, never advances the schedule). All three Python `ConfigWatcher._watch` copies reconnect after any `Exception` and keep `_watch_task` with an exit-logging done-callback. `PnLPatternConsumer` retries each event 3 times in place, then parks a poison event (consumer-local `_is_poison` allow-list) or replays a non-poison one up to a bounded DB-health probe at the 5th replay, and parks via log -> idempotent `analysis.pnl.event_parked` ledger emit -> cursor advance. No proto, migration or config key. Launched 2026-10-30 via PR #1368 (commit df521ff5 and launch date at feature.md:9-10; PR #1368 at feature.md:45). All 15 steps executed sequentially (sdd-batch-execute) under the operator's standing authorization (operator chat 2026-10-28, session_01NpS3HShZK6pSnogA7CFo2f).

**Why (irrecoverable rationale)**:
- Wrap the loops, do not harden each seam: the unguarded seams (`DurableSchedule.seed` / `next_sleep_seconds` / `advance`, incl. the `advance` inside `_tick`'s own `except`) are covered by one wrapper, (no per-seam `try` is added, `design.md@1ed63958:23`). The r2 synthesis rationale keeps the diff off the lines peers 244/246/260 were editing in the same files and ties this to the user's directive to "preserve as much as you can while having low rework" (old context.md@1ed63958:264; peer rebases listed at `design.md@1ed63958:102`, `recon.md@1ed63958:268-277`).
- The seed sits in `retry_until_ok` and the sleep sits outside the `try` in `run_supervised`, so a failing seed or tick can never busy-spin (design.md@1ed63958:19-20, :24).
- The three watcher copies get byte-identical edits and the analysis watcher deliberately does NOT use `supervision.spawn`, to keep the three copies symmetric (consolidating them is out of scope for this feature, D-20; design.md@1ed63958:30, :156) (design.md@1ed63958:34, :126). The watcher backoff cannot be a config key because the watcher is the client that delivers config (design.md@1ed63958:153).
- Park state is in-memory, not a table: instance_count 1, and a migration brings a DBA gate, peer migration-number collision risk (260/262/272) and risk of leaking into `QueryPnLPatterns` (design.md@1ed63958:116). The durable record is the ledger event keyed `pnl_park:<seq>` (ledger idempotency makes the re-park after a failed advance exactly-once).
- Park order is log -> emit -> advance so a crash between advance and emit cannot lose the record (design.md@1ed63958:115); a raise in the advance propagates to the reconnect handler without resetting the replay pair.
- Fixed invariants, not config keys (`servicer.py:346-347` precedent): `_EVENT_MAX_ATTEMPTS=3`, `_EVENT_RETRY_BACKOFF_SECONDS=1.0`, `_REPLAY_ESCALATE_AFTER=5`, `_PROBE_TIMEOUT_SECONDS=5`, `_PARK_EMIT_TIMEOUT_SECONDS=5`, `_ATTEMPT_DB_TIMEOUT_SECONDS=10`, `_LOOP_ERROR_BACKOFF_SECONDS=30` (design.md@1ed63958:71; old context.md@1ed63958:558; `_ATTEMPT...` must exceed `_PROBE...`, code comment at `pnl_pattern_consumer.py:52`).

**Rejected alternatives**:
- Reusing `read_budget.is_transient_db_error` (r3) — allow-list defaulting to non-transient; OOM/deadlock/disk-full would park within about 2 s and lose realized_pnl and fees_total permanently ("lose data" at design.md@1ed63958:106; the two field names come from old context.md@1ed63958:283, :303; already in Ledger, see below).
- Widening `read_budget._TRANSIENT` to classes 40/53 — changes the read-path status mapping (P-03) to fix a consumer-policy problem (design.md@1ed63958:107).
- K=5 with two consecutive probe confirmations (r3 runner-up) — doubles time to park real poison (about 50-60 s) and does not fix the classifier gap; revisit only if contention-driven false parks are frequent (design.md@1ed63958:108).
- Probing the failing event's own tables instead of `_cursor()` — just as blind to statement timeouts (design.md@1ed63958:109).
- `asyncio.wait_for` around the park `_emit` at the call site (r3) — second error path; a keyword-only gRPC `timeout` inside `_emit`, swallowed by the existing except, is simpler (C-18) (design.md@1ed63958:110).
- Keeping existing post-commit emits byte-identical (no correlation_id) — contradicts the operator's 2026-10-21 trace decision; costs 2 lines to thread (design.md@1ed63958:111).
- Resetting the escalation counter on any successful `process_event` (r2) — see Scars (design.md@1ed63958:112).
- Replaying forever on any transient error (r2) — narrows FR-5 without operator sign-off (design.md@1ed63958:113).
- Parking after a wall-clock cap, or after N escalations without a probe — both park good events during a real outage (design.md@1ed63958:114).
- Park order log -> advance -> emit — a crash between advance and emit loses the ledger record (design.md@1ed63958:115).
- Persisted per-sequence attempt table / migration-028 parked-events table — see Why (design.md@1ed63958:116).
- Labelling the in-feature `@AC-7` edit as CHANGE — it is this feature's own unlaunched scenario, edited directly (design.md@1ed63958:117).
- Carried over from r1/r2: per-seam try hardening inside the ticks; a new local `_TRANSIENT` tuple; tolerating a failed seed; moving the seed into `run_supervised`; capped exponential backoff for loops and watchers (proposed at recon.md@1ed63958:316; design.md@1ed63958:123 lists it without a reason, so reason not recorded); retrying by reconnecting the stream (a reconnect-based retry works only if no later event has already advanced the cursor, recon.md@1ed63958:247-249; an in-place retry keeps ordering; design.md@1ed63958:124 gives no reason of its own); a per-caller backoff callable; the analysis watcher using `supervision.spawn` (design.md@1ed63958:118-126).
- From the r2 synthesis only (old context.md@1ed63958:226-239): adding an RPC deadline inside `_emit` for every caller (changes existing emits, P-03) — later superseded by the keyword-only `timeout` default `None`; a consumer-local wrapper around `is_transient_db_error` "so the two policies can diverge later" (speculative, YAGNI); building the park `AppendEvent` inline instead of extending `_emit` (duplicates `_emit`, C-18; old context.md@1ed63958:233); at-least-once park records with no idempotency key (the ledger already dedups, `ledger.proto:50`, so exactly-once costs one keyword with a stable-input key; cites fails.md:2118-2122; old context.md@1ed63958:234).

**Scars & gotchas**:
- The ledger `StreamEvents` replay is inclusive: the consumer reconnects from its own `_cursor()` and the first row delivered is the already-processed cursor row, which takes the `sequence <= cursor` early return as a "success". Any "reset on success" rule zeroes an escalation counter on every reconnect. Shipped rule: `pnl_pattern_consumer.py:190-192`. Current ledger anchor: `services/xstockstrat-ledger/src/grpc/ledgerServiceImpl.ts:254-255,314-321` (`maxSeq` seeded `fromSequence - 1n` so the first row is delivered; replay `cursor = maxSeq`, `sequence > $3`); `:200-202` is `queryEvents`' own `fromSequence` filter, not the stream. - A catch-all supervisor turns every existing test that stops a loop by raising an `Exception` subclass into an infinite loop. After Step 3 the two `@AC-7 @feature-156` jitter tests in `tests/test_fundsignal_loop.py` spun forever, so Step 3's full-suite run had to deselect them ("Do not run the full suite without that fix or deselecting them", old context.md@1ed63958:672-674). - Two different interim-red mechanisms, both recorded as expected when the service/test step split was kept (the opposite of the merged-pair resolution in insights.md:3805-3808, feature 256): (a) after Step 11 widened `_emit` with `timeout=`, 6 tests failed because `_emit` swallows every exception (best-effort), so a test fake `AppendEvent` lacking a `timeout` parameter raised a swallowed `TypeError` and showed up only as an empty `ledger.appended` (old context.md@1ed63958:853-856); (b) after Step 13 gave the repositories `timeout=`, 13 tests (11 in `test_pnl_pattern_consumer.py`, 2 in `test_owner_header_guard.py`) failed with a direct, unswallowed `TypeError: unexpected keyword argument 'timeout'` from `FakePool`/`FakeSnapshots`/`FakeSamples` (old context.md@1ed63958:951-955).

The first draft of the bound said "execute/fetch inside `process_event`", but the consumer's only direct queries are `fetchval`/`execute`; the rest live in `order_snapshots.py`, `pnl_positions.py` and `pnl_pattern_samples.py`, so six repository methods gained a keyword-only `timeout: float | None = None` pass-through (old context.md@1ed63958:906-917; Step 13 at :939-942).

**Deferred follow-ons**:
- Probe and event share the pool (old context.md@1ed63958:243): if the event itself leaks pool connections, the probe also fails or times out, the leak looks like an outage, and the event replays forever at ERROR (no park, no time cap).
