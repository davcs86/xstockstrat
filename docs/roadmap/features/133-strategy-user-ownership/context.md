## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: Shipped composite `(user_id, strategy_id)` ownership on analysis.strategies (+ strategy_cooldowns PK, + nullable backtest_runs.user_id), header-resolved ownership gating on every strategy-scoped RPC with uniform `PERMISSION_DENIED`, deletion of the server-side admin gate on ManageStrategy/SetStrategyLive, agent `x-user-id` forwarding for all 5 MCP tools, and UI BFF de-gating + cross-user IDOR e2e. Crucially, what shipped is *identity-only*: the feature's own headline promise (AC-4 — a live strategy evaluates against its owner's `union(watchlist, held, active-signal)`) was DEFERRED to feature 132 at execute time; 133 owner-keys the loop's state but leaves the firing universe as `signal_params.symbols`. The "close 132's cross-user-aggregation gap by construction" framing in feature.md is therefore aspirational, not delivered by 133.

**Why (irrecoverable rationale)**: Composite PK (not a bare owner-tag column) and backtest ownership-gating (not read-shared) were explicit user story-time decisions choosing the stricter, more invasive model. Uniform `PERMISSION_DENIED` on every ownership miss (existence OR owner-mismatch) is a deliberate divergence from the `xstockstrat-indicators` formula-ownership precedent (which splits NOT_FOUND vs PERMISSION_DENIED), chosen for stronger IDOR defense — a caller can never probe whether a `strategy_id` exists under another owner. The admin gate was *deleted, not augmented*, because the User Story requires non-admin self-service and `ADMIN_SCOPE` is granted only to `role==='admin'`, so ordinary traders were previously blocked from their own strategies entirely.

**Rejected alternatives**: Bare owner-tag column on a global `strategy_id` PK — leaves `strategy_id` ambiguous everywhere referenced as a bare string. Backtest left ungated — stricter model chosen at story time. New admin-scoped `ListWatchlists(user_id)` RPC variant — reachable by any internal gRPC client to port 50052, a bigger hole than the synthetic-header pattern. New trading → analysis edge to validate `strategy_id` ownership at order-place — `order.user_id` is itself unauthenticated (TRADING-N1 open), so the check is false security and a reliability regression. Two-migration split bracketing a manual operator step — db-migrator applies all pending migrations in one deploy run, no pause primitive exists. `psql -v` session-variable seed passing — golang-migrate uses its own driver, not psql. NOT_FOUND/PERMISSION_DENIED split — lost to uniform-deny per IDOR rationale.

**Scars & gotchas**: `_row_to_strategy_definition` silently did NOT surface the new `user_id` column — migrated rows would key the live loop by `""` while `hydrate_cooldowns` keyed by the seed id, breaking the cooldown gate on every restart (found only via tests; a recurrence of the fails.md-048 mapper-lockstep class). docker-compose.yml db-migrator needed a *concrete* `SEED_USER_ID` default (`:-<seed>`), not empty: `db-migrate.sh`'s `:?` guard hard-fails on empty, so an empty compose default would break `docker compose up` on any fresh local DB. Migration 013 templates the seed via `envsubst '$SEED_USER_ID'` (scoped-allowlist form) specifically because bare envsubst corrupts the migration's own `DO $$…$$` dollar-quoted block (a pre-recorded fail from 006-do-nginx-integration); there was NO existing envsubst invocation site in the pipeline to hook into. Seed `user_id = 80880990-2b79-4d85-8761-d8d9102c2efb` was operator-supplied, applied to dev and prod.

**Permanent deviations**: design said the live-loop resolves each owner's `union(watchlist, held, active-signal)` via `ListPositions(user_id=owner)` + synthetic-header `ListWatchlists` (AC-4) → shipped identity-only owner-keying of the 6 state dicts + entry_backfill, firing universe unchanged, feature-089 no-symbols precondition retained — the union composition with the existing firing contract was under-specified and the user deferred the shared `resolve_universe` builder to feature 132 (D-1). design said Step 17 records a live-loop `x-user-id` impersonation finding → shipped a forward-pointer deferral to 132 in context-constitution-findings.md (133 introduced no synthetic-header call site at all). design replaced the admin gate with ownership at RPC + SQL layers → shipped that, but the score subsystem was NOT re-keyed: the in-memory `_strategies` cache and `analysis.strategy_scores` table stay keyed by bare `strategy_id`, guarded only by RPC-layer owner cross-checks (D-2; two users sharing a strategy_id share one cached grade — IDOR fully closed, but the cache is not tenant-isolated). WatchlistBinding: after the seed migration, every *other* user's pre-existing watchlist binding to a legacy strategy_id now resolves to None (owner mismatch) → falls back to "unattributed" — strategy_id carried no ownership concept pre-feature, so the old cross-attribution was never validated (accepted migration-time trade-off, NO cleanup migration). `backtest_runs.user_id` left nullable and NOT threaded on new runs (D-4; attribution-only, `insert(user_id=…)` exists but is unused).

**Cross-feature signal**: 133 is the security/ownership hinge for a cluster — feature 132 owns the `resolve_universe` builder that 133 deferred AC-4 to; feature 131 was specced before 133 merged and had to be re-owner-scoped at execute time to avoid an IDOR via global `list_live_enabled()`. Pattern: when an ownership feature lands *before* features that read the same entities, every new cross-entity read in the later features must be re-verified owner-scoped — the pre-security spec cannot be trusted. The trading fork stays open by design: real strategy-ownership enforcement at order-place time is blocked on closing TRADING-N1 (unauthenticated order.user_id) first.

**Deferred follow-ons**: Owner-scoped firing universe (AC-4) → feature 132 `resolve_universe` (AC-4 satisfied by 132, not 133).
