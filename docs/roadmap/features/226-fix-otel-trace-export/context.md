## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-3 bug fix (Track C, 12 services, integration PR #1246, launched 2026-10-20 via promotion PR #1258, commit 65bbc3cb). Every runtime (Go x3, Python x4, Node backends x4, UI) now builds its trace exporter as OTLP/HTTP with no endpoint/url/insecure argument, so the SDK's own spec env handling (`OTEL_EXPORTER_OTLP_ENDPOINT` + `/v1/traces`, TLS from scheme, `OTEL_EXPORTER_OTLP_HEADERS`) drives it. The UI hook moved to `src/instrumentation.ts`; local compose points all 12 services at `http://otel-collector:4318`; Node/UI log export failures through a lazy WARN diag logger.

**Why (irrecoverable rationale)**:
- Root cause: exporters were wired for a local gRPC collector with explicit endpoint options that override spec env handling (Go passed a full URL to a `host:port`-only gRPC option; Python used `insecure=True` gRPC against an OTLP/HTTP-only gateway; Node passed `url: endpoint` verbatim; UI hook sat at repo root while the app uses `src/`). Evidence at triage: staging trading log `name resolver error: produced zero addresses`; no `[otel] tracing enabled` in UI startup log.
- Operator chose approach (a) standardise on OTLP/HTTP via env only (rejected (b) a collector on DO App Platform); scope traces only (metrics/logs became later features 250/274); failures must be visible in logs; a regression test in every one of the 12 runtime copies.
- Design depth: triage said full (>=2 services); operator chose quick, then asked for 2 more rounds (3 total, R3 SOUND, no Floor breach).
- Design decision (not a divergence): Node/UI cover only the raw header row of AC-1 while Go/Python cover raw + encoded (design.md:29,32; stated in the impl-spec coverage table, C-15) -> because raw is the form `deploy.yml:162-163` produces (implementation-spec.md:36).
- Plaintext local `http://otel-collector:4318` was judged outside `@AC-4 @feature-210` (mTLS everywhere) because the OTLP sink is not an inter-service gRPC hop, so no C-16 conflict (recon.md:89, design.md:77); a future mTLS audit could otherwise flag it.

**Rejected alternatives**:
- Remove the collector's `:4317` receiver — lost: it feeds the metrics/logs pipelines and the documented telemetrygen smoke tests.
- Add `@opentelemetry/api` to Next `serverExternalPackages` — lost: api globals are `Symbol.for`-keyed so bundled and external copies already share state.
- Child-process (stderr) Node test harness — lost: strip-types ESM breaks the lazy `require` in a child too; per-file process isolation is cheaper.
- `initTelemetry()` returning a shutdown handle — lost: test-only API surface (C-18); BSP timer path plus receiver assertions suffice.
- EXTEND `platform.feature` `@AC-1 @feature-171` with xstockstrat-ui — lost: hand-authored durable rule with no backing test; scope creep.
- Drop Go `WithTimeout(5s)` — lost: the 10 s SDK default outlives `main.go`'s 5 s shutdown context.
- Encoded `Authorization=Basic%20...` as the canonical header — lost: deploy produces the raw form and every SDK parses it; would force a needless secret change.
- `autoDetectResources: false` — lost: silently drops host/process/env resource attributes.
- Accept the per-boot `Accessing resource attributes before async attributes settled` diag error — lost: a false ERROR polluting the very signal FR-3 creates.
- Bump Node backends to sdk-node 0.218 / resources 2.x — lost: removes the detector workaround but rewrites `buildResource` x4 (feature-171 guard) for a SEV-3.
- `OTEL_METRICS_EXPORTER=none` / `OTEL_LOGS_EXPORTER=none` in deploy env — lost: config-dependent across both `.do` specs and compose; code-level empty arrays are self-contained.
- Deploy a collector on DO App Platform (operator option (b)) — lost at the product-spec Operator Decisions.

**Scars & gotchas**:
- Header premise was wrong. The defect report and product-spec Operator Decision 2 claimed the documented `Basic <token>` value yields no Authorization header and prescribed `Authorization=Basic%20<token>` with `%3D` padding. `deploy.yml:162-163` already prefixes `Authorization=`, and an empirical fake-receiver probe showed every SDK parses both raw `Authorization=Basic <tok>` and encoded `Authorization=Basic%20<tok%3D>`. The secret stays `Basic <base64(instanceId:apiKey)>`; the defect report got a `## Correction` section. The operator had already been told the encoded format in chat, so the corrected guidance had to be relayed. Operator Decision 2 is superseded, not just amended (AC-1 became a Scenario Outline with raw + encoded rows; Go/Python cover both, Node/UI only the raw row).
- `DiagConsoleLogger` in `@opentelemetry/api` 1.9.1 binds console methods at module load (`diag/consoleLogger.js:15-35`): the console.error spy must be installed before the first OTel import, with telemetry loaded via `await import()` afterwards, one file per process. This is why Node tests live in a separate `telemetry.export.test.ts` (the existing resource test loads api at import).
- Only the BatchSpanProcessor timer path routes export errors to `globalErrorHandler`/diag; `forceFlush`/`shutdown` reject quietly. Node/UI AC-3 sets `OTEL_BSP_SCHEDULE_DELAY=50` and polls for the logged `OTLPExporterError` `"code":"400"`.
- No Node service or UI declared `@opentelemetry/api` (0 hits; `.npmrc` hoists only `@bufbuild/*`), so a lazy `require` would have thrown and silently turned tracing off. Added `@opentelemetry/api ^1.9.0` (locks to 1.9.1) to ledger/identity/notify/config/ui.
- sdk-node 0.52.1 default async resource detectors read `.attributes` early and emit a false `diag.error` on every boot once any diag logger exists; `resourceDetectors: [envDetectorSync, processDetectorSync, hostDetectorSync]` removes it with an identical attribute set (mixed resources 1.30.1 detectors / 1.25.1 sdk-node merge; verified by probe, guarded by the "no OTel console.error before the 400" assertion). sdk-node registers its own diag logger when `OTEL_LOG_LEVEL` is set (`sdk.js:46-50`), so the WARN logger is only installed when it is unset.
- sdk-node 0.218 (UI) auto-starts env-default OTLP metrics/logs pipelines; empty `metricReaders: []` + `logRecordProcessors: []` bypass them (`sdk.js:146-177`) to keep UI traces-only.
- Go failure visibility needs no code: `otel@v1.45.0 internal/errorhandler/errorhandler.go:36` `log.Print(err)` is reached from the BSP drain-on-shutdown path (`batch_span_processor.go:380,386`) and `otlptracehttp client.go:281` puts `resp.Status` ("400 Bad Request") in the error. Go/Python AC-3 assert the receiver's 400 (old code never reaches a receiver, so genuine red).
- Go export failures log at INFO (OTel default handler writes via stdlib `log`, routed by `slog.SetDefault` to INFO; observed as `"traces export: ..."` at INFO, recon.md:23), so an ERROR-filtered log search will miss them.

This also forced the agent `test_telemetry.py` patch-target repoint (`proto.grpc` -> `proto.http`) into the Python service step, since that suite breaks once `-proto-grpc` is uninstalled. That file is shared with the Python test step, so the commit stages only the one-line hunk (done via a constructed blob because `git add -p` is unavailable non-interactively).
