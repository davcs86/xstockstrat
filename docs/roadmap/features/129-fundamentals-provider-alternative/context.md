## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: Shipped a second fundamentals provider (Finnhub) in xstockstrat-marketdata behind the existing `source.FundamentalsSource` interface, selectable at boot via a new `marketdata.fundamentals.provider` key — FMP was kept, not replaced, and Finnhub ships disabled (`marketdata.finnhub.enabled=false`). The RPC/proto contract was unchanged (comment-only proto edits). The quota guard grew a second shape (rolling per-minute window alongside FMP's daily cap). The feature's largest real risks were provider data-unit mismatches invisible to docs research, and a deploy-secret wiring gap invisible to the spec.

**Why (irrecoverable rationale)**: Finnhub over Twelve Data because Twelve Data's free/Basic tier categorically excludes all fundamentals (`/statistics` is Pro/Venture-only) — a hard FR-2 disqualifier independent of its generous 800/day budget; Finnhub's `/stock/metric` returns the full field set free at ~60 calls/min with no daily cap. Kept switchable rather than deleting FMP because two required-field facts (dividend-yield presence, per-symbol-vs-batch call shape) were unconfirmed at design time and an applied removal migration (F-01) is unfixable-in-place — switchable bought a real rollback path for one selector key.

**Rejected alternatives**: Full replacement of FMP in this feature — dividend-yield field + call shape unverified; deleting internal/fmp/ before the smoke test risked shipping a non-satisfying provider with no fallback. Baking symbols_per_minute≈20 into the seed migration at design time — a derived guess; F-01 makes a wrong migrated default uneditable; deferred to /sdd-spec, which verified the no-batch shape from finnhub-python's client.py (20 = 60÷3). Reusing the UTC-day quota counter unchanged, just resized — a day bucket can't protect a per-minute ceiling during a burst (a 200-symbol pass 429s under any daily total).

**Scars & gotchas**: Provider data-unit mismatches only a live API call surfaces — Finnhub's `marketCapitalization` is in millions USD (×1,000,000) and `roeTTM`/`currentDividendYieldTTM` are percentage-points (÷100), whereas FMP passes raw dollars and fractions; both are plausible-looking floats, nothing errors, and a same-shape client swap would have silently shipped market caps 1,000,000× too small and broken every dividend/ROE screener threshold (shipped code carries `/100` and `*1_000_000` with comments, so partly re-derivable — but the *why* and provider-contrast live only here). Dividend-yield field: two candidates (`currentDividendYieldTTM` vs `dividendYieldIndicatedAnnual`); chose the TTM one to parallel FMP's `dividendYieldTTM` semantic. `toProtoFundamentals`' empty-`Source` fallback was hardcoded `"fmp"` (an existing test's fake leaves Source unset); a Finnhub row would misreport as `"fmp"` until made `s.fundProvider`-aware. `fundProvider` is read once at boot and frozen, never re-read live in RPC handlers, because the boot-chosen client object and the config-key-name dispatch must never diverge.

**Permanent deviations**: Spec Step 2 asked only to confirm field *names* → shipped added explicit ÷100 and ×1,000,000 unit conversions (the live call surfaced unit mismatches the Instructions never anticipated; F-09 kept the step body immutable). Spec Step 12 required a full-stack grpcurl-against-deployed-instance smoke test → shipped client-level live-API verification only (AAPL/PLTR/SOFI direct calls) — no Docker/DB available; the full RPC/DB/cache/live-config path was never exercised end-to-end (see Deferred; user signed off).

**Cross-feature signal**: The vendor-credential deploy-wiring pattern is under-specified repo-wide — a follow-up audit found `BROKER_ACCOUNTS_ENCRYPTION_KEY` missing from docker-compose.yml's trading block since ~feature 023 (a pre-existing local-dev-breaking bug: trading `os.Exit(1)` guard never let it boot via `docker compose up`), unrelated to 129 but exposed by generalizing this feature's fix; the new `docs/runbooks/add-data-source.md` § "Wiring a New Vendor Credential Through Deploy" (10-file checklist) is the durable fix. Governance docs (CLAUDE.md, config-governance.md, reviewer-registry.md) still claimed sensitive keys use a `secret.*` prefix — dead since feature 076/migration 009 — exactly what would re-cause the config-key-for-a-credential mistake; fixed to state the actual env-var precedent.

**Deferred follow-ons**: FMP-removal fast-follow — FMP deliberately NOT deleted; removal of internal/fmp/, marketdata.fmp.* rows, tests is a named future step gated on real production confidence in Finnhub (operator flips `marketdata.finnhub.enabled` via config-rollout.md). True end-to-end verification (RPC + real cache write/read + `CountFundamentalsFetchedSince` rolling-window guard against real rows + SetConfig live rollout) never run — happens at actual deployment time. Partial-symbol-fetch quota drain (design Open Risk, accepted not solved): if 2 of 3 per-symbol calls succeed and the third fails, no cache row is upserted so the guard under-counts, but real Finnhub quota was consumed.
