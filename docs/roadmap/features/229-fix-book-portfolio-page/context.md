## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug (defect report `docs/reports/2026-10-16-portfolio-page-stuck-loading-defect.md`, now `resolved`). Book → Portfolio sat on "Loading portfolio…" forever and MCP `get_positions` / `query_bars` timed out at 60s while every component reported HEALTHY. Shipped via integration PR #1251 (merged to staging as `a914f69`, promoted by PR #1258, committed to main `65bbc3cbf93a03f5359b60228398a25e6f297f05`, launched 2026-10-20). No proto, no migration, no UI or agent change: portfolio now bounds its quote hop with a 4000ms deadline and marketdata bounds, budgets and prunes its quote path. Scope grew from 4 fix items to 8 through four debate rounds (cache-age guard, partial result, GetPnL Unavailable, snapshot guard).

**Why (irrecoverable rationale)**:
- Root cause was two defects compounding: marketdata `GetLatestQuotesBatch` had no time predicate over the 1h-chunk, never-pruned `marketdata.quotes` hypertable (estimates from recon/design, never measured live: ~142 days of staging quotes, ~1,250 hourly chunks past a 90-day cut per recon.md:147-149, ~3,400 chunks per unbounded call per design.md lock table) and starved marketdata's 2-connection pool; portfolio `latestQuotesFor` had no deadline and no hop (browser BFF → portfolio → marketdata) set one. `marketdata.retention.quotes_days` was documented but read by no code.
- Retention is an app-level `drop_chunks` loop, not `add_retention_policy`, because `add_retention_policy` is TSL-only and DO runs the Apache edition (backlog feature 040; 229 supersedes 040's `marketdata.quotes` row). `drop_chunks` and `timescaledb_information.chunks` are Apache-licensed.
- The recency window is 7 days (`latest_lookback_hours` 168) so 3-day weekends and holidays still hit cache; the operator chose it after asking whether old quotes could be "promoted to bars".
- `portfolio.marketdata.quote_timeout_ms` default is 4000 (product-spec round-1 value was 2500), bounds [500, 8000]: it must exceed marketdata's 2500ms cold budget plus a warm read so a cold-fetch timeout still returns the warm subset instead of timing out upstream. This is an operator change to a product-spec default (2026-10-16).
- ListPortfolios makes ONE union `latestQuotesFor` call across accounts: per-account calls meant N × deadline latency and the same symbol priced inconsistently across accounts (C-10(b)).
- Operator decisions that narrow/override earlier scope: (1) triage decision 2 (context.md 2026-10-16: tunables are config keys, 227 pattern) was narrowed by design round 1 (2026-10-16) — not a shipped-vs-design deviation, since design.md already specified them as fixed invariants — to: tunables are config keys EXCEPT retention cadence 1h, first-pass delay 1h, `lock_timeout` 2s, 24h step, 30s backstop, which are documented fixed invariants in marketdata CLAUDE.md (215 precedent; narrows decision 2; `quotes_days` stays the only retention key). (2) Track C with `quick` design depth overrode C-0's "full" recommendation (migration + ≥2 services signals); the debate was then extended to 4 rounds at operator request. (3) GetPnL Unavailable and broker-priced GetPnL are explicit operator sign-offs of scope additions.

**Ordering rationale (execute order was inside-out, one integration PR)**:
- Config bounds first: every new key is write-bounded in `SCALAR_BOUNDS_REGISTRY` before any reader exists (impl-spec Step Dependencies: "Steps 3-10 require Step 1").
- The recency predicate (Step 3) ships before or with the retention loop (Step 7) so the still-unbounded readers never contend with the `drop_chunks` locks (product-spec review round 2 warning, context.md 2026-10-16).
- Portfolio Step 9 has no code dependency on Steps 3-8 but is ordered after the marketdata budget (Step 5), because the 4000 > 2500 + warm-read relationship is only meaningful once that budget exists.
- Operator merge gates were mapped to steps: G1+G2 before Step 3's PR merged, G3+G4 before Step 7's PR merged (impl-spec Step Dependencies; context.md 2026-10-18 sdd-spec and impl-spec review). Execution instead used one integration PR #1251 with per-step commits (context.md 2026-10-18 sequential), so no per-step merge existed for them to block; they were recorded as blocking PR #1251's merge and were then bypassed (context.md 2026-10-19: "G1-G4 were not recorded before the merge"). Inference, not sourced: the single-PR execution mode made the per-step gate mapping unenforceable.

**Rejected alternatives**:
- `add_retention_policy` migration — lost: TSL-only, unavailable on DO Apache edition (feature 040).
- Quote → bar rollup instead of dropping — lost: `marketdata.ohlcv` already holds authoritative adjusted Alpaca bars for the same warm set; 30s mid-quote roll-ups (no volume) would be a lower-fidelity conflicting second bar source (the feature 056 dual-source class), and do not change the newest-quote window question.
- `DISTINCT ON` + time window for the batch read — lost: bounds locks but still reads every in-window row per symbol; SkipScan is TSL-only. Replaced by `unnest($1) CROSS JOIN LATERAL (… ORDER BY time DESC LIMIT 1)` (~1 tuple per symbol), same shape as the singular reader so batch == serial (feature 178 @AC-1 parity) by construction.
- Per-account deadlines in ListPortfolios — lost: N × deadline, cross-account valuation drift.
- Reusing 227's `marketdata.price.batch_timeout_ms` — lost: different RPC whose ceiling is tied to the analysis budget; keys stay independent.
- Inline literal cutoff as primary design — lost: churns the statement cache; kept only as the G1 fallback (needs operator sign-off + Deviation Log entry if used).
- One-shot first retention run — lost: ~3,750+ AccessExclusive locks in one call risks SQLSTATE 53200 (feature 153 class). Retention first pass at boot+1min also lost: contends with the old pod's unbounded readers during a rolling deploy.
- "Drop the 24 oldest chunks" per step — lost: operator kept the 24h TIME step (`min(oldest+24h, cutoff)`); progress is guaranteed because the oldest chunk's `range_end <= start+1h`, and the cache guard removes the sparse-chunk pin that motivated the refinement.
- 31-day code clamp on `quotes_days` — lost: SetConfig bounds `[31, 3650]` plus a skip-with-WARN guard when `days*24 <= lookback_hours` (for values written straight to the DB); no silent clamp.
- GetPnL → `Internal` or leaving the silent 0 — lost: Internal mislabels a transient dependency condition; `unrealized_pnl` has no presence bit so 0 would be a lie.
- Keeping feature 178's all-or-nothing cold failure — lost: one failed or stale symbol discarded good warm quotes.
- Skipping a snapshot when ANY position is unpriced — lost: one delisted holding would stop a user's snapshots forever; only the all-unpriced / `!ok` case is skipped.
- Moving the snapshot guard into marketdata (error on all-cold empty result) — lost: puts snapshot policy inside a shared RPC and contradicts the partial-result decision.

**Scars & gotchas**:
- pgxmock v4.9.0 does NOT strip `pgx.QueryExecModeExec`; it is matched as positional argument 0 (`pgxmock/v4@v4.9.0/expectations.go:139-172`), so repo tests must expect it explicitly (settled design's F-04 note).
- `drop_chunks(older_than => …)` takes polymorphic `"any"`: the bound parameter needs `$1::timestamptz`.
- Per-query `QueryExecModeExec` (unnamed statement → custom plan → cutoff constant-folded → plan-time chunk exclusion) is what makes the window effective even on direct non-PgBouncer connections (`pool.go:31-33`); runtime-only exclusion would lock every chunk on every read. Live proof is staging gates G1/G2, not unit tests (pgxmock proves SQL shape only).
- Lock math (corrected through round 2): ~4 relations per chunk on read (heap, PK, `quotes_time_idx`, `idx_quotes_symbol_time`) = ~672 locks at 168h, 2,880 at 720h; ~6 per drop (adds TOAST + index) = ~144 per 24h step; budget ~25,600. Retention bounds assume 1h chunks: any future `set_chunk_time_interval` on quotes must revisit the ≤24-chunks-per-step bound and the ~55h backlog drain.
- Ignored parse errors at `alpaca/client.go:313/:501` produce year-0001 quote times; without the cache-age guard those would create year-0001 chunks. Halted/delisted symbols would otherwise recreate dropped chunks every 30s via the warm poller.
