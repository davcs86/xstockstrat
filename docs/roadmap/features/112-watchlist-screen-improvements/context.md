## Archive Synthesis — 2026-08-16 — /sdd-archiver

**What**: Pure UI-composition rework of `/insights/watchlists` detail pane — no proto, BFF, migration, or config touch. Relocated per-symbol edit/delete controls into readiness-table rows via stateless `BindingRowControls` subcomponent; added inline strategy picker to add-symbol flow (single-call add-already-bound); added click-to-edit watchlist renaming. A two-layer concurrency guard was required beyond what design anticipated: `writeInFlight` boolean for intra-pane write races (Layer 1), and a shared `mutationKey`/`useIsMutating` + `|| isFetching` check to disable master-list switch buttons during cross-instance write races exposed by the `key`-remount mechanism (Layer 2).

**Why (irrecoverable rationale)**: `key={selected.watchlistId}` on the whole `WatchlistDetail` component (not per-piece-of-state keyed subcomponents) was chosen because the subcomponent approach reproduced the same leak-across-switch bug class for every new state variable added — it was fixed for one variable each time, then immediately recurred with the next. The outer key closes the whole class in one line. Verified as cheap: `queryClient.ts:14`'s 5s global `staleTime` means a remount within that window serves cached data with zero network calls. The `|| isFetching` clause on Layer 2 is load-bearing — not decorative — because `useInvalidatingMutation.ts`'s `onSuccess` fires `invalidateQueries` without awaiting it; `useIsMutating` alone misses the window between mutation reporting "done" and refetch settling. `WATCHLIST_WRITE_KEY` is non-per-watchlist because `watchlistId` is only known at `.mutate(input)` call time, not at hook-definition time. `addStrategyId` is intentionally not reset in `onSuccess` — UX choice to keep active strategy for repeat adds to same watchlist; only watchlist-switch remount resets it. Critical rule (irrecoverable from code): add-time picker uses `liveStrategies`; rebind picker uses `allStrategies` (to keep existing non-live binding visible).

**Rejected alternatives**: `useEffect`-keyed on `watchlistId` (one-paint stale-frame flicker). Per-piece-of-state keyed subcomponents (same bug class recurred 3 times in rounds R3-R5). Per-symbol `pendingSymbols: Set<string>` guard (only covers 1 of 4 write-pairings). Lifting mutation hooks to `page.tsx` (reverses the simplification the outer key achieved). Making `useInvalidatingMutation.onSuccess` globally async/awaited (blast radius on unrelated hooks). Per-watchlist `mutationKey` (`watchlistId` not available at hook-definition time).

**Scars & gotchas**: `pnpm test:e2e -- <args>` forwards the literal `--` token to Playwright CLI, desyncing argument parsing — use `pnpm exec playwright test <args>` instead. Pre-provisioned Chromium at `/opt/pw-browsers/chromium` requires `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` env var. Merging `origin/main-dev` mid-session introduced semantic drift: unrelated same-day defect fix split flat `strategies` list into `allStrategies`/`liveStrategies`/`strategyOptions()`, requiring re-spec of Steps 1, 2, 3, 5, 7, 8 and repointing 6 e2e test references. `useWatchlists().isFetching` as literally written would be a TypeScript compile error — the hook's declared return type at `useWatchlists.ts:17-21` only exposed `{ data, isLoading, error }`; fix: widen declared return type to add `isFetching: boolean`. A just-mounted `WatchlistDetail` for watchlist B briefly shows disabled controls when switched to while a write against watchlist A is still in the `isFetching` window — inherent to the Layer 2 guard mechanism, explicitly accepted in design.md §Open Risks as "self-resolving within the RPC/refetch round-trip; not data loss"; must not be treated as a regression.
