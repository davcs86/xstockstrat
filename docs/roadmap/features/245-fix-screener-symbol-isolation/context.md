## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug (Type bug, Track C). `ScreenerEngine.screen()` gathered `_eval_symbol` with no per-symbol guard, so one symbol raising a non-`grpc.RpcError` aborted the whole `ScreenSymbols` RPC (UNKNOWN, or INVALID_ARGUMENT for a `ValueError`). Shipped across 3 services in 10 steps (analysis 1-3, agent 4-6, UI 7-8, docs 9-10): `_eval_symbol_isolated` (`except Exception` only) turns a failing symbol into a kept row (status OK, `passed=false`, `score_unavailable=true`, empty raws, no criterion scores) that sorts last; one summary WARN/ERROR line plus a `screener.degraded_count` span attribute. The agent `screen_symbols` now forwards `score_unavailable`; `SymbolScreening` renders "Not evaluated". Launched 2026-10-30 via PR #1368 (commit df521ff5). Live anchors (re-read 2026-11-04): `screener.py:240` wrapper, `:486` fail-closed `_build_result` branch, `:162` span attribute, `:169-175` ranked list (sort `:174`).
**Why (irrecoverable rationale)**:
- Origin: feature 160 fixed one trigger (`bar.time`) without adding isolation; feature 176's concurrent fan-out kept the serial loop's missing try/except (product-spec Problem Statement, now deleted).
- Degraded row is KEPT, not dropped: a dropped row makes a symbol silently vanish and AC-1 could not assert "is present", so it would not be red on the buggy code (P-06).
- Row shape is `score_unavailable` + `passed=false`, status OK, never INSUFFICIENT_DATA: a gap-less INSUFFICIENT_DATA row starts the `/insights/screener` poll (`page.tsx:120-129`) and the "Fundamentals pending" badge; feature 144 kept that status for transient causes only.
- Raws are discarded (fresh `_seed_row`): `_normalize_universe` min-max runs over every row carrying a raw, so a partial raw from BAD would shift the other 49 scores. That is what makes the pinned AC-1 oracle ("each of the other 49 rows equals the same request run without BAD") hold. AC-1 gives BAD the highest signal conviction so a kept raw would visibly break the oracle.
- `eval_failed` bool is set once at row creation and read by subscript `row["eval_failed"]` (never `.get(..., False)`), so seed drift fails loudly. `_build_result` early-returns on it before the default `passed = True`, avoiding a repeat of the `bef4258` scar (a raw-less all-soft row would otherwise come out passed=True + score_unavailable=True).
- Operator decisions (binding, recorded 2026-10-20): designs run in FULL mode only for automated fixes (operator overrode triage's `quick` recommendation); design gate auto-approved once rounds >= 2, no Floor breach, no blocking objection, and every @AC CHANGE covered by an operator decision. Design ran 4 rounds; there was no CHANGE to an existing @AC. Sequential execution approved by standing authorization, operator chat 2026-10-28 (session_01NpS3HShZK6pSnogA7CFo2f): checkpoint mode `report`, C-16 promotion auto-confirmed unless it changes an existing @AC, merge-train authorized.
**Rejected alternatives**:
- `gather(return_exceptions=True)` + isinstance split — needs an explicit CancelledError re-raise and a zip to recover the symbol; the wrapper gets both free (recon listed the `admin_audit.py:58-59` precedent; the wrapper won).
- Drop the degraded row — silent missing symbol; AC-1 not red on buggy code.
- New `ScreenResultStatus` value (e.g. EVAL_ERROR) — proto change (C-04/C-09) breaking exhaustive UI/agent enum handling; too much for SEV-2. (Triage said escalate to full design if chosen.)
- INSUFFICIENT_DATA as the degraded status — re-triggers screener poll and pending badge; pollutes `coverage_gaps` and the `dataless_bars` summary.
- Default `_build_result` path — would pass a raw-less row (`passed = True`).
- Keep partial raws — shifts the other 49 normalised scores (fails.md fix-mcp-screener / screener-data-readiness-polling rule: universe-relative values must come from the intended membership).
- Escalate an all-failed scan as ValueError — servicer maps it to INVALID_ARGUMENT, mislabelling a code fault. Option (b), INTERNAL when every row degraded — contradicts FR-1 "RPC returns OK" for N=1 and also "needs an unrecorded P-03 user clarification" (design.md Rejected Alternatives).

- Rely on score 0.0 to sort degraded rows last — feature-144 rows reach exactly 0.0 (`scoring.py:57-58`); hence the 3-part key `(score_unavailable, eval_failed, -score)`.
- Per-symbol WARN plus summary WARN — double-reports, against the `screener.py:129-130` no-double-report invariant.
