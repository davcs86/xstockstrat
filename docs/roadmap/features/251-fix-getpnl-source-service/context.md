## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug fix. `PortfolioService.GetPnL` queried ledger fills with `SourceService: "trading"` while trading stamps `"xstockstrat-trading"` and the ledger matches exactly, so `realized_pnl` was always 0 with no error. Fixing the literal unmasked more defects, so the shipped fix is wider: GetPnL reads the canonical source (`tradingSourceService`, `portfolio_service.go:779`), resolves each fill's side (payload `side`, else `order.created`/`order.submitted` lookup), folds per `trading_mode|account_id|symbol` in ledger `sequence` order and fails closed (`ErrFillUnattributable` -> FAILED_PRECONDITION). Trading fill payloads gained an additive `side` key (`trading.go:1853`, `:1874`). Error mapping became ctx-first (`classifyGetPnLError(ctx, err)`, `toGRPCError` gained FailedPrecondition/DeadlineExceeded/Canceled). The `/trader/positions` fill lineage (second reader of the same wrong literal) now reads the caller's own orders and runs one point query per order (`src/lib/positionLineage.ts`, `LINEAGE_MAX_ORDERS = 50`). Launched 2026-10-31 via PR #1387.

**Why (irrecoverable rationale)**:
- Why the fix grew past the literal (product-spec.md:27-38, :118-123; recon.md:224-242, all deleted): the wrong filter made the fold run over an empty set, which hid (1) unsigned sell qty with no `side` in the fill payload (a sell would fold as a same-direction add, `pnl.go:68-71`), (2) a ledger that emits `nextPageToken` but never reads `page_token` (GetPnL's page loop would replay page 1 once the filter matched), and (3) the silent `slog.Warn` + `break` on query error (a short fold). Recon's verdict: "FR-1 cannot ship safely without addressing" the paging gap.
- Why side is resolved from sibling events instead of fixed at the producer alone: ledger rows are immutable (`deny_mutation` triggers, ledger migration 001), so history keeps the side-less shape forever; a producer-only change cannot satisfy AC-1/AC-2. Producer `side` was added for new rows; the consumer lookup stays for history (design.md §2, §4).
- Why CI missed both original defects (synthesis; echoes fails.md:577): the `GetPnL` test double ignored the request (`watchlist_service_test.go:268-271`), `stopLedger` also ignores it (recon.md:261-263), and the only fixture that produced a non-zero realized figure used a signed sell qty the producer never writes (product-spec.md:122-123). The triage report's control fixture stored the sell as `-10`, a shape trading never emits (breaks PORTFOLIO-4, product-spec.md:112-114), so the spec forbade reusing it.
- Why a portfolio-local const + parity test rather than a shared source-service constant: product-spec.md:60-61 notes a Go constant does not reach the TypeScript lineage site; recon.md Risks ('No shared source-service constant') framed the choice as shared constant vs literal + producer-consumer parity test. Shipped: const `tradingSourceService` plus `TestGetPnL251_SourceServiceParity` (`getpnl_source_parity_test.go:10`).
- Why an unresolvable side returns FAILED_PRECONDITION (not fold-as-buy, skip, or UNAVAILABLE): feature 229 never-fabricate posture; the ledger is immutable with no backfill so the failure is permanent, and UNAVAILABLE would invite retries onto the ledger's single query connection (design.md Rejected Alternatives).
- Why the lineage was re-built per order rather than just correcting the literal: ledger `QueryEvents` has no user predicate, so correcting the filter alone would have shipped every user's `order.filled` events to the browser (product-spec.md:40-48), and the old single platform-wide 100-event page could miss the trader's own fills (AC-19).
- Why the fold key includes `account_id` and the sort is by ledger `sequence`: `pnl.Fold` keys by symbol only, so cross-account fills would net; a (user, mode, symbol) group mixing fills with and without `account_id` is refused rather than guessed (FR-4, AC-14/AC-15). `sequence` is global-monotonic, but its order reflects racing-goroutine insert order, so interleaved partials may differ from the broker figure (accepted risk).

**Rejected alternatives** (design.md Rejected Alternatives, 2026-10-21; all lost for the stated reason):
- Dropping the `SourceService` filter — loses the producer pin the parity test guards.
- `order.created` preload (singleflight, detached ctx, watermark) — livelock/identity hazards; replaced by per-order lookups for the caller's side-less fills only with a positive-only cache (empty answers never cached because `order.created` can land after its fill, `trading.go:1805` at design time).
- `errgroup.SetLimit(2)` for lookups — limit is per-call not global, ledger has one query connection, `golang.org/x/sync` was `// indirect` (F-08). Sequential lookups shipped.
- Fold-as-buy / skip an unresolved side — violates feature 229 never-fabricate. UNAVAILABLE for it — invites retries.
- A page cap on the ledger drain — data-tuned permanent outage; termination guards (repeated token, repeated event_id, empty page with token) instead.
- A sequence-only keyset or `to_timestamp(double)` cursor (ledger) — design rejected them because order was `recorded_at` and a double loses precision. 257 nonetheless shipped a sequence-ordered token (see Permanent deviations).
- Ledger `QueryEventsRequest` user field (field 7) — proto gate (C-09) unnecessary while scoping stayed in the BFF (kept as a gate-(iv) escalation). Feature 263 later added `owner_only = 7` (merge-order.md:79).
- B9 option (b), pure-chain `toGRPCError(connect.NewError(...))` test — leaves the adapter line (`portfolio_handler.go:276-282`) and the DeleteWatchlist path unproven. B9 option (a) (test-only `export_test.go` seam, external `package service_test` adapter test) shipped. A production handler-side service interface was rejected (C-18).
- Package-level side cache — breaks cold-cache premise of the tests; shipped as a zero-value-safe `PortfolioService` field.
- Exporting `posRow`/`positionCols`/`anyArgs` to `service_test`, a bufconn gRPC server, a `Block` field on the shared fake, migrating `fillEvent` into testdata (owned by the live-fold follow-up) — each rejected as scope or duplication (design.md §6).
- Portfolio reading `trading.orders` directly, or a BFF platform-wide lineage drain — cross-service DB read; unbounded browser-path read. This is why FR-3 uses the caller's own `ListOrders` plus per-order point queries (design.md:246).
- Insertion-ordered partials in production (a slice instead of the `latestPartials` map) — a production change for test convenience; the sequence sort already makes production deterministic (design.md:228).
- Fake-ledger choices (design.md:222-224): return `Unimplemented` for `TimeRange`/`FromSequence` instead of silently ignoring them (the fails.md:577 masking pattern); keep the fake's paging code so the FR-5 consumer (no page-1 re-fetch) is tested on portfolio; do not reproduce the ledger's `recorded_at` keyset cursor in the fake (the fake has no `recorded_at`; the cursor was to be proven ledger-side).
- Operator-only scope splits were never taken: defer FR-2 to a named follow-up and restate AC-1/AC-2 as source_service-only, or defer FR-3/AC-3 to `fix-position-lineage-source-service` (product-spec.md:125-142; old context.md@1ed63958:42-45). Both needed explicit operator sign-off recorded in context.md; none is recorded, so the unweakened full scope stood by default.
