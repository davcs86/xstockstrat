## Archive Synthesis — 2026-11-18 — /sdd-archiver

**What**: An insufficient-data backtest on the symbol-page Backtests card can now be fixed in place by any signed-in user: "Backfill missing data" requests a one-symbol, daily-bars, GAPS_ONLY, no-overwrite backfill from `gap.start` through the backtest window end, shows progress from the card's own `jobId`, then offers a manual "Re-run backtest". The server side is a tier-T1 self-serve envelope on ingest `TriggerBackfill` (eight conditions, first-failed-condition denial token, per-symbol de-dup in one transaction under `pg_advisory_xact_lock`) plus one new config key `ingest` / `backfill.self_serve_max_range_days` (default and seed 730, config migration `051`). The insights strategy-page button is opened to non-admins (they send GAPS_ONLY, admins keep an unchanged request). Agent `trigger_backfill` wording, `mcp-tools.md` and the `strat-lab` skill were brought in line in the same PR. The homelab (staging only) is to be set to 8 jobs and a 1830-day cap by a runbook subsection in `docs/runbooks/config-rollout.md`; DigitalOcean stays at 3 and 730. Landed on main-dev as integration PR #1553 (squash commit 0787a1a1) and promoted to main by #1573 (dd41417d). No proto change, no ingest schema migration, no BFF change, no new hook, no lock-breach counter here.

- Why the span default is 730 and the homelab is 1830 (D-17): the self-serve span is `prefix_calendar_days(max warmup bars)` plus the 366-day card window, 666 days at 200 bars and 1825 at 1000 bars. Analysis `backtest.max_range_days` (730) is checked against `request.range` only (analysis `servicer.py:928-935`) so it does not cap the warmup prefix; an earlier 1096 default was justified by the wrong coupling (O-22). This feature owns the homelab 1830 only because it owns the key (D-28).
- Why the ranges are widened (D-5 -> D-8): recon/analysis showed `gap` is the pre-window prefix span (prefix start -> window start), so backfilling exactly the gap can leave the backtest window empty: on the definition path the re-run could return OK with zero trades, and on the SMA path it leaves a window gap instead (the two failure paths traced at the O-2 close, analysis `servicer.py` ~1315-1322, 1574-1578). The operator widened the request to `gap.start` through the window end under GAPS_ONLY, which skips present bars at ingest, and the first FR-2/@AC-2 text ("over exactly the missing range") was amended.
- Why de-dup is a single transaction with an advisory lock, emit and spawn after commit (D-19): `insert_job` only calls `db_pool.execute` so a connection can be passed without a signature change; `has_active_job` did not exist (debate.md D-9 had cited `backfill_jobs.py:111`, which is the `= ANY(symbols)` predicate in `list_jobs`; Step 5 created it). Ingest's six stateless services run through a per-database PgBouncer transaction pool; a transaction-scoped advisory lock is the form that is safe there (this is an inference from root CLAUDE.md § Connection Pool Budget, not a recorded decision). De-dup applies to self-serve requests only; admins are not de-duplicated, and the test rows never pair an admin job with a self-serve job (O-30).
- Why ALREADY_EXISTS carries no job id and the card shows no link or polling (R-4, D-20): the existing job may cover a different range, which would falsely trigger the D-7 "No vendor data" state. An admin multi-symbol job therefore blocks self-serve for its symbols for its whole duration, accepted.
