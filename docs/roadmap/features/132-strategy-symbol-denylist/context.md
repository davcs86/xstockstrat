## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: Shipped a per-strategy deny list that inverted the old opt-in `signal_params.symbols` allowlist into `union(watchlist ∪ held ∪ (signals iff signal_eligible)) − denied`, owner-scoped via feature 133 and layered onto feature 131's live-attribution machinery. Landed as the last of a four-feature cohort (execute order 133 → 134 → 131 → 132), by stacking on 131's still-open PR #954 then rebasing onto main-dev after 131 merged. Scope grew well past "a deny field": forced a fair-share live-loop scheduler, a `signal_eligible` gate, entry-only deny semantics, and the live loop's first-ever portfolio read dependency.

**Why (irrecoverable rationale)**: Entry-only deny (not absolute) — a denied symbol must never blind a user to an *exit* on capital they already hold, so deny subtracts from the entry edge only; held-denied positions keep exit/REDUCE tracing and are flagged `muted` in place (overrode FR-1's literal "regardless of held position"). `signal_eligible` + fair-share both required, for different reasons: the flag bounds the unbounded platform-wide `QuerySignals` term (default-off, for 1-2 screening strategies), but the user explicitly rejected relying on it alone — even with zero flagged strategies, `watchlist ∪ held` balloons every strategy's universe and the old `max_strategies_per_cycle` cap truncated over an *unordered* SELECT, permanently starving arbitrary pairs; so the fair scheduler was built now, not deferred. Muted = dedicated `bool`, persisted via a `provenance` "denied" marker: a muted pair is an *exclusion*, the opposite of provenance's positive semantics (conflating repeats the 023 ordinal/cardinal trap); a `bool` (not enum) also dodges the 067 enum→TS-exhaustive-Record break.

**Rejected alternatives**: Absolute deny (deny wins over held) — deletes a held symbol's exit trace, stops monitoring a position the user owns. Reusing `Opportunity.provenance` as the muted *classifier* — it's the positive-origin list feeding `_primary_source`; kept only as the persistence *carrier*. Single `union − denied` resolver return — cannot express "keep held-denied for exit but block entry"; required the structured `(universe, deny_entry, union, denied)` return. Integer rotation cursor (`% len`) — no stable index→pair identity under a per-cycle-rebuilt list; identity-keyed `bisect_right` resume is churn-/restart-safe. entry_backfill pair-set from `strategy_cooldowns` keys — a strict subset omitting the never-persisted >365d-old open positions feature 116 exists to anchor. allowlist × `signal_eligible` left as silent precedence — silent no-op of a user-set toggle; rejected at write with `INVALID_ARGUMENT` on the *merged* definition. Client-derived muted rows in the UI — the Opportunities page loads no strategy defs.

**Scars & gotchas**: `analysis.opportunities` has NO `muted` column and fixed INSERT/SELECT column lists, so a top-level `row["muted"]` is silently dropped at persist; the bool rides the existing `provenance` JSONB and is derived read-side (`"denied" in provenance`). `deny_entry` must NOT reach `_replay_state` — `_apply_transition` is the shared core for both the live `latest` path and restart replay; if it leaked into replay, a held-denied symbol reconstructs flat-on-restart and its exit never fires. The UI conviction-filter exemption is not enough: the backend `ListOpportunities` read query's own conviction floor (opportunities.py:105) also had to become `WHERE conviction >= $2 OR provenance ? 'denied'`, or muted (conviction-0) rows vanish at the DB layer for any `min_conviction>0` reader — filter exemptions must apply at EVERY layer that filters. Held+denied and bucket-predicate double-row / PK-collision hazards: a watchlist-denied pair could land in both `curated` and `muted_only` → duplicate `opportunity_key`; fixed by disjoint buckets (`muted_only = muted and not (is_watchlist or is_held or is_live)`) and by flagging the existing held row rather than emitting a second. Adding `Opportunity.muted` to the proto immediately red-fails the OR-F descriptor-parity test the moment codegen runs — forced the `_row_to_opportunity` mapper + `_MAPPED` line pulled forward into Step 3, inert until Step 7.

**Permanent deviations** (D-1..D-4 lived only in the pruned design.md + implementation-spec.md; captured here): entry_backfill readiness — design said capture the portfolio channel object + wire explicit `channel_ready()` + RpcError-retry → shipped reuses the live loop's own best-effort drains (already swallow failures, return empty) with NO channel capture or new constructor deps (D-3). live-loop safety guard (FR-6) — design said the live loop "never imports/calls any trading/portfolio RPC" → shipped performs a *read-only* owner-scoped portfolio query for universe resolution; `test_no_trading_imports`'s forbidden set dropped `portfolio_pb2` (kept `trading_pb2`/`PlaceOrder`) and the guard was reworded to "never places orders / touches the trading write surface" (D-4; the loop still never writes trades). `strategy_symbols` fate — design Step 3 said "replace with `resolve_universe`" → shipped KEPT `strategy_symbols` as `resolve_universe`'s internal allowlist extractor because its 5 callers migrate across Steps 5/7/9 (D-1; no behavior change). muted mapper timing — design placed it in Step 7 → shipped pulled it into Step 3 because the parity test breaks at Step 2 codegen (D-2). 089 empty-symbol precondition REMOVED — 132 deleted the `if not strategy_symbols(...)` guard feature 089 added, because under the deny model an empty deny + empty allowlist is now a VALID config that fires the whole union (AC-1); the new "empty config → fires" behavior is grep-visible in `resolve_universe`, but the fact that a prior feature's guard was deliberately removed and 089's stated rationale knowingly inverted lives only in the pruned files — reads as a regression once gone.
