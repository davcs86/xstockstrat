## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: A read-only Data Explorer (`/insights/data-explorer`) and two agent tools (`query_bars`, `query_fundamentals`) over data the platform already stored; the backend query RPCs already existed. The only backend change is cursor pagination on `GetHistoricalFundamentals` (previously unbounded). It added the first agent→marketdata edge (`MARKETDATA_ENDPOINT`). Launched 2026-09-25 via PR #1177.
**Why (irrecoverable rationale)**: Pagination went into the proto, not the client, because spec review flagged that FR-5 required pagination on a response that had none (user decision). Last-refresh uses the existing `Fundamentals.as_of` (field 14), not a new `fetched_at` (user: "more useful: data accurate as of"). The agent CSV is raw `text/csv` in an `EmbeddedResource`/`TextResourceContents`, not base64 (`BlobResourceContents` is banned by feature 072). Out of scope (product-spec): cross-symbol comparison/correlation views, writing or modifying data, new data sources, real-time streaming (already served by `StreamBars`/`StreamQuotes`).
**Rejected alternatives**: Bare `TextContent` for agent CSV (no `mimeType`); a `period_end`-only cursor (annual FY and Q4 share a `period_end`; pinned by `TestQueryHistoricalFundamentals_CompositeCursorSamePeriodEnd`); a new `fetched_at` field; a server-side streaming CSV BFF route (the ledger export wraps a streaming RPC); a custom Load-More accumulator (`useInfiniteQuery` already does it); JS truthiness for missing metrics (breaks legitimate zeros such as `dividend_yield`; MARKETDATA-11); `filterAsOf` as a post-LIMIT filter (short pages — pushed into SQL before LIMIT); a timeframe selector (daily is the only requestable interval since feature 143).
**Scars & gotchas**: Cursor-uniqueness proof: the PK is `(symbol, fiscal_period, period_type)` yet `(period_end, fiscal_period)` is a safe cursor because `edgar_client.go:buildPeriod` derives `fiscal_period` deterministically (`Qn-YYYY`/`FYYYYY`), fixing `period_type` per symbol; the token is the last row actually returned, compared with strict `>` over a pageSize+1 overfetch (`marketdata_repo.go:716-766`); a malformed token resumes from page 1. pgxmock tests prove SQL text only (pair with a live-DB smoke test, insights.md:1963). Raw `page.route` bodies must be Connect-JSON wire fixtures (RFC3339 strings, int64 as strings). Step 8's verification command (`tests/test_query_tools.py` alone under `--cov-fail-under=40`) cannot pass; the full suite (456 passed, 78.09%) is the gate. `.do/app*.yaml` use `${xstockstrat-marketdata.PRIVATE_DOMAIN}:50053`, not the literal in the spec. `tests/test_tools_endpoint.py` hardcodes an exact tool-name set — a SEVENTH tool-count surface beyond the six in recon. `buf breaking` was valid only after fast-forwarding the local `main-dev` ref (202 merged mid-run). Pydantic: `TextResourceContents` is built with the `mimeType` alias but read as `.mime_type`. The `GetBars` ascending cursor can silently drop bars at a page boundary when new bars arrive (recon risk 8, fails.md:143) — acknowledged, never mitigated. The explorer accepts arbitrary date ranges and "no wider lock scope" than `GetBars` was claimed but never tested (feature-153 chunk-lock OOM).
**Permanent deviations**: `total_count` is always 0 (product-spec said it is returned; design left it at the `GetBars` wire-default; the UI must not render "0 results"). The `query_bars` docstring (`tools.py:348-349`) is half false: "omitting `start_date` returns the newest page" is true, but with no start and no token the handler uses `QueryRecentBars` (no `next_page_token`, `marketdata_service.go:225,240-246`) and a token with no start goes to ascending `QueryBars` over `[end − defaultBarLookback, end]`, not "older pages"; the Data Explorer defaults From/To to empty (`page.tsx:104-105`), so Load More is absent by default and AC-8/9 hold only with an explicit start (every test stubs `GetBars`). The CSV resource URI is percent-quoted (`quote(symbol, safe='')`, `tools.py:362,400,426`, a path-traversal guard mirroring `backtest_view`) vs the spec's raw URI. "Last refreshed" renders `YYYY-MM-DD HH:MM UTC` (`page.tsx:70-74`), not the full ISO the acceptance requires (AC-11/12). The CSV filename was first `{symbol}_1Day_bars.csv`, later fixed to the date-range form (falls back when no range is set). An extra snapshot-CSV button exists outside any AC. The first listed asset is auto-selected on load. The agent `query_bars` takes `timeframe="1Day"` and `start_date`/`end_date`. The promoted agent suite (`acceptance/backfilled-data-queryable.feature:27,28,59,66`) and the source `acceptance.feature` use `include_history`/`period_type`/`historical_fundamentals` whereas the tool takes `mode`/`period_types` and returns `periods`; no timeframe selector exists though AC-1/2/8/11/16 say the user "selects" one; AC-20's "pagination controls" are Load more + client-side `DataTable` paging. The C-16 CHANGE sign-off for the 49→51 tool-count scenario that design cites has NO record, and its cited durable suite `agent-postgres-mcp.feature` does not exist. `MARKETDATA_ENDPOINT` was promised in agent `CLAUDE.md` (0 matches). CSV export covers only loaded pages (design promised UX copy or a Load All + Export; never built).
**Cross-feature signal**: `QueryHistoricalFundamentals` pages oldest-first, so the newest filing is on the last page — why feature 211 added `LatestHistoricalFundamental` (`marketdata_repo.go:769-772`); `last_refreshed` (max `filed_date` of loaded pages) under-reports staleness until all pages load. Feature 210 later moved the agent→marketdata channel to `mtls.secure_channel` (`client.py:1721`). The agent tool count went 49→51 at launch and is now 43 after 214.
**Deferred follow-ons**: Fix the `query_bars` docstring and the explorer default-range behaviour (or give the no-start path a token); reconcile the promoted agent vocabulary and timestamp format; add `MARKETDATA_ENDPOINT` to agent `CLAUDE.md`; Load-All/partial-export copy; decide on the snapshot CSV button; document or drop the `fiscal_period` format assumption (design.md:114).
**Runtime-invariant recommendations (→ /context-constitution)**: Candidate MARKETDATA-*: `GetBars` with no start is "newest page, no `next_page_token`", with a start it is oldest-forward with a token — consumers claiming pagination must pass an explicit start (check feature 140's entry first). Candidate MARKETDATA-*: `QueryHistoricalFundamentals` is oldest-first with a `(period_end, fiscal_period)` keyset cursor.
