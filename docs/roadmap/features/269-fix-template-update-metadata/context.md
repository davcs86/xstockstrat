## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug fix (debt-radar D-41). `ManageTemplate` UPDATE in indicators (FORMULA) and analysis (STRATEGY) now persists `name`/`description` (full-replace) and still bumps `version` once; indicators `retire` now stamps `updated_at`; ingest `retire` is first-wins (`COALESCE(retired_at, NOW())`, `updated_at = NOW()`) and ingest CREATE rejects an empty `template_id` with INVALID_ARGUMENT (the `uuid4()` mint is gone). Three independent per-service repairs; no proto, migration, config or UI/agent change. Launched via PR #1368 (committed df521ff51091a86e813950b34afff09ac4e8821b, 2026-10-30).
**Why (irrecoverable rationale)**:
- Metadata is mutable and a metadata-only UPDATE still bumps `version` (product-spec.md@1ed63958:54-59, resolved at triage; the @AC CHANGEs were operator-sanctioned via the D-41 scope decision + the r2 design gate, design.md@1ed63958:119-121). Immutable metadata would have needed a UI change plus a reject path nothing asked for. Suppressing the bump would have been a new payload-diff capability.
- Cost knowingly accepted (FR-2): a cosmetic rename still bumps `version`, so every instance holder sees "update available" and the next instantiation records a higher `origin_template_version` (recon.md@1ed63958:114-115; product-spec.md@1ed63958:20, :57-59).
- RETIRE is first-wins because two of three services already were, and it keeps the original retirement time for audit (product-spec.md@1ed63958 § Open Questions).
- Empty-id CREATE rejects rather than mints because two services already rejected and the config-ui disables save on an empty Template ID (`page.tsx:479`, product-spec.md@1ed63958).
- `update(meta, payload_json)` replaced `update(template_id, ...)` so it mirrors each repo's own sibling `create(meta, ...)` and each call-site diff is one line (design.md@1ed63958:80).
- Per-class description normalization copies each class's own `create`: indicators binds `meta.description or ""`, analysis binds raw `meta.description` (r1 adversary, C-18; old context.md@1ed63958:91, :174).
- Proof design (the substance of the debate): in-memory fakes re-implement the SQL in Python, so updating a fake to "the fixed semantics" proves nothing about the SQL. Proof is therefore (1) repo tests asserting SQL text AND bound args (`fetchrow.call_args.args`), (2) one REQUIRED analysis real-PG file because the `local_pg` harness already existed there, (3) handler tests that are wiring-only (spy at the repo boundary, no clock or first-wins logic in the fakes). Cites fails.md:2253 and :2709 (design.md@1ed63958:39-54, recon.md@1ed63958 § Risks).
**Rejected alternatives**:
- `update(template_id, name, description, payload)` signature — lost to `update(meta, payload_json)` (design.md@1ed63958:80).
- Shared Python template-repository module (D-20) — crosses service package boundaries, out of spec scope, would collide with 266-fix-db-tls-fail-closed (which carries D-20); it would have given one SQL source and one real-PG test (design.md@1ed63958:81). The r1 adversary's further reason: it needs a cross-service package plus coordination with 266 for "three ~10-line SQL edits", which C-18 treats as speculative (old context.md@1ed63958:147).
- `COALESCE(NULLIF($2,''), name)` keep-prior UPDATE — adds a second UPDATE rule diverging from ingest; nothing asked for it (design.md@1ed63958:82).
- Rejecting an empty `name` with INVALID_ARGUMENT — listed as an option in recon.md@1ed63958 § Risks; the design chose full-replace (matches ingest and the UI, which always sends both fields). No separate loss rationale was written for this option beyond that choice.
- Empty-`template_id` guard on every ingest op — would change ingest UPDATE/RETIRE from NOT_FOUND to INVALID_ARGUMENT with no @AC asking for it; rejected under the low-rework instruction, so aligning ingest UPDATE/RETIRE empty-id to INVALID_ARGUMENT is not a recorded follow-on (design.md@1ed63958:83; old context.md@1ed63958:149).
- Copying `local_pg` into the indicators and ingest conftests — about 50 lines of fixture per service, the per-feature rig fails.md:2253 rules out; replaced by a durable follow-up note (design.md@1ed63958:84).
- Inline DDL copy in the analysis real-PG test — drifts from the real schema; lost to reading migration 026 plus a no-other-migration guard (design.md@1ed63958:85).
- Running every analysis migration in order for the real-PG test — not viable, 026 depends on `SEED_USER_ID` and earlier tables (design.md@1ed63958:86).
- Handler-level @AC-2 proof via injectable-clock / first-wins fakes — proves only the fake (design.md@1ed63958:87).
- SQL-text + bind proof everywhere with no analysis real-PG — repeats the vacuous-green pattern where a harness exists (design.md@1ed63958:88).
