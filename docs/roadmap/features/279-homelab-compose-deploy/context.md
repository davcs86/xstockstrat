**Rejected alternatives** (design.md@1ed63958:87-101 unless noted):
- Replace DO now — operator chose parallel deploys.
- `grpc_health_probe` binary — needs PEM files; the self-probe reuses `mtls.ClientConfig`.
- Migrator tolerance only behind a homelab env flag — operator: one semantics everywhere.
- Down-migrate on rollback / migrate after health — destructive / new code may need the new schema.
- Dirty-and-ahead keeping feature 225's `force 0` — the old image cannot see a newer contract file; fail closed.
- Fold the ahead logic into `migration-dirty-guard.sh` — keeps the guard's contract untouched; separate checker.
- Hand-written CI fixture `.env` — cannot catch a workflow that forgets a value; CI runs the real script.
- `TRADING_MODE` in operator `APP_ENV` — second, typo-prone mode knob (`@AC-9 @feature-196`).
- `HOSTNAME` in the ui Dockerfile — changes the DO image (out of scope).
- Root `/api/health` ui route + 9th `PUBLIC_HEALTH_PATHS` entry (round 6 proposal, withdrawn round 7) — duplicate static handler, two-way coupling with 271.
- Gatus probing `/auth/login` — proves a rendered page, not health.
- Deep agent health endpoint — per-call channels; backends have their own checks; restarting the agent fixes nothing.
- `APP_URL` assertion in `render-assert.jq` — duplicates edge hostnames; Gatus pins it.
- "APP_ENV line N" hint — stripped lines make N wrong; runbook gives a local repro.
- `enabled: false` on UI probes until 271 — homelab-edge decisions.md "staging probes always on"; operator kept alerting (old context.md@1ed63958:162-163, 235).

**Scars & gotchas**:
- WIP defects found by design recon, not by the author: D1 `TRADING_MODE` absent from the homelab compose (trading broker default `trading.go:2597`, marketdata Alpaca `Paper` `main.go:107`, and the indicators watcher, which reads `TRADING_MODE` with a `paper` default `services/xstockstrat-indicators/app/config/watcher.py:49` (recon.md@1ed63958:97); production would have run paper); D2 ui binds `process.env.HOSTNAME` (next@15.5.27 `dist/build/utils.js:1316`), which Docker sets to the container id, so `nc -z localhost 3000` never passes and every deploy rolls back (old context.md@1ed63958:41-44). Later: G1 no `defaults.run.shell: bash` (no pipefail), G2 re-run attempts reused the release name, G3 D1/D2 not yet in compose, G4 homelab-edge runbook still listed APPLICATION_ENV in APP_ENV and lacked the live-account warning (old context.md@1ed63958:91-95).
- D3: golang-migrate v4.17.1 `readUp` → `versionExists(from)` fails when the DB version is newer than the image's files; so an old migrator on a newer schema never starts the old stack. `Migrate.Version()` reads only the DB driver (`migrate.go:385-396`) (old context.md@1ed63958:45-48, 62).
- Dirty-AND-ahead: the old release's `migration-dirty-guard.sh` derives its contract floor from its own files only, so a new contract file at N+1 is invisible → `force 0` + full replay (the path `@AC-18 @feature-225` forbids) (old context.md@1ed63958:63-66).
- Checker call-site rules: call via `bash` (no exec-bit blast radius on DO), BEFORE the dirty `case` so any checker crash fails closed, `|| ahead=$?`→`return 0` / `exit 1`; strip leading zeros and compare with `[ -gt ]` (octal trap on `008`/`009`); reuse the guard's dirty regex and exit 2 on an unparsable dirty string; zero `.up.sql` files with a numeric version → exit 2; image check uses `test -f` for the checker (`test -x a -x b` is invalid) (old context.md@1ed63958:76-79, 82-83, 98-99). marketdata has no `007` (recon.md@1ed63958:41), so pass 4 of `migration-rerun.sh` computes marketdata's top version instead of hard-coding 009.
- compose dotenv: a parse error quotes the offending line, and an unclosed quote quotes the rest of the file (including runtime-minted mTLS keys, unmasked) into the job log → stderr filtered to `required variable … is missing a value` lines in both `homelab-render-check.sh` and the homelab-edge gate (H1/H1b; AC-31, AC-32). compose-go accepts `KEY: value`, so the APP_ENV key-strip regex must end `[=:]` and the runbook says APP_ENV is single-line `KEY=value` (old context.md@1ed63958:96-98, 105-111; design.md@1ed63958:53,55-57).
