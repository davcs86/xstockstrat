## Archive Synthesis — 2026-10-07 — /sdd-archiver

**What**: A symbol-level ranking scalar `symbol_score` so a trader can compare which symbol to trade: a geometric rank-decay sum of feature 199's per-opportunity `composite_score` × a grade-derived strategy weight, persisted per row, stamped identically on every row of a symbol, and exposed as an opt-in sort (value 3) in the `/insights` UI (the agent only projects the field — `client.py` has no `sort` parameter, so it can never request symbol-score ordering server-side; the proto comment says non-UI callers keep the UNSPECIFIED blended order). Shipped grade-only: the per-strategy operator override was descoped. Launched 2026-09-24 via PR #1169.
**Why (irrecoverable rationale)**: Split out of 199 because the user's real goal, stated during 199's design, was *symbol* comparison. Two worked examples define the orderings: 2 opportunities at 0.80 must beat 1 at 1.00 (flipping the feature-190 MAX-per-symbol partition sort), and a symbol with `fundamental_macd_blend` must beat a same-count symbol without it (delivered by grade-A vs grade-C weights, not an override). At γ=0.5: AAPL 2×0.80 → 1.20 beats MSFT 1×1.00, and beats PENNY 6×0.30 → 0.5906 (the geometric cap is what stops many weak opportunities running away). Provisional/absent grade = floor = proven grade-F weight 0.5 (operator decision; dropped a separate `provisional_weight` key): an unproven strategy must never outrank an evidenced one. Default sort stays CONVICTION (making `symbol_score` the default would CHANGE `@AC-10 @feature-190`). The weight is the continuous cached `overall_score` through `floor + (1−floor)·overall` (grade ranges are disjoint, so `@AC-4` holds by construction: `w_A ≥ 0.9` vs `w_C < 0.825`, 0.919 vs 0.814); `grade_lookup` returns the continuous score plus the provisional flag, not the letter. Config reads use `get_float_present` (code-default-only like the sibling `composite_*` keys, F-07) so an explicit 0 passes through (γ=0 collapses the fold to MAX; floor=0 allows a zero weight). γ is read-clamped to [0, 0.99]; a γ-specific `SCALAR_BOUNDS_REGISTRY` entry was avoided to stay in-analysis. Main compute needs no heal (the candidates dict has no disposition filter); only the surgical heal needs the disposition-free `symbol_composite_terms`, and the composite fold anchors `best_direction` on RAW conviction with the strategy-weight layer orthogonal. NULL composites are skipped, never coerced to 0, so heal and compute agree.
**Rejected alternatives**: Per-strategy operator override in any form in v1 (deferred at the round-5 gate: four must-fixes for a knob defaulting to a no-op 1.0 — phantom-vs-real migration conflation, grade-fingerprint wipe, full-replace wipe, heal/compute parity gap). Override as an `analysis.scoring.strategy_weight_overrides` JSON config blob (the deleted `source_weights` anti-pattern, fails.md:1155/1537; insights.md:3356) and on the strategy entity (insights.md:3361); per-strategy dynamic 4-segment config keys `…strategy_weight_override.<strategy_id>` (no 4-segment precedent in the analysis namespace, ~40 keys all 3-segment; C-05). Full-recompute requeue for the heal path (latency + never-resurrect rule). Heal via the disposition-aware `read()` (round 3 corrected it to a disposition-free read; heal parity is asserted against the RAW table). An extra `list(user_id)` query for `owned_ids` (YAGNI). FOR-UPDATE/advisory lock on the heal UPDATE (the single idempotent statement self-heals). Persisting a pre-weighted term or `symbol_score_terms` JSONB. `scoreColor` for the UI value (`symbol_score` is a non-[0,1] ordinal; the fails.md:313/418 bug) — plain 3-decimal via `formatComposite`. Read-time computation (the fold is rank-dependent and ordered, not a SQL window aggregate). A discrete A–F → weight-map config. Alternative saturating shapes named in the product-spec open question — a capped/soft-max and noisy-OR `1 − Π(1 − wᵢ·sᵢ)` — were named but never compared; geometric rank-decay was chosen on the worked orderings alone.
