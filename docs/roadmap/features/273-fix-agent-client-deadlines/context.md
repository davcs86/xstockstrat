## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug fix (debt-radar D-16, `docs/reports/2026-10-21-agent-client-deadlines-defect.md` (pruned 2026-11-04; git show 9892b610:docs/reports/2026-10-21-agent-client-deadlines-defect.md)). Every agent -> backend unary RPC in `services/xstockstrat-agent/app/client.py` now carries a call-site `timeout=`: `_RPC_TIMEOUT_S = 10.0` on 67 calls, `_LONG_RPC_TIMEOUT_S = 45.0` on RunBacktest / ScreenSymbols / RunFundamentalsScan / TriggerBackfill (4 calls); `ListOpportunities` (227) and `get_config_value` (247, `_CONFIG_READ_TIMEOUT_S = 3.0`) keep their own. `tools.py` passes `deadline_s` at all 39 pre-existing catch sites plus six new `AioRpcError` wraps; `_grpc_error_message` gained keyword-only `write=` ("outcome unknown, verify before retrying") and a server-detail pass-through. The inbound `ValidateToken` (auth.py) is bounded too and an identity stall answers 503 without `WWW-Authenticate` (FR-6/@AC-11, added at the design gate). Root-cause hypothesis (triage): per-call channel boilerplate with no shared call helper, so a default deadline had nowhere to live (old context.md@1ed63958:19-20). 12 steps, launched 2026-10-30 via PR #1368 (df521ff5).

**Why (irrecoverable rationale)**:
- Constants, not `agent.*` keys: the budgets are fixed nesting invariants under the MCP client's 60 s cap (PLAT-13), and a config key cannot bound the config read itself (circular, per 247). Changing a value needs a spec amendment (old design.md@1ed63958:31-37; old product-spec.md@1ed63958:90-94).
- Per-site kwargs, no `_unary` helper: a helper would rewrite ~73 sites that 215/240/241/245/249 also edit (C-18 low-rework trade-off; old design.md@1ed63958:167-168).
- Reuse the 10 s default for ValidateToken instead of a dedicated 3 s: no ValidateToken p99 existed; Step 1 later measured it at <=134 ms (121.9 ms max, 58 spans, dev, 24 h) so 10 s is very loose but was never tightened (old context.md@1ed63958:849-851).
- Verb-derived `write` default (any verb not in a read set counts as a write) plus a guard "every catch site in a mutating tool passes `write=` explicitly", instead of a per-row W/I table asserted in CI: the table would couple CI to a hand-kept classification that sibling features must keep updating (old context.md@1ed63958:483, :618). The W/I table survived only as design rationale (old design.md@1ed63958:76-92 write table). The one verdict marked idempotent: `manage_watchlist` update (replace-all `UpdateWatchlist`, single transaction, `watchlist_repo.go:199-210`, a cancel rolls back).
- `manage_strategy update` and `set_strategy_live` default to W because no path:line evidence showed a replay is side-effect free (old design.md@1ed63958 write table).
- 503 (not 401) on identity DEADLINE_EXCEEDED/UNAVAILABLE: the 401 carries the `WWW-Authenticate` re-auth pointer, so a slow identity would make the Claude.ai connector re-authorize through the same stalled identity, effectively a logout (old context.md@1ed63958:450, :672).
- Trace id for ValidateToken: `_authorized` mints `_new_trace_id()` before the call and stamps `claims["trace_id"]`, so the auth hop and tool hop share one id (operator 2026-10-21 standing "propagate x-trace-id as much as possible", no C-03 waiver). `auth._metadata()` previously returned `[]`; round-2 claim that auth.py "carries the trio" was false (old context.md@1ed63958:293). `ValidateToken` forwards only `x-trace-id`, not `x-user-id`/`x-access-scope`, because the call runs before auth (old context.md@1ed63958:763-764).
- Scenario shape: @AC-4 was split into @AC-4/@AC-9 for wall-clock flakiness; @AC-10 (AST guard) was added because @AC-5 samples only 9 of ~71 sites; @AC-8 lets IngestSignal answer and stalls only the follow-ups, because stalling IngestSignal would stop the chain at the first call (old context.md@1ed63958:50-62, :80-82).

**Rejected alternatives**:
- Rewording the generic `deadline_s=None` DEADLINE_EXCEEDED text to "within the deadline" — lost: breaks the 227 contract `tests/test_tools.py:2096` (`"within" not in msg`; the `write=True` variant asserts the same at `:2153`); FR-4 is met instead by passing `deadline_s` at each catch site (old context.md@1ed63958:107, :277).
- Shared `_unary(stub_call, req, *, long=False)` helper — lost: rework across ~73 sites vs five concurrent features.
- Channel-level deadline / pooled channel — lost: AGENT-1 (ephemeral channels), `mtls.secure_channel` (`mtls.py:37-43`) has no deadline option.
- Middleware `asyncio.wait_for(57)` as primary fix — lost: no gRPC deadline reaches the server, no DEADLINE_EXCEEDED surfaced (fails @AC-1/2/3/5/9/10), hides which call stalled.
- Raising the long budget toward ~54 s — lost: FR-2 fixes 45 s and 10 s auth + 54 s would be 64 s > MCP timeout.
- Deferring ValidateToken to a follow-up defect — lost: 2 kwargs vs a full triage-to-execute cycle; operator instead amended FR-6/@AC-11 (old context.md@1ed63958:182, :671).
- Pulling auth.py in "under Expected" without an amendment — lost: repeats the agent-mcp-oauth scope-creep fail (fails.md:485 as cited in the design) and leaves a user-visible change with no @AC (C-15).
- Dedicated 3 s `_AUTH_RPC_TIMEOUT_S` — lost: tighter than FR-1's own 10 s with no measured p99, and it turns brief identity slowness into fail-closed rejections (old design.md@1ed63958:185-186).
- Literal None-only server-detail pass-through ("`deadline_s is None` -> `exc.details()`") — lost: dead at every site that now passes `deadline_s`, including `run_backtest`.
- Relative (x1.05) elapsed-time assertions on scaled clocks — lost: ~10-45 ms slack flakes on CI; replaced by exact `timeout` kwarg assertions plus an absolute budget + 0.5 s bound.
