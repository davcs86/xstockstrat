**Why (irrecoverable rationale)**:
- D-18 resolved to Option A (re-describe, OQ-1 = A; OQ-2 moot) because the user's standing directive was "low rework". Option B needed the proto gate, OHLCV plumbing at 4 analysis sites and a warm-up recheck, and would have invalidated stored grades and `pnl_pattern_samples` (design.md@1ed63958:144-148; old context.md@1ed63958:247, 604).
- The D-10 check sits in the PARENT process, after the `returncode != 0` branch, because it is the only seam that covers every early-exit path (`SystemExit`, `os._exit(0)`, frame-traversal exits), and because placing it before the rc!=0 branch would relabel timeout / memory_exceeded / import_blocked results owned by @feature-228 and @feature-209 (design.md@1ed63958:151-160).
- The rc!=0-with-empty-stderr fallback error (`formula exited with code N before producing output`) is in scope because product-spec FR-1 requires a non-empty `error` (product-spec.md@1ed63958:34-37; old context.md@1ed63958:608). Round 2 had downgraded it to non-blocking on the false premise that no FR-1 exists, yet still folded it in (old context.md@1ed63958:306-309, 329, 527); /sdd-design made it mandatory (see Scars).
- Accepted forgery: a formula that prints a valid marker line and then calls `SystemExit(0)` still "succeeds". Accepted because it is the author's own output, not an isolation breach (design.md@1ed63958:185-187; old context.md@1ed63958:622).
- D-54 uses an inline `row.get("pending_intent_id") is None` predicate after each raw `get_by_id`, not a call to `_load_formula`, because `_load_formula` "cannot be reused directly: it returns a converted formula and may serve from cache" (recon.md@1ed63958:79-80).
- The pending-hidden NOT_FOUND runs before the SYSTEM_AUTHOR and owner checks, and is also what ADMIN or a non-owner gets on a pending row, so a pending row is indistinguishable from a missing one (the no-existence-leak rule, @AC-1 @feature-224). A non-pending system or foreign row still gets PERMISSION_DENIED (@AC-23, @AC-28) (recon.md@1ed63958:82, 161-164; design.md@1ed63958:25-26).
- The D-10 `_fail` closure carries `stdout`/`stderr` because /insights `FormulaRunResult.tsx:92-98` and agent `tools.py:1486` render them (design.md@1ed63958:56-57). The timeout branch is deliberately NOT routed through `_fail`: its shape blanks stdout and must not be copied (design.md@1ed63958:63; old context.md@1ed63958:106). Round 1 cited C-01 as a "stdout preservation" rule; round 2 called that a miscitation and re-grounded on the renderers (old context.md@1ed63958:345).
- No agent code change, by design-gate decision: `test_formula` passes the sandbox result through (`tools.py:1488-1495`) and `manage_formula` already maps NOT_FOUND (`tools.py:232`) (implementation-spec.md@1ed63958:40-48; old context.md@1ed63958:587-589).

**Runtime-invariant recommendations (→ /context-constitution)**:
- INDICATORS-*: sandbox success requires a parsed `__OUTPUT__:` line on rc==0; the wrapper prints the marker with a leading `\n`; the parent keeps the LAST marker line and parses strictly; the check runs after the rc!=0 classification so timeout / memory_exceeded / import_blocked labels are preserved. (Already recorded in indicators `CLAUDE.md` § Declared Formula Outputs "No-output failure" by Step 9; candidate for an INDICATORS-* invariant only if the module constitution lacks it.)
- INDICATORS-*: `UpdateFormula`/`DeleteFormula` must hide `pending_intent_id` rows with NOT_FOUND before the system-author / owner checks (order: missing-or-pending → system author → owner → deleted). Reason: a pending row must be indistinguishable from a missing one (no-existence-leak, @AC-1 @feature-224). This is the second incomplete-guard defect in these two handlers (recurrence of fails.md:75-78, 063), so it is a candidate for a Constitution rule (ID to be assigned at promotion), not only a module invariant.
