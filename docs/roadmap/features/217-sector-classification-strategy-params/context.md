## Archive Synthesis — 2026-10-14 — /sdd-archiver

**What**: A point-in-time sector store in marketdata (plain-table SCD-2 `symbol_classification`, natural PK `(symbol, valid_from)`, fed by a single FMP gateway) plus per-sector strategy param overrides (`StrategyDefinition` field 15) that analysis resolves per bar for backtests and from the current sector for live surfaces. Extended (AC-14) so the same overrides reach fundamentals-input formulas — card issuers/banks are balance-sheet funded, so a generic `de_bad=2.0` zeroes their D/E sub-score; AXP is the case. Launched 2026-10-08 (PR #1233). The classification table starts empty and the refresh job ships gated off (`marketdata.classification.enabled`).

**Why (irrecoverable rationale)**:
- Caching and point-in-time are the same decision: a Type-1 overwrite cache destroys reclassification history that cannot be reconstructed.
- Hybrid seeding was a user decision: every symbol's current FMP sector is seeded at the `1900-01-01` epoch sentinel (not 1970, which collides with the protobuf unset-Timestamp default; no platform bar predates 1900), then forward Type-2 refresh. Pure forward-accrual was rejected for giving no immediate backtest value.
- C-16 SIGN-OFF by user davcs86: the epoch-seeded span applies today's sector to historical bars — a deliberate, bounded look-ahead on the parameter-selection axis only; post-go-live is strict PIT; a real reclassification before go-live is invisible; numeric values stay data-at-or-before-t. It is surfaced via the existing `BacktestResult.warnings` channel plus the `source='seed'` column — no new proto field (avoids the enum/parity fan-out).
- Sector-aware fundamentals scoring was folded in so there is ONE override mechanism. Calibrate real sector `de_bad`/`roe_bad` values only after the data-defect fixes 222 (quarterly ROE not annualized) and 223 (stored EDGAR periods) land.
- Keeping classification-store and per-sector-params as ONE long feature (rather than two) was a user-resolved fork even though Group B depends on Group A's FR-5 RPC (ordered A-before-B inside the spec). Per-sector params live in the strategy definition (per-strategy user data, `manage_strategy`/proto), not the config service. Granularity is sector-only (~11 GICS) in v1; industry/sub-industry out of scope; an unknown sector falls to the mandatory default bucket so the engine never fails. Providers other than FMP (EDGAR/Fama-French, Finnhub) are out of scope.

**Rejected alternatives**:
- Type-1 cache — loses the history PIT needs. Hypertable — ~1–2 rows per symbol means no chunk-lock surface, and it would add the feature-153 lock budget for nothing. EDGAR/Fama-French or Finnhub as source — FMP is already wired and GICS-flavored; EDGAR would be a new US-only client.
- Per-bar as-of RPC — the feature-153 lock-exhaustion hot path over a 400-day window. Segment-and-recompute at sector boundaries — breaks indicator warmup.
- Per-component field-7 override map — bloats every component, can't share a param across components. Child table for per-sector params — the JSONB precedent from 132/133 means no analysis migration.
- Three per-path FMP day-counters — true spend ~3× cap. Pure in-memory budget — re-grants the cap on restart. Post-hoc increment without reserve/refund — reopens the check-then-act race. A refund-on-non-200 exists because a 503 storm would otherwise self-throttle later real fetches (the AC-4 regression).
- New `BacktestResult` field for the seed marker; pure forward-accrual (user-rejected).

**Scars & gotchas**:
- Migration collision: feature 223 merged `008` before 217; golang-migrate never applies a version below the current one, so 217's `007` would have been silently skipped on any environment already at 008. Renumbered `007`→`009`; `007` is intentionally unused (Step 3's body still says 007 and is immutable).
- AC wording defect: `@AC-6/7/8/10/13` said "RSI oversold threshold", which in the rule grammar is a rule `rhs` literal, not a component param; reworded to the RSI `period` param (operator-approved C-15 amendment). Overrides on rule-rhs literals are unsupported.
- AC-14 spec gap: a fundamentals-input formula returns early into `_fundamentals_formula_series`, which builds its params from `comp.params` and would have bypassed an override threaded only through `_compute_component`. This arrived as a post-`implementation-ready` operator scope extension and was folded into the Deviation Log instead of rewriting step bodies.
- The FMP provider default is `finnhub`, so a fundamentals-only FMP client would not exist for classification; `main.go` now always builds ONE shared `*fmp.Client` (a second instance would silently split the budget into 2×cap). The limiter carries 2% headroom so dispatch jitter can't land rps+1 calls in one vendor second.
- Docker Hub 429 rate-limited the codegen image: stubs generated host-native with the CI-pinned toolchain after proving an empty-`git diff` baseline; Playwright ran host-native with `--no-deps`; local lint used `golangci-lint` v2.13.1 built with go1.27 (CI pins v2.14.0). The `strategy-authoring.spec.ts` "Edit navigates" test fails identically on the base tree (pre-existing).

**Permanent deviations**:

The definition fingerprint folds field 15 (feature-152 `@AC-6` precedent: a changed override clears the derived grade) per design/recon; the shipped fold was not re-verified at archive time. The prefix warm-up uses the hungriest sector variant (`warmup.py`).
