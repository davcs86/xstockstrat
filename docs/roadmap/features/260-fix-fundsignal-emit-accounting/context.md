Cite forms: `<file>@1ed63958:N` is a line of a pruned file at the pre-archive SHA; `old context.md@1ed63958:N` is the pre-archive context.md. design.md claims are cited to design.md only where design.md says them.

**What**: Fixes two silent-loss bugs in the fundamentals signal producer (`FundamentalsSignalLoop.run_once`, xstockstrat-analysis; debt-radar D-43, D-57, SEV-2, Track C). A claim row in `analysis.fundsignal_emitted` with `signal_id IS NULL` now means "in-flight" and is released on every unconfirmed exit; `signals_emitted` counts only accepted signals; a `GetFundamentalsMulti` chunk that raises is counted in `deferred_count` and ends the run `partial` (`partial` > `budget_deferred` > `completed`). Retries are made stable: direction cuts include the day's stored scores, and non-force `valid_until` is date-anchored so ingest dedups a lost-response retry. Analysis-only: no migration, no ingest code change, the proto edit is one comment (`analysis.proto:564`). Executed 2026-10-29 (9 steps), launched 2026-10-30 via PR #1368 (commit df521ff5, feature.md:36).

**Why (irrecoverable rationale)**:
- Root cause as triaged: one row meant both "claimed" and "emitted"; `_paced_fetch` had no bucket for failed chunks (product-spec.md@1ed63958:65).
- Release-on-failure was chosen over letting a later run take over a NULL row because the manual `RunFundamentalsScan` does not take `self._lock`, so a takeover could steal an in-flight claim and double-emit (design.md@1ed63958:190-192). The unchanged `ON CONFLICT DO NOTHING` claim INSERT is therefore kept as the in-flight fence (design.md@1ed63958:42-44).
- Releasing the claim after ingest already accepted a signal is deliberately safe: if the confirm UPDATE raises, the `finally` releases the claim and the exception propagates; the next non-force run re-emits with the date anchor, ingest dedups it, and that run confirms (design.md@1ed63958:70-72).
- Retry correctness needed more than the two D-ids name: direction is part of ingest's conflict key, so a one-symbol retry that recomputes cuts over its own universe always yields "buy" (`buy_cut == sell_cut`) and would store a contradictory sell+buy pair (design.md@1ed63958:81-84, 203-205). Recon had already flagged this (recon.md@1ed63958:193-194: `_map_directions` recomputes over the smaller retry universe and direction is in ingest's conflict key), but the r1 proposal still had no reference set and the round-1 adversary caught it. Hence the reference-score cut; hence `_already_emitted` widened in place to return `{symbol: score}` (one query, C-18) (design.md@1ed63958:76-80).
- Mode-dependent `valid_until` anchor: the r1 design date-anchored every mode, which would turn a same-day `force` re-emit into an ingest dedup no-op, contradicting analysis CLAUDE.md "force re-emits" and needing operator sign-off outside D-43/D-57. r2 anchors only non-force at `as_of_date` 00:00 UTC (which also matches the already-documented `valid_days` contract) and keeps `force` at `now` (design.md@1ed63958:87-97, 178-180, 327-335).
- No migration: a claim-state column was rejected as disproportionate for a crash-only edge case (design.md@1ed63958:201-202).
- Operator decisions (binding): 2026-10-21 scope is D-43 and D-57, Track C for all SEV-2 grouped from the 2026-10-20 debt-radar scan, citing precedent #1264 (old context.md@1ed63958:13-14, 46-50); standing 2026-10-21 directive to propagate `x-trace-id` wherever possible, no C-03 waiver, only work with no originating request (the loop) may mint its own context (old context.md@1ed63958:237-240); design gate r2 on 2026-10-22: "APPROVED as synthesized" (design.md@1ed63958:5). The operator's own words give no reasoning beyond that string; the design-synthesizer's r2 rationale adopted the adversary's refinements "in line with 'preserve as much as you can while having low rework'" (old context.md@1ed63958:223), so low rework was a standing directive. Execution ran under the operator's standing authorization of 2026-10-28/29 (session_01NpS3HShZK6pSnogA7CFo2f, "Start executing features 241-276" via batch-execute): checkpoints unattended (`report`), C-16 promotion auto-confirmed unless it changes an existing @AC rule, merge-train authorized (255/275 deferred), DB and prod steps operator-only (old context.md@1ed63958:407-413).

**Rejected alternatives**:
- Date-anchor `valid_until` for `force` too (r1 step 5) — lost: same-day force re-emit becomes an ingest dedup no-op; needs sign-off outside scope (design.md@1ed63958:178-180).
- Move idempotency into ingest (`idempotency_key`, or `as_of_date` in the dedup key) — lost: turns ingest `@AC-9/@feature-224`, `@AC-4/@feature-166`, `@AC-2/@feature-173` into CHANGE and needs a proto field plus migration (design.md@1ed63958:181-183); too much rework for SEV-2 under the operator's low-rework directive (old context.md@1ed63958:189).
- Unconditional `finally` release — lost: one no-op DELETE round-trip per symbol through PgBouncer even on success (C-18); replaced by a `confirmed` flag (design.md@1ed63958:184-185).
- Release only in explicit `except` branches — lost: misses `CancelledError` unless `BaseException` is caught (design.md@1ed63958:186-187).
- Confirm UPDATE scoped by `run_id` only (r1) — lost: a stale run could still overwrite a confirmed row; adding `signal_id IS NULL` is free (design.md@1ed63958:188-189).
- Re-claim NULL rows via `ON CONFLICT DO UPDATE ... WHERE signal_id IS NULL` — lost: lock-less manual RPC (above) (design.md@1ed63958:190-192).
- Retry using a direction stored on the claim row — lost: release deletes the row; keeping a failed-state row needs a new column plus a migration numbered 028 at the time (design.md@1ed63958:193-194).
- Narrow `_already_emitted` to `signal_id IS NOT NULL` (recon's recommendation, recon.md@1ed63958:105, 180, 238; also proposer r1) — lost: breaks the in-flight DO-NOTHING fence and the zero-cache-call guarantee, and spends `GetFundamentalsMulti` budget on rows DO NOTHING skips anyway. design.md says /sdd-spec must not re-introduce it (design.md@1ed63958:195-200); the impl-spec carried a grep guard for it (implementation-spec.md@1ed63958:538-540, 598).
- Claim-state/timestamp column (migration 028) for stale-claim takeover — lost: DBA gate and batch-wide NNN renumbering risk for a crash-only edge (design.md@1ed63958:201-202).
- Map directions over the retry universe only — lost: collapses to "buy" (design.md@1ed63958:203-205).
- Convert `FundamentalsScanSummary.status` from a string to an enum (C-04) — rejected: it is existing wire and the conversion is out of scope for a SEV-2 comment-only proto fix (implementation-spec.md@1ed63958:624-625).
- Accept the rare double row instead of making the retry idempotent (an OQ-2 option, product-spec.md@1ed63958:70-71, recon.md@1ed63958:245-247) — not chosen; design.md records no reason for not choosing it.
