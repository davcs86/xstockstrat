## Archive Synthesis — 2026-08-19 — /sdd-archiver

**What**: What shipped is materially larger than the story asked for. The story was "use shadcn's formal CLI instead of our hand-rolled `src/components/ui/`," but mid-`/sdd-design` the user rejected the "preserve the Nocturne dark identity" premise and supplied a concrete tweakcn preset (`bLTl5gh6`, style `radix-rhea`), forcing a full Tailwind v3.4.3→v4 migration, a new dependency stack (`@base-ui/react`, unified `radix-ui`, `@tabler/icons-react`, `tw-animate-css`), OKLCH tokens replacing HSL, and a per-call-site rewrite of the 3 combobox consumers onto a Base-UI compound API — dark-only, no light mode. Umbrella parent of the 120–123 shadcn-migration series; established the repo's CLI-vendored-primitive convention.

**Why (irrecoverable rationale)**: The scope pivot was a deliberate user Commandment-level override (C-11/P-04), not a discovery — the original quick-mode design had already chosen "preserve Nocturne HSL, stay on v3" and passed its adversarial round; the user overrode the premise. Full v4 was chosen over the smaller "colors-only, stay on v3" alternative explicitly offered via AskUserQuestion. The "this preset needs Tailwind v4" conclusion is *proven* not inferred: the preset's globals.css emits `@import "shadcn/tailwind.css";` and the `shadcn` npm package has no such export in its `exports` map (verified against node_modules in a scratch spike).

**Rejected alternatives**: Preserve Nocturne HSL on generic stone/new-york, stay on v3 — user rejected hybrid preservation mid-session; its CLI-behavior findings stayed valid. Rebuild combobox on generic shadcn Command+Popover — moot; the chosen preset ships its own Base-UI Combobox. Colors-only port staying on v3 — declined by user. Light+dark support — user chose dark-only; `.dark` folded into `:root`, light dropped.

**Scars & gotchas**: `shadcn apply --preset ... --yes` still prompts "continue?" (pipe `y` via stdin) and needs a pre-existing components.json or the underlying `add` hangs. The CLI "Validating Tailwind CSS" preflight fails with only `@tailwindcss/postcss` — a bare `tailwindcss@4.3.3` dep must also be present. The preset regeneration breaks the whole-repo build in one atomic pass (combobox compound API + button/badge cva missing buy/sell/paper keys), so whole-repo `pnpm build` can't be intermediate verification (scoped grep/tsc --noEmit per step until Step 7). `apply --preset` silently touched two undeclared files (layout.tsx Roboto, lib/utils.ts dup cn()). badge.tsx warning/info first guessed (amber-500/primary) then corrected to real yellow-500/blue-500 via `git show` — F-04 near-miss. Sandbox outbound network blocks browser automation even to tweakcn/ui.shadcn.com, so running the actual CLI in a scratch repo copy (workspace-protocol dep stripped) was the only path — strictly more authoritative than scraping. Dev-mode cold-compile of the heavier dep graph (13k+ modules for /config-ui) times out e2e; switched to production `pnpm build && pnpm start`.

**Permanent deviations**: design §3 said re-add TableRow's custom `hover:bg-accent/30 data-[state=selected]:bg-accent` → shipped deliberately did NOT, keeping the preset's stock -muted tokens (re-imposing old -accent would recreate the rejected hybrid; only color differs). **CardTitle overridden from the preset's `<div>` back to `<h3>` — an UNGUARDED permanent deviation**: the preset renders `<div>`, shipped forced `<h3>` because `getByRole('heading')` finds nothing otherwise (broke chart-panel.spec.ts:124, impl-spec:950-957). Unlike the buy/sell variants this `<h3>` fix has NO Vitest guard, so the next `apply --preset` silently reverts it and re-breaks heading a11y + e2e; a future agent greps `<h3>` with no way to know the preset emits `<div>`. So card.tsx (overrode preset) and table.tsx (kept preset) both diverged, in opposite directions — card.tsx is the more dangerous because unprotected.

**Cross-feature signal**: Established the repo's CLI-vendored-primitive convention (ui/CLAUDE.md § Styling): any hand-authored primitive is silently overwritten by a future `apply --preset`. Became load-bearing in children (123 bumped recharts v2→v3 early because of it; 121/122 reasoned about variant/primitive drift). The mechanical variant-regression-test guard (not attribution comment, which doesn't survive --overwrite) originated here — but the CardTitle `<h3>` override shipped without such a guard, a live example of the class this convention exists to prevent.
