## Archive Synthesis — 2026-08-16 — /sdd-archiver

**What**: Hardened existing binary kill switch into a three-state trading halt (`ACTIVE`/`REDUCE_ONLY`/`HALTED`) via new parallel config key `platform.trading_state` (left `platform.maintenance_mode` untouched). Core non-obvious work: fixed `xstockstrat-portfolio`'s `GetPosition` handler to distinguish "no position" (NotFound) from "backend failure" (Internal) — previously both returned `CodeNotFound` unconditionally — because that distinction makes REDUCE_ONLY's fail-closed design implementable. Audit trail landed on existing `config.config_audit` table (DB trigger, no new cross-service dependency).

**Why (irrecoverable rationale)**: Parallel key (not in-place widen): proto3 oneof type-mismatch causes `Watcher.GetBool()` to silently return `false` on a string-valued row — disables the kill switch during rollout, exactly wrong for a safety gate. Per-`trading_mode` seed rows: operator can halt live trading without freezing paper testing during an incident. REDUCE_ONLY fails closed on ANY `GetPosition` error (not just NotFound) — this gate is the enforcement point, not advisory. `CancelOrder` deliberately ungated (mirrors feature 030 — operator's sole de-risk tool). `config.config_audit`-only audit: the WatchConfig-subscriber mechanism was found structurally broken in design round 5 — `ConfigValue`/`ConfigSnapshot` carry no `actor`/`reason` field, `config.Watcher` has no on-change hook. C-04 (enum over string) explicitly deferred: only one producer/consumer at launch; re-evaluate when feature 102 or 107 lands.

**Rejected alternatives**: Widen `maintenance_mode` in place (silent fail-open on type mismatch). Fail-open on `GetPosition` error during REDUCE_ONLY (matches `checkPortfolioRisk` semantics but wrong for an enforcement gate). WatchConfig-subscriber ledger-emit for audit (structurally cannot deliver actor/reason). Generic config validation schema (overbuilt). Share 030's `ReplaceOrder` gate (orthogonal concerns).

**Scars & gotchas**: `Watcher.GetBool()` on a string-valued row silently returns `false` (proto3 oneof zero-value-on-type-mismatch) — found only because design adversary read the implementation, not just the call site (`services/xstockstrat-trading/internal/config/config.go:162-170`). `config.Watcher` has no exported snapshot setter — unit test REDUCE_ONLY via zero-value `Watcher` (nil-map reads return zero/default value in Go) and independent pure-helper tests (`parseTradingState`, `isExposureIncreasing`, `isReplaceRiskReducing`). `portfolio_handler.go:GetPosition` (lines 43-53) mapped ALL errors to `connect.CodeNotFound` unconditionally — both the sentinel in the repo layer AND `classifyGetPositionError` helper in the handler must be fixed. `implementation-spec.md` Step 7's primary instruction had a duplicate `:=` bug — execute used the footnoted "hoist and reuse" alternative. Go proxy sandbox: `proxy.golang.org` cannot resolve exact-pinned deps in sandbox; workaround: `go mod tidy` + `git checkout -- go.mod go.sum` before every commit. Playwright test stash race: "No tests found" when Playwright reads a stashed file — not a real failure, re-run after stash pop. Ledger stream-key convention for `platform.trading_state` events: correct is `trading_state:{trading_mode}` (matching key's value granularity), NOT `trading_state:{account}` — `recon.md` actively recommended the wrong per-account pattern (copy of feature 030's); that recommendation is being deleted. `recon.md:79`'s stream-key recommendation was wrong for this key. `configServiceImpl.ts` `ListKeys` staleness bug (selects `default_value` column, not live `value_data` column) — found during recon, flagged for a separate defect report, NOT fixed in this feature.

**Permanent deviations**: product-spec.md FR-5/AC-4 specified ledger-event audit trail → shipped `config.config_audit`-only (no ledger events). Stacked-branch PR strategy used for the five-feature program (100→101→023→030→102) instead of SDD sequential-mode default.

**Unresolved open risk (accepted, not mitigated)**: Fail-closed REDUCE_ONLY can defeat its own purpose during a correlated outage — if `xstockstrat-portfolio` is down at the same time as a market dislocation, the fail-closed gate blocks exposure-DECREASING trades (which REDUCE_ONLY is supposed to allow). This was the adversary's counter-argument in design.md §Open Risks and was accepted at the 5-round hard cap. Named mitigation evaluated and deferred to `/sdd-spec`: derive exposure direction from `trading`'s own local order/fill history (`trading.orders`) first, falling back to the cross-service `GetPosition` call only when local data is ambiguous. Neither the unresolved status nor the `trading.orders`-first mitigation path is visible in the shipped code.

**Cross-feature signal**: Feature 102 later built the internal-caller authz path (`x-internal-caller` gRPC metadata field + hardcoded allow-list in `services/xstockstrat-config/src/grpc/authz.ts`), direction-restricted so automated callers can only move `platform.trading_state` toward restriction — now the platform convention for internal-caller config writes. `GetSnapshot` at `portfolio_handler.go:86` has the same unconditional `CodeNotFound` bug `GetPosition` had — standing defect.
