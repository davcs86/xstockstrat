**Why (irrecoverable rationale)**:
- D-17 sends UNSPECIFIED instead of blocking order entry: blocking adds a dead state while the server already owns the derivation (`resolveTradingMode`) (product-spec.md@1ed63958:44). Gating the READ hooks on a known mode was rejected for the same dead-state reason, and because separate per-environment DBs make the unfiltered UNSPECIFIED read safe (design.md@1ed63958:169).
- Reconnect on a CLEAN stream end, not only on error: both streams are meant to run forever, so an OK end is the D-11 silent stop in a different shape (design.md@1ed63958:163; round-2 reversal of r1's rejected alternative, old context.md@1ed63958:152, :264).
- Indicator clears on the first item of the new attempt OR after `STREAM_STABLE_MS` (3000 ms), never on `onHeader`: the BFF opens the backend stream lazily inside its generators (`traderBff.ts:46-52`, `:85-91`, design-time line numbers), so headers prove only that the BFF was reached; first-message-only would never clear on quiet streams (design.md@1ed63958:161-162).
- Single-slot fallback store, overwrite + clear on dismiss/pathname change, no keyHash clear-on-success: only watchlists set a `mutationKey` (`useWatchlists.ts:86-170`, design-time line numbers), so any keyless success would clear an unrelated error, i.e. silent under-reporting against FR-5 (design.md@1ed63958:160). A lingering banner after a successful retry is the accepted, visible trade-off.
- Reconnect replay is safe: trading `StreamOrderUpdates` replays its snapshot on every reconnect, judged idempotent under keyed state plus `pickFresherOrder`; notify `streamAlerts` registers a subscriber with no backlog (implementation-spec.md@1ed63958:887-891). INFERENCE, not stated in the spec: alerts emitted during a disconnect are never re-delivered, and the mount-only bell count does not refresh.
- Backoff has no jitter: "YAGNI; two streams per tab" (implementation-spec.md@1ed63958:910).
- Operator decisions (binding, 2026-10-22; old context.md@1ed63958:82-86): NC-D (inert `strategy_id=""` rows) deferred, FR-4 floor is the UI one-liner; x-trace-id must propagate, no C-03 waiver (reconnects reuse `tradingClient`/`notifyClient`). Batch execution ran under the operator's standing authorization (chat 2026-10-28/29, `old context.md@1ed63958:507-511, :552-555`; session_01NpS3HShZK6pSnogA7CFo2f: unattended `report` checkpoints, C-16 promotion auto-confirmed, PR opened and merge held) (old context.md@1ed63958:507-511).
