## Archive Synthesis — 2026-11-04 — /sdd-archiver

**What**: SEV-2 bug fix (debt-radar D-28, D-29; Track C) in xstockstrat-analysis only. `_fetch_bars_paged` now raises `_BarFetchError` ("refusing to return a truncated series") when a token-bearing request returns no fresh bar AND re-issues a non-empty `next_page_token`; an empty response token stays EOF. `RunBacktest` became a thin `@owner_scoped` wrapper over `_run_backtest(request, context, disarm)`: it reads `analysis.backtest.max_duration_seconds` presence-aware at call time (default 300, `0` = no limit, negative = 300 + WARN), runs the body under `asyncio.timeout`, and maps an expired deadline to `DEADLINE_EXCEEDED "backtest exceeded Ns deadline"`. A `_BarFetchError` (symbol or benchmark) now fails the whole run as `FAILED_PRECONDITION "backtest bar series incomplete: ..."`. No proto, no migration, no UI change. Merged #1369 (`484896de`), promoted via #1387 (`0cfaa489`), launched 2026-10-31. All 7 `@AC-*` are already promoted to `services/xstockstrat-analysis/acceptance/fix-analysis-backtest-bounds.feature`.

**Why (irrecoverable rationale)**:
- Rename-plus-wrapper beat every alternative because it kept the diff in the region peers 215/244/274 were editing minimal and kept the persistence tail out of the bound (operator instruction: "preserve as much as you can while having low rework"; old context.md@1ed63958:232). Disarming at `self._backtests[backtest_id] = result` means a run that times out during compute writes no evidence/history (keeps `@AC-3 @feature-149`), while a run past that point always finishes persistence and the `completed` event (design.md@1ed63958:87-97).
- `FAILED_PRECONDITION` (not `UNAVAILABLE`) for `_BarFetchError`: both causes (marketdata's `cursor = start` re-serve; the `_MAX_BAR_PAGES` cap) are deterministic, and the servicer reserves `UNAVAILABLE` for transient store outages (`:684/:2536/:2566` at design time), so a retrying agent/skill would loop (design.md@1ed63958:202-203).
- D-28 discriminator = option (a) (token sent AND response token non-empty) because marketdata's `cursor = start` fallback always re-serves the first page with its own non-empty token (a first page is only tokened when range > 500 bars), so (a) catches the real hazard and satisfies `product-spec.md:23` ("genuine EOF still returns") without a spec amendment (design.md@1ed63958:35-38, :181-183; operator gate approval 2026-10-22, old context.md@1ed63958:433-435).
- Whole-run failure was design's chosen behaviour, not an execute drift: one truncated symbol now fails the entire multi-symbol run (`FAILED_PRECONDITION`) and a benchmark `_BarFetchError` moves `UNKNOWN` -> `FAILED_PRECONDITION`; before, the per-symbol skip and "a partial run stays OK" let it through (design.md@1ed63958:59-62).
- Negative limit falls back to 300 rather than "no limit": a typo like `-1` must not silently remove the bound; only `0` disables (old context.md@1ed63958:205 in the r1 state block).

**Rejected alternatives**:
- Stricter D-28 rule (b): raise whenever a token was sent and the page has no fresh bars, whatever the response token — lost because it exceeds `product-spec.md:23` and needs a spec amendment + new AC (design.md@1ed63958:181-183). Note: recon had recommended this stricter form (recon.md@1ed63958:78-80, :202-203); design narrowed it.
- Whole-body `asyncio.wait_for` mirroring the screener (`:3786-3796`) — lost because a cancellation can land between the evidence write and the `completed` event, leaving a half-persisted run (design.md@1ed63958:195-196). Recon had recommended this (recon.md@1ed63958:208-210).
- Bounding only the compute section / `_compute_backtest`+`_persist_backtest` split — lost: too many locals to thread, collides with 215/274 (design.md@1ed63958:197-199).
- Skip the symbol with a `CoverageGap` instead of failing the run — lost: contradicts "fails loudly" and still writes evidence from a fault the run detected (design.md@1ed63958:200-201). Cost accepted: one bad symbol now fails a multi-symbol run (see Why).
- `UNAVAILABLE` for `_BarFetchError` (recon.md@1ed63958:144-145 suggested it) — lost, see Why.
- Mapping every `TimeoutError` to `DEADLINE_EXCEEDED` — lost: would misreport inner `wait_for` timeouts from peers 215/274; replaced by `cm.expired()` check that re-raises otherwise (design.md@1ed63958:186-187).
- Passing the asyncio `Timeout` object into the body — lost to a narrow `disarm` callable (C-18) (design.md@1ed63958:208).
- `SCALAR_BOUNDS_REGISTRY [0,3600]` bound in xstockstrat-config — lost: adds config-service scope and cannot catch the real hazard (positive-but-small value) (design.md@1ed63958:204-205).
- Retiring the key (OQ-1, would have needed config migration 033) — lost; spec default was enforce and the debate kept it (design.md@1ed63958:206-207).
- I-2 as a `details().startswith('backtest exceeded')` prefix match in the agent — lost: couples agent to analysis message text; and a retroactive I-2 fallback at step 4 — lost: reintroduces same-file collision with 273; ownership went to 273 before spec (design.md@1ed63958:184-190).
- G-1 fixed 90 s threshold from an assumed Cloudflare ~100 s origin timeout — lost: ungrounded in the repo, so the threshold became an operator input; and G-1 over completed pairs only — lost: biased low, so orphan-`started` counts were added (design.md@1ed63958:191-194).
