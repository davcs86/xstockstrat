## Archive Synthesis — 2026-08-16 — /sdd-archiver

**What**: Added exponential age decay (`exp(-ln(2)/half_life × age_hours)`) to the Opportunities queue's `signal_axis` ranking inside `_compute_opportunities`. A signal's contribution becomes `raw_conviction × source_weight × decay_multiplier` (composing multiplicatively with feature 134's `source_weight`). Age is computed from `ExternalSignal.ingested_at`, a proto field added by this feature to expose an already-stored DB column (`ingest.newsletter_signals.ingested_at NOT NULL DEFAULT NOW()`, migration 001) that `QuerySignals` had never selected. The half-life is configurable at runtime via `analysis.scoring.signal_decay_half_life_hours` (float, default 24h); 0 or negative disables decay for rollback.

**Why (irrecoverable rationale)**: The original 2026-05-26 spec targeted `combine_score`/`compute_signal_score` as invoked from `RunBacktest` — feature 097 had retired that blend before this spec was implemented, making the premise code-false on every axis. Retargeted to `signal_axis` on 2026-08-13 per explicit user direction. `ingested_at` was chosen (over source publication timestamp) because it is platform-controlled and immune to newsletter timestamp manipulation. `now_utc` is captured immediately _after_ the `_drain_active_signals` await (`:2098`) resolves — not before — to avoid a race where a signal ingested concurrently with that async call could carry `ingested_at > now_utc`, producing a structurally negative age. Thesis/direction selection deliberately stays keyed on raw conviction (not decayed): FR-1 scopes decay to `signal_axis` only. A new `get_float_present` method was required on `ConfigWatcher` because `get_float` uses `v.float_val or default` — a stored `0.0` is falsy in Python and would silently return the `24.0` default, defeating FR-3's rollback contract.

**Rejected alternatives**: Sentinel-value zero-trap workaround (negative half-life as disable signal) — diverges from FR-3 wording and `get_int_present` precedent. Doc-only NaN tripwire — `max()` argument-order-dependent. Companion `ingested_at_known` bool proto field — overbuilt; `HasField()` on the Timestamp submessage is the minimum fix. Inline decay inside the targets sub-loop — multiplied debug log volume by `len(targets)`. Code-level `min`-bound on `half_life_hours` at config-registration time — `isfinite()` use-site guard already closes the failure mode.

**Scars & gotchas**: `_compute_opportunities`'s signals-merge section is a **three-level nested loop** (symbol → targets/strategies → signals); decay, logging, and missing-count must be hoisted above the `targets` loop into a `sig_contribs` list. `session_end_seconds` (`servicer.py:2184`) is a bars-derived running max inside the bar-fetch loop — not in scope at the signals-merge write site (`:2163`) and not a wall-clock timestamp; do not confuse with `now_utc`. `sig.HasField("ingested_at")` is valid on a plain `google.protobuf.Timestamp` submessage (not a oneof); when absent (epoch 1970) decay underflows to ~0.0 for every signal — a platform-wide signal blackout. Treat as `decay_multiplier=1.0` (fresh). `ConfigWatcher.get_float` (`watcher.py:124-130`) uses `v.float_val or default` — stored `0.0` is falsy; use `get_float_present` for any analysis config key where 0 is a meaningful operator-set value. The `analysis.scoring.*` config keys are runtime-registered, not seeded by migration — they do not appear in config-ui until an operator issues a manual `SetConfig`. The getter unit tests for `ConfigWatcher` live in `TestConfigWatcherGetters` inside `test_analysis_servicer.py`, NOT in `test_config_watcher.py`.

**Permanent deviations**: design.md pseudocode showed `weight_for(sig.source)` → shipped `source_weights.get(sig.source, 1.0)` using the real landed feature-134 symbol `source_weights`. implementation-spec.md Step 6 said `get_float_present` tests go in `test_config_watcher.py` → shipped in `test_analysis_servicer.py::TestConfigWatcherGetters` alongside sibling getter tests.

Any future feature touching this function should check `merge-order.md` for existing coordination rows before assuming the current code shape.
